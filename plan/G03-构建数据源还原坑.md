# G03 · 构建数据源还原坑（全站工程纪律）

> 已两次实锤：直接改工具页 HTML 的 meta/简介/deep-dive，会在任何人跑 `_build.py` 时被 json/i18n 数据源**还原**。

## 问题清单
1. **meta description / title / WebApplication LD**：源在 `json/tools.json`、`json/industry-<ind>.json`、`json/industry-groups.json`、`i18n/tools/<ind>.json`——改 HTML 无效。
   - 实锤案例：egfr-calculator 误标修正两轮才根治（HTML 改完被 build 冲回，最终改 4 个 json 源）。
2. **deep-dive 区（dd-example/dd-list/FAQ）**：源在 `i18n/tools/content_deepdive.json`。
   - 实锤案例：convert-glucose「语义相反」workaround、sanwei 铅垂/水平厚度、detector-18 算例值。
3. **正文首个 `<p>`（含 CJK）**：`_prerender_tool_body` 用 `i18n/tools/<ind>-body.json` intro 覆盖；说明块必须用 `<div class="formula-desc">` 而非 `<p>`。
4. **h1/面包屑/面包屑 LD**：「只写一次」字段，缺失才注入，不刷新——改名需三处同步。

## 解决方案（固化 SOP，不必开发）
1. 任何「改文案」任务先 `grep -rl "<旧文案>" json/ i18n/` 判断是否有源；有源改源，无源改 HTML。
2. 收尾模板：改源 → `_build.py` → `grep -c` 新文案在 HTML 存活 → 提交。
3. 建议后续在 `_build.py` 加「源优先」警告日志（列为可选开发项 G03-DEV-1）。

## 受影响
全站 5008 页（凡涉及 meta/intro/deep-dive 文案修改的任务）。
