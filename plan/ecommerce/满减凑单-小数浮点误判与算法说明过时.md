# 满减凑单：小数浮点误判与算法说明过时

## 问题

候选价格和门槛直接用 JavaScript 浮点数相加比较。门槛 0.80、当前金额 0、候选 0.1 和 0.7 时，二者相加可能为 0.7999999999999999，搜索判定无法达到门槛，甚至提示全部候选不足，尽管金额合计恰好 0.80。页面公式说明仍描述单件、两件及全部候选策略，而实际代码使用最多 22 个候选的子集搜索，文案与实现不一致。静态分析，交互待复核。

## 解决方案

明确金额精度并使用整数分进行求和、比较和输出，对超过支持精度的输入提示用户；同步公式说明为当前子集搜索规则、每个候选是否只能使用一次及数量上限。验证恰好达标的小数、三件组合和候选不足场景。
