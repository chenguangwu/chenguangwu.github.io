# 工作协议：门禁提速与既有铁律（老板 2026-11-14 明确提速）

> 目的：解决「一个小问题跑一次全量门禁、积压不动」的慢模式。提速但**不丢质量铁律**。

## 一、提速新协议（覆盖旧「每改必跑全量门禁」模式）

1. **批量改、合并提交**：同类修复一次合并多个（目标每批 6–12 文件），减少门禁与提交次数。不再「一个小问题跑一次全量门禁」。
2. **门禁分层**：
   - 小改动只跑轻量校验：`node --check` 语法、`scripts/verify_<分类>_calc.js` 单分类 verify、`audit_verify_input_ids.js`、JSDOM 两态锁等秒级项；**不每次跑全量 `run_gates.py`**。
   - 一律 `env -u NODE_OPTIONS` 跑（NODE_OPTIONS shim 会破坏 process.env）。
3. **全量门禁频率**：每 **2–3 小时**跑一次 `env -u NODE_OPTIONS python3 scripts/run_gates.py`；跑通后**一次性 push**（攒批，避开 Actions cancel-in-progress）；其他时间**不跑全量、不 push**。
4. **门禁后台跑期间并行准备**：跑全量门禁时在后台挂着，期间把下几批方案确认好（读源码、定改法），跑完直接开干。
5. **本地 commit 照旧**：每批改完仍本地 commit（不 push），攒到 2–3h 窗口统一全量门禁 + push；push 前先 `git fetch origin audit/interaction-review` 并 `git merge --ff-only` 回流复核分支。

## 二、仍须遵守的既有铁律（不许因提速而丢）

- **先核验真伪再动手**：fake-tools 等清单多为 2026-11-04 快照，已被 `audit/interaction-review` 分支（冲刷 9017 文件）大量修好；动手前必须先 grep / 读源码确认「声称缺失的功能确实缺失」，禁止照单盲改。
- **改源为主**：改页面功能/默认参数/预设/公式/输入初值 → 同步更新 verify inputs/expect/ref 并清零；本项目源即 `tools/*.html`。
- **销账纪律**：修复后从分类清单**整条删除**条目（不得留 ✅）；同批在 `plan/已修复/` 新建交接档。
- **不擅改已上线内容**：之前线上已验证调好的内容不要擅改以免改出问题。
- **验证走可恢复路径**：`git diff` / `--skip-build`；禁止擅自批量删除；确需删由老板手动删。
- **部署闭环**：push 后**单次**查询 GitHub Actions run success 即算完成，**不再做线上 MD5 逐字节比对、不 sleep 等 CDN、不循环轮询**。

## 三、优先级

- 真功能缺陷（名不副实 C/D、死输入 A、算错 B）优先；纯文案对齐（P3）成本最低可顺手做。
- 一次性可合并的同类修复尽量同批：如多个「计时/音频类名不副实」工具一起加真实功能。
- 已确认被 audit 分支修好的条目（capacitor/child-support/court-fee/salary-after-tax/flow-cytometry/semen-analysis/gradient/stats-13 等）**不再重复改**。
