# NAT 类型通过不同连接端口比较误判

- **受影响工具路径**：`tools/telecom/nat-type-test.html`；共用实现 `js/network-toolbox.js`。
- **问题描述**：工具对每个 STUN 服务器分别创建候选收集过程，比较各映射端口是否相同并标为锥形或对称 NAT。不同连接不保证使用同一本地端口；即使映射端口一致，也不能由此推断过滤行为或完整 NAT 类型，当前分类可能误导用户。请求还会接触第三方 STUN，需一并核对项目数据安全约束。
- **解决方案**：不把现有结果判定为 NAT 类型；在无法控制同一源地址和端口、无法检验过滤行为的浏览器环境中显示“无法确定”，解释观测范围及限制。确需精确检测时，先评估与项目纯前端、禁外部服务约束的兼容性，不默认引入后端。
