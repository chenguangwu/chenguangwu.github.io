# 子网规划零前缀与点对点广播字段

- **受影响工具路径**：`tools/telecom/subnet-planner.html`
- **问题描述**：原前缀为 /0、按数量划分 1 个子网时，新前缀仍为 /0，但 JavaScript 左移 32 位相当于左移 0 位，新掩码错误显示为 255.255.255.255。/31 按点对点链路显示两个可用地址，却仍将末地址标为广播地址；/32 同样显示广播地址，语义不清。
- **解决方案**：对 /0 掩码显式处理，统一两种划分模式的边界规则；为 /31 点对点和 /32 单主机说明适用场景，不将端点地址误标为普通子网广播地址。覆盖 /0、/30、/31、/32 和数量为 1 的样例。
