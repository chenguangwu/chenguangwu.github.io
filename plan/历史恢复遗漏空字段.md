# 历史恢复未清空原本为空的字段

## 问题描述

共性代码先用 `if(v!==''&&v!=null) out[e.id]=v` 跳过空字段保存快照，恢复时只遍历记录里的字段赋值，不清除其他控件。若旧记录中某个字段为空、后来填入该字段，再恢复旧记录，后来输入仍会参与重新计算，结果可能不同于保存时。对临床评估尤其需要优先处理。

已从源码确认的代表路径：`tools/nephrology/jixingshensunshang-kdigo-fenqi.html`。例如保留一个 `uo12` 为空的有效记录，随后填入低尿量，再恢复该记录：`uo12` 不在旧快照中，因此不会被清空，而计算会读取它并可能改变分期。已在隔离的本地 Chromium 中实测：基线/当前肌酐均为 100、体重 70、时间 24 小时、未进行 RRT、12 小时尿量为空时保存的结果为“无 AKI”；随后把该尿量设为 0 并点击旧记录，尿量仍为 0，结果变为“AKI 2 期”。其他历史列表交互和时间合并逻辑仍需覆盖。

## 范围核查

静态筛选同时包含上述省略空值语句、`for(var k in rec)` 和 `TBKit.history.mount` 的页面共有 3,043 个；这只是候选范围，个别页面可能另有清空逻辑，不能据此断言全部受影响。可从仓库根目录用以下只读脚本输出完整路径，后续按高风险临床工具优先逐类复核：

```sh
python3 - <<'PY'
from pathlib import Path
for p in sorted(Path('tools').glob('*/*.html')):
    s = p.read_text(encoding='utf-8')
    if "if(v!==''&&v!=null) out[e.id]=v" in s and 'for(var k in rec)' in s and 'TBKit.history.mount' in s:
        print(p)
PY
```

## 解决方案及验收

保存和恢复完整表单状态，包括空值、复选框/单选框未选状态；恢复前明确清理本工具纳入快照的字段，避免误清无关控件。旧记录无法区分历史空值与不存在字段时，定义可预期的兼容处理并明确提示；不要直接把旧结果当作新结果。优先用有可选项的计算页以及 KDIGO 页面验证：保存记录 A、修改或新增字段得到 B、恢复 A 后核对所有字段及计算结果；覆盖重置、刷新、切换语言和浏览器本地历史清空。
