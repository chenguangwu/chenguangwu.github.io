# G07 · 性能与移动端（全站）

> **2026-11-21 全量收口核验**：本文件所列问题已处理完毕，仅作历史档案；当前代码由 210 个 verify 全绿、4,426 页构建、12,102 段内联脚本 0 语法错误及全量门禁覆盖。

## 已知问题
### P1. 页面体积与请求数
- 描述：真实工具页平均 30.7KB HTML（2026-11-21 复核，原「20KB」已更正），公共 JS（common.js 含 TBKit+enhance 系列）体积大且全站必载；移动端弱网首屏可感知慢。
- 方案：a) common.js 按需分包（share/chart/preset 懒加载）；b) 关键 CSS 内联审计；c) Lighthouse 移动端分数全站抽样建基线。
- 受影响：全站（js/common.js）

### P2. enhanceTimeInput 系统性副作用
- 描述：js/common.js ~3478 行把 input[type=time] 转 text+时分 select，破坏页内「固定下标 querySelectorAll」取值全站扫描仅 1 页显式中招，但该增强与自定义 time 逻辑组合仍有回归风险。
- 方案：enhanceTimeInput 增加 `data-tb-noenhance` 白名单跳过；或改为不替换 DOM、仅附加 picker。
- 受影响：js/common.js（凡用固定下标取 time input 的页面）

### P3. 移动端交互可用性
- 描述：多输入行在窄屏的布局、number 键盘（inputmode）覆盖不全；图表 touch 目标小。
- 方案：抽样 20 热门页真机过一遍（G06 S1 同步做），补 inputmode/viewport 适配清单。
- 受影响：全站表单页

### P4. SW 缓存体验
- 描述：三桶缓存策略已稳定；但「更新后旧页面先渲染再刷新」的体验在弱网偶发闪变。
- 方案：低优先；观察 G06 上线后反馈再定。

### 已落地：导航数据瘦身 + 面板按需加载
- 症结：全站 4700+ 工具页都由 `js/nav-menu.js` 渲染顶部导航，为拿到「12 个一级分类 + 子行业名/图标/数量」
  在**每个页面冷启动**下载了 1.2MB 的 `industry-groups.json`（其中 99% 是下拉面板才用的工具卡描述）。
- 改法：`scripts/gen_industry_groups.py` 在同一次构建里额外产出 `json/nav-groups.json`（18KB，仅分类骨架）；
  `js/nav-menu.js` 首屏只拉瘦身版，用户**第一次悬停/点击一级分类**时才拉全量，工具列先显示「载入中…」再补齐；
  全量未到时切换子行业会自动补拉后重渲染。样式补 `.tb-megapanel-loading`。
- 效果（同机同法复测 8 页）：首屏传输量 **1,830 KB → 665 KB（-64%）**；首页仍按需用全量数据（分类卡片需要）。
- 交互回归（真机 hover/click）：首屏 json 请求仅 `nav-groups.json`；悬停后出现 `industry-groups.json`，
  面板 9 个子行业 / 24 张工具卡、无 loading 残留；切换子行业卡片正常重建。
