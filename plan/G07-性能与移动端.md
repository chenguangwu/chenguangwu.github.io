# G07 · 性能与移动端（全站）

## 已知问题
### P1. 页面体积与请求数
- 描述：平均页 20KB HTML，但公共 JS（common.js 含 TBKit+enhance 系列）体积大且全站必载；移动端弱网首屏可感知慢。
- 方案：a) common.js 按需分包（share/chart/preset 懒加载）；b) 关键 CSS 内联审计；c) Lighthouse 移动端分数全站抽样建基线。
- 受影响：全站（js/common.js）

### P2. enhanceTimeInput 系统性副作用
- 描述：js/common.js ~3478 行把 input[type=time] 转 text+时分 select，破坏页内「固定下标 querySelectorAll」取值全站扫描仅 1 页显式中招，但该增强与自定义 time 逻辑组合仍有回归风险。
- 方案：enhanceTimeInput 增加 `data-tb-noenhance` 白名单跳过；或改为不替换 DOM、仅附加 picker。
- 受影响：js/common.js（凡用固定下标取 time input 的页面）

### P3. 移动端交互可用性
- 描述：多输入行在窄屏的布局、number 键盘（inputmode）覆盖不全；图表 touch 目标小。
- 方案：抽样 20 热门页真机过一遍（G06 S1 同步做），补 inputmode/viewport 适配清单。
- 受影响：全站表单页

### P4. SW 缓存体验
- 描述：三桶缓存策略已稳定；但「更新后旧页面先渲染再刷新」的体验在弱网偶发闪变。
- 方案：低优先；观察 G06 上线后反馈再定。

## 2026-11-03 审计补充（只读审计）

### 确认缺陷 G07-A：公共资源体积与「平均页 20KB」描述不符（中）
- 问题：本文件 P1 写「平均页 20KB HTML」，实测真实工具页（排除 `index.html`）平均 **30.7KB**、中位 30.0KB、P95 45.5KB、最大 77.8KB；公共 JS `js/common.js` **212KB**、`js/tool-i18n-en.js` **684KB**（仅英文态动态加载）、`js/i18n.js` 56KB、`css/common.css` 72KB。移动端弱网首屏成本被低估。
- 证据：`python3` 统计 4775 个工具页（含 83 存根）体积；`ls -lh` 上述资源。
- 影响：全站；首屏 LCP/带宽。
- 方案：P1 分包优先级提高——`common.js` 已 212KB，建议把 `chart`/`share`/`preset` 拆为按需加载（预设条现为全站 3845 页使用，可保留常驻，chart/share 懒加载）；大页面（>60KB，P95 以上）单独列清单做内容/内联脚本瘦身。
- 未覆盖：未跑 Lighthouse（本轮禁跑门禁/构建），无真实设备数据。
