# 二维码：容量图与实际生成模式和批次不一致

受影响工具：`tools/it/qrcode.html`

问题：生成器会根据单行内容选择数字、字母数字或字节模式，并将多行拆成多个二维码；容量图却把整个输入按 UTF-8 字节合并计数、仅查字节模式容量，并称其为当前内容所需最小版本。纯数字输入可能被高估，多行输入甚至可能显示超容量，而各行实际均可生成。

解决方案：图表应与生成共用逐项内容、编码模式和实际编码能力；批量时展示选中行或每行的版本，并标明估算条件和超限状态。分别用纯数字、字母数字、中文、单行与多行，在各纠错级别下对照实际编码器的模块数。

证据范围：本机无头 Chrome 以本地文件加载，并用图表接口桩捕获数据；30 位纯数字在 M 级实际生成版本 1，图表数据却为版本 3。可视图表、批量及 HTTP 场景仍待复核。
