# 时间格式转换：仅按位数推断单位会误读历史时间戳

## 问题

纯数字按字符位数判断秒、毫秒、微秒或纳秒，缺少手动选择单位。有效的 Unix 毫秒时间戳 `1000` 表示 1970-01-01 00:00:01 UTC，却被按秒解释为 00:16:40；同一个数字加前导零也会改变位数和解释结果。单位并不能由位数唯一确定，用户处理早期时间戳或不同精度数据时容易得到完全不同的日期。

## 解决方案

增加秒、毫秒、微秒、纳秒的显式选择，自动识别只作为带歧义提示的便利功能，并显示实际采用的单位；说明 JavaScript Date 对亚毫秒部分的精度处理。覆盖短毫秒、前导零、负数及各单位相同时间点的对照。
