# Unicode 零宽匹配重复计数

## 受影响工具路径
- `tools/it/regex.html`

## 问题描述
全局零宽匹配只将 `lastIndex` 加 1；启用 Unicode 标志时，代理对中间位置可能回退到字符起始位置，重复匹配。用页面 Worker 原脚本运行 `/(?:)/gu`，文本为 `😀`，返回 1001 个位置均为 0 的匹配，而正确位置是 UTF-16 偏移 0 和 2。高亮、匹配数及复制结果因此不可信。

## 解决方案
按照 Unicode 模式推进完整码点，非 Unicode 模式推进一个码元；覆盖表情、普通字符、混合文本、行首行尾等零宽表达式，确认位置和数量与 JavaScript 标准匹配行为一致。
