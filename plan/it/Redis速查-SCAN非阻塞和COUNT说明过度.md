# Redis 速查：准确说明 SCAN 的开销

- 受影响工具：`tools/it/redis-cheatsheet.html`
- 问题：正文和 FAQ 将 SCAN 描述为“不阻塞”，并称 COUNT 控制单次扫描量；实际每次调用仍会占用服务器执行时间，COUNT 是工作量提示而非严格返回数量上限。用户可能据此在繁忙实例上设置过大的扫描量。以上依据页面文案和实现语义分析，需对照所支持的 Redis 官方文档版本复核。
- 解决方案：说明渐进迭代降低单次遍历压力但不保证零阻塞，COUNT 为提示、结果可重复或为空且游标归零才结束；补充限速、去重与线上负载观察示例，同步 FAQ、结构化数据及中英文内容。
