# Base64 转换器：非规范填充位未提示

## 问题

Base64 解码直接调用浏览器的 `atob`，没有检查最后一个编码字符中未使用的位。使用 Node 的 `atob` 对照，`Zg==` 和非规范的 `Zh==` 都解成 `f`；浏览器的宽松解码可能掩盖编码损坏或不规范输入。Base32 路径已有末位检查，两种模式对严格性的表现也不一致。具体浏览器行为待复核。

## 解决方案

提供严格校验或清晰的非规范提示，检查末组未使用位、填充数量和所选字母表；若保留宽松解码，说明其接受范围并允许复制规范化编码。验证标准和 URL 安全模式、可省略填充的输入及非零尾位。
