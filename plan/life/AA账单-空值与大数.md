# AA 账单：空值和大额计算

受影响工具：`tools/life/bill-splitter.html`

## 空总金额仍输出零元结论（源码确认）

简单模式 `calcSimple()` 把空总金额按 0 处理，并输出各人分摊额和“合计已对齐”，与空值不应产生计算结论的规则冲突。0 元本身仍是合法输入。

解决方案：区分空串与数字 0，空串只提示填写金额并清除旧结果、导出数据；输入 0 时正常显示零元分摊。验证有效金额→清空→0→恢复有效金额。

## 简单模式缺少安全金额边界（源码确认，需浏览器隔离复现）

简单模式虽然校验输入有限，但 `total * (1 + tip / 100) * 100` 可能溢出或超过安全整数；随后浮点误差可使 `rem` 成为巨大的有限数，`for (k < rem)` 会执行极多次而冻结页面。例如总金额 `1e100`、小费 0、三人各 1 份时，按代码算得余数约 `1.24e86`；总金额 `1e308` 则会使分值溢出、余数变成 `NaN`，导致无效结果。高级模式已经检查 `Number.isSafeInteger(totalCents)`，简单模式没有同等检查。极端值复现应放在可终止的独立浏览器进程中。

解决方案：在分配余数前校验总额、小费计算结果及分值均有限且为安全整数，并给出可理解的上限提示；同时检查每人份数总和与中间乘积，保证循环有有限上界。验证正常分摊、0、最大边界及超大金额/小费输入，确保不冻结且不保留旧结果。
