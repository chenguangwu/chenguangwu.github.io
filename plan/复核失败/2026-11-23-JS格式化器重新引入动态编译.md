# JS 格式化器重新引入动态编译

- 来源：`plan/security-sweep/part-01.md` 中 `tools/it/js-formatter.html` 动态编译治理记录，原结论为已移除 `new Function(src)`。
- 现状：`tools/it/js-formatter.html` 的 `doValidate()` 再次使用 `new Function(src)`，`minifyJs()` 也对输出调用 `new Function(out)`。两处只编译、不调用生成函数，不能据此认定会执行用户代码，但与原「移除动态编译」修复结论不符；限制 `unsafe-eval` 的 CSP 环境会拒绝这两处编译，使语法检查及压缩误报失败。
- 建议：使用本地静态 JavaScript 解析器进行语法检查，或恢复明确标注能力边界的静态检查；避免动态代码编译，并在禁止 `unsafe-eval` 的 CSP 下验证普通脚本、非法语法及压缩结果。模块语法需明确支持范围。
