# 复核失败：F-N209 SIN 全零与字母剥离误判有效

## 原移交记录

- 原问题：`tools/finance/sin-validator.html` 静默剥离非数字字符（如 `130692544abc`），以及 `000000000` 通过 Luhn 后被判有效。
- 修复声明：仅允许数字、空格和连字符，其他字符直接拒绝；首位 0 不判有效；有效号和带分隔符的输入正常通过。
- 移交验证：财务分类验证 426/426，输入 id 审计通过，声称非法字符均被拒绝。

## 独立复核结果：部分修复，整条失败

在真实 JSDOM 中执行页面业务脚本并调用 `validate()`：

- `000-000-000` 判无效；`130692544abc` 提示非法字符；`130692544` 与 `130 692 544` 判有效，以上通过。
- 输入纯字母 `abc`，输出却是「等待输入...」，并未按移交声明提示非法字符。`validate()` 先以剥离后的空 `digits` 判断等待输入，导致非法字符守卫未执行。
- 输入 `130692544<img src=x onerror=alert(1)>`，虽然提示非法字符，`#output` 内实际出现一个 `img` 节点。用户输入 `raw` 先插入 HTML 字符串，新增非法字符分支又将其写入 `innerHTML`，因此拒绝路径仍解析不可信 HTML，可能执行注入的事件处理代码。

## 位点与待处理

- `tools/finance/sin-validator.html` 的 `validate()`：约第 245–253 行。
- 以原始输入是否为空区分空态，再优先拒绝非法字符；所有输入回显必须按文本安全插入，不能交给 `innerHTML` 解析。补测纯字母、仅标点和包含 HTML 的非法输入，并断言无注入节点或事件执行；保留有效输入及全零回归。
