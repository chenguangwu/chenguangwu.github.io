## 问题与修复

- 失败点：① 旧示例 `123456789`（9 位）在 UPC-A（需 11/12 位）、ITF（需偶数位）根本无法生成；② 「请按规范长度与校验位填写」与页面实际行为相反 —— Code 128 / UPC-A 的校验位由工具自动算，Code 39 与 MSI 的校验位是可选且由工具追加，ITF 页面并不代算 GTIN-14 校验位。同族 EAN 页的中文源与页面早已改成正确文案，说明该模板缺陷只修了一页。
- 根因：`i18n/tools/content_deepdive.json` 的条码族 examples 由同一模板批量生成，各页字符集、长度、校验位口径不同却共用了含糊文案；英文映射键与值也沿用旧串。
- 修复位点（每页三处逐字同步）：`i18n/tools/content_deepdive.json` 的 `it/barcode-<slug>.examples[0].body`、`i18n/tools/en/it/barcode-<slug>.json` 的中文键 + 英文值、构建后页面 `tools/it/barcode-<slug>.html` 的 `dd-ex-body`。
  - CODE128：任意 ASCII 文本 `ABC-1234`，模 103 校验符号自动计算，偶数位纯数字自动切 Code C，无固定长度档位。
  - CODE39：`CODE-39`，`*` 起止符由工具添加，Mod 43 校验位仅勾选时由工具追加。
  - ITF：14 位 `12345678901234`，只保留数字、奇数位前补 0 后两两交织；ITF 无自校验，GTIN-14 mod 10 校验位须业务系统先算好，本页不代算（如实说明，不冒称功能）。
  - MSI：`1234567`，无 / Mod 10 / Mod 11 / Mod 1010 由工具追加校验位，无需手填。
  - UPC：11 或 12 位 `03600029145`，11 位自动补校验位、12 位核对末位并在不符时给出正确值。
- 顺带清理：`i18n/tools/en/it/barcode-ean.json` 里与新中文文案并存的旧孤儿键（旧中文示例 + 旧英文译文）已删除；EAN 页新键译文原本已存在，无需改动。全族 `请按规范长度与校验位填写` 已零残留。

## 独立复核失败（2026-11-10）

- CODE128 新示例文案声称可输入「任意 ASCII 文本」，与实际编码器不符：调用真实 `ToolBoxBarcode.encode('code128', '\u0001a')`（两个字符均为 ASCII，码点 1 和 97）返回 `ok=false`，错误地提示仅支持 ASCII 0～127。编码器只选择单一 A/B 子集，不支持同一串同时需要控制符与小写字母的子集切换。故不能宣称任意 ASCII；当前文本输入框也不能输入全部控制字符。
- 待处理：将中英文示例及相关说明改为准确的可输入与编码范围，或实现所承诺的子集切换；以真实条码库而不是只断言桩透传来覆盖边界。
