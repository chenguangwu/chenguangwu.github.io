## IT-N492 / IT-N493 Codabar 深度解析示例仍错误

- 页面：`tools/it/barcode-codabar.html`；构建源：`i18n/tools/content_deepdive.json` 的 `it/barcode-codabar`。
- 数据位拒绝 `A1B2C` 和 `AAA` 已验证；但交接包含原复核的深度解析问题，源和页面仍写「输入数字串（如 `123456789`）→ 渲染 CODABAR 条码图形；请按规范长度与校验位填写」。该输入缺 A–D 起止符，实际不能生成；标准 Codabar 不要求校验位，页面同一 FAQ 也称不含校验位。
- 待处理：修改构建源及英文内容为实际可用的起止符示例和准确校验位口径，核对构建后的页面；不得仅改公式区。

## D-N21 SVG 过期回调提前退出导致对象 URL 泄漏

- 页面：`tools/design/svg-to-png.html` 的 `generate()`。原问题中清空后旧图片不得恢复预览和下载结果已修复。
- 但这次加的过期 token 守卫位于 `URL.revokeObjectURL(url)` 之前，旧 `onload` 和 `onerror` 一旦过期即 `return`，对应 blob URL 永不释放。独立运行页面 `generate()`：创建 `blob:1`，清空并再次转换，然后触发旧 `onload`，得到 `created=["blob:1"]`、`revoked=[]`；反复转换会累积占用内存。
- 待处理：过期的成功及失败回调均释放各自对象 URL，同时保证旧回调不改写新预览或下载结果；覆盖两类旧回调及连续转换。

## IT-N421 标签去重跨越扩展与私有段导致合法标签被拒

- 页面：`tools/it/locale-lookup.html` 的 `__lcValid()`。原两个重复 variant / 扩展 singleton 已拒绝，但新逻辑把所有 5–8 位子标签作为 variant、所有单字符子标签作为扩展 singleton，不区分所处段落。
- 独立调用：`en-u-ca-gregory-x-gregory` 和 `en-US-x-1-1` 均返回 false；`Intl.getCanonicalLocales()` 均接受。前者重复文字分别处于 Unicode 扩展和私有用途段，后者的 `1` 均为私有用途子标签，不违反 variant 或 singleton 的唯一性。
- 待处理：按语法位置仅对真正的 variant 和扩展 singleton 分别判重，私有用途 `x` 后停止扩展判重；覆盖重复与合法跨段同名。

## IT-N555 CJK 扩展块末尾未分配码位仍伪造名称

- 页面：`tools/it/unicode-lookup.html` 的 `isCjkAssigned()`、`lookupName()`。韩文算法和 `U+3FFFF` 已验证，但代码把整个区块末尾都当作已分配。
- `lookupName(0x2B73F)`、`0x2B81F`、`0x2CEAF`、`0x2EBEF`、`0x3134F` 均返回 `CJK UNIFIED IDEOGRAPH-…`；Python Unicode 15.1 `unicodedata.name(chr(code), 'UNASSIGNED')` 对这五个码位均返回 UNASSIGNED。交接声明只覆盖真实已分配区间，但实际仍伪造名称。
- 待处理：按明确版本的 Unicode 已分配码位而非区块边界判断，并核对各扩展区首尾和未分配码位。

## IT-N355 单键嵌套序列仍生成多个或零个 XML 根

- 页面：`tools/it/yaml-to-xml.html`。单键平坦多元素数组已包裹 root，但判断只看外层数组长度，`ser()` 会递归展开内部数组。
- 页面真实输入 `items:\n  -\n    - a\n    - b` 解析为单个嵌套数组，输出 `<items>a</items><items>b</items>`，仍有两个并列根；独立调用 `jsonToXml({items:[[]]}, '', false)` 输出空串，没有根元素。
- 待处理：根据实际递归序列化结果确保唯一根，保留普通单元素行为，覆盖空、嵌套及多层数组。

## IT-N549 长词库后缀突破最大长度

- 页面：`tools/it/team-name-generator.html` 的 `generate()`。数字和符号后缀不再丢失，但词库后缀可能长于最大长度，`Math.max(1,maxLen-suffix.length)` 无法同时保证后缀与长度。
- 独立运行实际函数：领域创意、古风、最大 6、词库后缀、种子 x、数量 30，输出含 `G Collective`、`I Studio`，长度分别 12、8，超过用户最大 6。
- 待处理：为超长词库后缀定义可用约束策略，保证最终名称不超限；覆盖词库、数字、符号和短长度。

## IT-N358 多行数组注释仍破坏引号内内容

- 页面：`tools/it/toml-to-yaml.html` 的 `stripComment()`、`tSplitTop()`。交接的注释 `# ]` 双引号普通例已正确，但剥注释只识别双引号且仅查看引号前一个字符。
- 独立执行实际 `parseToml()`：合法输入 `dependencies = [ # ] note\n  'a#b',\n  'tokio',\n]` 预期 `['a#b','tokio']`，实际仅得到一个错误字符串 `"'a\n'tokio'"`；`#` 在 TOML 单引号字面字符串内却被当成注释，后续元素也被合并。双引号字符串末尾有转义反斜杠后接注释也会错误判定引号状态。
- 待处理：区分 TOML 基本字符串、字面字符串和真实注释，并正确处理转义反斜杠；覆盖多行数组和注释中的括号。
