# ToolBox 计划与修复总控（MASTER）

> **本文件只记规则与索引，不记进度、批次流水、修复清单或状态快照。**
> 修复内容先写进 `plan/已修复/` 待复核；写完记录后，原任务文件中的对应条目必须整条删除。复核通过后，该记录**直接删除**；复核失败则写入 `plan/复核失败/<日期>-第N批.md`，并从 `plan/已修复/` 删除原记录，待重做后重新移交。

## 0. 最新规则（2026-11-21 定，最高优先级）

1. **MASTER 只记规则**：不再往本文件写「最新进度」「已修到第几批」「门禁日志」「分类状态」等任何流水；进度以 `git log`、`plan/复核失败/` 与现存未复核记录为准。
2. **先建修复记录，再删原条目**：每批在 `plan/已修复/` 新建 `YYYY-MM-DD-<分类>-第N批-<主题>.md`；记录落盘后，把当前任务文件（`plan/` 根目录下尚未收口的台账）中的对应条目（标题及其全部子项）**整条删除**，不留 `✅ 已修` 占位。
3. **`plan/已修复/` 是复核前暂存区**：禁止新建 `plan/已修复归档`、`已修复归档` 或任何二级归档目录；**复核通过 → 直接删除该记录，不保留、不归档**；复核失败 → 写入 `plan/复核失败/<日期>-第N批.md` 并从 `plan/已修复/` 删除原记录，待重做后重新移交。
4. **修复方只负责修复与移交**：修复、验证、本地提交后移交；是否通过由其他 agent 独立复核，修复方不得自行判定复核通过。
5. **只本地提交，不 push**：除非老板在当轮明确要求推送，否则只做本地 commit，不执行 `git push`。
6. **任务文件只有全部条目清零才能删**：文件内仍有任何未修复、未实现或未明确结案的条目（含低优先增强、待核项）时不得删除；不得以「已判定为非问题」「属于增强项」为由提前删文件。只有每条都已有修复记录或明确处置结论、文件内再无任务项时，才删除该任务文件。
7. **按文件顺序逐文件收口**：按 `plan/` 根目录现存任务文件的路径顺序选定当前任务文件，再按文件内条目顺序从上到下修复；当前文件全部条目处理完，才进入下一个文件，不得跨文件东修一块、西修一块。当前文件全部修完后按第 6 条删除该任务文件。
8. **清单内连续执行，不因单批停下**：全量扫描形成清单后，按清单一批接一批修复、验证、本地提交，不等待逐批确认；仅当需要专业口径裁断、涉及高危操作或用户明确叫停时暂停。每轮清单清零后自动进入下一轮扫描；连续两轮无新增可修项才视为完工。
9. **扫描与修复分两阶段**：所有现存任务清零后，按第 5 节 8 类一次性全量扫描、先建齐完整清单，再集中修复；禁止扫一类修一类、修一批再回头扫下一批。修复期间不重扫，清单清零后才启动下一轮扫描。

## 1. 目录与职责

- `plan/MASTER.md`：规则与索引，唯一总控文件。
- `plan/*.md`：现存任务文件或参考台账；只有仍含未结案条目的才是任务文件，全部清零后按第 6 条删除。
- `plan/guidelines-map.md`：指南/量表版本参考台账（参考文档，非任务），登记页面已标注的指南年份与替代关系。
- `plan/units-factors.md`：单位与换算因子基准（参考文档，非任务），供页面、verify 与正文算例统一口径。
- `plan/已修复/2026-11-23-量表总账白名单历史档案.md`：量表加权与白名单审计历史档案（原 `plan/scale-ledger-whitelist.md`，已归档）。
- `plan/scan-remaining-2026-11-23.md`：8 类全扫后仍剩余的条目（唯一现存扫描任务文件）。
- `plan/已修复/`：修复后待复核记录，一批一文件；复核通过后删除该记录，复核失败移入 `plan/复核失败/`。
- `plan/复核失败/`：复核未通过条目；修复方重做后移回 `plan/已修复/` 重新移交。
- `agent` 工作区、`/tmp`、构建产物不存放长期任务资料。

## 2. 修复协作流程

1. **先核验再动手**：`plan/` 中的旧条目可能是历史快照，动手前读当前源码确认问题仍存在；不得照单盲改。
2. **一批一主题，按文件推进**：同一任务文件内优先合并同类问题成批修复；只有当前文件全部修完并删除后，才按路径顺序进入下一个任务文件。
3. **同步用例**：改公式、阈值、选项、空态或提示时，同步更新对应 `scripts/verify_<分类>_calc.js` 的 inputs / expect / ref，并确保用例具备判别力（不能只是输入回显或默认态重复）。
4. **构建与轻量校验**：每批至少跑 `python3 _build.py`、内联脚本语法检查、`python3 _test_static.py`、对应分类 verify；改 `css/js/json/i18n` 必须先构建再提交。
5. **全量门禁**：`env -u NODE_OPTIONS python3 scripts/run_gates.py --skip-build` 按 2–3 小时节奏在后台跑；跑全量期间并行准备下一批，不空等。
6. **记录**：在 `plan/已修复/` 写清原问题、修复位点、验证证据、构建/门禁结果；随后删除原任务条目。
7. **复核**：复核通过 → 直接删除该记录（用户明确要求，不保留）；复核失败 → 写入 `plan/复核失败/<日期>-第N批.md`，并从 `plan/已修复/` 删除该记录，待重做后重新移交。

## 3. 内容与构建数据源规则

- **文案走源**：`intro` / `meta description` / FAQ / deep-dive / 英文文案由构建从 `i18n/tools/<行业>.json`、`i18n/tools/content_deepdive.json`、`i18n/tools/en/<行业>/<slug>.json`、`i18n/guides/<slug>.json` 等源重注入；直接改 HTML 可能被 `_build.py` 还原。
- **`formula-desc` 例外**：页内公式说明块可直接改 HTML；说明块用 `<div class="formula-desc">`，不要用 `<p>`，避免被首个 `<p>` 的 intro 预渲染覆盖。
- **JSON-LD FAQ**：工具页 FAQPage 结构化数据不由 `_build.py` 重建；改 FAQ 正文后要同步手改 JSON-LD，并用 `json.loads` 校验。
- **改后复查**：手改工具页后必须重跑构建并抽查关键串仍存在；被覆盖时改数据源，不反复手补。
- **URL 与存根**：删除或迁移工具页按项目 AGENTS.md 的 URL 维护规则处理；`TOOLBOX-REDIRECT` 存根到期必须物理删除，并提交死链。
- **纯前端**：不得引入后端、上传用户数据；计算与历史留在浏览器本地。

## 4. 验证边界

- 静态检查、node 复算和 verify 用例只能证明代码与用例一致，不能替代临床阈值、处方补偿、法规口径等专业复核。
- 涉及医疗、法律、金融等专业判断的条目，若无法确认权威口径，移入待裁断清单，不强行判通过或失败。
- 抽样验证优先覆盖改动页的关键结果、边界输入、空态和英文态；不以“页面能打开”作为生效判据。

## 5. 完工后循环质量扫描（2026-11-22 定）

> 所有现存任务文件全部清零、`plan/` 根目录只剩参考台账后，任务不算结束，必须再起一轮「问题扫描」。**扫描与修复必须分两个阶段：先把 8 类问题一次性全部扫描完、形成完整任务清单，再集中进入修复；禁止扫一类修一类、修一批再回头扫下一批。** 修复期间不重新扫描，只按已形成的清单逐条收口；清单全部清零后，才启动下一轮全量扫描。连续两轮全量扫描均无新增可修项，才视为真正完工。

扫描范围以 `tools/` 工具页为主，同时覆盖 `guides/` 与站点公共资源，按以下 8 类分桶：

1. **功能错误 / Bug / 可优化补齐**：计算结果错、边界与空态异常、事件绑定失效、导出/复制/历史不可用、可补的实用能力。
2. **UI 布局异常 / 可改进美观度**：错位、溢出、移动端不可用、控件拥挤、配色与层级不一致、可读性差。
3. **中英文不全**：英文态残留中文、缺英文键；**重点排查缺中文**（`?lang=en-US` 正常但简体态露出英文），专业名词与单位符号除外。
4. **SEO 文案**：描述过短、信息不全、与实际功能不符或表述错误；标题、H1、描述、结构化数据不一致。
5. **新增同类工具**：在现有分类下补空白工具，**必须满足纯前端、无后端、无上传、浏览器本地完成**；一次只新增可独立验证的小批。
6. **无用脚本文件清理**：未被任何页面/构建/门禁引用的一次性脚本、临时产物、重复工具脚本；删除前必须全站检索引用并跑门禁确认。
7. **批量脚本误插功能**：模板或批量脚本给页面插入了该工具实际不需要的模块（无关输入、无效按钮、多余导出、通用占位区等），按页核对后删除。
8. **其他长期有益建议**：性能、可维护性、内链结构、可访问性、数据源一致性等；只落为可执行任务，不写空泛建议。

扫描产出的任务文件统一放 `plan/` 根目录，文件名体现分类（如 `scan-bugs.md`、`scan-i18n.md`）；每条必须带页面路径、复现/判定依据、期望结果。**必须 8 类全部扫描完成、清单一次性建齐后才开始修复；扫描阶段只读与记录，不改代码。** 修完按第 2 条写入 `plan/已修复/` 并删除原条目。
