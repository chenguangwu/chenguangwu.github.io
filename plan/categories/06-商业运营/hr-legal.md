### L-N1 年假分档在 10/20 年整点错档（高，确认）
- 问题：`standardAnnualLeave` 用 `years <= 10`、`years <= 20` 判断，10 年整仍给 5 天、20 年整仍给 10 天，与同页公式「满 10 年不满 20 年为 10 天、满 20 年为 15 天」相反；页面自带预设「老员工 10 年工龄」正好落到错误档。
- 证据：`tools/hr/annual-leave-calc.html:242-247` 判定，`:123` 规则文案，`:369` 预设 tenure=10。node 原函数复算：tenure=10、months=12 → 5.0 天；tenure=20 → 10.0 天；tenure=10.1 → 10 天、20.1 → 15 天。
- 影响：该页会把整 10 年、整 20 年员工的法定年假少算 5 天，且与年假折算页的口径无法对齐。
- 方案：改为 `years < 10` / `years < 20`；补 10/20 整点与 9.9/10.1/19.9/20.1 回归用例，并把预设标签改为可复现的「10 年工龄」。

### L-N2 五险一金深度解析承诺「自动封顶」，页面无社平/上下限输入（中，确认）
- 问题：深解示例称「若当地上限为社平 3 倍，超基数部分按上限计，工具自动提示封顶」，但计算函数直接按 `base × 比例`，页面没有社平工资或缴费基数上下限字段，也无任何封顶提示。
- 证据：`tools/hr/social-insurance.html:207` 承诺；`:304-314` 计算仅用 base；输入仅 salary/base 两项 `:139-140`。node 复算：base=30000、salary=10000 → 合计 18,030 元，结果、明细与标签中「封顶/上限」命中为 false。
- 影响：用户按页面说明输入超上限基数时得到偏高的单位/个人缴费，且无任何提示，与「自动提示封顶」矛盾。
- 方案：增加「当地社平工资/基数上限」选填，超限时按上限计并在结果标注；或删除该承诺句，改为「本页不校验上下限」。

### L-N3 基数≤0 只清「合计」，单位/个人/明细/实得保留上一次结果（中，确认）
- 问题：`calc` 在基数 ≤0 时仅把 `totalVal` 置「—」并 `return`，`totalLbl`、`splitBox`、`detailTable` 未清空，继续显示上一次的金额与基数。
- 证据：`tools/hr/social-insurance.html:305-306` 早退；`:320-327` 其余输出。node 内存 DOM 复算：base=10000 计算后再把 base 改 0 调 `calc()` → totalVal「—」，但 totalLbl 仍为「单位 3,760 (37.60%) + 个人 2,250 (22.50%)　·　基数 10,000 元」，split/明细保留 6,010 元合计。
- 影响：清空或误填基数后页面同时出现「—」与旧金额，用户可能把旧明细当新结果复制或导出。
- 方案：早退时统一清空 totalLbl/splitBox/detailTable（或整块置灰并禁用复制/导出），并补「清空基数」用例。

### L-N4 「税后实得」只扣个人社保公积金，未扣个税（中，确认口径）
- 问题：结果卡「税后实得约 = salary − 个人社保合计」，页面没有任何个人所得税逻辑，字段名与「税后」含义不符。
- 证据：`tools/hr/social-insurance.html:323`；全页无税率/个税分支。默认 salary=10000、base=10000、个人合计 2,250 → 显示「税后实得约 7,750 元」，实际尚未扣个税。
- 影响：HR 与员工核对工资条时会把「社保后」误当「到手」。
- 方案：改名为「扣除个人社保后（税前）」并注明未计个税，或联动同目录个税/反推工具后再展示「到手」。

### L-N5 个税反推「起征点 0」被静默替换为 5000（中，确认）
- 问题：`parseFloat(...) || 5000` 把合法数值 0 当空值。
- 证据：`tools/hr/gross-up-calculator.html:273`；node 复算 afterTax=8000、rate=0.225、threshold=0 与 threshold=5000 输出完全相同：税前 10,451.61、计税工资 3,100.00、个税 100.00。
- 影响：用户测试零起征点或特殊口径时结果仍按 5000 计，且无提示。
- 方案：用 `Number.isFinite` 区分空值/NaN 与有效 0，并在结果区显示「当前起征点」。

### L-N6 个税反推二分上界不足，极高税后+高社保率时税前被低估（中，确认边界）
- 问题：`high = max(afterTax*2+10000, 100000)` 未随社保率/税率放大；税后工资高且社保率取控件上限 0.5 时，上界处净额仍远低于目标，二分收敛到上界。
- 证据：`tools/hr/gross-up-calculator.html:253-268`（`:255` 上界）。node 复算 `afterTaxToGross(400000,0.5,5000)` 返回 810,000，按该税前计算的净额仅 240,160，距目标 400,000 差 159,840；页面仍按 810,000 展示社保/个税/税前。
- 影响：高税后工资 + 0.5 社保比例（控件允许 0–0.5）下，反推结果严重偏低。
- 方案：倍增 `high` 直到净额 ≥ afterTax 再二分（或按 `afterTax/(1-rate-0.45)` 估初值），返回前校验残差；同时校验 rate<1。

### L-N7 N+1/2N 两页接受负月薪并输出负赔偿，无拦截（中，确认）
- 问题：两页均用 `parseFloat(...) || 0` 读取工资，最后只拦截 NaN/Infinity，不拦截负数；HTML 的 `min` 不阻止手动输入负值。
- 证据：`tools/legal/labor-compensation-n1.html:281-283,323`；`tools/legal/severance-pay.html:280-282,316`。node 原函数复算：3 年、月薪 -10000、未通知 → N+1 页「N倍经济补偿 -30,000、应支付总额 -40,000」；2N 页违法解除 → 「应支付总额 -60,000」。两页均正常渲染，未出现错误提示。
- 影响：负工资被当作有效结果展示并可导出 CSV，属明显无效输出。
- 方案：工资/年限/封顶统一校验为正有限数（年限≥0、工资>0、封顶≥0），非法时清空结果并提示；补负值与空值用例。

### L-N8 N+1 封顶示例的代通知金与代码/公式不一致（中，确认页内矛盾）
- 问题：深解「封顶情形」示例写「35000×12=420,000，+代通知金 35,000=455,000」，但代码代通知金取原月薪（未封顶），公式框也写「1 个月原月薪」；同页两处口径打架。
- 证据：`tools/legal/labor-compensation-n1.html:239` 示例，`:159` 公式文案，`:305` `noticePay = noticeGiven===0 ? salary : 0`。node 复算：20 年、月薪 40000、封顶 30000、未通知 → 基数 30,000、N=12、补偿 360,000、代通知金 40,000、总额 400,000（非示例的 455,000）。
- 影响：用户按示例预期 455,000，实际页面给 400,000（月薪越高差异越大），无法判断哪条口径为准。
- 方案：统一说明代通知金按上月工资/原月薪且不受社平 3 倍封顶限制（与法条一致），并把示例改为可复现数字（如月薪 40000 → 400,000），或增加「代通知金基数」选择项。

### L-N9 2N 页「合法解除（N或N+1）」无 +1 入口与计算（中，确认功能缺失）
- 问题：解除情形下拉写「合法解除（N或N+1）」，但计算只有 N 与 2N 两支，没有「是否提前 30 天通知/代通知金」输入，合法解除永远只出 N。
- 证据：`tools/legal/severance-pay.html:178-182` 选项；`:303-305` 仅 `illegal ? 2N : N`；页面无 notice 字段。node 复算：3 年、月薪 10000、选合法解除 → 应支付总额 30,000（无 +1）。
- 影响：用户以为选「合法解除」可算 N+1，实际少算 1 个月；与 N+1 页功能重复且口径不全。
- 方案：把下拉改为 N / N+1 / 2N 三支并加「是否提前 30 天通知」，或把选项文案改为「合法解除（仅 N）」。

### L-N10 诉讼费知识产权案件「有金额按财产案件」未实现，统一封顶 1000（高，确认）
- 问题：知识产权民事案件有争议金额时，代码用 `500 + 金额×1%` 且 `min(…,1000)`，而同页 detail 文案与《诉讼费用交纳办法》口径均为「有金额按财产案件分段」。
- 证据：`tools/legal/court-fee.html:320-323`（`:322` 上限 1000，`:323` 文案「有金额按财产案件」）；财产案件分段在 `:298-308`。node 复算：知产 50 万 → 1,000 元，财产案件同额 8,800 元；知产 100 万 → 1,000 元，财产案件 13,800 元。
- 影响：本页是「诉讼费计算器」，知产案件标的 50 万以上时少算 7,800 元以上，直接影响起诉预算。
- 方案：知产分支在 amount>0 时复用财产案件分段函数（抽出 `propertyFee(amount)` 共用），无金额时才取 500–1000 区间；补 10 万/50 万/100 万用例。

### L-N11 标的金额为 0 或负数仍按 50 元收财产案件受理费（低，确认）
- 问题：`amount <= 10000` 直接返回 50，未排除 amount≤0；负数也会显示「标的金额 -1 元、全额受理费 50.00 元」。
- 证据：`tools/legal/court-fee.html:299`；node 复算 amount=-1 → 全额受理费 50.00 元，无提示。

### L-N12 抚养费两个预设的 select 值与选项不匹配，点击即报「无效值」（高，确认）

### L-N13 抚养费比例选项「取25%/取45%」与实际值 20%/40% 不符（中，确认）
- 问题：默认选项文案「20%-30%（一个子女，取25%）」的 value 是 0.2，实际按 20% 算；「40%-50%（两个及以上，取45%）」value 是 0.4，实际按 40% 算。
- 证据：`tools/legal/child-support.html:184,186` 选项，`:330` `ratio = parseFloat(ratioSelect)`。node 复算：月收入 12000、选默认项 → 基础抚养费 2,400 元（20%），文案承诺 25% 应为 3,000 元；选「取45%」→ 4,800 元（40%），45% 应为 5,400 元。
- 影响：用户按文案选择会得到低于标注下限/中值的金额，两孩家庭少算 600 元/月。
- 方案：要么把 value 改为 0.25/0.45，要么把文案改为「20%」「40%」；建议拆成 20/25/30/40/45 五档并保留自定义。

### L-N14 抚养费「子女数量」选择框不参与任何计算（中，确认）
- 问题：`childCount` 只被读取一次，后续比例、金额、总额均未使用；把 1 孩改 2 孩结果完全不变。
- 证据：`tools/legal/child-support.html:320` 读取；`:326-347` 无引用（全页仅 `:161,320,390,391` 出现）。node 复算：12000 元、20%、5 岁、生活 2000，childCount=1 与 2 输出均为 2,400 元/月、374,400 元。
- 影响：用户以为选择子女数会自动上浮比例，实际是死输入；两孩场景只能靠手选 40–50% 档。
- 方案：按子女数自动带出默认比例（1 孩 20–30%、2 孩以上 40–50% 且总上限 50%），或选择后提示并禁用无关项；若保留纯手动，删除该下拉。

### L-N15 抚养费「当地生活水平」兜底直接覆盖比例金额，零收入仍出 2000/月（中，确认）
- 问题：`baseSupport = Math.max(baseSupport, livingCost)` 把「当地生活水平」当成每个子女的最低抚养费，且不校验收入；结果同时显示「支付比例 20%」与被抬高的金额，零/负收入也会得到生活水平金额。
- 证据：`tools/legal/child-support.html:334` 兜底、`:350` 比例展示、`:353` 备注、`:319` 收入空值→0。node 复算：收入 3000、20%、生活 2000 → 基础 2,000 元（显示仍为 20%，实际相当于 66.7%）；收入 0 → 2,000 元/月、至 18 岁 312,000 元。
- 影响：比例结果被静默改写，用户无法知道 2,000 元按哪条口径得出；零收入场景与「以财物折抵」的法定说明冲突。
- 方案：把生活水平作为「参考下限提示」而非直接改写金额（或明确标注「按当地生活水平下限计」并同时显示比例法金额）；收入≤0 时提示按当年总收入/同行业平均或财物折抵，不直接出正数。

### L-N16 抚养费自定义比例 0 被替换 25%，年龄>18 月付与总额自相矛盾（低，确认）
- 问题：自定义比例用 `|| 25`，输入 0 变 25%；`min=10/max=50` 只在 HTML 上，JS 不校验；子女年龄可超 18，月付仍按比例显示，但「至18岁总额」为 0。
- 证据：`tools/legal/child-support.html:327-331`、`:192`；`:336-337,357-358`。node 复算：自定义 0% → 比例 25%、基础 3,000 元；年龄 20 → 「每月应支付 2,400 元、至18岁总额 0 元」。
- 影响：边界输入下结果自相矛盾，且无法判断 0 比例是否被接受。
- 方案：区分空值/0，比例限制在 10–50（或按业务放宽）并提示；年龄>18 时明确提示已成年、停止月付并隐藏总额；补 18/19 岁边界用例。
