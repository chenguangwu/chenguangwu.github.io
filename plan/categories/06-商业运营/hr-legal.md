### L-N65 离职率分母用“期末在职人数”，与参考表“平均在职人数”及行业口径不一致（高，确认）
- 问题：`rate=left/head*100`，`head` 输入只有“在职人数”，没有期初人数；参考表却写“离职人数/平均在职人数”。页面无法按平均在职人数计算。
- 证据：`tools/hr/analysis-29.html:120`（页面公式）、`:126`（仅“在职人数”输入）、`:193`（参考表平均在职人数）、`:225`（`rate=left/head`）。
- 复现（node）：head=120、left=15 → 12.50%；若期初 135、期末 120（期间离职 15），平均在职 127.5 → 15/127.5=11.76%，页面仍为 12.50%；head=100、left=200 → 200%。
- 影响：缩编期离职率被系统性高估，无法与“平均在职人数”口径的行业基准对比。
- 方案：增加“期初/期末在职人数”，按 `离职人数/((期初+期末)/2)` 计算；或明确改名为“期末在职口径离职率”并删除参考表平均口径；校验 `left<=head`。

### L-N66 标题/简介承诺“留人优先级”，输出无岗位维度、无排序（中，确认）
- 问题：meta/标题写“测算离职影响与留人优先级”，深解列“核心岗位流失风险测算”，但 `calc()` 只输出期间离职率、替换成本、产能损失、总成本、人均成本、降 30% 节省，没有任何岗位/优先级/排序字段。
- 证据：`tools/hr/analysis-29.html:10-11`（meta/标题）、`:172`（深解核心岗位场景）、`:232-238`（六项聚合输出）。
- 复现（源码）：任意输入 → 结果区固定为 6 个聚合数字 + 一条通用提示；代码中无 `role`/`priority`/`sort` 变量，亦无岗位输入。
- 影响：用户无法据此判断“先留谁”，标题承诺的“留人优先级”未兑现。
- 方案：增加岗位行（岗位/人数/替换成本/胜任周期/月产出），按离职成本或风险分降序输出“留人优先级 Top3”；否则删除“优先级/核心岗位”表述。

### L-N67 负离职人数/负胜任周期/离职人数>在职人数照算，负成本仍提示“较低水平”（中，确认）
- 问题：`num()` 只把 NaN 归 0，`calc()` 只校验 `head<=0`；`left/rep/ramp/out` 无下界，`rate` 也不要求 ≤100%。
- 证据：`tools/hr/analysis-29.html:221`（num）、`:223-231`（计算与提示）。
- 复现（node）：head=120、left=−15 → 离职率 −12.50%、替换成本 −270000、爬坡损失 −562500、总成本 −832500、可节省 −249750，提示仍是“离职率处于较低水平”；head=100、left=200 → 200%，提示“偏高”。
- 影响：负成本、负“节省”与 200% 离职率均被正常渲染，数据不可信。
- 方案：`head>0`、`left>=0` 且 `left<=head`、`rep/ramp/out>=0`；不满足时结果区红字提示并中止计算。

### L-N68 深解“5.5/7.8/8.5→7.4、按权重合成”与页面 0–100 等权公式（85.5）矛盾；四级/ROI 未实现（高，确认）
- 问题：深解算例把 5.5/7.8/8.5 当作“需求紧迫/计划可行/训后效果”按权重合成 7.4；页面却把 8.5 当满意度、5.5/7.8 当培训前后分，按 `(L1+L2+L3)/3` 得 85.5。深解还称“柯氏四级打分合成 ROI”，页面只有 L1–L3、无 L4、无 ROI。
- 证据：`tools/hr/assessor-training-hr.html:126`（等权公式、0–100）、`:163`（四级/ROI）、`:166`（“综合 7.4”）、`:220-225`（实际计算）。

- 影响：深解算例无法复现，“按权重/四级/ROI”均为未实现承诺。

### L-N69 “L3 行为层”实为成绩提升率（学习层），pre=0 或 post<pre 时 L3 取 0/−200（中，确认）
- 问题：`improveRate=pre>0?(post-pre)/pre*100:0`、`l3=min(100,improveRate*2)`，标签写“L3行为层（能力提升率）”；参考表的行为层是“行为改变人数/参训人数”，并非能力分提升率。
- 证据：`tools/hr/assessor-training-hr.html:220-232`；参考表 `:194-195`。
- 复现（node）：pre=0、post=10、满意度 8.5、通过率 88 → improveRate=0、L3=0、总分 57.67（需改进），明明能力从 0 升到 10；pre=10、post=0 → L3=−200、总分 −9.0。
- 影响：把“学习层”误标为“行为层”；零基线/负增长得到 0 或负分，评分区间被击穿。
- 方案：L3 改称“学习层（成绩提升）”，行为层另设“行为改变率”输入并按参考表公式；`l3` 夹紧 0–100，`pre=0` 时提示“基线为 0，无法算提升率”。

### L-N70 满意度/通过率/能力分无范围限制，总分可 113.3/100 仍判“卓越”（中，确认）
- 问题：`l1=sf*10`、`l2=pr` 直接使用，`pre/post` 也无 0–10 限制；输入越界时总分可 >100 或 <0，但仍按 /100 展示并套用 ≥85 卓越。

- 影响：越界输入被放大成“卓越”，评估结论失真。

### L-N72 生成数量上限 50 但数据只有 8 条，>8 时循环重复；预设标签写“员工编号”与制度生成无关（中，确认）
- 问题：`cnt` 允许 1–50，`shuffled[i % shuffled.length]` 只有 8 个元素；n>8 必然重复。预设按钮标签为“5/12/30 个员工编号”，与本页“制度生成”语义不符。

- 方案：数量上限降为 8，或改为 8 类 × 变体组合去重；预设标签改“5/12/30 份制度”并把 value 对齐。
