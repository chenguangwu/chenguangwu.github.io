### RE-N1 公摊换算无输入校验，空套内输出「得房率 = NaN %」、负系数输出 200%/Infinity（高，确认）
- 描述：`calc()` 直接用 `+value || 0` 取值后算 `公摊=套内×系数/100`、`得房率=套内÷(套内+公摊)`，没有面积/系数的正负与区间校验，也没有对 `NaN/Infinity` 结果做拦截或提示。
- 证据：`tools/realestate/convert-area-shared.html:202-206`（输入框 `:130-131`）。复现 套内 0、公摊系数 20 → 实际输出「公摊面积 = 0.00 ㎡ / 建筑面积 = 0.00 ㎡ / 得房率 = NaN %」，页面照常渲染且无任何提示；套内 100、系数 −50 → 「公摊面积 = −50.00 ㎡ / 建筑面积 = 50.00 ㎡ / 得房率 = 200.00 % / 公摊率 = −100.00 % / 得房率评价：优秀」；系数 −100 → 「得房率 = Infinity % / 建面相当于套内的 0.000 倍」。
- 影响：给房看面积核对的核心页，零值/负数（空格误触、粘贴负号）会输出负数公摊、200% 得房率甚至 NaN/Infinity，且被判「优秀」，用户无法察觉输入有误。
- 方案：进入计算前校验 `inner > 0` 且 `0 <= ratio <= 100`（或按产品定义给上限），越界标红并停止渲染；输出前对 `rate` 做 `isFinite` 判断，非有限值提示「请输入有效的套内面积与公摊系数」。

### RE-N2 公积金页倍数可负，直接输出负「建议可贷额度」（高，确认）
- 描述：守卫只挡 `balance`、`monthlyFund`、`fundYears` 三项为负，`multiplier`、`payMultiple`、`cap` 未校验；负倍数使 `amt1/amt2` 为负，`Math.min` 后「建议可贷额度」与评级一起给出负数。
- 证据：`tools/realestate/fund-loan.html:271-311`（守卫 `:279-282`，输入 `:145-171` 虽有 `min="0"` 但挡不住手输/粘贴）。复现 余额 80000、余额倍数 −1、月缴存 2400、缴存 5 年、月供倍数 60、上限 600000 → 实际「按余额倍数测算 ¥−80,000 / 建议可贷额度 ¥−80,000（约 −8 万元）/ 额度评级：较低」；月供倍数 −60 → 「按月缴存测算 ¥−144,000 / 建议可贷额度 ¥−144,000」。
- 影响：贷款额度页给出负额度，用户若直接抄入购房预算会严重误判；负数结果也未触发「请输入合理的数值」。
- 方案：把 `multiplier`、`payMultiple`、`cap` 纳入同一守卫，要求 ≥0 且倍数 >0；越界标红停止，不做静默兜底。

### RE-N3 公积金页「当地额度上限」卡片与实际取值口径脱节（中，确认）
- 描述：结果卡直接用 `fmt(cap)` 展示上限，但额度计算是 `cap > 0 ? min(raw, cap) : raw`；`cap` 为 0 或负数时该卡片仍显示 0/负数，而最终额度不受其约束，正是公式框宣称的「min(两法, 上限)」之外的第三种分支。
- 证据：`tools/realestate/fund-loan.html:291`（`finalLimit = cap > 0 ? Math.min(rawLimit, cap) : rawLimit`）与 `:302-303`（上限卡 / 建议额度卡）。复现 余额 80000、倍数 20、月缴存 2400、5 年、月供倍数 60、上限 0 → 实际「当地额度上限 ¥0 / 建议可贷额度 ¥144,000」，页面同时出现上限 0 与高于 0 的建议额度；上限 −100000 → 上限卡「¥−100,000」，最终额度仍为 ¥144,000。
- 影响：两张卡片互相矛盾，用户无法判断上限是否已生效；负上限还渲染成负金额。
- 方案：`cap <= 0` 时把上限卡显示为「未设置（不限）」并同步改文案；或明确要求上限 >0 才参与取小，否则标红提示。上限卡数值改为展示实际生效的上限（`cap > 0 ? cap : rawLimit`）。

### RE-N4 价格折扣页折扣率越界，输出负实售价与负等效折数（中，确认）
- 描述：业务 `calc()` 仅经 `__tbInputGuard` 校验「必填 + 有限数值 + 标价非 0」，折扣率未限制 0–100；`sp=A*(1-B/100)` 在 B>100 时为负，B<0 时优惠额为负。
- 证据：`tools/realestate/price-discount-1.html:662-680`（守卫 `:663` 的 `__D` 只把 `v0` 当分母，输入 `:130-132`）。复现 标价 8800、折扣率 150 → 实际输出 实售价 −4,400.00、优惠额 13,200.00、等效折数 −5.0 折、实售占标价比 −50.00%；折扣率 −20 → 实售价 10,560.00、优惠额 −1,760.00、等效折数 12.0 折、占比 120.00%。
- 影响：与电商折扣页同类（06-F1），房地产定价页同样能把负数成交价与负数优惠直接复制进报价单。
- 方案：在业务函数入口校验 `0 <= B <= 100`，越界标红并停止输出；`input max="100"` 不能替代 JS 校验。

### RE-N5 二手房评估：负房龄反而加价，修正叠加突破本页引据的 ±15%/±25% 无提示（中，确认）
- 描述：房龄系数 `max(0.80, 1-age*0.005)` 只封顶下跌、不封顶上涨，`age` 为负时系数 >100%；同时「其他修正（%）」无区间校验，与楼层/朝向/装修/学区系数连乘后可远超本页引据表写的「单项 ≤15%、累计 ≤25%」。
- 证据：`tools/realestate/market-valuation.html:306-340`（守卫 `:316-319` 只校验面积与参考均价，`age` 输入 `:189`、`extra` 输入 `:204`，引据表 `:247` 写「单项修正一般不超过 15%、累计不超过 25%」，结果 `:338` 展示「房龄折损系数」）。复现其余取默认值、仅把房龄改为 −8 → 实际「房龄折损系数 104.0%（房龄 −8 年）、评估单价 46,160.15、综合修正幅度 +21.47%」；房龄 8 → 单价 42,609.37、+12.13%，即负房龄使估值反向抬高约 3,550 元/㎡。其他修正 −60 → 综合修正 −55.15%（超过 25% 无提示）；其余修正 +25 且选择最高系数档 → +44.37%。
- 影响：把「房龄」录成负值（或误用负数表达「比参考盘新」）会得到高于参考均价的估值且无任何提示；修正幅度失控时页面仍照常给「合理区间 ±5%」。
- 方案：`age >= 0` 且给出上限（如 ≤ 设计使用年限），`extra` 限制在 −30%~+30% 内并在累计修正 |幅度|>25% 时提示「修正累计超出规范指导值」；房龄系数改为 `Math.min(1, Math.max(0.80, 1-age*0.005))`。

### RE-N6 户型评分：建面 120㎡ 处理想间数跳档，1㎡ 之差少 3 分；面宽/进深缺失静默扣 35 分（中，确认）
- 描述：理想间数用 `<70→2、<120→3、<160→4、其余→5` 的硬边界，导致 119.9㎡ 与 120㎡ 的 3 室在「房间数」维度差 3 分；面宽/进深为 0 时 `s2`、`s4` 直接记 0，没有「请输入面宽/进深」提示，而结果只把比值显示成 `--`。
- 证据：`tools/realestate/layout-score.html:285-348`（守卫 `:293-296` 只校验面积，理想间数 `:323-326`，`s2/s4` `:305-320`，比值展示 `:346`，维度说明 `:195-199` 仍写「3 室最优」）。复现 建面 119、套内 95、面宽 8、进深 10、3 室、南北通透 → 实际 得房率 79.83%、s5=10、综合 94.8 良好；建面 120、套内 96（房间数同为 3、其余不变）→ 得房率升至 80.00%、s1 由 39.66 升至 40.00，但 s5 由 10 掉到 7、综合反降为 92.1。面宽与进深都留空（建面 100、套内 78、3 室、通透）→ 实际 s2=0、s4=0、综合 61.0，仅显示「面宽进深比：--」，无错误提示。
- 影响：边界档位让「多 1㎡ 反而更差」；缺失面宽/进深时用户以为评分偏低是户型问题，实际是必填项未填被静默计 0（合计最高只能到 65 分）。
- 方案：理想间数改为区间重叠或按四舍五入连续取值（如 `120㎡` 的 3 室与 4 室同分），并把维度说明改为按面积适配而非「3 室最优」；面宽、进深任一为 0 时标红提示并中止，或在结果中显式标注「该维度未评分（不计入满分）」。

### RE-N7 租金定价：综合修正在 −100% 以下仍参与加权，产生负租金与负区间下限（中，确认）
- 描述：三个可比案例的 `adj`（综合修正 %）只做 `num()` 取值，未限制下限；`adjustedUnit = 单价 × (1+adj/100)` 在 `adj <= -100%` 时为 0 或负数，仍按权重进入加权平均与区间极值。
- 证据：`tools/rental/rent-2.html:215-263`（案例构造 `:217-219`、过滤条件仅 `rent>0 && area>0 && w>0` `:220-221`、修正单价 `:229`、加权 `:234`、区间 `:243-244`）。复现 仅把案例 A 的综合修正改为 −150%、其余默认（A 4500/85㎡、B 5200/95㎡、C 4800/88㎡，目标面积 90㎡）→ 实际 加权单价 27.97 元/㎡·月、建议月租金 2,517 元、「租金区间 −2,382–5,025 元/月」。
- 影响：修正系数的负号/幅度填错即可得到负数挂牌价与自相矛盾的区间，页面无提示，且该结果会写入历史与导出。
- 方案：校验 `adj` 在 −50%~+50%（或至少 >−100%），越界标红；区间下限 `Math.max(0, minRent)` 兜底并在文案注明「已剔除负值案例」。

### RE-N8 收益还原：负资本化率/负净收益无拦截，输出负收益价格与负回收年限（中，确认）
- 描述：`__tbInputGuard` 只把 `v1`（资本化率）当分母拦截「等于 0」，不拦负数；负资本化率使 `V=A/cap`、`回收=1/cap` 同时为负，负净收益同理。
- 证据：`tools/realestate/return-1.html:633-651`（守卫 `:634` + `__D={"v1":"v1"}` `:182`，公式 `:641-645`，输入 `:130-132` 无 min）。复现 年净收益 216000、资本化率 −4.8 → 实际 收益价格 −4,500,000.00 元、静态回收年限 −20.83 年、收益价格 −450.00 万元（月净收益仍为 +18,000.00，正负混排）；净收益 −216000、资本化率 4.8 → 收益价格 −4,500,000.00 元。
- 影响：收益法估值的核心页可输出负房价与负回收期，且同一结果框里正负并存，容易被误当作有效估值。
- 方案：`A > 0` 且 `0 < B <= 30`（或按业务给上限）才计算；越界标红提示「净收益须为正、资本化率须在 0–30% 之间」。

### RE-N11 成新率法折旧页成新率越界，输出负折旧/超 100% 现值（中，确认）
- 描述：重置成本与成新率均无正负/区间守卫，`已提折旧 = 重置成本×(1-成新率/100)`、`现值 = 重置成本×成新率/100` 直接计算；成新率 >100% 得到负折旧，<0 得到负现值。
- 证据：`tools/realestate/depreciation-2.html:130,132,557-565`
- 复现：重置成本 1,000,000、成新率 150 → 已提折旧 -500,000.00、现值 1,500,000.00、折旧率 -50.00%，判读仍为“成新度较高”；成新率 -20 → 已提折旧 1,200,000.00、现值 -200,000.00、折旧率 120.00%。
- 影响：越界成新率会产生负折旧或超过重置成本的现值，且结果卡与文字结论仍按正常区间措辞，容易被当作估值结果使用；与既有 RE-N4 折扣区间问题同类，但页面与字段不同。
- 方案：成新率限制在 0–100、重置成本要求 >0；越界标红停止计算，并修正“成新度”判读只在 0–100 内生效。

### RE-N12 年限法折旧页负使用年限不被拦截，过小年限使 10 年累计折旧超重建成本（中，确认）
- 描述：`__tbInputGuard` 只把使用年限为 0 视为分母非法，负数照常通过；`年折旧 = 重建成本×95%÷年限`，且“10 年累计折旧”固定按年折旧×10、“30 年半程账面成本”固定按重建成本÷2，均未随年限收敛到残值。
- 证据：`tools/realestate/cost-depreciation.html:130,132,634,641-645`
- 复现：重建成本 900,000、使用年限 1 → 年折旧 855,000.00、10 年累计 8,550,000.00（为重建成本的 9.5 倍）、30 年半程账面成本仍为 450,000.00；使用年限 -30 → 年折旧 -28,500.00、10 年累计 -285,000.00。
- 影响：负年限直接产出负折旧；年限小于 10 年时累计折旧超过应折旧总额（95%），30 年账面值也与实际年限脱节，三张结果卡互相矛盾。
- 方案：使用年限要求 >0（建议 ≥1）；“10 年累计折旧”按 `min(10, 年限)×年折旧` 并封顶 95% 重建成本；“30 年半程账面成本”按 `重建成本×(1-95%×min(30,年限)/年限)` 推导，年限 ≥30 时显示残值 5%。
