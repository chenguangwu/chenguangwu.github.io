### T-N9 IRR 二分区间仅覆盖 −0.99%～1000%，负 IRR 与超高 IRR 被误报为输入无效（高，确认）
- 描述：`calcIRR()` 以 `low=-0.99`、`high=1000`（单位为百分数）做二分，未按实际收益率范围扩张；两端 NPV 同号即返回 `NaN`，结果区统一显示「请输入至少两期现金流（需有正有负）」，把「有解但不在区间内」与「输入无效」混为一谈。
- 证据：`tools/audit/irr-table.html:270-287,346-347`。复现 `flows=[-100,50]`（真实 IRR −50%）→ `calcIRR()` 返回 `NaN`，同函数端点 NPV 为 `−49.50`（−0.99%）与 `−95.45`（1000%）；`flows=[-100,5000000]`（真实 IRR 约 4,999,900%）→ 同为 `NaN`，端点 NPV `+5,049,894.95` 与 `+454,445.45`（node 内存复算）。
- 影响：`tools/audit/irr-table.html`；亏损项目的负 IRR 永远无法算出，早期高回报项目亦被判无解，直接违背工具核心用途。
- 方案：按现金流规模设定区间（如 −99.9999%～1e6%）或改用多项式求根/对数尺度搜索；区分「区间内无解」「多解」「输入无效」三种提示；补测 −50%、−99%、500%、1000%、200000% 五组输入。

### T-N12 财务比率分析把空值/零分母当 0 并评级「良好」，复制报告与结果卡不一致（中，确认）
- 描述：`val()` 将空值兜底为 0，比率统一用 `分母>0 ? 比值 : 0`；对「越低越好」的指标 0 会被评成「良好」，零流动负债还被显示为 0:1「偏低」。复制报告则用 `||1` 兜底，与页面卡片算出不同数值。
- 证据：`tools/audit/ratio-analysis.html:265,292-318,324-325,341-350,359-367`。复现全部输入清空 → 资产负债率 `0.00% 良好`、权益乘数 `0.00 倍 良好`、存货周转天数 `0 天 良好`，综合得分 2/10「偏弱」；流动负债 0、流动资产 500000 → 卡片流动比率 `0.00:1 偏低`，而 `copyReport()` 输出 `500000.00`；股东权益 0 → 权益乘数 `0.00 倍 良好`（node 内存复算）。
- 影响：`tools/audit/ratio-analysis.html`；缺失数据被读成「稳健」，且复制出的报告与屏幕数字冲突，审计留痕不可靠。
- 方案：区分「空值」与「真实 0」；分母为 0 显示 N/A 而非 0；「越低越好」指标不得对 0 给良好评级；复制报告复用 `calc()` 同一结果对象，删除 `||1` 兜底；补测空值、零负债、零权益、零存货四组。

### T-N13 直线摊销接受负年限与残值高于成本，主结果与摊销计划互相矛盾（中，确认）

### T-N14 年数总和法不校验「计算第几年」与残值上限，越界年份给出 0 或负折旧（中，确认）
- 描述：守卫把 `c`、`n`、`yr` 列为必填并禁 `n<0`，但未限制 `1≤yr≤n`，也未要求 `s≤c`；公式说明还写明「图表另要求 1≤yr≤n、原值≥残值」，即主计算明确放行越界值。
- 证据：`tools/accounting/depreciation-syd.html:127,223-287,292-301`（负值表仅 `n`，见 `:262`）。复现 `c=100000,s=10000,n=10,yr=12` → 第 12 年折旧 `−1636.36`、占原值 `−1.64%`；`yr=11` → `0.00`；`yr=0` → `18000.00`；`c=100,s=200,n=10,yr=1` → `−18.18`；`yr=1.5` → `15545.45` 且标签写「第1.5年」（node 内存复算）。
- 影响：`tools/accounting/depreciation-syd.html`；越界年份与非整数年份输出看似正常的折旧额，易被直接抄入折旧表。
- 方案：校验 `yr` 为 1～n 的整数、`s≤c`、`n` 为正整数；错误时不生成结果与导出，并提供逐年折旧表供核对「各年合计 = 原值−残值」；补测 `yr=0/1/10/11/12/1.5`、`s>c`。

### T-N15 工薪税把雇主承担部分从员工「税后实得」中扣除（高，确认）
- 描述：页面把 `w − w×(雇主率+雇员率)` 作为「税后实得」，等于把雇主缴费也从员工工资里扣掉；实际员工到手只应扣雇员部分，雇主部分是单位成本。
- 证据：`tools/tax/payroll-tax.html:228-236`（`:234` 为 `(w-T)`）。复现 `w=10000, er=0.2, ee=0.08` → 工薪税 `2800.00`、页面「税后实得」`7200.00`；按工资口径员工实得应为 `9200.00`，单位用工成本 `12000.00`（node 内存复算）。
- 影响：`tools/tax/payroll-tax.html`；到手工资被少算整整一个雇主缴费额，用户据此做预算或薪资谈判会被直接误导；费率取负值时还会出现负税与「实得」高于工资。
- 方案：拆成三项——「员工扣款 = w×雇员率」「员工实得 = w−员工扣款」「单位用工成本 = w×(1+雇主率)」，或明确标注原「税后实得」为「扣除双方缴费后的余额」；校验两项费率非负且合计不超过 1；补测 `er+ee>1` 与负费率。

### T-N16 偿债保障倍数对零/负 DSCR 用 1e-9 兜底，伪造 10 亿倍负担率（中，确认）
- 描述：`偿债负担率 = 1 ÷ max(DSCR,1e-9)`，把负值与 0 一并夹到 1e-9，输出 1,000,000,000；该数值既非真实倒数也无业务含义。
- 证据：`tools/accounting/debt-service-coverage.html:270-280`（`:277`）。复现 `OCF=-150, ds=60` → DSCR `−2.50`、盈余现金 `−210.00`、偿债负担率 `1000000000.0000`、覆盖率 `−250.0%`；`OCF=0, ds=60` → DSCR `0.00`、负担率同样 `1000000000.0000`（node 内存复算）。
- 影响：`tools/accounting/debt-service-coverage.html`；明显资不抵债的场景反而显示一个巨额的「负担率」，与 DSCR 语义冲突，且会进入数据表/CSV。
- 方案：仅当 DSCR>0 时计算倒数，DSCR≤0 显示「不适用/无法覆盖」；负 OCF 保留负 DSCR 但禁止派生负担率；补测 `OCF=-150/0/90`。

### T-N17 印花税把税额加到凭证金额构造「含税金额」，0 税率时税率倒数显示万亿（中，确认）
- 描述：页面以增值税式 `a×(1+r)` 生成「含税金额」、以 `a×r/(1+r)` 生成「按含税价反算税额」，但印花税是就凭证金额计征、并不并入凭证金额；同时 `1 ÷ max(r,1e-12)` 在 0 税率时输出 1e12，且金额/税率无正负校验。
- 证据：`tools/tax/stamp-duty.html:226-234`。复现 `amount=1000000, r=0.05%` → 税额 `500.00`、含税金额 `1000500.00`、税率倒数 `2000.000`、反算税额 `499.75`；`r=0` → 税率倒数 `1000000000000.000`；`amount=-1000` → 税额 `−0.50`、含税金额 `−1000.50`（node 内存复算）。
- 影响：`tools/tax/stamp-duty.html`；「含税金额」会让用户误以为合同金额应加上印花税，反算项也建立在错误税基；0 税率与负金额输出无意义数值并可导出。
- 方案：删除「含税金额/按含税价反算税额」或改名为「计税依据 = 凭证金额」；移除无业务含义的「税率倒数」；校验金额非负、税率 0～法定上限；补测 `r=0`、负金额、0.005% 借款合同档。

### T-N18 优惠资本利得税无任何校验，负税率/税率>100% 产生负税或税后为负（中，确认）
- 描述：页面公式说明自述「无强校验，非数输入按 0 兜底」；`r` 可取负数或大于 1，`T=g×r`、`税后=g−T`、`有效税率=T/g` 全部照算，未与 0～法定优惠税率区间对照。
- 证据：`tools/tax/capital-gains-effective.html:120,224-233`。复现 `g=100000, r=-0.1` → 税额 `−10000.00`、税后利得 `110000.00`、有效税率 `−10.00%`；`r=2` → 税额 `200000.00`、税后利得 `−100000.00`、有效税率 `200.00%`；`r=0` → 税率倒数 `1000000000000.0000`（node 内存复算）。
- 影响：`tools/tax/capital-gains-effective.html`；负税额等于「退税」、税后利得反而高于税前收益，若用户把 `r` 当百分数输入（如输 20 而非 0.2）会得到 20 倍收益的税额。
- 方案：校验 `g≥0`、`0≤r≤法定上限`，并在标签中写明「小数输入，0.2 = 20%」；非法输入阻止结果与导出；移除「税率倒数」或改为「税率百分比」；补测 `r=-0.1/0/20/2`。

### T-N19 IRR 历史记录不包含现金流，回放结果与记录值可能不符（中，待验证）
- 描述：历史快照只遍历 `input[id]`，而现金流输入在 `renderList()` 中动态生成且不带 `id`；因此记录只含三个扫描参数，回放时用「当时的参数 + 当前现金流」重算，记录里的结果值与回放显示可能不一致。
- 证据：`tools/audit/irr-table.html:294-302,431-443,469-483,494-521`。`__irr_tableSnap()` 选择器为 `input[id],select[id],textarea[id]`，现金流行模板 `:297-300` 无 `id`；`history.record({rateStart,rateEnd,rateStep,结果})` 在 `:517-520`。实际 localStorage 行为尚需运行时确认。
- 影响：`tools/audit/irr-table.html`；用户从历史恢复后看到的结果未必是当初保存的结果，审计留痕不可复现。
- 方案：为每期现金流生成稳定 `id`（如 `cf-t0`）并纳入快照，或把现金流数组整体序列化进记录；恢复时先重建行再计算；补运行时验证刷新与回放一致性。
