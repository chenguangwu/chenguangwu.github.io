### R-H1 毛保费的附加费率口径与页面引据自相矛盾（高，确认）
- 描述：页面代码按「毛保费 = 纯保费 × (1 + 附加费率)」计算，但同页引据明确写「附加费率 = 附加费用 / 毛保费」，换算应为「毛保费 = 纯保费 / (1 − 附加费率)」，两套口径不能同时成立。
- 证据：`tools/insurance/gross-premium-loading.html:120` 公式框给出乘法口径；`:167-174` 引据表写附加费率按毛保费计提并给出除法换算；`:289-299` 代码执行 `pp*(1+load)` 与 `1/(1+load)`。node 复现：纯保费 10、附加费率 0.4 → 页面毛保费 14.00、纯保费占比 0.71429；按引据口径应为毛保费 16.67、纯保费占比 0.60000。
- 影响：`tools/insurance/gross-premium-loading.html`；同一输入可差 19%，页面内部引据和结果互相矛盾，用户无法判断采用哪套口径。
- 方案：二选一并全页统一。若采用「附加费率按毛保费」的引据口径，改为 `pp/(1-load)` 且校验 `0 ≤ load < 1`；若保留乘法口径，则把引据表改写为「附加费率按纯保费加成」，并同步公式框、结果标签、图表和指南，避免把两种定义混称「附加费率」。

### R-H2 纯费率的「百分数 / 小数 / 差额」三项量纲不成立（中，确认）
- 描述：纯费率是「元/暴露单位」，页面再乘 100 标成「%」、除 100 标成「小数」，并把「暴露单位 − 期望损失（元）」直接相减，三项都没有可解释的基准或单位一致性。
- 证据：`tools/insurance/pure-premium-rate.html:120` 公式框列出这三项；`:280-284` 代码执行 `ppr*100`、`(exp-el)`、`ppr/100`；`:302-306` 表内同样输出。node 复现：期望损失 1000、暴露 100 → 纯费率 10.00 元/单位，页面另显示「纯费率百分数 1000.000」「纯费率小数形式 0.10000」「风险单位与损失之差 -900.00」。
- 影响：`tools/insurance/pure-premium-rate.html`；三项既不能用于报价也不能用于核对，容易被误读为「纯费率 1000%」。

### R-H8 赔付准备金的「进展期」因子把长尾准备金越乘越小（高，确认）
- 描述：链梯法先算「最终赔款 − 已付」，再乘以随年限递减的因子（1 年 0.85、2 年 0.65、5 年及以上 0.15）。因子既不是链梯发展因子，也不符合「期限越长、未决责任越大」的方向；结果会随长尾年限增加而下降。
- 证据：`tools/insurance/claim-reserve.html:156-169` 的「进展期（年）」选项值为 0.85/0.65/0.45/0.30/0.15；`:307-309` 代码 `clReserve = clUltimate - paidLoss; clAdjusted = clReserve * devFactor`。node 复现（已赚保费 10000、预期赔付率 65%、已付 3500、RBNS 1200、结案率 70%）：链梯未调整准备金 1500；2 年因子 0.65 → 975；5 年因子 0.15 → 225。长尾业务反而只提 225。
- 影响：`tools/insurance/claim-reserve.html`；长尾业务准备金被系统性低估，与「长尾业务需更多准备金」的业务常识相反。
- 方案：明确链梯法的输出应为 `最终赔款估计 − 已付`，删除与年限无关的缩放；若确需按进展期调整，改为「未结案比例 / 发展因子」且随年限递增，并在公式框给出可复算的因子来源。

### R-H9 赔付准备金依赖 HTML 的 min 属性，负输入仍参与计算（中，确认）
- 描述：页面在输入框写了 `min="0"`，但 `calc()` 直接 `+el.value`，不检查 validity；负数可直接输入并参与损失率法与链梯法，产生超过终极赔款或为负的准备金。
- 证据：`tools/insurance/claim-reserve.html:137-159` 的 input 均带 `min="0"`；`:286-312` 的 `getVal` 与 `calc()` 不做非负校验。node 复现：已付 -3500、其余默认 → 损失率法 IBNR 8800、准备金 10000（已超过预期终极赔款 6500）；链梯最终赔款 -5000、调整后准备金 -975。
- 影响：`tools/insurance/claim-reserve.html`；负值输入会产出明显违背业务含义的准备金，且仍写入历史与导出。
- 方案：用 `checkValidity()` 或显式范围校验拦截负值/空值；负值时不计算、清空结果并禁用导出；对 `expectLossRatio`、`closeRate` 补充上限校验。

### R-H10 IBNR 准备金可显示负数，预设还会主动生成负值（高，确认）
- 描述：页面直接用「已报案赔款 × (发展因子 − 1)」作为 IBNR，没有截零或方向校验。发展因子小于 1 时 IBNR 为负；「示例 0.5×」预设把已报案赔款减半、因子设为 0.625，必然得到 -750000。
- 证据：`tools/insurance/ibnr-reserve.html:120` 公式框承认「因子 <1 表示高估已报告」；`:223-229` 代码 `ibnr=r*(f-1)`，未截零；`:264-266` 预设 `{reported:'2000000', factor:'0.625'}`。node 复现：默认 4000000、1.25 → IBNR 1000000；点「示例 0.5×」→ IBNR -750000、最终赔款 1250000；因子 0 → IBNR -4000000。
- 影响：`tools/insurance/ibnr-reserve.html`；准备金为负在会计与监管口径上不成立，预设直接演示出该错误。
- 方案：校验发展因子 `> 0`，并对 IBNR 取 `max(0, …)` 或明确拆出「高估已报告」的负值口径；预设改为因子 ≥1 的合理情景；公式框、结果标签和导出同步说明截零规则。

### R-H11 IBNR 页深度解析示例改用「已发生 − 已报告」，与本页发展因子模型不一致（中，确认）
- 描述：页面主计算只接受「已报案赔款」和「发展因子」，深度解析却用「已发生 400 万、已报告 320 万 → IBNR 80 万」举例，引入本页不存在的「已发生」输入，无法复核主计算结果。
- 证据：`tools/insurance/ibnr-reserve.html:126-132` 只有 `reported`、`factor` 两个输入；`:120` 与 `:223-229` 按 `reported*(factor−1)` 计算；`:305` 深度解析示例写「400−320=80 万」。node 复现：默认已报案 4000000、因子 1.25 → 页面 IBNR 1000000、最终赔款 5000000；示例口径 4000000−3200000=800000，两者相差 20 万。
- 影响：`tools/insurance/ibnr-reserve.html`；示例与主计算不是同一模型，用户按示例输入无法得到页面结果。
- 方案：示例改成「已报案 400 万 × (1.25−1) = 100 万」，并逐年或按因子说明最终赔款 500 万；若要保留「已发生/已报告」口径，应新增对应输入并明确与因子法的换算关系。

### R-H12 费用率页负费用会触发 10⁻⁹ 兜底，保费费用比暴涨到 1e16（中，确认）
- 描述：页面只用 `max(费用, 1e-9)` 防止除零，未拦截负费用。负费用时费用率为负，而「保费与费用比」把分母替换成 1e-9，输出 10^16 量级，两个指标方向完全冲突。
- 证据：`tools/insurance/expense-ratio.html:120` 公式框写「保费 ÷ max(费用,10⁻⁹)」；`:278-284` 代码按此实现；`:291-311` 表格同样输出。node 复现：保费 10000000、费用 2500000 → 费用率 25.00%、保费费用比 4.000；费用改为 -2500000 → 费用率 -25.00%、保费费用比 10000000000000000.000、差额 12500000.00。
- 影响：`tools/insurance/expense-ratio.html`；负费用本应报错，却被包装成一个天文数字的「保障倍数」，容易误导。
- 方案：先校验费用、保费为非负且保费 >0；删除 1e-9 兜底或改为明确提示；负值时不生成结果/历史/导出。

### R-H13 综合成本率页负赔款会被判为「承保盈利」（高，确认）
- 描述：页面只拦截空值和分母为零，未限制赔款支出、营运费用非负。负赔款会使综合成本率为负，页面仍按 `cr < 100` 判为「承保盈利」，并给出超过 100% 的承保利润率。
- 证据：`tools/insurance/combined-ratio.html:118` 公式框只写三项非空守卫；`:222-273` 输入守卫只对 `premium` 判零；`:280-286` 代码 `cr=(c+e)/p*100` 与 `cr<100?'承保盈利':'承保亏损'`。node 复现：保费 10000000、费用 2500000、赔款 -6500000 → 综合成本率 -40.00%、结论「承保盈利」、承保利润率 140.00%。
- 影响：`tools/insurance/combined-ratio.html`；负赔款/负费用会直接翻转承保结论，属于会误导决策的结果。
- 方案：校验赔款、费用、保费均为非负有限数且保费 >0；负值时中止并清空结果；承保结论只在输入合法时展示，导出同步过滤。
