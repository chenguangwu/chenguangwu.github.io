# 第989批：排列组合工具增加实际方案展示

## 原始问题

`tools/science/combination-calculator.html` 与 `tools/science/permutation-calculator.html` 只接受元素数量 n、r，输出方案数与公式；用户无法输入具体元素查看实际组合/排列。教学、抽签、排班等场景仍需手工列举；大结果只有 BigInt 数量，缺少小规模探索能力。

## 实现

新增共享纯函数 `js/tools/combinatorics-schemes.js`（`window.TBCombinatorics`）：

- `parseElements(text)`：按换行、回车、逗号、中文逗号、顿号、分号、Tab 拆分并 trim 去空。
- `tokenNames(tokens, dedupe)`：去重保留首次顺序；按位置模式给重复项追加 `#2/#3`（A、A#2）。
- `uniqueCombinationCount(tokens,r)`：按元素类型计数做 DP，返回 BigInt。
- `uniquePermutationCount(tokens,r)`：按剩余类型计数 DFS + memo，返回 BigInt。
- `combinationSchemes` / `permutationSchemes`：去重模式按类型枚举，按位置模式按索引枚举，天然不产生重复序列。

两页新增可折叠「查看具体方案（可选）」面板：

- 元素列表 textarea；填写后 n 自动取列表长度，r 仍由用户填写。
- 「相同文本视为同一元素（去重）」复选框，默认勾选；关闭后重复文本按位置区分。
- 方案 ≤500 条时每页 20 条展示，提供上一页/下一页；复制当前页；导出全量 CSV（序号 + 方案）。
- 去重组合数用类型 DP，去重排列数用类型 DFS；组合与排列分别在方案数说明中给出 C(n,r)/P(n,r) 与去重后的差异。
- 方案数 >500 时只显示数量与提示，不生成列表。
- 排列去重计数有指数级状态风险：当 P(n,r)>500 且元素类型>10 时跳过精确去重计数，改用上限 P(n,r) 直接限流，避免 26 个互异元素取 20 个导致页面卡死/爆内存。
- 分页页码统一 `Number()` 归一并兜底 0；`__combPage/__permPage` 对 delta 做 `Number(delta)||0`。
- 新增控件与动态文案均中英双语（`.tb-bi` + `__combEn()/__permEn()`）；复制/导出内容、CSV 表头、空选占位、错误提示均随语言切换。

## 回归用例

`scripts/verify_science_calc.js` 新增 7 条：

1. 组合去重 A,A,B r=2：方案数 2，含 A + A、A + B（C(3,2)=3 因重复合并降为 2）。
2. 组合按位置 A,A,B r=2：方案数 3，含 A#2，与去重态互斥。
3. 组合 r=0：方案数 1，显示「（不取元素）」，验证顿号解析。
4. 组合上限 C(26,20)=230,230：只显示数量、不产生 `.scheme-item`。
5. 排列去重 A,A,B r=2：方案数 3，含 A → A、B → A（P(3,2)=6 降为 3）。
6. 排列按位置 A,A,B r=2：方案数 6，含 A#2，与去重态互斥。
7. 排列上限 26 取 20：P=560,127,029,342,507,827,200,000，显示「上限 P(n,r)」且不生成列表，锁定防卡死逻辑。
