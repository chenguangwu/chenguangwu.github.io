# 558 批：阶梯提成档位校验与加价率口径（MS-F3 / MS-F4）

日期：2026-11-15
范围：`tools/sales/commission-calculator.html`、`tools/sales/cost-price-margin.html`

## MS-F3 阶梯提成档位上限非单调时重复计佣

### 问题
`getTiers()` 只把最后一档强制设为 `Infinity`，中间档上限不校验递增。`calcTiered()` 以
`seg = Math.min(sales, cap) - prevCap` 分段，遇到逆序档位（如 100000 → 50000）时 `seg` 为负被跳过，
但 `prevCap` 仍回退到较小值，下一档又从低处开始累计，同一段业绩被重复计佣。

复算：档位上限 100000 / 50000 / ∞、比例 3% / 5% / 8%、销售额 200000，
旧实现输出 15000（100000×3% + 150000×8%），正确分段应为 3000 + 8000 = 11000。

### 修复
- `getTiers()` 不再把非法/空值静默折算成 0，保留原始输入交给校验。
- 新增 `validateTiers()`：
  - 每档比例必须在 0–100%；
  - 除最后一档外，上限必须为正数且严格递增（最后一档留空表示无穷）。
- `calc()` 的阶梯分支先校验，失败时结果区显示错误、`window._lastResult` 置空、弹 toast，不进入计算。
- 公式说明补一句「区间上限须从低到高严格递增」。
- 英文态错误文案按 `TBKit.util.isEn()` 输出英文。

### 验收
- 默认档位 200000 → 12000（1500 + 2500 + 8000）。
- 逆序 100000/50000/∞ → 提示「阶梯区间上限须从低到高严格递增」，无结果、无历史缓存。
- 中间档上限留空 → 提示填写正数上限。
- 某档比例 120% → 提示 0–100%。
- 恢复默认后重新计算仍为 12000。

## MS-F4 「利润率」输入实为加价率，参考表公式与实现相反

### 问题
售价模式实际使用 `售价 = 成本 × (1 + 输入率)`，输入率是成本加成（加价率），但输入框与模式名都写「利润率」；
同页「公式与标准引据」表却写 `售价 = 成本 / (1 - 毛利率)`，与实现相反。成本 60、输入 40 时输出售价 84、
利润率 28.6%，与「输入 40% 利润率」的直觉冲突。

### 修复
- 输入标签改为「加价率（成本加成 %）」；模式选项改为「已知成本+加价率 → 求售价」「已知售价+加价率 → 求成本」
  「已知成本+售价 → 求利润率/加价率」。
- 公式框统一为 `售价 = 成本 × (1 + 加价率)`、`成本 = 售价 ÷ (1 + 加价率)`，并明确
  `利润率 = 加价率 ÷ (1 + 加价率)`。
- 引据表「售价」行改为 `cost×(1+markup)`，新增「利润率换算」行 `markup/(1+markup)`。
- 深度解析（`i18n/tools/content_deepdive.json`）示例改为「成本 100、加价率 25% → 售价 125，对应利润率 20%」，
  FAQ 同步说明输入口径与结果卡双口径。
- 英文第三层字典同步新键（含 deep-dive 拆句碎片），无残留。

### 验收
- 成本 60、加价率 40% → 售价 84.00、利润 24.00、利润率 28.6%、加价率 40.0%。
- 引据表显示 `成本×(1+加价率)` 与 `加价率/(1+加价率)`。
- `sales/commission-calculator` 与 `sales/cost-price-margin` 英文探针均 0 残留。
