## 1. Identicon 引据表算法标错（322）

- **复核失败点原文**：引据表为「算法 · Java String.hashCode(乘31)」，出处却写「FIPS 180-4 (SHA-2)」——实现并非 SHA-2 / FIPS 标准，引用失实。
- **修复位点**：`tools/design/identicon-generator.html` 该行出处改为 `Java Language Specification §15.8.2, String.hashCode (not a SHA/FIPS standard)`，中文 data-zh 同步注明「非 SHA / FIPS 标准」。
- **验证证据**：`grep "String.hashCode"` 命中；静态测试无死链。
- **判别力实测**：旧值 `FIPS 180-4 (SHA-2)` 已不存在。

## 2. Favicon 深解承诺 ICO 套装（327）

- **复核失败点原文**：深解「输出：ICO 与 PNG 套装可下载」，但页面只导出多尺寸 PNG，从不生成 `.ico`。
- **修复位点**：页面深解与 `i18n/tools/content_deepdive.json` 的 `design/favicon-generator` 同步改为「多尺寸 PNG 图标可下载（16–256px，单张或批量；本工具不生成 ICO）」。
- **验证证据**：`grep "本工具不生成 ICO"` 命中；`git diff` 仅该条 JSON 变更（indent=1 保持）。

## 3. 徽章页文案承诺 SVG/双色/图标（330）

- **复核失败点原文**：公式说明写「以 SVG 绘制圆角或盾形徽章」，深解算例为「build|passing 双色胶囊 + 输出 SVG」，FAQ 写「复制 SVG CSS」，引据表写「SVG 输出 / W3C SVG 1.1」；而实现只生成单个 CSS `span`（文字+配色+圆角+字号+实心/描边/药丸/圆点），无 SVG、无双色、无图标。
- **修复位点**：`tools/design/badge-generator.html` 的 intro、formula-desc、深解算例、FAQ 两问、引据表整行改为 CSS 口径；`content_deepdive.json` 的算例、FAQ、summary 同步。
- **验证证据**：`grep "W3C CSS 2.1 盒模型"` 命中；门禁 `verify_design_calc.js badge-generator` 通过。
- **判别力实测**：旧「SVG / 双色 / 盾形」表述全部消失。

## 4. 提示词算例 20 分条件不成立（341）

- **复核失败点原文**：算例称「任务与输出格式未选 → 仅角色计入已填、降为 20」，但同一算例里约束仍填写 ⇒ 实际为 40 分（角色+约束）。
- **修复位点**：页面与 `content_deepdive.json` 同步改为「任务与输出格式也未选、且约束一并清空，则仅角色计入已填、降为 20」。
- **验证证据**：`grep "且约束一并清空"` 命中页面与 JSON。

## 5. SVG 预览可发起外链请求（337）

- **复核失败点原文**：`generate()` 只要输入含 `<svg>…</svg>` 就把整段原文交给 `innerHTML`：`<svg></svg><img src="https://…">` 中 SVG 外的 img 未被处理，SVG 内的 `<img src>`、`<iframe>`、CSS `url(https://…)`、`@import` 也未过滤，真实浏览器预览时会发起外链请求（隐私泄露）。
- **修复位点**：`tools/design/svg-viewer.html`
  - `generate()` 先用 `match(/<svg\b[\s\S]*?<\/svg\s*>/i)` 只取 SVG 片段，SVG 外 HTML 不再进入解析器；
  - `sanitizeSvg()` 新增：移除 `img/iframe/object/embed/audio/video/source/link/meta/base` 元素；`src/srcset/poster/data/background/action/formaction` 仅放行内联位图 data URI；CSS `url(...)` 仅放行 `#id` 与内联位图，其余替换为 `none`；移除 `@import`；
  - `__svgStillDangerous()` 终检同步覆盖上述痕迹与 `url(`。
- **验证证据**：`verify_design_calc.js` 新增 `SVGE2026` 用例：输入含 SVG 外 `<img src>`、SVG 内 `<img src>` / `<image href>` / `style="fill:url(https://…)"` / `<iframe src>`，断言清洗结果与预览 innerHTML 均无 `evil.example` 且正常文本 `SVGE2026` 保留。现有 A/B/C/D 四类 XSS 用例全部保持通过。
- **判别力实测**：回退「只取 SVG 片段 + 新清洗规则」后，预览保留 `<iframe src="https://evil.example/f">` ⇒ `URL=LEAK` 转红。
