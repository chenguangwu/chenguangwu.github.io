## 1. TOML 零年仍生成不可解析日期（218）

- **复核失败点原文**：`tomlDateLiteral` 已校验月日、闰年与时区范围，但只取四位年份、未拒绝 `0000`；`tomlVal('0000-01-01')` 输出裸值，Python `tomllib.loads('d = 0000-01-01')` 报 `Invalid date or datetime`。
- **根因**：日期校验分支只覆盖月/日/时分秒/偏移，缺少年份下界；`\d{4}` 把 `0000` 当合法年份放行。
- **修复位点**：`tools/it/json-to-toml.html` 的 `tomlDateLiteral` 在解出 `y` 后加 `if(y < 1) return null;`，日期与日期时间共用同一分支，两者一并退回普通带引号字符串。
- **验证证据**：新增门禁 `UC218Z`——输入 `{"d":"0000-01-01","t":"0000-01-01T00:00:00Z"}`，断言两项都输出带引号字符串且不出现裸值 `d = 0000-01-01`。`node scripts/verify_it_calc.js json-to-toml xml-validator` ⇒ 19/19（既有 UC224BAD1/BAD2/LEAP/OFF/D/T/K 全部保留）。
- **判别力实测**：撤掉 `y < 1` 后输出裸值 `d = 0000-01-01`、`t = 0000-01-01T00:00:00Z` ⇒ `UC218Z` 转红。

## 2. Proto 旧专项用例仍要求非法 map 通过（219）

- **复核失败点原文**：页面 `parseOneof` 已按 protoc 拒绝 oneof 内 map，`verify_it_calc.js` 4/4；但 `scripts/_verify_it_batch233.mjs:103–104` 仍断言 oneof 内 map 解析成功，专项执行 11/12，与 `protoc 29.3` 的语法结论相反。
- **根因**：重做时只改了 verify_it_calc.js 的口径，老批次专项脚本没同步。
- **修复位点**：`scripts/_verify_it_batch233.mjs` 第 103–106 行：断言改为 `r2.err` 含 `❌`、且输出不含 `"opts"`（即 oneof 内 map 被拒绝）；保留第 101–102 行「普通 message 内 map 解析成功」作为合法对照。
- **验证证据**：`node scripts/_verify_it_batch233.mjs` ⇒ `12/12`（失败项转绿，含非法 oneof 拒绝与合法 map 通过两项对照）。
- **判别力实测**：把页面 `parseOneof` 的 map 拒绝分支去掉后，该断言（`err` 含 ❌）转红，说明断言确实锁住语法结论。

## 3. 合法命名空间被误判为 XML 错误（310）

- **复核失败点原文**：`tools/it/xml-validator.html` 只要同名元素的 `namespaceURI` 含 `parsererror` 即判解析错误；`<root xmlns="https://example.com/parsererror"><parsererror>valid</parsererror></root>` 被误报格式错误。专项 3/3 未覆盖该形态。
- **根因**：旧判据用 `/parsererror/i.test(ns)` 子串匹配命名空间，用户自定义命名空间 URL 里带该字样就会命中；这与「解析器错误文档」没有必然关系。
- **修复位点**：`calcTool()` 的错误识别改为按错误文档的可靠特征：
  - Firefox：`namespaceURI` 匹配 `newlayout/xml/parsererror.xml`（错误文档专用命名空间）；
  - Chromium：文档根是 XHTML 命名空间的 `<html>`，且 `parsererror` 也在 XHTML 命名空间；
  - 孤立节点（无 `parentNode`，兼容自研 stub）仍判错误。
  合法用户元素（含命名空间 URL 带 `parsererror` 字样）不再命中。
- **验证证据**：新增三条门禁——`XML310NS`（自定义命名空间含 parsererror 字样 ⇒ 格式良好）、`XML310FF`（Firefox 错误文档 ⇒ 格式错误）、`XML310CR`（Chromium 错误文档 ⇒ 格式错误）；`node scripts/verify_it_calc.js xml-validator` 随套件 19/19 通过，既有 XML310/XML310E 保留。
- **判别力实测**：把判据还原成 `/parsererror/i.test(ns)` 后 `XML310NS` 转红；把判据放宽成「一律忽略命名空间」后 `XML310FF`/`XML310CR` 转红——三条用例形成互斥对照。
