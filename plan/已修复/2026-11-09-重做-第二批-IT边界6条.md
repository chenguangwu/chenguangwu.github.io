## 1. IT-N489 JSONPath 负步长越界边界未按方向收敛
- 失败点：`$.a[99::-1]` 返回 6 项且首项 undefined；`$.a[:-99:-1]` 丢首项 1；`$.a[-99::-1]` 误返回 `[1]`。
- 根因：正/负步长共用把索引夹在 `[0,len]` 的 `norm()`。负步长必须按迭代方向把上下界夹在 `[-1,len-1]`，并区分「显式负索引」与「省略终点」；显式越界值也要夹紧到方向端点。
- 修复位点：`tools/it/json-path.html` — `jsonPath()` 切片分支拆成 `normPos(v,dflt)`（夹 `[0,len]`，省略 start→0 / end→len）与 `normNeg(v,dflt)`（夹 `[-1,len-1]`，省略 start→len-1 / end→-1），循环统一为 `for(i=s0; step<0 ? i>e0 : i<e0; i+=step)` 并加 `0<=i<len` 守卫。
- 证据：新增 2 例（共 13 组切片）。负步长/省略/越界一组命中 `JP=5,4,3,2,1|5,4,3,2,1||5,4,3,2||5,3,1|`（含 `[99::-1]`、`[:-99:-1]`、`[-99::-1]`、`[4:0:-1]`、`[0:5:-1]`、`[::-2]`、空数组）；正步长一组命中 `JP2=||1,2,3|3,4,5|1,4|5,3`（含 `[99:]`、`[:-99]`、`[-99:3]`、`[2:99]`、`[::3]`、`[4:1:-2]`）。原有 `[4:0:-1]`、`[::-1]`、`[-1:]`、`[0:5:2]` 四例保持通过。

## 2. IT-N528 镜像未完全校验，仍可生成类型错误 YAML
- 失败点：`[nginx]` 输出 YAML 数组、`123` 输出整数、`&foo` 输出 null；旧校验只枚举 `#`、少数关键字与空白/引号。
- 根因：镜像名以裸标量拼进 YAML，且没有按容器镜像引用语法做白名单校验。
- 修复位点：`tools/it/kubernetes-yaml-generator.html` — 新增 `KY_IMG_RE`（registry 主机可带端口 / 小写路径 / 可选 tag / 可选 `@sha256:<64hex>` 摘要）做最终白名单；保留原有三条具体错误提示（`#` 开头、YAML 关键字/空结构、空白/引号）以免破坏既有契约；生成时把镜像统一写成 YAML 单引号标量 `image: '…'`。
- 证据：新增 3 例 — 6 个非法输入（`[nginx]`、`&foo`、`*alias`、`{a}`、`a//b`、`nginx:latest:bad`）全部命中 `K8=REJECT|REJECT|REJECT|REJECT|REJECT|REJECT`；`123` 命中 `image: '123'`（引号保证 YAML 解析为字符串）；`ghcr.io/team/app:1.2.3` 命中 `image: 'ghcr.io/team/app:1.2.3'`（合法复杂镜像未被误伤）。同步旧自动补强用例 expect `image: redis:7-alpine` → `image: 'redis:7-alpine'`；原有 6 条名称/端口/镜像错误用例保持通过。

## 3. IT-N474 取模右操作数为常量或函数时仍被误转百分比
- 失败点：`7%pi` → `(7/100)pi`、`7%sin(1)` → `(7/100)sin(1)`，语法错误；页面同时声明支持取模与 pi/sin。
- 根因：`%` 后的操作数起始判别只用 `/[0-9(+\-]/`，遗漏页面 `MATH_ALLOWED` 放行的常量与函数名、小数点起始操作数。
- 修复位点：`tools/it/math-evaluator.html` — 判别字符类扩为 `/[0-9A-Za-z.(+\-]/`；代码注释与页内「工作原理与说明」同步写明操作数起始符范围及歧义约定（`50%+3` 按取模，需要百分比加数写 `(50/100)+3`）；`i18n/tools/en/it/math-evaluator.json` 的公式区英文映射同步改为与新中文文本一致的键与译文（**顺带修**：原英文键已滞后于中文文本，英文态存在 CJK 泄漏）。
- 证据：新增 2 例（共 13 个表达式逐项数值比对）— `ME=OKOKOKOKOKOKOKOKOK`（`7%pi`、`7 % pi`、`7%sin(1)`、`7%e`、`7%.5` 及 `15%`、`.5%`、`50%*120`、`7%3` 护栏），`ME2=OKOKOKOK`（`7%-pi`、`7%+sin(1)`、`7 % -3`、`7 % +3`）。原有 8 条 IT-N474 取模/百分比用例与 8 条 IT-N470 安全护栏用例保持通过。

## 5. IT-N551 二维码清空后仍能下载旧 PNG
- 失败点：清空文本并 `generate()` 后 `__qrMeta=null` 但 `window.__qrCanvas` 仍在，`downloadPNG()` 触发一次旧图下载。
- 根因：旧修复只清 SVG 元数据；`generate()` 的空分支与异常分支都没作废旧画布，`downloadPNG()` 也只看画布不看元数据。
- 修复位点：`tools/it/text-qr.html` — `generate()` 一开始即 `window.__qrCanvas=null; window.__qrMeta=null`，异常分支再次清空；`downloadPNG()` 要求画布与元数据同时有效。
- 证据：新增 2 例 — 清空路径用 `createElement('a')` 桩捕获 `downloadPNG()` / `downloadSVG()` 的实际点击，命中 `QR= CANVAS=NULL META=NULL`（零下载）；异常路径命中 `ERR=CLEAR RECOVER=OK DL=DL:qrcode.png`（异常后清空 → 桩替身恢复合法生成 → 真实下载一次新 PNG）。原有 2 条 text-qr 用例保持通过。

## 6. IT-N471 小尺度向量仍被显示成零向量和零叉积
- 失败点：A=(1e-7,0,0)、B=(0,1e-7,0) 输出 `A = (0,0,0)`、`A × B = (0,0,0)`、面积 0，却同时写 `sinθ=1 → θ=90°`。
- 根因：① `fmt()` 用 `Math.abs(x)<1e-12` 判零；② 更隐蔽的是 `toLocaleString()` 默认只保留 3 位小数，即便去掉阈值，1e-7 仍显示成 0；③ `mag()` 朴素平方在下溢尺度为 0；④ 角度/平行判定依赖 `mA*mB`，小尺度会下溢。
- 修复位点：`tools/it/vector-cross-product.html` — ① `fmt()` 仅真实零显示 0，`|x|<1e-3` 或 `>=1e15` 走 `toExponential(3)`；② `mag()` 改按最大分量缩放；③ 新增 `fmtScaled(c,mA,mB)` 指数分解，在 `mA*mB` 下溢时用归一化叉积 × |A| × |B| 展示量级；④ 角度与平行判定改用归一化向量（`atan2(sinθ, cosθ)`、`sinT<=1e-9`），不再依赖会下溢的乘积；⑤ 非有限分量直接阻断；⑥ 页内「公式说明」与 `i18n/tools/en/it/vector-cross-product.json` 英文映射同步更新（原英文键同样已滞后）。顺带把 `tools/it/vector-magnitude.html` 的 `fmt()` 一并对齐 `<1e-3` 口径。
- 证据：新增 3 例 — 小尺度正交命中 `A = (1.000e-7, 0, 0)` 与 `A × B = (0, 0, 1.000e-14)`；小尺度反向共线命中 `B = (-1.000e-7, 0, 0)` 与 `θ = 180°`；1e-200 极端下溢命中 `A × B = (0, 0, 1e-400)` 与「叉积绝对量级低于双精度可表示范围」说明。原有 12 条 IT-N471 用例（钝角 135°、反向 180°、正交 90°、锐角 45°、零向量等）与 vector-magnitude 的 6 条用例保持通过。
