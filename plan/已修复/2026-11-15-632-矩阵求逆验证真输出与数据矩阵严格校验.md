## 一、修了什么

### 1. SMS-109 — 矩阵求逆的「验证」由死代码改为实测输出

**文件**：`tools/science/matrix-calculator.html`

**旧缺陷**：求逆分支里

```js
const check = mul(A, inv);   // 算完从未使用
steps += '<div class="step-line"><strong>验证：</strong>A · A⁻¹ = I（单位矩阵）</div>';
```

`check` 是死代码。步骤行只打印「A · A⁻¹ = I」这句**定义**，用户看不到任何实际验证结果——属于「承诺未实现」。

**修复**：

```js
const check = mul(A, inv);
let __maxDev = 0;
for (let i = 0; i < n; i++) for (let j = 0; j < n; j++) {
  const t = Math.abs(check[i][j] - (i === j ? 1 : 0));
  if (t > __maxDev) __maxDev = t;
}
const __tol = Math.max(1e-9, __matEps(check));
const __bad = !(__maxDev <= __tol);
```

步骤区现在输出三行：

1. **验证 A · A⁻¹（应为单位矩阵）** → 实际渲染乘积矩阵
2. **与单位矩阵最大偏差：|Δ| = 2.22e-16** → 实测偏差（toExponential(2)）
3. 偏差超容差时该行标红并提示「超出容差，求逆结果数值上不可靠」；否则「在容差内」

容差取 `max(1e-9, max|check 元素|·1e-12)`：单位阵量级为 1，1e-9 对双精度求逆足够宽松（2×2 实测 1e-16 级），又不至于把真错判成通过。

**同批附带**：该页 9 个运算分支（add / sub / mul / scale / transpose / det / inv / rank / power）的标签原本全部硬编码中文，EN 态会整片残留 CJK。本批统一走 `__matIsEn()` 分流，`calculate()` 头部注入 `const __mEn = __matIsEn();`。

### 2. SMS-168 — 数据矩阵「演示模块数」改为严格整数校验

**文件**：`tools/design/data-matrix.html`

**旧缺陷**：

```js
const size = Math.max(8, Math.min(24, parseInt(document.getElementById('size').value) || 14));
```

三个静默：

| 输入 | 旧行为 | 后果 |
|---|---|---|
| `42` | 钳位成 24 | 用户不知道输入被改，照常出图 |
| `14.5` | `parseInt` 截断成 14 | 小数被当成合法阶数 |
| 空 / `abc` | `|| 14` 兜底 | 静默用默认值 |

**修复**：改为 `Number()` + `Number.isInteger()` 严格校验：

```js
const __szRaw = document.getElementById('size').value.trim();
const __szNum = Number(__szRaw);
if (__szRaw === '' || !Number.isInteger(__szNum) || __szNum < 8 || __szNum > 24) {
  // 提示 + 清 preview / table / diff / chart + 置 lastURL = ''
  return;
}
const size = __szNum;
```

关键点：**必须清 `lastURL`**，否则停算后「下载」按钮仍能导出上一次的图，形成新的谎言。

**为何不改 8–24 这个范围**：引据表已写明「规范为 10×10 至 144×144 的偶数规格；本工具的演示模块数 8–24 只是画布阶数，不是规范尺寸」。原 plan 条目所称「与引据表四档矛盾」中的「四档」表述已不存在，剩余真实缺陷只是缺校验。
