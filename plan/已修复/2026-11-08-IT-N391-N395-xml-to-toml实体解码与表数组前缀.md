## 一、缺陷与修复

### IT-N394 XML 实体不解码，`&amp;` 等原样写进 TOML 值
- 失败点：属性正则直接取引号内原文（`attrs[m[1]]=m[2]`），文本节点只 `trim()`，全文没有实体解码 ⇒ XML 语义上的 `Tom & Jerry` 被写成 `Tom &amp; Jerry`（回读值错误，典型双重转义）。
- 根因：解析器把「原始文本」直接当值用，缺「XML 文本→字符」这一步。
- 修复位点：新增 `xDecode(s)`（`calcTool` 内、`xmlToJson` 之前）——单次 `replace` 同时处理命名实体（`amp lt gt quot apos nbsp`）与数字引用（`&#NN;` / `&#xNN;`，用 `String.fromCodePoint`，越界保留原文）；属性赋值改为 `xDecode(m[2])`，`nodeVal` 的 `#text` 与叶子文本改为 `xDecode(text.trim())`。
- 证据：`<name>Tom &amp; Jerry</name>` → `name = "Tom & Jerry"`；`<t>&#65;&#x42;</t>` → `t = "AB"`；`<a url="x&amp;y"/>` → `"@url" = "x&y"`；`<r>&amp;amp;</r>` → `r = "&amp;"`（只解一层，不会二次解码）。

### IT-N395 嵌套表内的同名兄弟元素生成 `[[item]]` 而非 `[[config.item]]`
- 失败点：`dumpTable` 的数组表分支固定写 `'[['+tKey(k)+']]'`，完全忽略传入的 `prefix` ⇒ `[config]` 内的 `item` 数组被提升为根级表数组，TOML 回读后 `config` 下面没有 `item`。
- 根因：prefix 只在「普通子表」分支往下传，数组表分支既不拼前缀也不传前缀。
- 修复位点：`dumpTable(t,sort,prefix[])` 改为**路径段数组**，数组表分支 `var sub=prefix.concat([k])` 并同时用于表头与递归；新增 `tPath(parts)` 逐段 `tKey` 后拼点号——旧写法把原始键名拼进 prefix，键里含点号/空格时深层表头会写成 `[r.a.b."c.d"]`（TOML 读成 5 层），现为 `[r."a.b"."c.d"]`（正确的 3 层）。`dumpToml` 起始 prefix 改传 `[]`。
- 证据：`<config><item><a>1</a></item><item><a>2</a></item></config>` → 两条 `[[config.item]]`；`<r><a.b><c.d><e>1</e></c.d></a.b></r>` → `[r."a.b"."c.d"]`；`<r><s><t><u>1</u></t></s></r>` → `[r]` / `[r.s]` / `[r.s.t]`（普通深层表未受影响）。

### IT-N391（xml-to-toml 侧）：「缩进」下拉未被读取
- 失败点：页面提供「缩进：2 空格 / 4 空格 / Tab」，`calcTool` 只读排序复选框，该值从未被 JS 使用。
- 处置：TOML 无缩进语义（缩进只为可读性，且本页输出是「表头 + 键值」平铺），与 yaml-to-toml 侧同口径——**移除该下拉**，同步删掉 `resetForm()` 里的 `selectedIndex` 复位、以及 4 个预设里的 `indent` 键。
- 顺带：原第 4 个预设「Tab 缩进的嵌套配置」在控件删除后已无意义，换成「嵌套重复元素」（`<config><item>…</item><item>…</item></config>`，正好演示 N395 修复后的 `[[config.item]]`）。
- 验证：jsdom 实测 `document.getElementById('indent') === null`、`resetForm()` 不再抛错且 source 复位为默认样例；`audit_verify_input_ids.js` 僵尸 id 0。

## 二、判别力说明（为什么 N391 这条没有新增用例）

「删掉一个从未被读取的控件」没有行为契约可断言：harness 的 `getElementById` 对**任意 id 都会自动造桩元素**（`getEl` 里 `if(!(id in elements)) elements[id]=makeEl(...)`），所以 `getElementById('indent')===null` 在桩里恒为 false，写出来就是假断言；而任何“控件消失但功能不变”的断言又对输入不敏感 ⇒ 必然成为判别器眼里的逃生项。故本条只以 jsdom 真机 null 检查 + 僵尸 id 审计为证据，不凑用例。

另：`errs: ["dataGrid: rows is not iterable"]` 是本页与 toml-to-xml 的**harness 兜底噪声**（`dataGrid` 是页面里定义了但从未调用的辅助函数，兜底步骤用无参方式调它才抛），不是页面缺陷，不影响用例判定。
