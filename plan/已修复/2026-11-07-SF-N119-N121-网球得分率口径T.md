## 根因
1. **SF-N119**：`readInputs()` 的 `valid` 只判 `total>0 / ace≥0 / df≥0 / fi∈[0,100] / bf≥0 / bs≥0`，漏了 `ace<=total`、`df<=total`、`bs<=bf`；校验失败仅 `setInvalid` 标红，`:212-215` 的中止分支（`if(!iv.valid) return`）因 `valid` 永真而进不去，指数照常算出、可破 100。
2. **SF-N120**：页面标题与引据表、深度解析都讲「得分率」，但 `calc()` 只读 `total/ace/df/firstIn/bpFace/bpSave` 六项，既无发球分区得分输入也无全场得分率输出——纯属空头承诺。
3. **SF-N121**：破发点挽救率 `bf>0?bs/bf*100:100`，面对 0 时记 100% 并占 0.30 权重，等于 0/0 白送 30 分；同一组数据 bf=6/bs=0 反而只 20「待提升」。

## 修复位点
- `tools/sports/wangqiudefenlvfenxi.html`
  - `readInputs()`：新增 `ace<=total`、`df<=total`、`bs<=bf` 三项 `errs.push` 与 `setInvalid`；新增 `p1w/p2w/rt/rw` 读取与四项校验（一发得分≤一发命中数、二发得分≤二发球数、两者之和≤总发球分、本方全场得分≤全场总得分）。
  - `calc()`：`p1Rate = firstInCount>0? p1w/firstInCount*100 : null`、`p2Rate = secondCount>0? p2w/secondCount*100 : null`、`totalRate = hasRt&&hasRw? rw/rt*100 : null`；破发点改为 `bpSaveRate = bf>0? bs/bf*100 : null`，`wSum = 0.40+0.15+0.15+(bf>0?0.30:0)`、`efficiency /= wSum`；无破发点样本时输出「—」+ 归一说明。
