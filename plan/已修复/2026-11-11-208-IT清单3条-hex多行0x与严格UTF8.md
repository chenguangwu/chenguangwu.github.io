# 2026-11-11 第208批 · IT-N261/N262/N263 hex-encode 多行 0x / 评分启发式 / 严格 UTF-8

## 清单项
- **IT-N261**：多行或"每字节 0x"的 hexdump 粘贴因 `^0x` 只去一次而报非法；编码侧 prefix 也只在整串首加一个 `0x`（中，确认缺陷）
- **IT-N262**：历史/数据表/图表与 CSV 恒空（`textContent` 读 textarea）+ `/错误|Error/` 判 0 启发式（中，确认缺陷）
- **IT-N263**：解码侧默认 `TextDecoder` 静默把非法 UTF-8 替换成 U+FFFD，且 `dec` 未接入历史（中，确认缺陷）

## 改动
`tools/it/hex-encode.html`：
1. **N261 解码**：`text.replace(/^0x/i,'').replace(/[\s:,;_-]/g,'')` → 先 `replace(/[\s:,;_-]/g,'')` 再 `replace(/0x/gi,'')`，每行/每字节前缀与大小写 0X 都能处理。
2. **N261 编码**：`(prefix?'0x':'') + parts.join(sep)` → `if(prefix) parts=parts.map(h=>'0x'+h)`，勾选前缀时逐字节加（`0x48 0x69`），与 C 数组 / hexdump 约定一致。
3. **N262**：`__hex_encodeScore()` 删掉关键词判 0 正则，恒返回 1（与第198批 N246 同型）；历史读取侧 `r.value` 已由 F-N189 全站修复覆盖（`#output` 是 textarea），本批不再重复改。
4. **N263 严格解码**：`new TextDecoder('utf-8',{fatal:true,ignoreBOM:true})`，失败时逐字节流式统计非法字节数、输出 Latin-1 对照串与 `0xXX` 原始字节列表；中英提示均内联 helper。
5. **N263 解码进历史**：新增全局 `__hex_encode_mode`（enc/decode 各自置位），把 `dec` 也包进 extras（原版只包了 `enc`），记录写 `模式=编码/解码` 并把该键插入表头 keys；历史回放按 `rec['Mode']||rec['模式']` 选回 `enc()`/`dec()`，旧记录无方向键时仍按 enc 兼容。
6. 静态文案同步：工作原理公式说明、算法说明 `<p data-zh>` 改为新口径（逐字节 0x + 严格解码 + Latin-1 对照）。

`i18n/tools/en/it/hex-encode.json`：上述两条中文键与英译值同步更新（en JSON 为「中文键→英译值」，key/value 均改）。
