# 复核失败重做批次 · 申请再次复核

## R-N6 净趸缴必填失败后仍导出上一次保费并写历史

**失败点（原复核记录）**
- 页面：`tools/insurance/net-single-premium.html`。
- 复现：默认有效计算后清空保额 B 再计算，页面提示「请填写保额」，历史却保存该错误并沿用旧保费数值 81763.70；随后导出仍生成上次保额 1000000 的旧明细 CSV。

**根因**
- 通用必填守卫 `if(__ig){...return;}` 在 `__nspLast=null;` 之前 return，守卫触发时旧 `__nspLast`（上次有效计算的保费/逐年明细）未被清空；而导出入口 `if(!__nspLast){...return;}` 与历史写入均依赖 `__nspLast`，故沿用旧数据。

**修复位点**
- `tools/insurance/net-single-premium.html` `calcTool()`：将 `__nspLast=null;`（本次输入非法时不得再用上一次的明细导出）移至函数最开头、必填守卫之前；守卫与各字段校验 return 时 `__nspLast` 已为空，导出被 `if(!__nspLast)` 阻断、历史不再写旧值。

**验证证据**
- `env -u NODE_OPTIONS node scripts/verify_it_calc.js net-single-premium` 全绿（含新增用例）。
- 新增回归用例：预置 `__nspLast={nsp:81763.70}`、清空 B 后 `calcTool()`，断言贴回结果区的 `R6_LAST=NULL`（修复前守卫 return 早于清空 ⇒ `R6_LAST=STALE`）。旧保费数值不出现在判定串、非回显。

**判别力实测**
- 单文件判别器 `node scripts/discriminate_check.js verify_it_calc.js`：1333 用例已检、正确变红 1333、逃生项 0。本用例锚 `__nspLast` 状态标记，输入无关、非回显；回退源码（清空置于守卫之后）后转红，确认门禁可捕获回归。
