## 一、缺陷与根因（两套模板同根因）

全站历史快照模板有**两个世代**，都会在「历史恢复」上出错，但表现一致、根因相同：

| 模板 | 判定特征 | 页数（带复选框） |
|---|---|---|
| Snap 模板 | `function __<pre>Snap(){…}` + `document.querySelectorAll('input[id],select[id],textarea[id]')` | 349 |
| 旧模板变体 | `function __<pre>Raw(id){…}` + `function __<pre>Restore(rec)` + 显式 `record({字段表})` | 3 |

原始写法只记录「勾选中的项」：

```js
var v=(t==='checkbox'||t==='radio')?(e.checked?(e.value||'1'):''):e.value;
if(v!==''&&v!=null) out[e.id]=v;      // 未勾 ⇒ 不入快照（稀疏）
```

由此派生三个真缺陷：

1. **恢复时不清除当前多勾的项**：`Restore`/`mount` 只遍历记录里已有的键，页面上后来多勾的项原样留着。
   实测（`it/chmod-calculator`）：记录 600 → 手改成 777 → 点历史恢复 → **仍显示 777**（应为 600）。
2. **「全不勾」状态永不入历史**：全部不勾时快照为空对象，`Extras` 判定「无有效输入」直接早退，
   于是 000 这类合法配置永远存不进去。
3. **旧模板变体更严重：勾选态根本没进 `record`**：`record({fy:Raw('fy'), …, lab:lab, la:la})` 是手写字段表，
   页面上的复选框 id 一个都没列 —— 恢复任意一条历史，勾选态都保持「当前值」，等于完全没恢复。
   这 3 页（`civil/rebar-anchorage` / `health/milk-tea-calories` / `welding/weld-strength`）单列修复。

## 二、处置

### Snap 模板（349 页，同构两处）

```js
// ① 快照全量：未勾记 '0'，不再跳过
var v=(t==='checkbox'||t==='radio')?(e.checked?'1':'0'):e.value;

// ② 恢复回调 try{ 之后，先清掉记录里没有的勾选
var __cbs=document.querySelectorAll('input[type=checkbox],input[type=radio]');
for(var __ci=0;__ci<__cbs.length;__ci++){
    if(!Object.prototype.hasOwnProperty.call(rec,__cbs[__ci].id)) __cbs[__ci].checked=false;
}
```

### 旧模板变体（3 页，三处）

```js
// ① Raw：未勾记 '0'
return e.checked?'1':'0';

// ② record 前补全勾选态（原字段表根本没列复选框）
var __rec={…原有字段表…};
var __cbs=document.querySelectorAll('input[type=checkbox],input[type=radio]');
for(var __ci=0;__ci<__cbs.length;__ci++){if(__cbs[__ci].id)__rec[__cbs[__ci].id]=__cbs[__ci].checked?'1':'0';}
TBKit.history.record(__rec);

// ③ Restore 开头先清空未记录的勾选
function __<pre>Restore(rec){ var __cbs=…; for(…){ if(!hasOwnProperty(rec,id)) e.checked=false; } … }
```

`Restore` 里的 `e.checked=(String(e.value)===String(rec[k])||rec[k]==='1'||rec[k]===true)` 保持原样，
故**旧记录（存的是 value 如 `+80`）与新记录（存 `'1'`）双向兼容**，不会让历史里已有的记录失效。

## 三、顺带修掉的真 BUG（2 类）

### 1. `health/milk-tea-calories`：`Extras` 越作用域，整块静默失效（高价值）

`__milk_tea_caloriesExtras()` 里 `['一杯总热量', total+' kcal']` 的 `total` 是 `calcTool()` 内的 `const`，
Extras 取不到 ⇒ 每次调用抛 `ReferenceError: total is not defined`。而页面把它包成：

```js
calcTool = function(){ __tb_fn0(); try{ __milk_tea_caloriesExtras(); }catch(e){} };
```

**异常被空 `catch` 吞掉**，症状是「加料明细表恒空 + 历史永不记录 + 导出恒空」，页面上完全看不出报错。
修法：在 Extras 内按同一口径就地重算 `topKcal` / `total`（与 `calcTool` 公式逐项一致）。

> 同类风险已全站排查：见 §四 的 4270 页 Extras 可调用性审计，仅此 1 页命中。

### 2. `it/area-code-lookup` / `it/country-code-lookup`：用户输入直接拼 innerHTML（DOM 注入点）

`<p data-zh="输入：${raw}"><strong>Input:</strong>${raw}</p>` 里 `raw` 是原始输入，
带引号/标签即可改写 DOM 属性与结构。改为走站点 `escHtml`（含无 `ToolBox` 时的本地兜底链）。

## 五、工具链自身缺陷（本批踩到并修掉的 5 处）

1. **锁硬要求 `Snap()`**：旧模板变体页直接报「未找到 Snap 函数」，3 页无法纳入验证。修：识别 `Raw(id)` 模板，快照改读最近一条 `record`。
2. **`boxIds` 只认 `type` 在 `id` 之前**：`<input id="x" type="checkbox">` 全部漏采 ⇒ 误判「页面无复选框」。修：先抓整个 `<input …>` 再判类型。
3. **JS 拼接模板被当成静态 id**：`id="chk-' + a.id + '"` 被截出 `chk-`（恰好符合 id 字符集）⇒ 凭空 3 条 FAIL。修：id 必须**引号配对**（`(["'])([^"']*)\1`）。
4. **模板片段过滤误伤真实值**：首版用「标签内含 `'+`」排除，把 `value="+80"`（奶茶加料）的整页复选框全排除。修法同上（改为只校验 id 引号配对）。
5. **审计脚本单片跑 4270 页 JSDOM OOM**（`window.close()` 不彻底释放，4 GB 堆爆，exit 134）。修：按 400 页切片多进程，`--max-old-space-size=3072`。
