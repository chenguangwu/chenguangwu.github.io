## 修复位点

### FE-N70 敲击用 `performance.now()`、期望时刻用 `AudioContext.currentTime`，两钟不同源导致几乎全部判漏击（高，确认源码缺陷）
- **文件**：`tools/music/rhythm-trainer.html`（纯前端源码，非构建产物）
- **缺陷**：`startTraining` 里 `startTime = ctx.currentTime + countInDuration`（音频上下文时钟，从 `AudioContext` 创建瞬间归零）；而 `onTap` 记录的是 `performance.now()/1000`（页面导航时钟）。两者原点相差「页面打开到首次点开始训练」的时长，`calculateScore` 直接相减将其作为固定偏移；容差仅 `max(0.8×格长, 80ms)`（60 BPM 宽拍也只有 800ms），因此停留几秒再训练时绝大多数敲击被判「漏击」，命中数≈0、准确率恒 0%，历史记录被 0 分污染。
- **修复**：`onTap` 改为 `const now = getAudioCtx().currentTime;`（约 L1011-1015），与 `startTime` 同源；`getAudioCtx()` 返回页面级持久实例（`audioCtx` 惰性创建并复用），故时基一致且无需改 `startTime`。
- **根因**：同一测量链路混用两种时间原点（音频上下文时钟 vs 高精度导航时钟）。

### FE-N71 命中列表小节号 off-by-one，每小节第 4 拍被标成下一小节（中，确认源码缺陷）
- **文件**：`tools/music/rhythm-trainer.html`
- **缺陷**：`beatIdx` 是 1 基拍号，`measureNum = Math.floor(beatIdx/4)+1` 应为 `Math.floor((beatIdx-1)/4)+1`；于是 `beatIdx=4`（第 1 小节第 4 拍）被算成「第 2 小节」，每小节最后一拍都被错标到下一小节。
- **修复**：`const measureNum = Math.floor((beatIdx - 1) / 4) + 1;`（约 L1155），`beatInMeasure = ((beatIdx - 1) % 4) + 1` 保持原式。
- **根因**：1 基索引误用 0 基整除公式。
