## 修复位点

### T-N6 净现值对无效折现率与期数仍给出结论（高）
- **文件**：`tools/audit/npv-discount.html`（`calc()`、`updateFlow()`、`renderList()`、`__npvChartDraw()`）
- **缺陷**：参数全部走 `parseFloat(...)||0` / `parseInt(...)||1` 兜底，非法输入被悄悄替换成 0 或 1，照样输出「看起来可用于投资决策」的 NPV：
  - 清空折现率 ⇒ 按 0% 算，NPV 60,000.00；
  - 折现率 −150% ⇒ `1+r = −0.5`，折现因子正负交替，NPV −630,000.00；
  - 折现率 −100% ⇒ 分母 0，结果区显示 `--` 但仍给 ROI 60%；
  - 清空初始投资 ⇒ 当 0 算，NPV 126,471.13；
  - 年金期数 0 或 2.5 ⇒ `parseInt||1` 兜底成 1 期（2.5 先被 `parseInt` 截成 0 再兜底）；
  - 某期现金流清空 ⇒ `parseFloat||0` 当 0 算。
- **修复**：
  1. 新增 `__npvParse(id)`：`parseFloat` + `isFinite`，**空值/非数返回 NaN**，从此区分「空」与「零」；
  2. 新增 `__npvBlock(msg)`：把错误写进 `#stats`（⚠ + 原因，并标注「参数不合法，已停止计算」）、清空 `#detailBody` 与 `#npvChart`、置 `window.__npvBlocked = true`，直接终止本次计算；
  3. `calc()` 校验链：折现率必填 → **折现率必须 > -100%**（否则折现因子无意义）→ 初始投资必填 → 年金模式「每期金额必填 + 期数须为 1–1000 的整数」→ 自定义模式「至少一期 + 每期现金流不得为空」；通过后置 `__npvBlocked = false`；
  4. `updateFlow()` 空值存 `NaN` 而非 0；`renderList()` 回显时 `NaN` 渲染为空串，避免把 `NaN` 写进 input 的 `value`；
  5. `__npvChartDraw()` 增加 `__npvBlocked` 早退并清空图表，非法参数不再留下一条按错误参数画的曲线。
- **根因**：用 `||0` / `||1` 兜底所有解析失败，把「输入非法」静默变成「输入为 0/1」，错误被吞掉后继续产出数字。

### T-N8 净现值说明示例与实际公式不一致（低）
- **文件（真源）**：`i18n/tools/content_deepdive.json`（`/audit/npv-discount/examples/0/body`）、`i18n/tools/en/audit/npv-discount.json`（中文键 + 英文值）、`i18n/guides/npv-discount-guide.json`（键带前导「：」+ 英文值）
- **缺陷**：示例写「系数取 4 位 0.9259… → 现值 23148+25719+27783+22050+13612 = 112312 → NPV 12312」，而页面是**按全精度因子**算现值、只把因子显示成 4 位。用 4 位系数相乘必然对不上页面的 2 位金额，差异约 3 元。
- **修复**：以全精度折现因子重写示例并标注精度——
  - 因子全精度：0.925926、0.857339、0.793832、0.735030、0.680583（并注明「页面表格按 4 位显示」）；
  - 各期现值：23148.15、25720.16、27784.13、22050.90、13611.66，合计 **112315.00**；
  - NPV = 112315.00 − 100000 = **12315.00**。
  - 三处真源同批文本级替换（未用 `json.dump`，避免整档重排噪音），`audit_deepdive_source_sync.py --check` 扫描 4573 页、不一致 0。
- **根因**：示例是用「已舍入的系数」手算的，而页面代码用的是未舍入系数，两套舍入口径混用。
