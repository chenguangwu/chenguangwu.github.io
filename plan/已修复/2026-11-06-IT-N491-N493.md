### IT-N491 Codabar 编码表大面积非法，默认预设起止符就错（高，已修复）
- 原问题：`CODABAR` 表与页面自述规则（7 单元、2–3 宽）自相矛盾——`$`=NWWWWWN（5 宽）、`:`/`/`/`.`/`C` 为 4 宽、`D` 只有 6 单元，20 个字符中 17 个结构非法，仅 `0/1/3` 等少数正确；默认预设 `A12345B`、`C9999D` 的起止符全落在错误集合里，扫描器会拒读或误读。
- 修复（2026-11-06，`tools/it/barcode-codabar.html`）：整表按 **AIM BC3-1995 / USD-4（NW-7）** 重写（条 空 条 空 条 空 条 顺序）：
  `0 NNNNNWW / 1 NNNNWWN / 2 NNNWNNW / 3 WWNNNNN / 4 NNWNNWN / 5 WNNNNWN / 6 NWNNNNW / 7 NWNNWNN / 8 NWWNNNN / 9 WNNWNNN / - NNNWWNN / $ NNWWNNN / : WNNNWNW / / WNWNNNW / . WNWNWNN / + NNWNWNW / A NNWWNWN / B NWNWNNW / C NNNWNWW / D NNNWWWN`。
  取值依据：三份独立来源交叉一致（docs.rs `barcodes` crate `codabar.rs`、CodeProject《Drawing Barcodes in Windows Part 2》、dcode.fr Codabar 表；仅 `+` 一项 dcode 记作 4 宽，与另两份的 3 宽冲突，取多数且符合「2–3 宽」不变量的 NNWNWNW）。
- 门禁回归用例（`scripts/verify_it_calc.js`，2 条）：① 遍历全表断言 `BAD=none`（每字符 7 单元、宽单元 2–3 个；修复前 BAD 列表含 17 项）；② `buildCodabar('A0A').bits === 'NNWWNWNnNNNNNWWnNNWWNWN'`（逐字符码字 + 字符间窄空 `n`）。

### IT-N492 非法字符被静默丢弃、标签仍显示原文；不校验起止符（中，已修复）
- 原问题：`buildCodabar()` 对表外字符 `continue`，`generate()` 仍把原始 `raw` 写进标签 ⇒ 输入 `A12X345B` 时条码实际只编码 `A12345B`，标签却显示 `A12X345B`；输入 `12345`（无起止符）也照常出图，读码器无法判读。
- 修复（2026-11-06）：`buildCodabar()` 返回 `{bits, text}` 或 `{error}`——
  - 逐位校验表外字符，报「第 N 位含非法字符「x」（仅支持 0-9 - $ : / . + 与起止符 A/B/C/D）」并带位置；
  - 强制首/末字符属于 `A–D`，否则分别报「首字符/末字符必须是起止符 A/B/C/D（如 A12345B）」；
  - 长度 < 3（起止符之间无数据）直接报错；
  - `generate()` 把 `error` 文本转义后写入结果区（不再出图），标签改用规范化后的 `built.text`。
  - 新增 `__cbEn()` 双语（TBKit 未就绪时按 `?lang=en-US` / `html[lang]` 兜底），`_verify_en_cjk.mjs --container=output` → `OK_EN`。
- 门禁回归用例：① 输入 `abc123测试` → 「第 7 位含非法字符「测」…」（原自动补强用例断言的是输入回显，本次同批改为依赖位次的强断言）；② 输入 `12345` → 「首字符必须是起止符 A/B/C/D」。`it/barcode-codabar` 5/5 通过。
