# 389 设计 · 二维码生成器改真实编码（D-N208）

- 批次：第 389 批
- 台账项：D-N208（二维码生成器不生成任何二维码，只输出随机配置文本）
- 页面：`tools/design/generator-8.html`
- 相关源：`i18n/tools/design.json`、`i18n/tools/design-body.json`、`i18n/tools/content_deepdive.json`、`i18n/tools/en/design/generator-8.json`、`scripts/verify_it_calc.js`

## 一、原状

页面只有「生成数量」一个输入，`gen()` 用 `Math.random` 拼出 N 段「配置参数 #i」（渲染模式 / 画布尺寸 / 边距 / 纠错等级 / 前景色 / 示例链接 / 圆角模块 / 定位点样式）+ 一段 `.qr-N` 容器 CSS。全页无 canvas、无矩阵、无下载，也没有「输入网址或文本」的控件。

文案却写「输入网址或文本…生成二维码…支持导出」，`formula-desc` 更直接写「调用内置 qrcode.js 按文本生成二维码」—— 而 **`js/qrcode.js` 连 `<script>` 标签都没引**，「调用」纯属虚构。

## 二、改法：接上已有库，做成真工具

项目内已有 `js/qrcode.js`（Kazuhiko Arase，MIT，56 KB，`qrcode(typeNumber, ec)` + `addData` + `make` + `getModuleCount`/`isDark`，`typeNumber=0` 时自动在 1–40 间选版本）。

1. **引入库**：`<script src="../../js/qrcode.js"></script>`（与 `qr-code-styled.html:250` 同款路径）。
2. **换输入**：删掉「生成数量」，改为
   - `#qrtext` 多行文本（每行一个二维码，上限 20 行）
   - `#qrsize` 画布像素 128–1024
   - `#qrecl` 纠错等级 L/M/Q/H
   - `#qrmargin` 静区模块 0–10（默认 4，ISO/IEC 18004 要求 ≥4）
   - `#qrfg` / `#qrbg` 前后景色
3. **重写 `gen()`**：按 UTF-8 字节长度自动选版本 → Byte 模式编码 → 库内 Reed-Solomon 纠错 + 掩码择优 → 逐格读 `isDark()` 拼成紧凑 SVG path（`M x yh1v1h-1z`），`viewBox = 模块数 + 2×静区`。
4. **容量前置拦截**：版本 40 Byte 模式上限 L 2953 / M 2331 / Q 1663 / H 1273 字节，超出直接给「内容过长：N 字节，超出 X 级 N 字节上限（版本 40），未生成」，不静默截断。
5. **导出**：SVG 走 Blob 直下；PNG 走 `Image` → `canvas` → `toBlob`。按钮用 `data-qrdl` / `data-i` 事件委托。
6. **参数防御**：`qrBuild` / `qrSaveBlob` 对零参调用返回空结构（门禁会用零参探针遍历顶层函数，首轮 `errs` 就是 `qrBuild: Cannot read properties of undefined (reading 'ec')`）。
7. **改名 + 文案**：`二维码生成器（已有，可加强定制）` → `二维码生成器（可定制尺寸、纠错与静区）`；meta×6、formula-eq/desc、tool-notes、介绍块、features、deep-dive（summary/示例/FAQ）、`design.json`、`design-body.json`、EN 字典（23 条新增 + 9 条失效键删除）全部同步。
8. **动态中英**：`isEnMode()` + `T(zh,en)` 覆盖汇总行、信息行、超容量提示、空输入、库未加载、两个下载按钮。

## 三、门禁改造（本批唯一的基础设施改动）

harness 只执行内联脚本、不加载外部 `<script src>`，所以页面里的 `qrcode` 在门禁中是 `undefined`，无法验证真实编码。

改 `scripts/verify_it_calc.js`：
- 新增 `loadQrcodeCtor()`，在独立 vm 里加载一次 `js/qrcode.js` 取构造函数；
- 编译页面脚本时把 `qrcode` 作为 **new Function 形参**传入（不是挂 `globalThis`，避免污染后续用例）：
  ```js
  const pageQrcode = /js\/qrcode\.js/.test(html) ? loadQrcodeCtor() : undefined;
  const compiled = new Function("document", …, "Date", "qrcode", `…`);
  fns = compiled(…, FrozenDate, pageQrcode);
  ```
- 未引用该库的用例拿到 `undefined`，行为与改造前完全一致。

## 五、坑

- **断言不能锚 SVG 属性**：`collectStrings()` 剥标签时会把 `fill="#123456"` 整块吞掉，颜色类用例在门禁里恒红（首版第 4 条就这么红的）。改锚文本信息行。
- **title 后缀是自动拼的**：`_build.py::seo_tool_title` 在工具名 <8 中文字或 <20 字符时追加 `_seo_modifier` 从 intro 里抓的短语，实测抓到「静区与前后景色」「IEC 18004 自动选版本与掩码」这类机械拼串。解法：`design.json` 的 `title` 直接写成「名 - 描述」复合形式（函数见 `\s[-—–]\s` 就原样返回），并在 HTML 内统一工具名。
- **H1 走 HTML、title 走 design.json**：只改 design.json 不会改 H1，两边都要改。
- 页面里 `grep '随机'` 已归零 —— 改造后不存在任何随机参数。
