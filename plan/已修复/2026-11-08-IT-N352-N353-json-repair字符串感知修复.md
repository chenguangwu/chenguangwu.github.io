- 修复日期：2026-11-08

- 用例：`scripts/verify_it_calc.js`（`it/json-repair` 三条）

## IT-N352（高）字符串内的 `//`、`/* */` 被当注释删掉，合法 JSON 静默改值

**失败点**：`repair()` 一上来就用两条全局正则删注释，完全没有字符串状态，随后才做引号/尾逗号处理。

```js
// 修复前
function repair(s){
  s=s.replace(/\/\*[\s\S]*?\*\//g,'');
  s=s.replace(/\/\/[^\n]*/g,'');
  ...
}
```

**根因**：正则式替换是无状态文本操作，`"https://example.com/api"` 里的 `//`、`"P/*x*/Q"` 里的 `/* */` 与真实注释无法区分。删完再 `JSON.parse` 成功，页面就打「✅ JSON 合法」绿标，用户复制走的是被改过值的数据。

**修复位点**：`tools/it/json-repair.html` 脚本区 `function repair()` 及其四个新辅助函数：

1. `jrSkipString(s,i)` — 从开引号跳到闭合引号之后（认 `\` 转义），是全套的公共基元。
2. `jrStripComments(s)` — 逐字符扫描，遇引号整段跳过，只在字符串外删 `/* */` 与 `//`。
3. `jrNormalizeQuotes(s)` — 单引号串转双引号（内部 `"` 转义为 `\"`，`\'` 还原为 `'`）。
4. `jrQuoteBareKeys(s)` — 字符串外、且紧跟在 `{` 或 `,` 之后的 `标识符:` 补双引号。
5. `jrStripTrailingCommas(s)` — 字符串外、`,` 后仅剩空白即遇 `}`/`]` 才删。
6. `repair()` 入口先 `try{JSON.parse(s);return s;}catch(){}` —— **原样合法就一个字节都不改**。

**行为变化（有意为之）**：旧实现的正则会把 `{`/`,`/`[`/`:` 之后的空白连同引号一起吞掉（把空格一并吃掉），新实现全程原样保留空白。因此既有用例的 expect 由 `"name":"probe","n": 2` 改为 `"name": "probe", "n": 2`（同步更新 ref 说明）。这是「少改写原文」的收益，不是回归。

**验证证据（node 直跑修复后函数）**：

| 输入 | 修复前 | 修复后 |
|---|---|---|
| `{"a":"P/*x*/Q"}` | `{"a":"PQ"}` 且报「合法」 | 原样返回 |
| `{"url":"https://example.com/api"}` | `{"url":"https:` 报解析失败 | 原样返回 |
| `{'u':'https://example.com/api','p':'P/*x*/Q',}` | URL 被截、`/*x*/` 被掏空 | `{"u":"https://example.com/api","p":"P/*x*/Q"}` |
| 默认样例 | 可用 | 输出 `{\n  "name": "ToolBox", \n  "tools": [1, 2, 3]\n}` |

## IT-N353（中）文档表格承诺「键无引号 → 补双引号」，代码里没有这条规则

**失败点**：`tools/it/json-repair.html` 参考表第 4 行写 `{a:1}` → `{"a":1}`，深度解析示例也照此写；`repair()` 里只有四条针对单引号的规则，没有任何裸键规则。

**根因**：文档先行、实现漏做。用户照页面自带示例操作，得到的是「⚠️ 仍无法解析」。

**修复位点**：同页新增 `jrQuoteBareKeys()`（见上），现在 `{a:1,}` → `{"a":1}`、`{a:1,b:2}` → `{"a":1,"b":2}`，与文档一致（文档因此不需要改）。

**附带同步**：说明列表里「若结构本身严重损坏（缺括号、键名无引号且非数字），仍可能失败」已过时（裸键现在支持），改为「缺少括号或引号未闭合」，并补一句「字符串内容（URL、正则、含 `//` 的文案）不会被当作注释删除」；英文源 `i18n/tools/en/it/json-repair.json` 同条同步。
