# 第1263批 · AI-N16 摘要关键词滑窗碎片修复

## 问题
`tools/ai/ai-text-summarizer.html` 的 `splitWords()` 对每个 token 无条件生成全部 2-gram/3-gram，导致中文关键词面板出现「工智」「人工智」等重叠碎片，英文出现 `ac`、`mo` 等无意义字母片段，用户拿不到可用词表。

## 修复
`splitWords()` 重做：英文完整单词（保留原小写）直接入表；中文用 `Intl.Segmenter('zh',{granularity:'word'})` 按词切分；环境不支持 Segmenter 时退回原 token，**不再生成任何滑窗 n-gram**。`keywords()` 的停用词与频次排序保持不变。

## verify
`HOST_CASES` 新增 `kind: "keywords"` 真机 DOM 用例：注入中英混排重复文本，点击 `extractKeywords()`，从 `#result .sent-item` 逐 token 精确断言：
- 不得出现 `工智` / `人工智` / `ac` / `mo` 碎片；
- 必须保留 `machine` / `learning` / `人工智能` / `机器学习` 等完整词。

踩坑：初版对整段文本做子串判断，`人工智能` 天然包含 `工智`、输入里的真实单词 `in` 也命中「碎片」清单，造成假红；改为按关键词 token 精确比对，并剔除真实单词 `in` 后全绿。

旧版 `9/10`（精确红在 `工智`），修复版 `10/10`；`ai calc 128/128` 不变。修复版恢复只用 `fixed` 副本，哈希一致。
