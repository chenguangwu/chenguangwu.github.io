## 修改

### 1. 时间戳英文智能识别

- 新增 `unitEn`，秒/毫秒/微秒/纳秒完整中英文。
- 成功提示、位数过多、显式单位位数过多、范围超限、无法识别全部走 `tsT(zh, en)`。
- 英文提示示例：`Recognized as seconds timestamp (10 digits) → seconds, milliseconds and datetime synced; the unit was inferred from digit count — choose an explicit unit above if this integer means something else.`

### 2. 日期加减月底规则

- 新增 `#calcMonthRule` 下拉：`clamp`（默认，截断到目标月末）/ `overflow`（保留浏览器原生溢出）。
- `clamp` 先取目标月 1 日做探针，再用 `new Date(ty,tm+1,0).getDate()` 得最后一天，`Math.min(start.getDate(), lastDay)` 截断，保留时分秒毫秒。
- `overflow` 保留原生构造器溢出。
- 公式说明与计算说明同步中英文。

### 3. 秒表即时计时

- 新增 `swNow()`：优先 `performance.now()`，不可用时回退 `Date.now()`。
- `swStart` / `swLoop` 使用 `swNow`。
- `swPause` 暂停前即时 `elapsed = swNow() - startTime` 并刷新显示。
- `swLap` 计圈前即时重算总耗时，再计算本圈差值。
- 说明与 FAQ 改为：后台仅节流动画帧、显示可能暂停刷新；暂停/计圈按单调时钟重算，总耗时仍准确；系统休眠是否计入取决于浏览器/系统，跨休眠用时间戳工具复核；手动改系统时间不影响 `performance.now()`。

### 4. 十六进制解码

- 先 `compact = text.replace(/[\s:,;_-]+/g,'')`。
- 规范化后为空 → “未检测到完整十六进制字节”，不再成功输出空串。
- `0x` 分支只接受 `^(?:0x[0-9a-fA-F]{2})+$`；非开头位置出现 `0x` → “前缀出现在字节内部”，不再全局删除。
- 再校验十六进制字符与偶长度，`body` 参与 `parseInt`。
- 公式说明同步严格语法。

### 5. 二进制编解码

- 两页新增/完善状态：`idle` / `empty` / `invalid` / `ok` / `fail`。
- 输入或重新输入时清空上次成功/失败结果，非法输入不保留旧结果。
- 纯分隔符规范化后为空 → “未检测到完整二进制字节（只有分隔符）”。
- 严格 `TextDecoder('utf-8',{fatal:true,ignoreBOM:true})`；失败给出非法字节数、Latin-1 对照与 `0x` 字节视图，状态 `fail`。
- 合法中文、非法 UTF-8、纯分隔符、非法字符、成功后再次失败均有状态区分。
- 错误提示中英双语。
