## 一、deep-dive 示例显示转义后的 `<p><strong>` 标签（清单 D-N122 只记 5 页，实际约 96 页）

- 根因：`i18n/tools/content_deepdive.json` 的 `examples[].body` 写的是真实 HTML 标签 `<p><strong>…</strong></p>`；`_build.py` 注入 `dd-ex-body` 时经 `linkify_terms()`（约 `:3057` 的 `esc_html_py(html.unescape(...))`，拼装见 `:3304`）统一转义，页面于是把标签当文字显示。
- 影响面实测：
  - `content_deepdive.json` 中 `examples` 含 `<p><strong>` 的页面：**96 个**。
  - `tools/design/*.html` 产物含 `&lt;p&gt;&lt;strong&gt;` 的页面：**95 页**。
  - 清单 `D-N122` 仅登记 flexbox-generator / toast-generator / exposure-triangle / shutter-speed / gradient-from-color 共 5 页，严重低估。
- 两种修法：
  1. **改 JSON 源**：把 96 页 body 里的 `<p><strong>` 改为纯文本（去掉标签），同时把 `i18n/tools/en/design/*.json` 中以该 HTML 串为 key 的映射同步换键。零构建逻辑风险，但涉及约 96 页 × 2 文件。
  2. **改 `_build.py`**：让 deep-dive 的 `body` 不经 `esc_html_py` 转义（或对白名单标签放行）。一处生效，但会重写全站 deep-dive 区块，需评估内容源的 XSS 边界（当前源均为站内自维护内容，非用户输入）。
- 风险：两种都会让大量已上线页面变化；若英文态 key 未同步换键，整段会回退中文。
- 本批已局部处理：`design/color-shade-generator` 的示例已改为纯文本（顺带修好该页，en map 已同步换键）。
- 建议：先裁断修法，再立专项批次全量执行，真机抽查中 / 英 / 繁三态各若干页。
