# 第 1038 批 · RE-N2/N3 公积金倍数与上限口径清账

## 问题与根因
`tools/realestate/fund-loan.html` 的守卫只检查 `balance`、`monthlyFund`、`fundYears` 三项非负，`multiplier`、`payMultiple`、`cap` 未纳入：

- 余额 80,000、余额倍数 −1 ⇒ 余额法额度 −80,000，与缴存法 144,000 取小后，「建议可贷额度」与评级一起给出 ¥−80,000（约 −8 万元）；
- 上限 0 时上限卡显示「¥0」，但最终额度仍按两法取小得 144,000，两张卡互相矛盾；
- 上限 −100,000 时上限卡渲染负金额，最终额度仍为 144,000。

## 修复
抽出共用守卫 `__fundLoanInvalid()`，要求余额/月缴存/缴存年限 ≥0、两个倍数 >0、上限 ≥0（0 表示未设置），`calc()` 与 `copyResult()` 都调用，堵住复制负数结果的出口。

上限卡在 `cap <= 0` 时显示「未设置（不限）」（英文态 `Not set (no cap)`），不再显示 ¥0 或负数；`finalLimit` 仍按 `cap > 0 ? min(raw, cap) : raw` 计算，语义与卡片一致。

页面公式说明与 `i18n/tools/en/realestate/fund-loan.json` 的中文键/英文值同步改为新校验口径，避免英文态映射整条失配。

## verify 用例
新增三条 `realestate/fund-loan` 哨兵用例：

- 倍数 −1：断言提示存在且不含 `−80,000`；
- 上限 0：断言上限卡含「未设置」、不含 `¥0`，且建议额度仍为 `¥144,000`；
- 上限 −100,000：断言提示存在且不含负上限金额。

默认组（20 倍、上限 600,000）均不命中哨兵 ⇒ 零逃生。
