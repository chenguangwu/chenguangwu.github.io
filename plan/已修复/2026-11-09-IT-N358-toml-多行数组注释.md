## IT-N358 TOML 多行数组行内注释导致静默丢值

**失败点（原复核记录）**
- 页面：`tools/it/toml-to-yaml.html`
- 复现：输入合法 TOML `dependencies = [ # ] 备注`，后续两行分别为 `"serde",`、`"tokio",`，最后 `]`；输出仅有 `dependencies:`，两个依赖丢失。原因为初始行在剥除注释**前**检查括号深度，注释里的 `]` 被误当作数组结束，导致后续元素行不被吞并。

**根因**
- `parseToml` 在判断「当前行括号是否闭合、需继续吞并后续行」时，对 `rawVal`（含行内 `#` 注释）直接调用 `tDepth(rawVal)`；注释内容 ` # ] 备注` 中的 `]` 被计为闭合括号，使 `tDepth>0` 不成立，跳过多行合并循环，后续 `"serde",` / `"tokio",` 因无 `=` 被 `continue` 丢弃。

**修复位点**
- `tools/it/toml-to-yaml.html` `parseToml()` 内多行合并段（`var val0=stripComment(rawVal); if(/^\s*[\[\{]/.test(val0) && tDepth(val0)>0){...}`）：先用 `stripComment(rawVal)` 得到 `val0` 再判括号深度与正则，缓冲起始也用 `val0`。

**验证证据**
- `env -u NODE_OPTIONS node scripts/verify_it_calc.js toml-to-yaml` 全绿（含新增用例）。
- 新增回归用例：`inputs.source = "dependencies = [ # ] 备注\n  \"serde\",\n  \"tokio\",\n]"` → expect `["dependencies: - serde - tokio"]` 通过；回退源码（在剥注释前判深度）时该用例必红（依赖静默丢失）。

**判别力实测**
- 用例依赖注入的 `serde`/`tokio`（输入里元素带引号、注释是中文「备注」），输出无引号 ⇒ 非输入回显；默认样例（title/version/server/db）不出现该串 ⇒ 强判别、零逃生。回退源码后转红，确认门禁可捕获回归。
