# 第 1034 批 · SMS-70 月相照明度余弦模型清账

## 问题与根因
`tools/science/astronomy-toolkit.html` 的 `getMoonPhaseData()` 把照明度做成 8 段等距线性插值：各段端点固定 0/25/50/75/100%，并在 `12.91963 ≤ age < 16.61096`（约 3.69 天）全程写死 100%。实际月相照明度随日-地-月夹角连续变化，满月只在 `age = S/2` 的瞬间达到 100%；线性分段会系统性偏低估盈亏凸月，并制造 100% 平台。

## 修复
保留原有 8 段月相名称阈值，只把照明度改为标准相角模型：

```js
var illum = (1 - Math.cos(2 * Math.PI * moonAge / SYNODIC_MONTH)) / 2 * 100;
illum = Math.max(0, Math.min(100, illum));
```

`age=0`（新月）得 0%，`age=S/2` 得 100%，边界连续且不再有满月平台。

## verify 用例
新增 `science/astronomy-toolkit` 用例：`moonDate=2026-01-01`（页面按 UTC 12:00 取日，月龄 12.4215 天），断言月相名仍为「盈凸月」且照明度显示 `93.9%`。

独立复算：`S=29.530588`，旧线性式给 `50+(12.4215−9.22831)/3.69133×25≈71.6%`；余弦式给 `(1−cos(2π×12.4215/29.530588))/2×100=93.9%`。旧版 ⇒ `MOONILL_BAD 盈凸月/71.6`，默认态（moonDate 空→今天）不命中。

另：第 1033 批 SMS-74 探针用例同步更新为余弦模型期望（2026-09-25 满月 98.6%、2026-06-21 上弦月 37.9%），否则会被本批正确修复误判为红。
