## 修复内容

### 1. `tools/it/regex.html`：`__proto__` 命名捕获组

Worker 中复制命名组的两处普通对象 `{}` 改为 `Object.create(null)`，与原生 `m.groups` 的无原型语义一致，`__proto__` 赋值成为普通自有键，不再改写原型。

Chrome 实测 `(?<__proto__>a)` 在非全局模式显示 `__proto__`，`(?<constructor>a)(?<normal>b)` 在全局模式显示 `constructor` / `normal`。

### 2. `tools/it/regex.html`：旧复制请求失效

- `testRegex()` 每次重跑时同时 `__rxInvalidate('copy')`，使已发出的 copy Worker 回包因版本过期被丢弃。
- `copyMatches()` 在写剪贴板前再次核对表达式、标志、测试文本快照；不一致则提示「输入已变化，旧复制已取消，请重新复制」，不写入。

Chrome 用延迟 `Worker` 桩实测：旧请求在新输入重跑后返回，剪贴板写入为空；正常复制路径不受影响。

### 3. `tools/it/regex-escape.html`：ECMAScript 安全字面量

- U+2028 / U+2029 输出为 `\u2028` / `\u2029`。
- 孤立代理项输出为 `\uXXXX`，NUL 输出为 `\x00`。
- 新增「拼接安全（首字符）」勾选（默认关闭）：勾选后首位 ASCII 字母/数字输出为 `\xNN`，避免片段拼接到 `\`、`\1`、`\c` 前缀后改变含义。
- 反转义保持可还原；默认行为不变，旧回归不破坏。

Chrome 实测 `a<U+2028>b<U+2029>c` → `a\u2028b\u2029c`；孤立 U+D800 → `\uD800`；`1abc` + 拼接安全 → `\x31abc`，反转义回 `1abc`，`new RegExp(out,'u').test('1abc')` 为 true。

### 4. `tools/it/regex-common.html`：提取与严格校验分离

- 新增「匹配模式」：提取匹配（按形状）/ 严格校验（整段）。
- IPv4 提取加 `(?<![\d.])` / `(?![.0-9])` 边界，日期提取加数字边界，避免从 `1234.5.6.7`、`12024-01-01` 截取片段。
- 提取结果明确提示只按形状匹配：`999.999.999.999`、`2024-99-99` 会命中，但不等于有效。
- 严格校验：IPv4 四段 0–255；日期检查真实日历（含闰年）；其他类别要求整段匹配。
- 图表、扩展面板的正则同步边界；历史记录加入 `mode`。

Chrome 实测：提取 `999.999.999.999 1234.5.6.7` 仅命中前者；`10.0.0.1` 严格有效、`999.999.999.999` 无效；`2024-02-29` 有效、`2023-02-29` 与 `2024-99-99` 无效；`12024-01-01` 不被截取为日期。
