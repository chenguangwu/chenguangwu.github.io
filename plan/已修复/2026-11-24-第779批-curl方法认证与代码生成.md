## 修复内容（`tools/it/curl-parser.html`）

### 请求方法与数据位置

- 识别 `-G/--get`：数据追加到 URL 查询串，保留已有查询参数、`?`/`&` 分隔与 `#fragment` 顺序；默认方法 GET，请求体清空。
- 识别 `-I/--head`：默认方法 HEAD；显式 `-X` 仍优先。
- `-T/--upload-file` 默认 PUT；`-d/--data*` 无显式方法时默认 POST。
- `-G` 与 `-F`、`-I` 与 `-G` 等冲突组合给出“需人工确认”提示，不输出确定结论。

### 认证、Cookie 与头部语义

- `-u/--user` 保留为认证字段，密码默认脱敏为 `user:***`。
- `-b/--cookie` 保留为 Cookie 字段，值默认脱敏；`-c/--cookie-jar` 明确标为输出文件而非请求字段。
- `-A/--user-agent`、`-e/--referer` 写入请求头；显式 `Authorization`/`Cookie`/`X-Api-Key` 类头部的值也脱敏显示。
- `-o/-x/-m/-E/-w/-r/--resolve/--compressed` 等无法静态还原的选项列入“未纳入请求”，不再静默消费。

### 代码生成

- 新增“生成 fetch”“生成 Python”按钮与两个代码块、独立复制按钮。
- fetch 代码包含方法、headers、body（GET/HEAD 不输出 body）。
- Python requests 代码包含 `requests.request(...)`、headers 与 `data`；GET/HEAD 不带 body。
- 认证/Cookie 占位为 `***` 并附注释，用户需自行替换；点击“生成 Python”不再覆盖已生成的 fetch 内容。
