## IT-N355 YAML 单根数组映射仍可生成非法 XML

**失败点（原复核记录）**
- 页面：`tools/it/yaml-to-xml.html`
- 复现：输入 `items:\n  - a\n  - b`，输出两个并列根元素 `<items>a</items><items>b</items>`，XML 解析器报只能有一个根元素。属于本次修复顶层 XML 有效性时漏掉的单键数组分支。

**根因**
- `jsonToXml()` 末尾逻辑：`keys.length!==1` 才包 `<root>`；当 `keys.length===1` 时直接 `return ser(xName(keys[0]), obj[keys[0]], 0)`。若该唯一键的值是**多元素数组**，`ser('items', [a,b], 0)` 会把每个元素各生成一份 `<items>…</items>`，并列成多个根元素，违反 XML 单根约束。

**修复位点**
- `tools/it/yaml-to-xml.html` `jsonToXml()` 收尾段：
  - 单键 + 非数组值（标量/对象）→ 直接作为唯一根（合法）；
  - 单键 + 数组且**恰好一个元素** → `<items>x</items>` 本身已是合法单一根（保留既有行为，兼容 IT-N356 单元素用例）；
  - 单键 + 数组且**多于一个元素** / 多键 → 包一层 `<root>` 保证单一根元素。

**验证证据**
- `env -u NODE_OPTIONS node scripts/verify_it_calc.js yaml-to-xml` 全绿（含新增用例，既有单元素/顶层序列/标量/嵌套映射/属性文本等用例均无回归）。
- 新增回归用例：`inputs.source = "items:\n  - a\n  - b"` → expect `["&lt;root&gt; &lt;items&gt;a&lt;/items&gt;&lt;items&gt;b&lt;/items&gt; &lt;/root&gt;"]` 通过；回退源码（单键直接 `ser` 不包 root）时输出 `<items>a</items><items>b</items>`，无 `&lt;root&gt;` ⇒ 必红。

**判别力实测**
- 用例 expect 含 `&lt;root&gt;` 与两个 `&lt;items&gt;`，输入 YAML 原文不含尖括号 ⇒ 非输入回显；修复前输出无 root ⇒ 必红灯。回退源码后转红，确认门禁可捕获回归。
