## 一、修复内容

### SMS-152 · 太阳引潮项相位错 90°（高优）
- 根因：注释写「二至日（doy 172/355）引潮大、二分日（80/262）小」，代码却用 `abs(cos(solarAngle))`（solarAngle 从春分 doy 80 起算）——春分 cos=1 取峰值 0.46、夏至 cos≈0 取谷值 ≈0，峰谷完全颠倒。
- 修正：
  ```js
  const solarFactor = 0.46 * Math.abs(Math.sin(solarAngle));
  ```
  春分/秋分（sin≈0）→ 0%，夏至/冬至（|sin|≈1）→ 46%，与注释和日历常识一致。
- 同批更新 verify：潮差 expect 由 `0.86 米` → `1.08 米`（2024-06-01 doy153 近夏至，solar 由旧公式的极小值变为 0.437，high=0.52×(1+0.437)×0.906=0.677，潮差=1.6×high=1.08）。

### SMS-153 · 默认日期用 UTC 导致东八区凌晨错一天
- 根因：初始日期与「今天」按钮均用 `today.toISOString().split('T')[0]`（UTC），东八区 00:00–07:59 取到前一天。
- 修正：新增 `__tideLocalDate(d)` 用 `getFullYear/getMonth/getDate` 拼本地日期，两处调用替换。
  ```js
  function __tideLocalDate(d){
    const y=d.getFullYear(), m=String(d.getMonth()+1).padStart(2,'0'), day=String(d.getDate()).padStart(2,'0');
    return y+'-'+m+'-'+day;
  }
  ```

### SMS-154 · 纬度越界无校验
- 根因：`min/max` 只约束步进器，键盘可输 120°，`latFactor=0.3+0.7cos(120°)=−0.05` 使高潮/潮差为负。
- 修正：主算前置守卫，`!isFinite(lat)||Math.abs(lat)>90` 时停算并提示「纬度必须在 −90° 至 90° 之间（南北纬），请输入有效纬度」。空值也走此守卫（旧 `||0` 静默当赤道）。

## 三、教训

1. **判别器用纯默认态快照**（不注入 inputs/clicks）。新增用例的 expect 必须在"页面初始化后、无注入"的输出里**不出现**。本批首版用夏至 46% 做锚点，而页面默认快照日期恰是 2024-06-15（doy 167 也在 46% 峰区）⇒ 逃生。改用春分 0%（默认态 46%）才有效。
2. 节气日期要按实际 doy 换算：2024 是闰年，9/22 的 doy=266（solar 2.7%），真正谷值 doy=262 是 9/18。断言"0%"必须选到 |sin|<0.6% 的日子，否则四舍五入不到 0。
3. jsdom 断言读 `innerHTML` 时，`<strong>太阳引潮力贡献：</strong>46%` 的标签夹在文案中间，`indexOf('太阳引潮力贡献： 46%')` 会失败；应读 `textContent`（会拼成"太阳引潮力贡献：46%"，无空格）或用两版容错。
