## 一、IT-N415 无条件「✅ MSISDN 格式有效」

**缺陷**：`validate()` 只覆盖 `cc==='86' && nationalNum.length===11` 与 `cc==='1' && nationalNum.length===10` 两个分支，其余**全部**落到 `else { ✅ MSISDN 格式有效 }`。既无各国国内号长规则，也无 ITU-T E.164 的 15 位总长上限。清单复现的 `+86 1`、`+86 138001380000`、超长 22 位数字全部被判有效。

**修复**：新增 `CC_LEN` 各国国内有效号（NSN）长度表 `[min,max]`（约 100 条），`validate()` 重写为统一四段校验：

```js
const rule=CC_LEN[cc]||[4,Math.max(4,15-cc.length)];
const min=rule[0],max=Math.min(rule[1],15-cc.length);
if(normalized.length>15)            err='❌ 超过 E.164 上限 15 位（当前 N 位）';
else if(nationalNum.length<min||nationalNum.length>max)
                                    err='❌ 国内号码长度非法：+cc 需 min–max 位，当前 N 位';
else if(normalized.length<8)        err='❌ E.164 总长过短（至少 8 位）';
if(err){ put(html+'<p style="color:var(--danger);">'+err+'</p>'); return; }
```

错误在**任何**「✅ 有效」结论之前短路返回；基础信息（国家/地区码、国内号、E.164、号码长度）无论成功失败都展示，长度行同时回显「实际位数 / 规则位数」，便于核对。非 86/1 的通用分支改为「✅ 国际号码（按 E.164 长度校验）」，措辞不再暗示无条件放行。

## 二、IT-N416 国家码库仅 42 条

**缺陷**：`CC_DB` 42 条且**没有任何 3 位码**，但匹配循环却写 `for(len=3;len>=1;len--)` —— 3 位前缀永远命中不了。清单点名的 `852 / 886 / 853 / 880 / 966` 全部落入「❌ 无法识别国家代码」。

**修复**：`CC_DB` 扩到约 100 条，补全部常见 3 位码（212/213/216/218/234/254/256/351–358/370–386/420/421/852/853/855/856/880/886/961–966/971/972/974/977/992/998 等）。值改为 `[中文名, 英文名]` 二元组，配合 `__mL()` 双语输出。

**合规口径**：`852 / 853 / 886` 分别标注为「中国香港 / 中国澳门 / 中国台湾」，英文为 `Hong Kong, China / Macao, China / Taiwan, China`；页面静态标签由「国家代码」改为「**国家/地区代码**」，不把中国地区码表述为国家。

配套 `CC_LEN` 给出对应国内号长：852=8、853=8、886=9、880=10、966=9。

## 三、IT-N417 运营商查表键错位（比清单描述更深）

**缺陷**：清单只指出 `OP_DB['8613']` 缺 `'0'` 导致默认 `13800138000` 显示「未知（号段 1380）」。真机通读发现**根因是查表键本身错位**：

```js
const prefix4 = nationalNum.substring(0,4);       // "1380"
const opKey   = '86' + prefix4.substring(0,2);    // "8613"
const thirdChar = prefix4[3];                     // '0'  ← 拿的是第 4 位
```

即「按前 2 位分组 + 第 4 位查表」，而中国大陆运营商归属由**前 3 位号段**决定。后果不止 1380：`13312345678`（133 电信）也取第 4 位 `'1'`，查得 `OP_DB['8613']['1']='移动'` ⇒ **把电信错报成移动**。现有表内 195/198/199 等归属亦有错。

**修复**：整体替换 `OP_DB` → `OP_DB3`（3 位号段表，按工信部分配：移动 134–139/147/148/15x/172/178/18x/195/197/198，联通 130–132/145/146/155/156/166/167/175/176/185/186/196，电信 133/141/149/153/162/173/177/180/181/189/190/191/193/199，广电 192）+ `OP_DB4` 四位特例（`1349` 归电信），结果标注「号段 XXX，携号转网后可能变化」，避免把静态分配表当实时归属。

## 四、IT-N427 NANP 分支 10 个区号 + 无效区号照样有效

**缺陷**：`AC_DB` 只有 10 个城市，未命中显示「未知城市」后**仍无条件**追加「✅ NANP 号码 / ✅ MSISDN 有效」；`999` 这类未分配区号同样通过，`202`（华盛顿特区）显示未知。

**修复**：
1. `AC_DB` 扩到 80+ 条（覆盖美国各州主要 NPA 与加拿大 416/514/604/905 等），含 `202 → Washington, DC`；
2. 新增 `__mNanpErr(d)` 结构校验，独立于查表：

```js
if(!/^[2-9]\d\d$/.test(npa))         → ❌ 区号 NPA 首位须为 2–9
if(/^\d11$/.test(npa))               → ❌ N11 是保留服务码，不能作区号
if(npa[1]==='9'&&npa[2]==='9')       → ❌ N99 是保留未分配区号
if(!/^[2-9]\d\d$/.test(nxx))         → ❌ 局号 NXX 首位须为 2–9
if(/^\d11$/.test(nxx))               → ❌ N11 是保留局号
```

结构不合法时**只输出错误、不输出有效结论**；区号未收录仅影响归属地展示（显示「未收录地区」），不否定结构合法的号码 —— 避免把「表不全」升级成「误判无效」。

## 五、顺带修复：英文态动态结果区全中文残留（既有漏检）

真机 jsdom 取证发现：`_en_i18n_probe.mjs --check it/msisdn-lookup` 报「0 残留」，但那只是因为**默认态结果区是「等待输入...」**，`validate()` 产生的动态串根本没进静态 DOM。一旦注入号码，修复前的 `国家代码：+86 - 中国`、`运营商：未知（号段 1380）`、`✅ MSISDN 有效` 在 `?lang=en-US` 下**全是中文**。

**修复**：新增页面内 helper `__mL(zh,en)`（`(typeof TBKit!=='undefined'&&TBKit.util&&TBKit.util.isEn())?en:zh`），`CC_DB` / `OP_NAME` / 全部结果标签与错误文案改中英双元组；`__mEsc()` 对用户输入做 HTML 转义并去掉 `data-zh` 属性（原实现把 `raw` 直接拼进 `innerHTML`，存在注入面）。

- 真机 14 场景中英两态：**英文态中文残留 0 / JS 异常 0**；
- `--check` 0 残留、`--roundtrip` 0 不一致；
- `formula-eq` 改为描述新校验顺序，同步替换 `i18n/tools/en/it/msisdn-lookup.json` 中的中文原文 key（英文态说明不留旧口径）。
