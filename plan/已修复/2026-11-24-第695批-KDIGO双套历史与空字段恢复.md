# 第695批：KDIGO 双套历史与恢复空字段

## 修复项

受影响工具：`tools/nephrology/jixingshensunshang-kdigo-fenqi.html`

### 1. 页面自有历史与共享历史并存

原页面每次计算都写入 `tb_history_/tools/nephrology/...`，但自有历史面板 `#historyBox` 不存在，写入的记录永远不可见；可见的共享历史使用 `tbk_hist_...`，清空按钮只清后者，旧键继续保留肌酐、体重与分期。

修复：

- 删除不可达的自有 `saveHistory / renderHistory / restoreHistory / clearHistory` 逻辑与写入调用，历史统一走 `TBKit.history`。
- 启动时清理旧版 `tb_history_` 键，避免旧数据继续留在浏览器。
- `TBKit.history.mount()` 新增可选 `onClear` 回调；KDIGO 页挂载时传入旧键清理函数，点击可见“清空”同时清除两套键。

### 2. 共享历史面板在空表单加载时不显示

历史面板只在一次有效计算后才挂载；用户带着旧记录重新打开页面、表单为空时看不到历史。

修复：`DOMContentLoaded` 计算完成后主动渲染一次历史，空表单也能看到已有记录。

### 3. 恢复旧记录不清空原本为空的字段

历史快照只保存非空字段，恢复时只遍历记录里的键。若旧记录中尿量为空，用户后来填入 `uo12=0`，再恢复旧记录时 `0` 不会清空，可能把“无 AKI”重算成“AKI 2 期”。

修复：

- 恢复前先清空本页全部输入（基线、当前肌酐、体重、时间窗、6/12/24 小时尿量、RRT）。
- 再写入记录中存在的字段，旧记录缺失的空字段保持为空。
- 验证路径：旧记录“基线/当前 100、体重 70、24 小时、未 RRT、尿量空”恢复后结果仍为“无 AKI”，`uo12` 从 `0` 恢复为空。

### 4. 无效校验状态不再写入历史

原有效性评分只过滤“请输入”等少数前缀，“请选择 RRT”“请填写肌酐”等空态会被当成有效记录写入，污染历史并挤掉真实评估。

修复：空态前缀与评分正则补充“请选择 / 请填写 / 请先填写 / Please select / Please fill”等，校验未通过的结果不再落历史。

## 验证

本地 Chromium：

- 预置旧 `tb_history_` 键后刷新，旧键被删除。
- 预置一条无尿量的 `tbk_hist_` 记录，空表单加载即可看到历史面板。
- 填入 `uo12=0` 后点击该记录：`uo12` 清空，结果恢复“无 AKI”，不再变成 2 期。
- 点击“清空”：`tbk_hist_` 与旧 `tb_history_` 均不存在，面板消失。
- 页面无 `pageerror`；空态不再新增历史记录。

## 验证边界

本批只修复已实机复现的 KDIGO 页面。其他使用同类“快照省略空字段 + 按记录键恢复”的页面仍需逐类复核，不能因本批通过而认定全站同形候选均已修复。
