## BS-N34 原始行数把末尾换行算成一行、重复数随展示模式变化

### 问题
- `input.split('\n')` 对末尾换行多产生一个空元素，`a\nb\na\n` 被显示成 4 行。
- `dupCount = origCount - resultCount`；切到「仅重复行」「仅唯一行」「带出现次数」时 `resultCount` 是筛选后的展示行数，重复数与节省率随之跳变（示例 1 行重复被算成 3 行、节省 75%）。

### 修复
- split 后去掉末尾一个空元素，末尾换行不再额外计行。
- 重复行数统一按 `Σ(每行出现次数 − 1)` 计算，与展示模式无关；节省率仍为 `重复数 / 原始行数`。
- `resultCount` 保留为当前模式实际输出的行数。

### 验收
- `a\nb\na\n`：原始 3、结果 2、重复 1、节省 33%。
- 切到「仅重复行」：结果 1，重复仍为 1、节省 33%（修复前为 3 / 75%）。
- `toString\nalpha\nalpha`：完整保留 `toString` 行（N33 的 Object.create(null) 已在位）。

## BS-N35 数字排序把无数字行当 0

### 问题
- `extractNum` 无匹配返回 0，与真实 0 无法区分；升序时无数字行被插到最前，降序时被当成最大值。

### 修复
- 改为 `numOf()`，无数字返回 `null`。
- 数字升/降序比较时，无数字行统一排到末尾（两行都无数字时按当前字典序），有数字行再按数值与字典序比较。

### 验收
- `苹果 3 个 / 香蕉 / 梨 5 个 / 第2项 10`：
  - 数字升序 → `第2项 10, 苹果 3 个, 梨 5 个, 香蕉`
  - 数字降序 → `梨 5 个, 苹果 3 个, 第2项 10, 香蕉`

## BS-N36 忽略大小写去重未生效

### 问题
- 去重使用精确 `Set`，之后才读取「忽略大小写」；`Apple / apple / APPLE` 三行全保留。

### 修复
- 先读取 `ci`，去重键改为 `ci ? line.toLowerCase() : line`，与排序比较器同源。

### 验收
- 勾选「忽略大小写」+「去重」，输入 `Apple/apple/APPLE` → 仅保留 `Apple`。
