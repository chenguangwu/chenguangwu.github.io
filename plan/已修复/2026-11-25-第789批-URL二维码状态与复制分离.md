# 第 789 批：URL 二维码预览失效、地址校验与复制分离

- 受影响工具：`tools/it/url-qr.html`
- 关闭任务：
  - `URL二维码-地址输入变化后预览仍为旧链接.md`
  - `URL二维码-未验证地址且错误提示混淆容量问题.md`
  - `URL二维码-复制结果包含说明且失败时仍提示成功.md`

## 修复内容

1. 输入变化即失效旧预览
   - `#url` 增加 `oninput="invalidateQR()"`；输入变化清空 `lastQR` 与结果区，禁用复制链接、复制图片、下载图片。
   - 有内容时提示「输入已变化，请点击「生成」更新二维码」；清空输入则清空结果区。

2. 地址校验与错误分类
   - 新增 `normalizeQrUrl()`：缺少协议补 `https://`，必须为 `http/https` 且含有效主机名，返回 URL API 规范化后的 `href`。
   - `renderQR()` 改为返回 `{qr,n}`，库缺失返回 `{error:'lib'}`，编码异常返回 `{error:'encode',message}`，不再把两种失败都吞成 `null`。
   - 新增 `QR_MAX_BYTE`（L 2953 / M 2331 / Q 1663 / H 1273），生成前按纠错等级判断字节容量，超限单独提示上限并建议缩短链接或降低纠错等级。
   - 空输入、非法地址、超容量、库缺失、编码异常分别给出独立提示。

3. 复制链接与复制图片分离
   - 新增 `lastQR = {url,level,px,canvas}` 保存本次成功结果；`copyResult()` 只写 `lastQR.url`，不再读取结果区文本（原先会复制字节数、纠错等级和说明）。
   - 新增 `copyQrImage()`（`canvas.toBlob` + `ClipboardItem`）与 `downloadQrImage()`（PNG 下载，文件名含尺寸）。
   - 剪贴板 API 不可用、图片复制不支持、`toBlob` 失败、`write` 拒绝均分别提示失败并引导下载/手动复制；仅在写入成功的回调里提示成功。

4. 英文态
   - `i18n/tools/en/it/url-qr.json` 增补 `复制链接` / `复制图片` / `下载图片` 与四档尺寸选项英文。
