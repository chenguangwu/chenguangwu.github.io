# 第173批 · IT 清单 1 条 · pdf-split 强制升序违背「按填写顺序」承诺

- 来源：`plan/categories/01-IT开发/it.md` → IT-D35（问题表格行 + 族矩阵 + 逐页结论已同步更新）
- 修复日期：2026-11-11
- 类型：行为与承诺不符（页码范围解析强制升序），纯前端逻辑

## 失败点
`tools/office/pdf-split.html` 的 `parseRanges()` 末尾 `[...new Set(result)].sort((a,b)=>a-b)` 把所有页码重排为升序：`7-10,1` → `[1,7,8,9,10]`，与页面「提取的页面顺序按选择的页码顺序排列」「提取顺序即为填写顺序」两处明示承诺矛盾。

## 根因
去重时误加 `sort`；`Set` 本身已保持插入顺序，pdf-lib 的 `copyPages` 也按传入顺序保序，无需再排序。

## 修复位点
`parseRanges()` 返回 `[...new Set(result)]`，删除 `.sort()`。缩略图勾选模式 `getSelectedPages()` 的 else 分支排序保留（勾选无填写顺序语义，自然升序合理）。越界、区间反向、非法页码校验均未动。

1. **verify 强锁**：`scripts/verify_office_calc.js` 新增用例注入 `7-10,1`，expect `7, 8, 9, 10, 1`；pdf-split 2/2、office 全量 **11/11**。
   - 旧源码差分：换回 `HEAD` 旧 HTML → pdf-split 1/2 红（新锁在 harness 重试等待 5s 后超时判红）；恢复修好版 → 2/2 绿。
2. **JSDOM 真机**（`scripts/_verify_it_batch173.mjs`）：**9/9 PASS**，覆盖乱序离散、多段逆序、去重保首次位置、升序输入不变、单页、越界/反向区间仍拒绝、预览展示顺序与解析一致。
   - **踩坑**：页面顶层 `let totalPages` 不能用 `w.totalPages=20` 改写（只加 window 属性），须 `w.eval('totalPages = 20')` 在同一 realm 注入。
