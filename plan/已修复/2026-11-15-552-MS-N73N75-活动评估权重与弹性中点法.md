# 552 批：活动评估零值守卫与权重可调、价格弹性改中点法（MS-N73 / N74 / N75）

日期：2026-11-15　页面：`tools/marketing/assessor-65.html`、`marketing-price-elasticity.html`

## 问题与修复

### MS-N73 目标人数 / 预算为 0 被 `||1` 兜底（高）

- `targetPax`、`budget` 用 `+value||1`，0 被静默替换为 1，预算执行率可放大到 4500%，评分低至 −790.8；结果只 `Math.min(100,score)`，无下限，还可能出现虚假「卓越」。
- 已改为逐字段读取并校验：目标人数 >0、预算 >0、实际人数/支出 ≥0、满意度 0–10、达成率 0–100%；评分 `Math.max(0, Math.min(100, score))`；到场率 >100% 时标注「按 100% 封顶」计分；预算执行率低于 90% 也纳入改进建议。

### MS-N74 FAQ 称权重可调，实际硬编码（高）

- 新增四个权重输入（到场率 / 预算 / 满意度 / 达成率，默认 25/20/30/25），校验每项 0–100 且合计必须为 100%，否则提示当前合计值；结果卡回显所用权重。
- 公式框、formula-desc、FAQ 同步为「权重可在下方调整，合计须为 100%」。

### MS-N75 参考表中点法 vs 计算器端点百分比（高）

- `calc()` 改为弧弹性中点法 `[(Q₂−Q₁)/((Q₁+Q₂)/2)] ÷ [(P₂−P₁)/((P₁+P₂)/2)]`，与参考表/`price-elasticity.html` 一致；`saveHistory()` 同步。
- 100→80、100→70 的弹性由 1.50 修正为 1.59；默认 100→90、1000→1200 为 −1.73。
- 修正说明区示例（−2 → −1.73），公式框改为中点法并注明结果区的变动率仍用简单百分比。
- 新旧价格相同时提前提示「无法计算需求价格弹性」并跳过计算/历史，不再输出 0 与「完全无弹性」。
- 经营建议改由实际收入变化驱动（收入升/降/持平三档），不再仅凭 |E| 推断降价或提价有效。
