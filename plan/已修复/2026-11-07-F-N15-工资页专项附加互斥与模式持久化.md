## 1. 失败点

台账 F-N15 记录两个缺陷，本批一次性修完：

1. **房贷利息与住房租金直加**：`calculate()` 里 `totalSpecialMonthly = childrenEdu + continuingEdu + housingLoan + housingRent + elderly + infant`，两项法定不可同时扣除却直接累加。页面只有 `info-box` 的文字提示「住房贷款利息和住房租金不能同时扣除」，**无互斥逻辑**。房贷 1000 + 租金 1500 ⇒ 扣 2500（+ 赡养老人 2000 共 4500），正确口径仅需 1500（共 3500），税负被低估。
2. **模式不纳入持久化**：`let currentMode = 'monthly'` 是纯 JS 变量，不在任何 input 里；页尾的持久化 IIFE（`NS = tools/finance/salary-calculator.html`，`tb_uxp_<NS>#<id>`）只扫 `input[id] / textarea[id] / select[id]` 保存并在 `DOMContentLoaded` 恢复。用户切到年薪、填 24 万后刷新，`restore()` 恢复所有金额却**恢复不了模式** ⇒ 页面按月薪重算，24 万被当成月薪，`grossSalary = ¥240,000.00`（应为 ¥20,000.00）。

## 2. 根因

页面状态与「带 id 的表单控件」不同构（与第 34 批 F-N8 同类）；专项附加七项共用一个逐项累加循环，未把法定互斥编码进计算链。两处都只靠文字/内存变量承载状态，通用机制观测不到。

## 3. 修复位点（只改工具页 + 门禁用例）

**`tools/finance/salary-calculator.html`**

1. 新增快照输入：`<input type="text" id="salaryMode" value="monthly" style="display:none" oninput="__salarySyncMode()">`。
   **刻意不带 `readonly` / `disabled`** —— 持久化 IIFE 的选择器是 `input:not([type=hidden]):not([readonly]):not([disabled])…`，任一都会让它被排除，模式就存不进去。
2. 新增 `__salaryModeIsEn()` 与 `__salarySyncMode()`：以快照输入为单一真源同步 `currentMode`、两个页签 `active`、`salaryLabel` / `resultTitle` / `afterTaxLabel` 文案、`annualStats` 显隐，最后 `calculate()` 重算。**不改缴费基数**（避免覆盖用户已保存的 `baseSalary` / `housingBase`）。
3. `switchMode(mode)`：在 `currentMode = mode` 后写 `salaryMode.value = mode`；末尾 `calculate()` 之后派发 `input` 事件，触发 IIFE 的 `input → save(el)` 立即落库，同时 `oninput` 的同步函数幂等重算。
4. 互斥：`housingExclusive = housingLoan > 0 && housingRent > 0`，`housingDeduction = housingExclusive ? Math.max(...) : (loan + rent)`；`totalSpecialMonthly` 改用 `housingDeduction`。
5. 新增带 id 的结果容器 `<div id="salaryDeductionNote"></div>`（放在 `barChart` 之后），`calculate()` 在互斥触发时写入「实际采用值 / 未计入项 / 合计」，用 `en ? English : 中文` 动态双语，EN 态零 CJK；未触发时清空。

**刻意不动**：静态中文提示、公式框、`i18n/tools/en/finance/salary-calculator.json`。本页是「纯中文静态 + en map 运行时替换」模式，改静态中文串就必须同步 en map 键；新增内容全部走动态双语，因此 **en map 无需改动**，缩小改动面。互斥同样未做「置灰另一项」，采用提示 + 自动按较大者（与第 35 批 F-N19 口径一致）。
