## 第 45 条｜电费计算器空值与零价边界收口（2026-11-21）

- 问题：`energy/energy-cost` 的公式说明写「三项输入空值守卫，空值即提示」，实际 `num()` 把空串回退成 0：清空功率或电价会静默输出 `0.00 元`，与说明不符；折线图 `__ectSweep()` 还把合法的 0 电价/0 功率当作无效直接不绘。

- 回归：新增 `rate:""` 用例，energy 104/104；全量判别 12,486 条、正确变红 12,485、逃生 1（基线 `surveying/calc-1`）、跳过 7，无新增逃生；构建 4,426 页；12,102 段内联脚本 0 语法错误；静态 4,705 通过 / 0 失败 / 0 警告；英文态 `energy/energy-cost` 残留 0 页。

## 第 46 条｜税务四页空值守卫收口（2026-11-21）

- 问题：`tax` 下 4 个模板沿用 `num()` 把空串回退 0，税率/金额留空时静默输出 0 税额：
  - `gst-calculator`：金额或税率留空 → 0.00 税额；
  - `reverse-charge`：代扣金额或征收率留空 → 0.00 代扣税，且公式明确写「两项空值即提示并中止」但未实现；
  - `capital-gains-effective`：税率留空 → 0 税；
  - `stamp-duty`：税率留空 → 0 印花税。
- 修复：四页统一加原始字符串判空，缺项给出对应中文提示；再用 `Number()` + `Number.isFinite()` 校验，保留 0 的合法语义（0 税率/0 金额仍可算），拒绝负值与非有限值。
- 回归：tax 94/94；全量判别 12,490 条、正确变红 12,489、逃生 1（基线 `surveying/calc-1`）、跳过 7，无新增；构建 4,426 页；12,102 段内联脚本 0 语法错误；静态 4,705 通过 / 0 失败 / 0 警告；四页英文态残留均 0。
