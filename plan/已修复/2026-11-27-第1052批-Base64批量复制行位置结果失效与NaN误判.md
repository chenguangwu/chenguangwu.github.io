## 修复内容

### 1. 复制全部保留原始行位置

- `__batchCopyText(mode)` 默认按 `window._batchResults` 的完整行序列输出：空行输出空行，失败行输出 `【第 N 行失败：原因】`（英文态 `[line N failed: reason]`），成功行输出结果，保证复制文本与输入行号一一对应。
- 保留 `mode === 'success'` 分支，可只取成功且非空的结果；当前 UI 默认使用保留行位置模式。
- `copyBatchResult()` 的提示改为报告总行数、保留空行数量与失败行号；全部为空行或全部失败时提示没有可复制成功行，不再静默复制空串。
- 批量页增加说明：复制全部结果按原始行位置输出，空行保留、失败行占位、不改变行号。
- 尾随换行仍按 `__batchLines()` 既有规则只剥掉末尾一个换行符造成的空行；中间连续空行、行内空白原样保留。

### 2. 批量结果 HTML 不再误判 NaN / Infinity

- `renderBatchResult()` 移除对整段 `innerHTML` 的 `NaN` / `Infinity` / 非有限数值守卫，直接写入结果并同步 `window._batchResults`。
- 文本本身为 `NaN`、`Infinity` 时正常显示为编码/解码结果，不再出现“计算结果含无效值”并提前返回。
- `batchEncode()` / `batchDecode()` 空输入时调用 `__batchInvalidate()`，清空旧结果与复制数据后再提示，避免连续批次残留。

### 3. 切换算法或选项让批量结果失效

- `setAlgo()` 在清理单条输出后调用 `__batchInvalidate()`，切换 Base64 / Base32 / Base85 时清空批量结果与复制数据。
- `__b64OptionChange()` 在 URL 安全模式、自动检测变化时同样调用 `__batchInvalidate()`。
- 失效后结果区恢复“结果将显示在这里”，单条复制与全部复制都不会再拿到旧算法/旧选项的结果。
