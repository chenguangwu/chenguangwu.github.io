# 第166批 · IT 清单 1 条 · curl-parser 反斜杠续行被当 URL

- 来源：`plan/categories/01-IT开发/it.md` → IT-D31（问题表格行 + 逐页结论摘要已同步更新）
- 修复日期：2026-11-11
- 类型：高风险解析正确性缺陷（URL 识别错误），纯前端逻辑，无文案/口径变更

## 失败点
`tools/it/curl-parser.html` 切词前未处理 shell 的反斜杠续行（`\` + 换行）。当 URL 位于续行下游时（如 `curl -X POST \` 换行 `https://api.example.com/users`），`\` 作为独立 token 被首个非选项词捕获成 URL，真正 URL 因 `url` 已设而被忽略 ⇒ `url: "\\"`。页面第118行自述"需正确处理反斜杠续行"。

## 根因
`raw.match(/(?:\"[^\"]*\"|'[^']*'|\S)+/g)` 把续行符 `\` 当普通非空白 token；主循环里首个非选项词无条件设为 url。

## 修复位点
`parse()` 切词前：`const raw = raw0.replace(/\\[ \t]*\r?\n/g, ' ')`，把行尾续行（反斜杠后允许尾随空格/制表符 + 换行，兼容 CRLF）折叠为空格，再走原切词逻辑。只匹配行尾续行，不碰引号内 `\"`/`\\` 等转义。复用既有输出，i18n 0 残留。
