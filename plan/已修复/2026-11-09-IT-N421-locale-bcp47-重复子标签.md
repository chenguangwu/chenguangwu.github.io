# 复核失败重做批次 · 申请再次复核

## IT-N421 BCP 47 标签重复子标签仍被判有效

**失败点（原复核记录）**
- 页面：`tools/it/locale-lookup.html`
- 复现：输入 `de-1996-1996` 或 `en-u-ca-gregory-u-nu-latn`，页面显示「BCP 47 格式有效」；`Intl.getCanonicalLocales()` 均以 RangeError 拒绝，分别含重复 variant 或重复扩展单例。原格式正则允许两者重复。

**根因**
- `validate()` 仅用 `LC_RE`（RFC 5646 语法子集正则）判定，该正则只约束各段形态、不查重，故重复的 variant / 扩展单例 singleton 都能通过。

**修复位点**
- `tools/it/locale-lookup.html` `__lcValid()`：在 `LC_RE.test` 通过后，按 `-` 切分；
  - variant 段（5–8 字母数字 或 数字+3 字母）出现重复 ⇒ 拒绝；
  - 单字母扩展 singleton（`[0-9a-wy-z]`）出现重复 ⇒ 拒绝。

**验证证据**
- `env -u NODE_OPTIONS node scripts/verify_it_calc.js locale-lookup` 全绿（含新增 2 条）；既有 N422 回退、4 位 variant（1996）、UN M.49 三位 region、扩展单例等用例均无回归。
- 新增回归用例：
  - `inputs.input="de-1996-1996"` → expect `["不符合 BCP 47 格式"]`；
  - `inputs.input="en-u-ca-gregory-u-nu-latn"` → expect `["不符合 BCP 47 格式"]`；
  - 回退去重检查（去掉 variant/单例 Set 判重）时两用例必红（误判有效）⇒ 门禁可捕获回归。

**判别力实测**
- expect 命中「不符合 BCP 47 格式」提示文字，由注入的重复子标签触发，默认态（en-US）命中「✅ 有效」串、不命中「不符合」⇒ 强判别、零逃生。回退源码后转红。
