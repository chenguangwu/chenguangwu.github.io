# G10 第 49 批 · `__tbInputGuard` 页明细表残留（823 页系统化修复 + 4 页 calc 入口补丁）

- 批次日期：2026-11-08
- 修复范围：`tools/**` **823 页**（guard 包装）+ **4 页**（calc 入口清表）+ 4 个脚本 + 门禁新增 1 道（#232）
- 结论：全站 823 个带 `__tbInputGuard` 的页面，「护栏触发/计算早退后明细表仍留上一次的行、导出 CSV 带走旧数据」已清零；
  全量审计 **823 页 0 残留**。

## 一、根因

`__tbInputGuard` 命中时页面只做两件事：把提示语写进主结果容器、`return`。
但明细表（`TBKit.matrix.table('#<pre>Table', …)` 渲染、`导出明细 CSV` 读取的容器）是**上一次**
成功计算留下的 DOM，没有任何人清它。用户清空/填错必填项后：

- 主结果区显示「请填写「X」后再计算」——看起来是空态；
- 明细表里仍是上一组参数算出来的行；
- 点「导出明细 CSV」→ 导出的是旧参数的结果，被当成本次结果使用。

118 页抽样 **110 页命中（93%）**，属系统性缺陷而非个别页面疏漏。

## 二、修复内容

### A. 823 页：guard 触发即清空明细表（补丁 A，`scripts/_g10_guard_patch.py`）

把每页的 `function __tbInputGuard(_ids,_labels){` 原地改写成「包装 + Core」两层，包装只做一件事：
命中即清 `#<pre>Table`，再原样返回消息。

```js
function __tbInputGuard(_ids,_labels){
  var __r=__tbInputGuardCore(_ids,_labels);
  if(__r){var __t=document.getElementById('<pre>Table');if(__t)__t.innerHTML='';}
  return __r;
}
function __tbInputGuardCore(_ids,_labels){ …原实现… }
```

- 明细表 id 由页面源码 `matrix.table('#…Table'` 正则提取，不硬编码；
- **42 页存在两份同名 guard 定义**（早期批次插入 + 原文），后一份才生效 ⇒ 补丁用 `rfind` 只改最后一份，
  首轮误改第一份导致 42 页 `skip-nohdr`，第二轮补齐；
- 幂等闸：已有 `__tbInputGuardCore` 的页面直接跳过，不重复套壳。

### B. 4 页：calc 入口清表（补丁 B，`scripts/_g10_calc_clear_patch.py`）

这 4 页的 guard 不在计算路径上（被早期注入挂到了 `copyResult()` 之类），或页面自带前置校验先 `return`，
guard 包装救不到：

| 页面 | 早退点 |
|---|---|
| `cardiology/ckd-epi` | `if(document.getElementById('sex').value===''){…return;}` 在 guard 之前 |
| `nephrology/shenxiaoqiulvguolv-24h-jiganqingchu-ccr` | 自带校验先返回 |
| `marketing/marketing-ltv-cac-ratio` | 同上 |
| `ophthalmology/iol-power` | 同上 |

做法：在 `function calc(...)` 函数体开头插一行清表。成功路径末尾的 `__<pre>Render()` 会用
`TBKit.matrix.table`（真实实现首行就是 `box.innerHTML=''`）重写容器 ⇒ **对正常结果无影响**，
只有早退路径会留下空表。

> 只改这 4 页、不给 823 页都加：其余页面在空输入路径上本来就会用空 `rows` 调一次 `matrix.table`
> （真实浏览器里等于清表），无需重复改动，避免全站无谓 diff。

## 四、审计判据本身的三次返工（同类审计必看）

1. **`TBKit.matrix` 不能草率用 anyStub**：`matrix.table` 真实实现首行是 `box.innerHTML=''`。
   首版桩什么都不做，导致「页面其实已经用空 rows 重渲染清表」的页被判成残留 —— 9 页假阳性里有 5 页属此类。
   改为按 `js/tool-kit.js` 真实实现桩（清容器 + 建 thead/tbody）后归零。
2. **只数数据行不够，要用哨兵**：改成 `tbody tr` 计数后，页面在无有效输入时会往表里写
   「请先填写非负赔款…后再生成明细」这类**空态提示行**（`insurance/combined-ratio`、
   `insurance/endowment-premium`、`insurance/expense-ratio`、`insurance/pure-premium-rate`、
   `investment/sortino-ratio` 5 页），仍被算成「剩 1 行」。
   → 最终判据改为「**预置的哨兵行是否还在**」：哨兵没了 = 旧数据被清，页面爱写什么提示都无关。
3. **「主结果提示语」不等于「清表」**：`#result` 里的 `请填写「X」` 只是主结果容器的文案，
   与明细表 DOM 无关；任何只看 `#result` 的判据都会漏掉本批缺陷。
