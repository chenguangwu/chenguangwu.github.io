## 条目（`plan/categories/02-金融财务/insurance.md:120 / :126`）
- **R-H4**（中）：`tools/insurance/endowment-premium.html` 深度解析用「身故现值 14.88 万 + 满期现值 55.37 万 = 70.25 万、年保费约 4.7 万」举例，其中满期现值未乘 20 年生存概率，身故现值也与本页逐年死亡概率模型不一致。本页实跑（保额 100 万、q=1%、i=3%、n=20）：身故现值 **136,786.19**、20 年生存概率 **0.817907**、满期现值 **452,855.24**、合计 **589,641.43**、期初年金系数 **14.877475**、年缴保费 **39,633.17**；旧示例高估约 19%。
- **R-H5**（高）：年死亡率只做必填校验、不限制 `0 ≤ q < 1`；保险年数没有正整数校验，仅 `Math.min(num('n'),1000)` 静默截断。q>1 时 `(1−q)^k` 正负交替（q=1.5、n=3 → 生存概率 −0.125、满期现值 −114,392.71）；非整数年数则循环按整年累加、年金因子按小数年折现，两者口径不一致。

## 根因
1. 页面代码是逐年生存概率模型（`sp` 从 1 起每年 ×(1−q)，满期给付乘 `vⁿ·sp`），深挖示例却用「确定给付现值」的简写，两个模型被混称「两全保险保费」。
2. `__tbInputGuard` 只拦空值 / 分母为 0 / 全 0，负数、概率 >1、小数年数都是合法有限值，直接进循环。
3. 深挖示例由 `i18n/tools/content_deepdive.json` 注入工具页、`scripts/gen_industry_guides.py` 读同一真源生成 guide（但 guide 静态产物不由 `_build.py` 重建）；英文态靠「键 = 中文源串」查表，`scripts/apply_insurance.py` 是深挖真源的历史生成脚本。任一处不同步就会被构建或重跑回退、或英文态泄漏中文。
4. 历史 / 导出沿用「读历史摘要表」：`__endowment_premiumResText()` 过滤词不含新错误文案，`exportTable` 在非法态仍可导出旧表；缺少「最近一次有效计算」状态。
