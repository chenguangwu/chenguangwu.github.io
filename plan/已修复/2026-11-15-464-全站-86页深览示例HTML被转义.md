# 464 · 86 页深览示例把 HTML 标签当正文显示

## 问题
`i18n/tools/content_deepdive.json` 的 `examples[].body` 混用纯文本与 HTML（`<p><strong>输入：</strong>…`），
但 `_build.py` 的 `linkify_terms()` 会先做 `esc_html_py()` 整串转义再包术语内链。
结果 **86 个页面**的 `div.dd-ex-body` 直接显示
`<p><strong>输入：</strong>…`，而不是渲染后的排版；4 处 `dd-ex-title` 同样受影响。

## 根因
[_build.py](file:///Users/cgw/project/cgw/chenguangwu.github.io/_build.py#L3432-L3475) `linkify_terms` 契约是「输入纯文本、输出已转义 HTML」，
深览注入处却把 HTML 片段直接传进去 ⇒ 标签被当成文本。

## 修复
新增 `linkify_terms_html()`：按白名单标签正则拆分
（`p/strong/b/em/i/code/br/ul/ol/li/a/span/div/sub/sup`），标签原样保留，
标签之间的文本仍走 `linkify_terms`（转义 + 最长匹配术语内链 + 每页去重）。
`_build_deep_dive_html` 的示例标题/正文改用该函数；场景与 FAQ 保持原逻辑（纯文本）。

白名单 + `fullmatch` 双重约束，正文里出现的 `<`（如「命中 < 阈值」）不会被误当标签。

## 验证
- `dd-ex-body">&lt;p&gt;` 命中页 **86 → 0**；`dd-ex-body"><p>` 命中页 **0 → 86**。
- 抽样 `tools/design/favicon-from-emoji.html`：示例已渲染为三段 `Input / Processing / Output`。
- 二次 `python3 _build.py` 幂等（无反复转义/嵌套）。
- `python3 _test_static.py` **4685/4685**。

## 影响
全站 86 页深览示例的可见排版恢复；简体与 `zh-tw` 构建产物同步修复。
