# 金融 F-N72 / F-N73：NPV 页折现率越界与非数字现金流期序错位（已修 · 申请复核）

## 来源
- `plan/categories/02-金融财务/finance.md` 的 F-N72「折现率 −100% 时 NPV 为 Infinity 仍判可行」、F-N73「非数字现金流被静默丢弃、后续各期整体前移」。两条同属 `tools/finance/calc-3.html`，本批一并真修。

## 根因
- **F-N72**：`calc()` 用 `(parseFloat($('rate').value)||0)/100` 读折现率，无下界校验。`r = −100%` 时 `1+r = 0`、`df = 1/0 = Infinity`，数值经全局 `Infinity → —` 替换显示「—」，但 `conclusion` 在替换前按 `npv > 0` 判定，仍输出「项目可行（NPV > 0）」；`r < −100%` 时折现因子逐期变号，结论无经济意义。
- **F-N73**：`parseFlows()` 用 `.map(parseFloat).filter(n=>!isNaN(n))` 丢弃非法段且不占期号，`30000, abc, 30000` 被压成 2 期，后续现金流整体前移，NPV 系统性高估；连续逗号 `30000,,30000` 同样被压成 2 期，用户无从发现。

## 修复位点（`tools/finance/calc-3.html`）
- `parseFlows()` 重写为返回 `{vals, bad}`：按 `[,，\n]` 逐段切分（保留中间空段），段内空白分隔的多值逐个 `Number()` 解析；非法项/空段按 0 计入并登记期号，**不再用 filter 改变期序**。
- `calc()` 新增折现率下界守卫：
  ```javascript
  const rPct = parseFloat($('rate').value);
  // F-N72：折现率 ≤ −100% 时 1+r ≤ 0，折现因子无意义（−100% 得 Infinity），必须拒绝而非给出结论
  if(isFinite(rPct) && rPct <= -100){
    $('res').innerHTML = __en ? '<p style="color:var(--danger)">Discount rate must be greater than -100%.</p>' : '<p style="color:var(--danger)">折现率必须大于 −100%，无法计算 NPV。</p>';
    $('summary').innerHTML=''; $('detailTable').querySelector('tbody').innerHTML=''; return;
  }
  ```
- `calc()` 把非法项提示写入 `#res`（被采集容器），与结论同串输出：`第 N 项不是有效数字，已按 0 计入该期（期号保留）。`；英文态走页面既有 helper，零 CJK 残留。
- 合法输入路径的 NPV / PI / 期数 / 明细表计算完全不变。
