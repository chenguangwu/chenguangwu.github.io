## 一、F-N94 提前还款「导出明细 CSV」实为历史表（确认缺陷 · 真修）

- **失败点**：按钮 `onclick="__mortgage_prepaymentExport()"` 把 `#mortgage_prepaymentTable`（TBKit 自动历史表：时间 + 输入 + 结果摘要）传给 `TBKit.util.exportTable`，用户拿到的 CSV 不含「缩短期限 / 降低月供」的剩余期数、月供、总还款、总利息、节省额。
- **根因**：导出目标选错容器；页面已有 `#result` 结果区的两方案对比表，却另导一份摘要历史。
- **修复位点**：`tools/finance/mortgage-prepayment.html::__mortgage_prepaymentExport()`。改为导出当前结果区 `#result` 的 `p, tr` 逐行明细（表行按 th/td 拆列后以 ` | ` 拼），文件名 `mortgage-prepayment-detail.csv`，走 `TBKit.export.csv`。
- **裁断（与清单建议不同）**：清单建议「新增隐藏 `#mortgage_prepaymentDetail` 表 + 另设『导出历史 CSV』按钮」。本批**不新增第二份隐藏数据源**（会重复计算、有模式空洞、可见输出漂移），也不新增按钮（新标签须进 `js/tool-i18n-en.js` GEN_UI_MAP，扩大风险）。延续第 120 批 `simple-interest` / `tax-bracket` 已验证模式，直接导出当前结果区明细，可见输出零改动。
- 拒绝态（无对比表）时导出的是当前提示段，不会给出误导性的两方案数字。

## 二、F-N95 房贷非法首付静默清空 + 饼图残留（确认缺陷 · 真修）

- **失败点**：首付 <0 或 ≥100 时 `resetDisplay()` 后直接 return，无任何错误文案；`resetDisplay()` 只把 8 个数字节点置 `--`，不清 `#pieChart.style.background`，上一次本金/利息扇形继续显示。
- **修复位点**：`tools/finance/mortgage-calculator.html`
  - 新增 `__mcTx(zh,en)` 双语 helper；把原来的合一大条件拆成 **房价 / 年利率 / 贷款年限 / 首付比例 / 本金为 0** 五个分支，每条提示都带**当前输入取值**（避免静态串逃生）。
  - `resetDisplay(msg)`：清 `pieChart.style.background`（回退 CSS 默认全灰 `conic-gradient(... 0%, ... 0%, #eee 0%)`），并把提示写进 `#scheduleBody`（既被页面看见、也被 verify blob 采集的容器）的 `colspan=5` 行。
  - 边界覆盖：0% / 99.9% 合法、100% / 120% / -1% 拒绝；改回 30% 后饼图与 24 期明细完整恢复。
- 英文态动态文案零 CJK（真机断言）。

## 三、F-N97 公积金负余额/负房价自相矛盾（确认缺陷 · 真修）

- **失败点**：`balanceWan` / `housePriceWan` 只做 `parseFloat(...) || 0`，依据表按原值显示「余额 × 15 倍 −120.0 万」，最终额度却被 `if (maxLoan < 0) maxLoan = 0` 夹到 0.0 万。
- **修复位点**：`tools/finance/housing-fund-loan.html`
  - `calc()` 前置拒绝 `balanceWan < 0 || housePriceWan < 0`，在 `#result` 写带取值的双语提示并 return，不再展示额度依据/还款明细。
  - `__housing_fund_loanScore()` 补 `housePrice < 0` 的**显式业务判据**（不靠结果文案词表猜），负输入记未通过。
- **顺带修复（复核方判据同源）**：Score 词表原含 `无效`，会把「输入无效已按 2.85% 计」（利率越界回退默认值的**有效业务结论**）误判为失败。移除该词，改由输入状态判定；真机断言 `rate=99` 时 Score=1。
- **连带修复**：拒绝态没有 `#housing_fund_loanDetail`，原 `__housing_fund_loanExport()` 只 `showToast` 就 return，导出按钮点了没反应（`batch115` 实测 `dl:[]`）。改为在拒绝态也导出一份「本次输入无效说明」CSV，按钮不再空点，且 CSV 不含矛盾的依据行/负额度。
