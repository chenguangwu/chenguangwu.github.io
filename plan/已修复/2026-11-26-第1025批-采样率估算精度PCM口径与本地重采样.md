# 第 1025 批：采样率估算精度、PCM 口径与本地重采样

- 影响页面：`tools/audio/audio-sample-rate.html`
- 对应任务（6 个）：
  1. 频率上限精度不足
  2. 复制内容遗漏计算指标
  3. 历史结果误取知识说明
  4. 文件大小未说明 PCM 假设和单位
  5. 仅估算无法转换文件
  6. 清空时残留上次结论

## 修复

- 频率上限：改为精确 Hz（如 44.1k → `22,050 Hz`、48k → `24,000 Hz`），不再固定一位小数；标签改为“理论上限”，并注明是奈奎斯特上限、不代表实际设备频响。
- 数据量口径：`MB` 改为 `MiB`，标签改为“源/目标 PCM 数据量”，明确按未压缩 PCM 估算、不含 WAV 头与容器开销，MP3/AAC 应按实际码率；补充 `1 MiB = 1024²` 字节说明。
- 复制：新增 `__asrResult` 结构化结果与 `copyResultBtn` 禁用态；复制内容包含采样率、位深、声道、时长、双端比特率、双端 PCM 数据量、双端理论上限及 PCM 假设；无效时长时按钮禁用且函数拦截。
- 历史/CSV：`__audio_sample_rateResText()` 改取 `__asrResult.summary`，不再读固定“采样率知识” `.result-box`；删除无业务含义的“有效性趋势”图表。
- 清空态：时长空/0/非正时清空主结果、统计卡和副结论，显示“请输入大于 0 的有效时长（秒）”，并同步禁用复制，不再残留上次升降采样结论。
- 实际转换：新增“本地重采样与 WAV 导出”卡片。上传音频后按上方目标采样率，用 `OfflineAudioContext` 在浏览器本地重采样；支持 `<audio>` 试听、16-bit PCM WAV 导出；带请求序号、目标变化/换文件取消、解码失败提示，文件不上传。
- 页面标题/描述、深度解析、使用指南同步为“估算 + 实际重采样”口径。

## 验证

- 默认 44.1k→48k / 16bit / 2ch / 60s：显示源/目标 `22,050 Hz`、`24,000 Hz`，PCM 10.09 / 10.99 MiB；复制摘要包含全部输入条件与指标。
- 时长改为 0：主结果 `--`、统计为空、副结论“请输入大于 0 的有效时长（秒）”、复制按钮禁用；恢复有效值后按钮恢复。
- 历史记录结果列为“采样率：44100 Hz → 48000 Hz；位深 16-bit；声道 2；时长 60 秒；源/目标比特率…源/目标 PCM 数据量…理论上下限…（未压缩 PCM，不含容器开销）”。
- 上传 1s / 44.1k / 2ch WAV，目标 48k：转换成功，试听 Blob 解码为 48,000 Hz、1.00s、2ch；导出文件名 `one-48000Hz.wav`。
- 转换后把目标改回 44.1k：导出按钮禁用、试听隐藏、提示“目标采样率或音频已变化，请重新转换”，不会误用旧结果。
- `node scripts/verify_audio_calc.js` 15/15（含采样率 3 个新用例）；`_test_static.py` exit 0；`_audit_assets.py --check` 0 死链/0 lang 缺失/0 重复 id；`_audit_links.py --check` exit 0。
