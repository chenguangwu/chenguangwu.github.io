# 第731C批：金融五页数值边界与展示一致性修复

修复日期：2026-11-24
范围：`tools/finance/`（定投、夏普、货币、黄金、投资回报率）
验证：`node scripts/verify_finance_calc.js` 645/645；Puppeteer 五页边界用例全绿、无 pageerror。

## 1. 定投计算：月投入 0 被错误拦截

- 现象：`monthly=0` 时前置守卫把月投入当分母，直接提示「不能为 0」并停算；但初始本金 > 0 时复利增长本身成立，月投为 0 是合法输入。
- 修复：守卫白名单移除 `monthly`；改为仅当「每月定投」和「初始本金」同时为 0 时给出专门提示「初始本金与每月定投均为 0：没有可增长的本金，无法计算定投收益」，同时清空统计卡、明细表、期数与差异区。
- 边界：`monthly=0、initial=12000、1 年、12%` 期初投入 ⇒ 终值 ¥13,521.90、收益 +¥1,521.90。

## 2. 夏普比率：零波动率误算为零

- 现象：收益率序列标准差为 0（所有收益相同）时，旧代码用 `portStd>0 ? … : 0` 兜底，输出夏普 0 并给出评级，等于把「无定义」当成「表现中性」。
- 修复：序列模式算出 `portStd` 后先判定必须大于 0，否则清空统计卡并提示「标准差必须大于0：当前收益率序列的标准差为 0（所有收益相同），夏普比率无定义。」；正常分支直接 `excessReturn/portStd`，不再静默兜底。
- 直接输入模式原有的标准差 > 0 校验保持不变。

## 3. 货币换算：批量非法金额被静默转换

- 现象：`parseFloat` 前缀解析让 `12abc` 变成 12；批量换算里非法行被当成 0 或截断值照常出结果，导出/复制也会把脏数据带出去。
- 修复：新增 `parseMoneyStrict`（只接受普通十进制或规范千分位，如 `1,234.56`，可带正负号；拒绝字母、科学计数法、错位逗号、空值）与 `parseBatchInput`（逐行返回 `{lines, rows, errors}`）。
- 行为：主换算/反向换算非法即清结果并提示；批量非法行显示「第 N 行「原文」不是有效金额」且不参与换算；存在非法行时导出 CSV 与复制结果直接拒绝并 toast；金额 0 仍合法。

## 4. 黄金换算：空值与除零显示成零结果

- 现象：重量留空按 0 克、美元汇率留空按 0、金价为 0 时反算重量出现除零，页面仍展示 `¥0.00 / $0.00 / 0.0000 克` 等伪结果。
- 修复：新增 `readGoldNum(id,label)`（区分空值与非有限）与 `goldError(msg)` 统一错误输出；金价必须 > 0；美元汇率允许留空，留空时美元金额显示「未计算（美元汇率留空）」，非空必须 > 0；折价率必须 0–100；重量模式重量必须 > 0，总价模式总价不得为负；反算重量空值提示「请输入重量」，负数/非有限拒绝。
- 结果：空态只显示明确提示，不再出现 0 克/零元结论。

## 5. 投资回报率：定投亏损仍显示加号与收益色

- 现象：总收益模板固定 `+` 前缀并使用收益色，亏损时显示成 `+-¥x` 并被误读为正收益。
- 修复：`calcRegular` 新增 `profitPos/profitNeg/profitColor/profitSign/profitAbs`，总收益与期末终值按盈亏着色（正绿/负红/零中性），亏损显示 `-x`；IRR 名义/有效年化同样按正负着色。
- 边界：年化 -12%、月投 1000、1 年 ⇒ 终值 11,247.9、累计投入 12,000、总收益 `-752.1`，不再出现 `+`。
