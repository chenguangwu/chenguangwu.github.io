# 2026-11-07 · 金融-保险（R-H2 + R-H3）：纯费率页无量纲三项、负损失/负暴露仍出费率

## 条目（`plan/categories/02-金融财务/insurance.md:103 / :109`）
- **R-H2**（中）：`tools/insurance/pure-premium-rate.html` 把「元/暴露单位」的纯费率再乘 100 标成「纯费率百分数 (%)」、除 100 标成「纯费率小数形式」，并把「暴露单位数 − 期望损失（元）」直接相减。期望损失 1000、暴露 100 时纯费率 10.00 元/单位，页面另显示「1000.000」「0.10000」「−900.00」，三项都无可解释基准或统一量纲，容易被误读成「纯费率 1000%」。
- **R-H3**（中）：输入守卫只拦空值 / 非数 / 分母为零，未限制期望损失与暴露非负。期望损失 −1000 / 暴露 100 或 期望损失 1000 / 暴露 −100 都得到 −10.00 元/单位，负暴露还能反向得到正费率，且结果进入历史与导出。
- **顺带修（同文件「留存优化」）**：该页「示例 2× / 0.5×」预设同比例缩放分子分母，三档纯费率恒为 10.00，点击无变化（前批已修另两页，此处为最后一处）。

## 根因
1. 模板把「数值变换」当成「联动量」：×100 / ÷100 没有任何分母或基准（纯费率不是比例而是「元/单位」），不同量纲的「单位数」与「元」也不可相减。
2. `num()` 是 `parseFloat(...) || 0`，负数是合法有限值；`__tbInputGuard` 只判 `exp === 0`，负暴露直接通过。
3. `__pure_premium_rateExtras()` 早退条件 `!isFinite(num(...))` 对负数不成立 → 负数被写进明细表与历史；导出固定读历史摘要表 `exportTable('#pure_premium_rateTable')`。
