## 四、拒绝态守卫真修（investment-calculator，重要）

页面用全局 `investmentResultValid` 作 Extras / Export 的第一道守卫：

```js
function __investment_calculatorExtras(force){
    if (!investmentResultValid || typeof TBKit === 'undefined') return;   // 旧
function __investment_calculatorExport(){
    if (!investmentResultValid || typeof TBKit === 'undefined') return;   // 旧，且无强制刷新
```

后果：输入非法时 `calc()` 置 `investmentResultValid=false` 后 return，**整次失败操作不进历史、不进趋势、导出也直接返回** —— 正是复核方反复打回的「拒绝态写历史」类问题（F-N46 同源）。真机诊断确认非法态 `ResText()` 已返回「请输入合理的正数」，但手动 `Extras(true)` 仍 `hist=0`。

修法：
```js
function __investment_calculatorExtras(force){
    // 复核判据：拒绝态也要写历史并判未通过，不能用 valid 守卫把失败操作整个丢掉。
    if (typeof TBKit === 'undefined') return;
function __investment_calculatorExport(){
    if (typeof TBKit === 'undefined') return;
    __investment_calculatorExtras(true);
```
Score 已补业务判据，拒绝态记 `__tbScore=0`。

## 七、踩坑

1. **「拒绝态不写历史」比「拒绝态判通过」更隐蔽**：`ResText()` 有内容、`Extras(true)` 手动调用也不记录，根因藏在函数第一行的业务标志守卫；必须读完整 Extras/Export 而非只看 Score。
2. **`optional` 替换点 SKIP 要逐个核对**：本批 `investment-calculator` 的 `export-force` 因守卫写法不同而静默跳过，dry-run 日志里该页比其它页少一行，差点漏掉「导出前不刷新」。
3. **「非法值」必须由业务定义**：负折现率对 IRR 页是合法输入、负数对中文数字读法页也是合法输入；照抄 `-1` 会造成假失败。
4. `number` 输入被 JSDOM 归一化后，历史快照存的是归一化值，断言不能比原始注入串。
