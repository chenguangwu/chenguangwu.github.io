# 第 458 批：表格表头 scope 补齐

## 问题

全站 4,605 个工具页的参考表格、对照表大量使用 `<th>` 表头，但绝大多数没有 `scope` 属性。只读审计（2026-11-22）：

- 静态 HTML 区共有 **18,784 个 `<th>`**，其中 **18,784 个都没有 scope**；
- 这些表头分布在 4,605 个工具页，常见于参数对照、分级标准、单位换算、评分量表等；
- 屏幕阅读器在复杂表格中依赖 `scope` 把数据单元格归到正确的列/行标题；缺少时只能猜测，跨行跨列或首列为标题的表格容易读错。

## 修复

在 `_build.py` 新增 `ensure_table_header_scope()`，放在全站页面生成完成、繁体站生成之前：

- 扫描源 HTML（排除 `zh-tw/`、`_en-i18n/`、`node_modules`）；
- 按 `<table>` → `<tr>` → `<th>` 结构逐行判断：
  - 整行都是 `<th>`（表头行）→ `scope="col"`；
  - 行首是 `<th>` 且同行有 `<td>`（首列为行标题）→ `scope="row"`；
  - 其余 `<th>` → `scope="col"`；
- 已有 `scope` 的表头完全不动；
- **脚本、style、pre、textarea 块内不处理**，避免改动运行时生成的 HTML 字符串和代码示例。

## 过程事故与修复

首次实现使用 `re.split()` 切分受保护块，但正则同时捕获了外层整块与内层标签名，导致奇偶段判断错位，把 1,940 处 `scope` 写进了 426 个页面的 JS 字符串；其中 7 个页面的双引号字符串被破坏，`node --check` 报 `SyntaxError: Unexpected identifier 'col'`。

处理：

- 立即 `git checkout HEAD --` 回滚本批全部 4,607 个 HTML 文件；
- 改为 `finditer()` 按真实区间保留脚本块，只处理块外 HTML；
- 重新构建后复核：脚本区新增 `scope` **0 处**，静态区 18,784 个表头全部覆盖；
- 重新抽查受影响页面，双引号字符串不再被改写。

## 结果

- 构建输出：`Table header scope: 18784 cells in 4605 pages`；
- 二次构建：`Table header scope: 0 cells in 0 pages`，工作区文件数不变，幂等通过；
- 静态区复核：18,784 个 `<th>` 全部有 scope；`col` 18,734、`row` 50，非法取值 0；
- 脚本区复核：受保护块内新增 scope 0 处；原有 6 处为页面自身静态字符串，保持原样；
- 静态测试：4,626 passed / 0 failed / 0 warnings（4,606 个工具）；
- 死链门禁：16,743 文件 / 160,344 内链，0 死链；
- 资产完整性：0 资产死链 / 0 `lang` 缺失 / 0 重复 id；
- 内联标记位置审计：4,921 页，0 处加固片段违规；
- 全量质量门禁：268/268 passed（`GATES_EXIT=0`）。

## 变更规模

- `_build.py` + 4,605 个工具页；每页仅给既有 `<th>` 增加 scope 属性，无正文、脚本、样式改动；
- 行级 diff：12,971 insertions / 12,892 deletions（同表多表头合并到一行导致行数近似）。

## 后续

脚本区仍有少量页面在 JS 字符串里自带 `scope`（6 处），属于页面原有实现，不影响语法；运行时生成的表格若需要完整 scope，应按页面实际模板另批处理，不在本批范围内。
