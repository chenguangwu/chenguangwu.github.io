# 377 设计 · 音阶调号参考补全小调调号、和声/旋律小调与 I 级三和弦（D-N200）

- **分类**：04-设计创意
- **工具页**：`tools/design/music-scale-reference.html`
- **日期**：2026-11-14
- **缺陷编号**：D-N200（中，确认缺陷）

## 缺陷与根因

三个互相独立但同源的能力缺口：

1. **小调无调号**：`sigInfo` 的调号拼接只在 `type==='major'` 分支，选自然小调 / 五声 / 布鲁斯只剩频率行，"调号参考"页查不到小调调号。
2. **和声/旋律小调承诺落空**：deep-dive 宣称"可切换自然/和声小调"，FAQ 讲"和声小调升七级、旋律小调上行升六七级"，但下拉只有"自然小调"；`scales` 亦无对应音程。
3. **和弦构成仅静态示例**：参考表的"和弦构成"是固定文案，不随所选调变化；meta 又宣称"快速对照调号与和弦构成"。

## 修复

### 1. 补音阶类型（`scales` + 下拉）

- `harmonicMinor: [0,2,3,5,7,8,11]`（和声小调，升七级）
- `melodicMinor: [0,2,3,5,7,9,11]`（旋律小调上行，升六七级）

### 2. 拼写派生（不新增 24 条手写表）

和声/旋律小调 = 自然小调基础上做半音提升，`raiseSemitone` 按记谱惯例处理（降号音去一个 `b`、其余加 `#`）：

- `F` 自然小调 `F G Ab Bb C Db Eb` → 和声 `F G Ab Bb C Db E`、旋律 `F G Ab Bb C D E`；
- `A` 自然小调 `A B C D E F G` → 和声 `A B C D E F G#`、旋律 `A B C D E F# G#`。

同时抽出公共入口 `spellScale(root,type,pattern,rootIdx)`，把原先**三处重复的拼写分支**（`render` / `__musicExtras` 图表 / `msExportCsv`）统一，消除口径漂移风险。

### 3. 小调调号

新增 `MINOR_KEYSIG`（小调调号 = 关系大调调号，`Db` 小调取等音 `C#m`→4 升）+ `relMajorOfMinor`（由 `REL_MINOR` 反查，缺失时按 `pc+3` 等音兜底）。和声/旋律小调调号与自然小调相同（调号只由调决定，临时记号不入调号）。

### 4. I 级三和弦实时计算

结果区新增一行：取音阶第 1/3/5 音，按半音距离判定性质（4+7 大三、3+7 小三、3+6 减三、4+8 增三）。A 小调 → `A - C - E（小三和弦）`。中英文按 `TBKit.util.isEn()` 三元输出，避免 EN 态新增 CJK。

### 5. 文案同步（改一处扫全页）

功能补上后，原"不含和弦计算 / 不提供和弦计算 / 只列音阶与调号，不直接计算和弦"的表述全部与新实现矛盾，一并修正：

- `meta description` ×4（description / og / twitter / JSON-LD）：`；不含和弦计算。` → `；并给出所选调的 I 级三和弦构成。`
- `formula-desc`：改为"…并给出关系小调、各音级频率与所选调的 I 级三和弦构成…"
- `i18n/tools/design.json`：zh/en `intro` 同步
- `i18n/tools/en/design/music-scale-reference.json`：`formula-desc` key/value 同步（key 与新 HTML 中文串字节一致）、新增 `和声小调` / `旋律小调（上行）` 两个 option key、修正遗留的"不直接计算和弦" FAQ value
