## 一、真缺陷修复

### D-N115 `tools/design/exposure-triangle-calculator.html`（ISO 边界后等效组合不等效）
- 根因：等效组合循环里 `niso = clamp(ii+da)` 之后，ISO 分支的快门补偿仍用**期望档位差** `ns = si - da`。当 `ii+da` 越界被 clamp，实际 ISO 只变了 `(niso−ii)` 档，快门却变了 `da` 档 ⇒ 组合不再等效，但卡片统一标在「相同曝光量」下。
- 复现（默认 f/4·1/60·ISO200，EV=8.91）：`da=-2` ⇒ `niso=0`（ISO100，实际只降 1 档）、`ns=8`（1/15）⇒ EV=7.91，暗 1 档。
- 修复：结果卡片 `calc()` 与 CSV `__expExtras()` 两处同步改为 `ns = si - (niso - ii)`，按**实际档位差**补偿。修复后该卡片为 f/4·1/30·ISO100，EV=8.91 重新等效。
- 新增口径说明（`data-zh` 双语）：ISO 或快门到达档位边界时，等效组合自动按可用档位调整，仍保持相同曝光量。
- 说明：光圈分支本来就用 `neededSi = si + (na - ai)`（clamp 后的实际差），边界天然等效，无需改动。

### D-N119 `tools/design/shutter-speed-calculator.html`（结果 / CSV / 图表三个快门）
- 根因：结果区与 CSV 用标准档位表 `findIndex(s <= 1/effF)` + `safeIdx = baseIdx - isStops`，图表 `__ssChartDraw()` 却用连续值 `d1 = fv*crop` 与 `Math.round(d1 / 2^isStops)`。50mm·1.5x·3 档时结果区/CSV 给 1/15、图表给 1/9；且 `Math.round(90/8)=11` 会把 1/11.25 取成更慢的 1/11，违反公式框「向更快方向取整」。
- 修复：抽全局 `SS_STOPS` 档位表 + 公共函数 `ssStopsFor(f, crop, isStops)`（返回 base/safe 档位与分母），结果区、CSV、图表三处统一调用；图表两条曲线改用档位分母 `baseDen` / `safeDen`。小数防抖档加 `Math.round(safeIdx)` 兜底，避免 `stops[小数]` 取到 `undefined`。
- 结果区最终输出**逐字节不变**（既有用例 `42/1.5/2 ⇒ 1/30` 保持绿），只统一了图表口径。

### D-N117（EV 从不显示 / 图表 EV 轴光圈·ISO 符号反）
- 清单基于旧版档位式 `evFromIdx = (3−ai)+(6−si)−(ii−1)`（光圈/ISO 符号反）。
- 当前源码 `:234` 已是物理公式 `log2(N²/t) − log2(S/100)`；`:287` 的 `ev` **已被使用**（结果区标题「等效曝光组合（相同曝光量，EV x.x）」）；图表 `:479` 复用同一函数。
- 独立复现（node + vm 从页面源码抽数组与函数后执行）：基准 f/4·1/60·ISO200 = **8.91**；换 f/8 = **10.91**（+2，光圈收小 EV 升，方向正确）；换 ISO800 = **6.91**（−2，ISO 升高 EV 降，方向正确）。
- 结论：两个问题均已不存在，图表方向亦正确 ⇒ 销账。

### D-N116（±1EV 按钮方向）
- 清单基于旧版 `si = si - delta`。当前 `:326` 是 `si = clamp(si + delta)`：−1 档 ⇒ 1/60→1/125（更快、更暗、曝光量 −1），+1 档 ⇒ 1/60→1/30（更慢、更亮、曝光量 +1），与「曝光量变化」文案自洽。
- 残留歧义（1/60↔1/125 是标准档位近似 ≈1.06 档，且「±1EV」易与 EV 数值口径混淆）⇒ 本批仅做**纯文案澄清**：按钮改「−1 档 · 更暗 / +1 档 · 更亮」，工具栏改「曝光补偿（按标准快门档位，约 ±1 档）」，功能未改。
