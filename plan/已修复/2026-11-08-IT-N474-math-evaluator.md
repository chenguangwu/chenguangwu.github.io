## 一、缺陷：所有「数字 + %」都被无条件下压成百分比

页面 meta / h2 / `formula-list :120` 都宣称支持「取模」与 `%` 运算符，但求值前一步无条件改写：

```js
var js=expr.replace(/\^/g,'**').replace(/(\d+)\s*%/g,'($1/100)');
```

于是 `7%3` → `(7/100)3` → `SyntaxError: Unexpected number`，`10%3` / `10 % 3` 同样报错；而 `formula-eq` 又只写「数字后 % → (数字/100)（百分比）」，三处说法互相矛盾。另 `(\d+)` 只吃整数部分，`15.5%` 变成 `15.(5/100)` → `15 is not a function`。

**修复**：按清单方案一，用负 lookahead 判断 `%` 后是否还有操作数 —— 有则保留 `%` 交给 JS 原生取模，无则视为百分比：

```js
/* IT-N474：% 后若还有操作数（数字/字母/左括号）则是取模，保留 JS 的 % ；
   否则视为百分比（如 15%、50%*120）转成 (n/100)。小数百分比一并支持。 */
var js=expr.replace(/\^/g,'**').replace(/(\d+(?:\.\d+)?)\s*%(?!\s*[0-9A-Za-z_(])/g,'($1/100)');
```

| 表达式 | 修复前 | 修复后 | 判定 |
|---|---|---|---|
| `7%3` | 表达式无效 | `1` | 取模 |
| `10 % 3` | 表达式无效 | `1` | 取模 |
| `17%5` | 表达式无效 | `2` | 取模 |
| `100%7` | 表达式无效 | `2` | 取模 |
| `15%` | `0.15` | `0.15` | 百分比（护栏） |
| `50%*120` | `60` | `60` | 百分比（护栏） |
| `15.5%` | 表达式无效 | `0.155` | 小数百分比（顺带修） |

`formula-eq` 改述「数字后 % 且其后无操作数（后接运算符、右括号或结尾）时视为百分比 → (数字/100)，其余情况保留 % 作为取模运算符」，并同步替换 `i18n/tools/en/it/math-evaluator.json` 的中文原文 key（旧 key 删除）。
