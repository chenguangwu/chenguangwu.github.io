核心实现：

```javascript
const LEGACY_NO_SEMI = /^(?:amp|lt|gt|quot|nbsp|copy|reg)$/;
function dec(){
  const text = document.getElementById('input').value;
  if(!text) return alert(/* 双语提示 */);
  const fromCp = (cp, raw) =>
    (cp >= 0 && cp <= 0x10FFFF && !(cp >= 0xD800 && cp <= 0xDFFF)) ? String.fromCodePoint(cp) : raw;
  let result = text.replace(/&(?:#(\d+)|#x([0-9a-fA-F]+)|([a-zA-Z]+))(;?)/g,
    function(m, decNum, hexNum, name, semi){
      if(decNum !== undefined) return fromCp(parseInt(decNum, 10), m);
      if(hexNum !== undefined) return fromCp(parseInt(hexNum, 16), m);
      const key = '&' + name + ';';
      if(!Object.prototype.hasOwnProperty.call(REVERSE, key)) return m;
      if(!semi && !LEGACY_NO_SEMI.test(name)) return m;
      return REVERSE[key];
    });
  document.getElementById('output').value = result;
}
```

**取舍说明**：无分号命名实体只解 HTML5 legacy 子集中本工具表内确实存在的 7 个（amp/lt/gt/quot/nbsp/copy/reg），其余（`&rarr`、`&notin`）与 `AT&T` 原样保留，避免把普通文本误改。数字实体无分号按 HTML5 行为解（`&#65x` → `Ax`）。单次 `replace` 而非多轮，保证 `&amp;lt;` 只解一次得 `&lt;`、`&amp;amp` 得 `&amp`，不会把刚解出的 `&` 二次解码。表外实体（如 `&alpha;`）仍原样保留——`NAMED` 只有 39 条，工具名/meta 的「完整编解码」属 Q 批专项承诺条目，改动牵涉 SEO 标题/JSON-LD/面包屑，本批**未动**，仍留在清单专项段。

## 四、踩坑（记死）

1. **「源码不含 DOM API」断言不能匹配裸词**：修复注释里会写「不把输入交给 innerHTML / DOMParser」做说明，裸词正则会误报；应只判实际语句（`.innerHTML =` / `new DOMParser` / `document.createElement(`）。
2. **实体之间有空格，输出也保留空格**：`&nbsp &copy &reg` 期望 `\u00A0 \u00A9 \u00AE`（含两个空格），写 `\u00A0\u00A9\u00AE` 会假红；用 `includes` 逐字符判更稳。
3. **`dec` 与 `enc` 都是产结果入口**：全站模板常只包装一个，复核时「输出→历史→趋势→表格→CSV」必须逐个入口走，别只测主按钮。
4. **单次扫描优于多轮 replace**：多轮会二次解码；用一条总正则 + 回调既统一了带/无分号路径，也天然避免二次解码。
5. **清单边界**：删 N196–N198 三段时，终点要取「该页留存建议行」，不能取下一个 `### IT-N199`（中间还有「承诺 vs 实际」与「覆盖」两段审计记录必须保留）。
