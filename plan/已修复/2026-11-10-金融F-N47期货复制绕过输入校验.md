## 根因
- `tools/finance/futures-pnl-calculator.html` 的 `calc()`（L465-470）与 `addTrade()`（L504-506）在入口调用 `validateInputs()`，但 `copyResult()`（原 L674-703）完全没有这道校验。
- 复制路径独立用 `parseInt(...) || 1`、`parseFloat(...) || 0` 兜底：手数 0 被当作 1 手、保证金率 0 被当作 0，仍生成并复制完整盈亏文本；与同屏「输入有误」提示自相矛盾。

## 修复位点
- `tools/finance/futures-pnl-calculator.html` `copyResult()` 开头新增：
  ```javascript
  // F-N47：复制必须与 calc() 走同一道输入校验，避免用 || 兜底值复制出无效结果
  var errMsg = validateInputs();
  if(errMsg){
    var __en = (typeof TBKit!=='undefined'&&TBKit.util.isEn());
    var __label = __en ? 'Cannot copy' : '无法复制';
    var __msg = __en ? 'Invalid input. Fix the fields before copying.' : ('输入有误，无法复制结果：' + errMsg);
    document.getElementById('resultGrid').innerHTML='<div class="result-item" style="grid-column:1/-1;"><div class="label">' + __label + '</div><div class="value" style="font-size:14px;color:var(--danger);">' + __msg + '</div></div>';
    return;
  }
  ```
- 复用同一 `validateInputs()`，不新增第二套口径；错误写入已被采集的结果容器 `#resultGrid`，英文态经页面既有 helper 输出纯英文、无 CJK 泄漏。
- 有效输入下复制逻辑完全不变，不影响正常功能。
