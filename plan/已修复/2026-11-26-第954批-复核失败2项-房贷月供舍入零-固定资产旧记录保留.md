## 本轮处理

1. **房贷月供舍入为零导致首期结清** `tools/finance/mortgage-calculator.html`
   - `buildSchedule()` 等额本息在月供按分舍入后检查：`mp<=0` 或 `mp ≤ 首期利息`（利率 >0）时返回错误，不再把全部余额塞进首期并显示结清。
   - 等额本金在每期本金按分舍入后为 0 时同样返回错误。
   - `calculate()` 收到错误后清空结果与明细，按中英文提示“按分舍入后月供 X 元，不足以覆盖当期利息或无法形成有效分期；当前本金与期限不能生成正常还款计划”。
   - 真机：本金 0.01 元/0%/30 年 ⇒ 月供 0.00 元拒绝；0.12 元/100%/30 年 ⇒ 月供 0.01 元、首期利息 0.01 元拒绝；100 万/4.2%/30 年正常月供 ¥3,423.12，明细 24 行预览正常。

2. **固定资产旧记录被静默过滤并覆盖** `tools/finance/register-depreciation.html`
   - 删除加载时 `assets = assets.filter(isValidAsset)`；`assets` 保留全部原始记录，新增 `validAssets()` / `invalidAssets()` / `assetInvalidReason()`。
   - 汇总、列表、折旧明细、CSV 清单只遍历有效记录；旧记录隔离展示为“待修正旧记录”，说明已暂停折旧循环、仍保留在本地台账与 JSON 备份中，并提供“备份 JSON（含全部记录）”按钮。
   - `save()` 写入全部记录；新增/编辑/删除其他资产不会丢弃无效旧记录；`backupAssets()` 的 payload 增加 `validCount` / `invalidCount`，`assets` 数组保持全量。
   - `showDetail()` 对无效记录只提示不计算；CSV 导出跳过无效记录并在 toast 中说明用备份 JSON 保留。
   - 真机：预置 101 年旧记录 + 正常记录，重载后列表/汇总均显示“待修正旧记录”；新增一条后 localStorage 保留 3 条（`超龄设备:101` 未丢失）。
