## 一、改源码修复

### 围棋数子法「目/子」单位混用，胜负与显示互相矛盾（高）
- **文件**：`tools/chess/go-territory.html`
- **缺陷**：中国规则分支 `whiteScore = wT + wStones + komi`，把「贴目（目）」直接加到以「子」计的分数上；而阈值行却写「黑方须超过 180.5 + komi/2 目」。两者口径不一致导致：① 卡片把「子数」标成「总目」；② 极端输入直接翻转胜负。示例（komi=7.5、黑 空50+活90=140 子、白 空48+活85=133 子）：旧版算出白方 140.5「目」> 黑 140「目」⇒ 判**白方胜、目差 −0.5**，而按数子法黑方 140 子 > 180.5+3.75=184.25？——实际双方均未过半，正确结论应是按子差计：黑 140 vs 白 136.75 ⇒ 黑胜 3.25 子 = **+6.5 目**。
- **修复**（仅动中国规则分支，日本规则一字未改）：
  - 新增 `komiZi = komi/2`（1 子 = 2 目，与页内深解「中国贴 3¾ 子 ≈ 7.5 目」一致）；`whiteScore = wT + wStones + komiZi`。
  - 新增 `isChinese` 标志；`diff = isChinese ? (blackScore - whiteScore) * 2 : (blackScore - whiteScore)`（子差 → 目差）。
  - 卡片标签：中国规则显示「黑方子数 / 白方子数」「贴子（值=komi/2）」；日本规则仍「黑方总目 / 白方总目」「贴目」。
  - 文案：中国规则显示「贴子 3.75 子（= 7.5 目）」「黑方：活子 90子 + 围空 50目 = 140.0子」「白方：… + 贴子 3.75子 = 136.8子」「数子阈值：黑方须超过 184.25 子方胜；目差按 1 子 = 2 目 折算」。
- **根因**：同一模式内「目」与「子」两套单位混用，且只在阈值行做了 ÷2 折算、分值计算没有。

### 音符转换：非法输入后仍复制上一次的结果（中）
- **文件**：`tools/music/freq-note-converter.html`
- **缺陷**：`box.dataset.copyValue` 只在成功分支写入，错误分支（空输入/超范围/八度非法）不清除；`copyResult` 又回退 `el.textContent`。于是「先算 440 Hz → 清空输入 → 点复制」会把上一次的 `A4 440.0000 Hz` 当调音数据复制出去；若走 textContent 回退，复制的则是错误提示文字。
- **修复**：① `calcFreq2Note` / `calcNote2Freq` 取到 `box` 后立即 `delete box.dataset.copyValue`；② `copyResult` 去掉 textContent 回退，只在存在有效 `copyValue` 时复制，无值静默不复制。
- **根因**：复制值的生命周期未与「本次转换是否成功」绑定。
