## 修复位点

### B-F3 税后等效收益率页无输入校验，按百分数输入直接得负收益率（高）
- **文件**：`tools/banking/tax-equivalent-yield.html`、`i18n/tools/en/banking/tax-equivalent-yield.json`、`scripts/verify_banking_calc.js`
- **缺陷**：页面代码按**小数**口径（`TEY = muni/(1-tax)`），但同页说明写「3%÷(1−25%) → 4%」，用户照说明输入 `3` 与 `25` 会得到 **TEY = −12.500%**，`边际税率 = 2500.0%`，`免税溢价系数 = −1.0417` —— 结论完全反向（免税品种看起来远劣于 0% 应税收益）。税率恰为 100% 时分母为 0，只显示「—」；空值按 0 算且无提示。
- **修复**：
  1. **口径统一为百分数**（UI 输入 %，内部 `/100`）：输入标签改为「免税收益率 (%)」「边际税率 (%)」，默认值 `3` / `25`，`step` 0.1 / 1，占位符「如 3」「如 25」；`resetForm()`、三个预设、图表扫率函数 `__teySweep()` 同步；
  2. 校验：`muni > 0`（否则提示「免税收益率须大于 0」并拒绝）；`0 ≤ tax < 100`（税率 100% 时明确提示「分母为 0，等效收益率无定义」，不再显示「—」）；
  3. 明细表与主结果同口径，无效输入时清空旧表并写占位提示；
  4. `formula-eq` 说明改为百分数口径并写明校验规则，英文 map 键值同批替换（新增「免税收益率 (%)」「边际税率 (%)」键，占位符键改「如 3」「如 25」）。
- **根因**：计算口径（小数）与用户可见说明（百分数）不一致，且缺输入校验把错误放大成反向结论。

### B-F5 几何平均收益率页未声明小数口径，百分数输入得 10 倍或空结果（高）
- **文件**：`tools/investment/geometric-mean-return.html`、`i18n/tools/en/investment/geometric-mean-return.json`、`scripts/verify_investment_calc.js`
- **缺陷**：序列解析后直接 `(1+x)` 连乘，公式框未写单位，而深度解析算例用「+10%、+20%、−5%」。用户输入 `10 20 5` 得 **g = 1014.95%**、`10 20 -5` 因 `Π < 0` 得 `Math.pow` NaN 显示「—」、`abc` 同样「—」且无任何提示。
- **修复**：
  1. **口径统一为百分数**（内部 `/100`）：标签改为「收益率序列 r（%，逗号/空格分隔，亏损用负号）」，默认 `10, 20, -5`，占位符「如 10, 20, -5」；`resetForm()`、四个预设、计算说明示例（`10,20,−5 → 7.83%`）同步；
  2. 逐项校验：非数字 ⇒「⚠ 第 N 项「xxx」不是有效数字」；`v ≤ -100` ⇒「⚠ 第 N 项收益率 −100% 不合法：单期跌幅不能达到或超过 100%，否则 (1+r) ≤ 0，复合倍数无意义」——不再静默显示「—」；
  3. 序列为空 ⇒「请至少填写一期收益率」；
  4. `formula-eq` 与英文 map 同步百分数口径与逐项校验说明。
- **根因**：解析层默认小数、展示层用百分数，两个口径在同一个输入框上并存，且没有逐项校验兜底。

## 风险与迁移说明
- 两页的**输入单位从「小数」改为「百分数」**，属于破坏性口径变更：老用户 localStorage 里存的旧值（如 `0.03`/`0.1`）会被按新口径读成 `0.03%`/`0.1%`。判断为可接受——旧值本身就是错误口径下的产物，且两页都提供了「重置」按钮回到新默认值。
- 页面级 `placeholder` / 预设 / 计算说明 / 深度解析算例已全量对齐新口径；深度解析正文（`content_deepdive.json`）原本就用百分数叙述（`3%÷0.8=3.75%`、`(1.1×1.2×0.95)^(1/3)≈7.83%`），与修复后口径一致，无需改动。
