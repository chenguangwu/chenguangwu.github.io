## 修复内容

1. **压缩与美化输出完全相同**
   - `toProps(obj, compact)` 增加紧凑模式：压缩输出 `key=value`，美化输出 `key = value`，不再共用同一种分隔符。
   - 压缩/美化都复用 `escapeKey` / `escapeVal`，键含空格、`#`、值含换行等仍可往返解析。
   - 成功提示明确说明：注释与空行不保留，重复键保留最后一次；压缩额外说明已去除分隔符空格。
   - 新增 `PPMINFMT` 回归，断言压缩为 `a=1`、美化为 `a = 1`。

2. **简介误称支持行内注释**
   - 中文简介改为“整行注释（#、!）”，不再宣称行内注释；明确 Java Properties 只把行首 `#` / `!` 作为注释，`a=value # note` 的 `# note` 属于值。
   - 同步更新页面 `<meta name="description">`、`og:description`、`twitter:description`、JSON-LD、首段 `data-zh`、深度解析文案，以及 `meta[name=desc-en]`。
   - 更新 `i18n/tools/it.json` 中英文 intro、`i18n/tools/it-body.json` 英文 intro、`i18n/tools/en/it/properties-parser.json` 与 `i18n/tools/en/_common.json` 映射；`_build.py` 同步刷新引用该工具的相关卡片描述。
   - Chrome 中英文实测简介均只提“整行注释 / full-line comments”，不再出现 inline comments。

3. **解析失败后保留上次输出**
   - `propsToJson()`、`doBeautify()`、`doMinify()` 在操作开始时即清空输出；异常分支只显示错误，不再把上一次成功结果留在输出区。
   - 输入框增加 `input` 监听：内容一变立即清空输出与错误提示，避免旧结果被误认为当前输入的结果。
   - 新增 `PPSTALE` 回归：先成功解析再输入非法 Unicode，输出为空且错误以 `❌` 开头；Chrome 实测输入变更后输出/错误均清空。

4. **非法 Unicode 转义被静默接受**
   - `__ppUni()` 对不完整或含非十六进制字符的 `\u` 转义抛出错误，不再丢掉反斜杠后继续解析。
   - `parseProps()` 捕获键/值反转义错误并补上起始行号，错误形如「第 1 行值：非法 Unicode 转义 \u12G4：需 4 位十六进制（第 2 个字符）」。
   - 合法 `\u4f60\u597d` 仍解码为“你好”；字面双反斜杠 `\\u4f60` 仍不会被误解码；未知转义（如 `\z`）保持 Java 语义。
   - Chrome 实测键、值非法转义均报错并清空输出；合法四位转义正常解析。
