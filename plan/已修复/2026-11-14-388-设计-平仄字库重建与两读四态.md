## 一、复核：台账描述的「8 次误标」已不成立

提交 `7070d692e3`（fix(design): 修正波形/Aztec/阴影描述…与平仄/音阶算法）已做过补丁式修复：

- 新增 PING 首段 `床霜明疑头低思乡光`（正好是《静夜思》用字去重）；
- 清空 ZE 首段 `床上望霜举头低思故月地水是望明故乡光`；
- 从 PING 第二段移出 `望忘广`。

实测当前《静夜思》20 字判定全对，台账里「误标 8 次」的现象不复现。

但**根因未除**：ZE 库（2043 字）实际是「全常用字表」，混入大量平声字；PING 仅 174 字。判定顺序「先 PING 后 ZE」让交叉字侥幸判平，一旦某平声字不在 PING 的 174 字里就必然被判仄。实测 `河`（hé）、`流`（liú）、`楼`（lóu）、`风`（fēng）全部只收在 ZE ⇒ 判仄，而它们都是平声。原 verify 用例甚至把这个错误固化成了 expect（`河 仄`／`流 仄`／`楼 仄`）。

## 二、修法：用 `pinyin-pro` 在构建期重建字库 + 新增「两读」态

1. **重建字库**（字集 = 原 PING ∪ ZE 2101 字 + 三首内置示例诗用字，零未收录）：
   - 取 `js/pinyin-pro-3.29.5.min.js` 的全部读音（`{multiple:true, toneType:'num'}`），先滤掉轻声 `0`；
   - 叠加《平水韵》入声十七韵高频入声字表（约 300 字），入声字一律归仄（现代读一、二声的 `白/石/竹/国/一/不` 等因此正确归仄）；
   - 结果：平 992 字、仄 1071 字、两读 38 字、未收录 0。
2. **新增 `BOTH` 集合 + 四态判定**，跨平仄的多音字不再强行归一：

```js
function toneOf(ch) {
  if (BOTH.has(ch)) return 'both';
  if (PING.has(ch)) return 'ping';
  if (ZE.has(ch)) return 'ze';
  return 'unknown';
}
```

   `BOTH` 38 字：中 为 予 令 传 兴 冠 分 华 和 宁 将 应 弹 强 当 担 挑 教 曲 更 横 王 相 看 禁 空 胜 藏 行 观 论 过 遗 量 长 间 难。

3. **渲染四态**：新增 `.char-badge.both`（紫色虚线边框）+ 角标「两」+ `title="两读"`；图例从三态扩到四态。
4. **文案全量同步**（10 处）：meta description×3 + JSON-LD、副标题 `data-zh`、`formula-eq`、`formula-desc`（字数 990/1070/38 + 判定依据）、tool-notes 两条、结果区提示、FAQ、SEO 介绍块、intro-features、`design.json` intro（中英）、`design-body.json` intro（英）、`content_deepdive.json` 的 summary/示例/FAQ（该文件被 `_build.py` 的 `_DEEP_DIVE_BLOCK_RE` 覆写，必须改源）、EN 字典 12 条新增 + 11 条失效键删除。
5. **顺带修英文态**：「第 N 句」原为 JS 拼接的动态中文，字典级替换覆盖不到 —— 改用 `isEnMode()` 判定输出 `Line N`；角标改 `L/O/B`；title 改 `Level/Oblique/Both readings`；空输入与结果提示走 `T(zh,en)`。

## 五、坑与注意

- `content_deepdive.json` 是**单行紧凑 JSON**（128503 行），用 `json.dump(indent=2)` 会把它整体重排成 25 万行 diff。正确做法：`git show HEAD:…` 取原文 → 文本级精确替换 → 写回。
- `collectStrings()` 剥标签时会把 `title` 属性整块吞掉，所以徽章里「两读」二字采集不到，expect 只能锚角标「两」。第一版 expect 写「更 两读」直接变红。
- 入声表只收高频且确定的字，宁缺勿错；`的/吃/得` 之类现代高频虚词虽属古入声，仍保留在仄库（诗中几乎不用，影响可忽略）。
- 两读集合刻意只收 38 个高频跨平仄字，`风/疑` 这类「多音但次音极罕见」的字不标两读（否则判别力被稀释）。
