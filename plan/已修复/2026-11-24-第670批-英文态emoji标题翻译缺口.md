# 第670批：英文态 emoji 标题翻译缺口修复

## 背景

对全部 4,634 个工具页做 `?lang=en-US` 可见文本扫描，统计未被翻译的中文短语。结果暴露出一个**系统性匹配缺陷**，不是单纯缺词：

```html
<h4><span class="h4-icon">📝</span>工具简介</h4>
```

`translateBodyPhrases()` 按整节点 `textContent.trim()` 查表，得到的是 `📝工具简介`，而字典键是 `工具简介`，精确匹配必然落空。同类标题还有 `✨功能特点`、`🎯使用场景` 等。静态扫描中带这些标题的页面约 3,100 个，英文态展开“关于本工具”后仍显示中文。

## 修复

`js/tool-i18n.js`：

1. 静态正文短语匹配在精确键落空时，剥离 emoji 前缀后再查 `BODY_PHRASE_MAP` / `COMMON_PHRASES` / 行业短语。
2. 标题含子元素（如 `.h4-icon`）时，不再整节点覆盖，改为**只替换目标文本节点**，保留图标 `<span>` 与样式。
3. `BODY_CHANGED` 还原逻辑支持文本节点条目，切回中文可精确恢复原节点值。
4. 动态节点增量翻译同样增加 emoji 前缀回退，结果区新增的 `📊 平均速度` 一类标签也能命中。

## 核验

- `tools/daily-goods/shoe-size.html`、`tools/agriculture/calc-38.html` 英文态：
  - `📝About This Tool`、`✨Features`、`🎯Use Cases`
  - `<span class="h4-icon">📝</span>` 图标结构保留
- 同页 `I18n.set('zh-CN')` 往返：标题精确恢复为 `📝工具简介`、`✨功能特点`，0 脚本异常。
- `python3 _build.py` 后修复存活。
- 全量门禁 **274/274 通过**。

## 范围说明（重要）

本批修的是**可系统化修复的 emoji 标题匹配缺陷**，不是全量英文翻译。全站扫描仍显示：

- 4,634 个工具页中 **3,474 个**在英文态有 >20 个可见汉字；
- 可见中文短语 **52,636 个唯一值**，大量为中医、工程、医学等页面正文/结果标签，仓库内没有任何对应译文。

因此英文态的**整页内容级翻译**仍是长期内容工程，不能靠本批的匹配修复解决；本批只保证带 emoji 的通用标题/标签不再因匹配方式漏译。
