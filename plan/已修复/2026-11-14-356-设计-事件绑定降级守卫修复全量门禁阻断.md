## 一、问题（全量门禁唯一红项）

攒满 5 批后跑 `scripts/run_gates.py`，264 项里仅 `calculation regression` 失败：

```text
[15/264] calculation regression: node scripts/verify_calc.js
[design/flexbox-generator] ❌ JS ERROR: e.addEventListener is not a function
==== 1 FAILURES (84 pages) ====
GATES_EXIT=1
```

根因链：

1. `scripts/verify_calc.js` 的 DOM stub 中，由 `defaults` 预置的输入元素只有 `{ value: defaults[k] }`；只有 `getElementById` **按需新建**的元素才补 `addEventListener() {}`。
2. 第352批 D-N123 给 `flexbox-generator.html` 新增 `__bindFlexLive()`，对 `dir/just/ali/wrap/gap` 直接调 `e.addEventListener('change'/'input', ...)`。
3. `verify_design_calc.js` 复用 `verify_it_calc.js` 的 stub（元素带真实 `addEventListener(ev, cb)`），所以小门禁 `FLX live=5/5` 一直绿；两套 harness 能力不一致，问题只在全量门禁暴露。
4. stub 中 `document.readyState` 为 `undefined`，第 254 行走 `else` 直接调用 `__bindFlexLive()`，在页面初始化末尾抛错，整段脚本中断。

排查时统计：design 分类 108 个页面含 `addEventListener`，仅 flexbox 这一处在元素级绑定时未做能力判断，属个别遗漏。

## 二、修复（改源不改门禁脚本）

`tools/design/flexbox-generator.html` 的 `__bindFlexLive()` 增加能力守卫，并补中文注释说明降级原因：

```js
var e=document.getElementById(id);
/* 计算回归门禁的 DOM stub 只给输入元素 value，没有 addEventListener；
   缺能力时直接跳过绑定，不能让整段初始化脚本抛错而中断 calcTool()。
   真实浏览器仍走 addEventListener，保持「实时预览」的 change/input 双监听。 */
if(!e||typeof e.addEventListener!=='function'||e.__flexLiveBound) return;
e.__flexLiveBound=true;
e.addEventListener('change',function(){calcTool();});
e.addEventListener('input',function(){calcTool();});
```

决策：

- **不改 `scripts/verify_calc.js` 的 stub**。虽然给 stub 补 `addEventListener` 也能跑通，但改门禁脚本容易被误读为「为跑通而放宽校验」；让页面自身对缺能力环境不中断，是更稳的一侧。
- **不退回内联 `onchange/oninput`**，遵守「验证覆盖工具禁用内联事件副作用、统一 addEventListener」的既有铁律。
- 真实浏览器元素都有该 API，绑定行为与第352批完全一致，`FLX live=5/5` 保持绿。

## 三、强锁与旧源码差分

```js
clicks: ["var e=document.getElementById('dir');var saved=e.addEventListener;e.addEventListener=undefined;var r='Y';try{e.__flexLiveBound=false;__bindFlexLive();}catch(err){r='N';}e.addEventListener=saved;...'FLX degrade='+r+' bound='+(e.__flexLiveBound?'Y':'N');"],
```
