## 修复内容

### 1. `tools/it/css-escape.html`：反斜杠 + 换行续行

`unesc()` 在进入十六进制扫描前先识别 CSS 续行：反斜杠后为 LF、FF 时跳过 2 个字符；CRLF 跳过 3 个；单独 CR 跳过 2 个。解析值不再残留换行。

Chrome 实测 `a\` + LF / CRLF / CR / FF + `b` 均输出 `ab`；用 CSSOM 解析 `content:"a\<LF>b"` 读回 `"ab"`，与浏览器语义一致。

### 2. `tools/it/clamp-calculator.html`：标准引据

公式表由错误的 `clamp(x, lo, hi) = min(max(x, lo), hi)` 改为 `clamp(lo, x, hi) = max(lo, min(x, hi))`；参数约束行改为「最小值优先：lo ≥ hi 时仍取 lo」，不再写“由实现决定”。英文文案同步，并补入 `i18n/tools/en/it/clamp-calculator.json`。

Chrome 实测 `CSS.supports('width','clamp(100px, 50px, 10px)') = true`，反序边界计算值为 `100px`，与表内说明一致。

### 3. `tools/it/clamp-calculator.html`：极小边界精度

- 表达式边界舍入由 4 位小数提升到 8 位（`fmtSize`）。
- 精度容差由固定 `0.005px` 改为按数值量级缩放：`max(1e-9, |max-min|×1e-4)`，系数精度上限由 8 位提升到 12 位，避免 0.00004~0.00012px 区间在 3 位系数时被判“已足够”而输出 0px。
- 边界展示改用 `fmtBound`：常规值仍保留 2 位小数，绝对值小于 0.01px 时保留 8 位，因此极小值不会丢失端点。
- `lo/mid/hi` 与最大偏差均按实际生成表达式求值。

Chrome 实测极小输入 `0.00004 / 0.00008 / 0.00012px` 输出：

`clamp(0.00004px, 0.000009091vw + 0.000010909px, 0.00012px)`

边界 `320px=0.00004px · 中点760px=0.00008px · 1200px=0.00012px`，最大偏差 `0px`。舍入临界值 `0.00005 / 0.00010 / 0.00015px` 同样保持端点，中点显示 `0.0001px`。普通输入 16/24/48/375/1440 仍输出 `375px=16px · 中点907.5px=24px · 1440px=48px`。
