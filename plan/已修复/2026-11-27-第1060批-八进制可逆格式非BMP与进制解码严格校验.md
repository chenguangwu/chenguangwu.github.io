## 修复内容

### 1. `tools/it/text-to-octal.html`：无分隔/前缀格式可逆

- 无分隔符、`\` 前缀、`0` 前缀三种格式没有天然字节边界，自动位宽会产生歧义；输出端固定为 3 位（单字节最大 377），并在提示中明确说明。
- 反解端按当前分隔符与位宽解析：无分隔/前缀格式先去掉内部空白，再按固定 `位宽 + 前缀长度` 分组；长度不整除、前缀缺失、出现非 0–7 字符、单字节超过 255 均明确报错。
- 普通分隔格式仍按空白/`,`/`;`/`:`/`-`/`_`/`\` 切分；不再无条件删掉首位 `0`，避免把八进制 `010` 误读成十进制语义的 `10`。
- 反解每个 token 用 `/^[0-7]+$/` 整段校验，非法字符不再被 `parseInt` 部分吞掉。

Chrome 实测 `AB`：空格 / 无分隔 / `\` 前缀 / `0` 前缀 / 换行，配合 3 位、自动、6 位均可编码后原样往返；无分隔格式长度错误会提示「必须按固定 3 位一组解析」。

### 2. `tools/it/text-to-octal.html`：非 BMP 字符编码与展示

- UTF-16BE 代理对编码/解码路径复核：高代理项后跳过低代理项，`😀` 编码为 `330 075 336 000`，不再误报孤立低代理项；四字节代理对解码回 `😀`。
- UTF-8 非 BMP 字符按真实字节序列输出与展示：`😀` 为 `360 237 230 200`，与 `f0 9f 98 80` 一致，不再按 UTF-16 码元分别显示代理项替换字节。
- 可视化按 `Array.from()` 的码点切分，并把非 ASCII 可打印字符（含 emoji）直接显示，不再一律替换成 `·`；换行仍显示 `↵`、空格 `␣`、制表 `⇥`。

### 3. `tools/it/text-to-hex.html` / `tools/it/text-to-binary.html`：非法字符整段校验

- 十六进制反解在剥离 `0x` / `\x` 前缀与分隔符后，先检查是否为空，再用 `/[^0-9a-fA-F]/` 定位第一个非法字符并报错；奇数个半字节仍明确按左侧补 0 成一个字节，不做部分解析。
- 二进制反解先检查是否为空，再用 `/[^01]/` 定位第一个非法字符；末尾不足 8 位仍明确按左侧补 0，不再把 `0100000X` 这类输入部分解析后补成零字节。
- 错误信息进入输出框 `placeholder`，结果区保持为空。

Chrome 实测 `4G` 提示第 2 个十六进制字符非法；`0100000X` 提示第 8 个二进制字符非法，均无静默输出。

### 4. `tools/it/integer-base-converter.html`：说明与行为一致

- 公式说明由「越界自动钳制」改为「越界或非整数时保留输入并明确报错（不自动钳制）」，与 `convert()` 的实际严格校验一致。
- 同步更新 `i18n/tools/en/it/integer-base-converter.json` 英文说明；英文态实测显示 `out-of-range or non-integer input is preserved with an explicit error (no automatic clamping)`。
