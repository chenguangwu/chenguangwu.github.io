# 425 批：指南页自引用 canonical 修复与空壳指南文案补全

日期：2026-11-14
范围：`guides/*.html`（静态页）+ `json/guides.json` 标题同步

## 一、问题（全站扫描发现）

1. **2220 个指南页 canonical 指向不存在的 URL**
   - 文件实际路径为 `guides/<slug>-guide.html`，但 canonical / `og:url` / JSON-LD
     `mainEntityOfPage.@id` / 面包屑第 3 项 item 全部写成了
     `guides/<industry>-<slug>-guide.html`（如 `metalwork-detector-24-guide.html`）。
   - GitHub Pages 无重定向能力，该 URL 实为 404，等于把每个指南页的权重都指向死地址，
     是 GSC「已提交的网址返回 404 / 备用网页」的直接成因之一。
   - 2220 页中仅 5 个前缀 URL 恰好命中同名文件（跨页误指），同样属于错误 canonical。

2. **85 个「空壳指南」**
   - `<title>` / `<h1>` / 面包屑直接用 slug（如 `detector-24 使用指南`）。
   - meta description 为纯模板：「XX：在线输入参数即可即时得到结果，无需安装与注册。
     本指南整理核心功能、适用场景、使用步骤与常见问题，纯前端免费在线使用，数据不上传。」
   - 正文「功能说明」与导语同为一句话模板。
   - 返回按钮文案为 `→ 打开detector-24工具`。

3. **378 个相关工具卡与 84 个返回按钮仍显示 slug 名**
   - `detector-hardness`、`analysis-36` 这类原始 slug 直接作为链接锚文本展示。

## 二、修复方式

脚本化处理（一次性，可复现）：

- **canonical 自引用**：读取每页 canonical 的 basename，若与实际文件名不一致，
  把该页内所有该 URL 字符串（canonical / og:url / JSON-LD @id / 面包屑 item）替换为真实 URL。
- **空壳指南补全**：按 `<slug>-guide.html` → `tools.json` 的 `file` 反查工具；
  取不到时回退到页面「→ 打开工具」链接反解工具路径。取到后：
  - 标题：`{slug} 使用指南` → `{工具名}使用指南`（title / og:title / twitter:title /
    JSON-LD headline / 面包屑 span 与 LD name / h1 全部同步）；
  - 描述：改用工具权威描述 `d`（剥掉隐私套话尾句）；不足 70 字时补正文首条列表项，
    仍不足再补「本指南整理适用场景、操作步骤与常见问题。」；上限 150 字并按句读收口；
    同步 meta / og / twitter / JSON-LD description；
  - 导语与「功能说明」段落同改为该描述。
- **slug 锚文本**：相关工具卡与返回按钮，按 href 反查 `tools.json` 的 `name` 回填。
- **`json/guides.json` 标题同步**：85 条 title 同步为 `{工具名}使用指南`，
  工具页上的「使用指南」入口文案随之更新（`_build.py` 从这里取文字）。

## 三、验证

- 扫描全量 3426 个指南页：
  - canonical 与自身文件名不一致：2220 → **0**
  - `<title>` 仍为 slug：85 → **0**
  - description 仍含「在线输入参数即可即时得到结果」：85 → **0**
  - JSON-LD 解析失败：**0**
- `python3 _build.py` 连跑两次，指南目录内容哈希一致（`cc2a2b5f4a15c857`），构建幂等；
  构建未回改任何指南页（仅 `sw.js` 版本戳变化）。
- `python3 _test_static.py`：**4714/4714** 通过。
