# 第163批 · IT 清单 1 条 · convert-11 非法输入通过校验静默输出错误值

- 来源：`plan/categories/01-IT开发/it.md` → IT-N483（已整条删除）
- 修复日期：2026-11-11
- 类型：中风险计算正确性缺陷（非法输入被静默转成 0.0.0.0/截断值），纯前端逻辑，无文案/口径变更

## 失败点
`tools/it/convert-11.html` 的 `calc()`：
1. dot 分支校验 `x===''||+x<0||+x>255` 对 `NaN` 两个比较均 false ⇒ 非数字段（`1.2.3.x`、`1a.2.3.4`）放行，reduce 得 NaN ⇒ `toBin32(NaN)` 全 0 / `0.0.0.0` / 字符串 NaN。
2. dec 分支 `parseInt(v,10)` 只判范围，`1e3`→1、`12.9`→12、`0x10`→0，静默输出截断值。

## 根因
用 `+x` 隐式转数后比较区间，未先确认字符串本身是合法整数；`parseInt` 的前缀解析特性把非纯数字串截断成合法整数，校验只落在截断后的值上。

## 修复位点
`calc()`：
- dot 分支每段改为 `/^\d{1,3}$/.test(x) && +x<=255`，挡住非数字/空段/超3位/超范围。
- dec 分支先 `/^\d+$/.test(v)` 再用 `Number(v)`，并 `Number.isSafeInteger` + 0–4294967295 区间校验。
复用页面既有错误文案（`IPv4 格式无效` / `整数超出 IPv4 范围`），i18n 0 残留；页面口径声明本就是"输入合法才精确、非法提示格式无效"，修复落实声明。
