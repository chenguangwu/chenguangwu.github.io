# 复核失败重做批次 · 申请再次复核

## D-N1 对比度工具仍会对非法颜色生成结论

**失败点（原复核记录）**
- 页面：`tools/design/contrast-checker.html` 的 `onFgHexInput()`、`onBgHexInput()`、`updateAll()`。
- 复现：前景色输入 `GGGGGG` 后页面正确提示非法并清空比率；随后只将背景色改为合法的 `000000`，前景仍为 `GGGGGG`，页面却显示 **1.00 / 不达标**。原因是单个字段合法时即调用 `updateAll()`，没有验证另一个字段；`hexToRgb()` 将非法值回退为黑色。

**根因**
- `updateAll()` 直接对 `fgHex`/`bgHex` 调 `hexToRgb()`，而 `hexToRgb()` 对非法值静默回退 `[0,0,0]`；两字段仅在各自的 `onXHexInput` 内单独校验，没有一处统一兜底，导致「一字段非法 + 另一字段合法」时仍算出结论。

**修复位点**
- `tools/design/contrast-checker.html` `updateAll()` 开头加 `if (!isValidHex(fgHex) || !isValidHex(bgHex))` 双校验，任一非法即清空 `ratioNum`、写入错误提示 `颜色需为有效的 3 或 6 位 HEX 值` 并 `return`，不输出比率/评级/预览色。

**验证证据**
- `env -u NODE_OPTIONS node scripts/verify_it_calc.js contrast-checker` 全绿（含新增用例）。
- 新增回归用例：`inputs:{fgHex:"GGGGGG",bgHex:"000000"}` + `clicks:["updateAll()"]`，断言结果区出现 `颜色需为有效的 3 或 6 位 HEX 值`（修复前非法回退黑色算出 1.00/不达标，不含该提示）。默认合法色对（#FFFFFF/#000000 给 21.00）不命中，判别力真实。

**判别力实测**
- 单文件判别器 `node scripts/discriminate_check.js verify_it_calc.js`：1336 用例已检、正确变红 1336、逃生项 0。本用例锚错误提示串，回退源码后转红，确认门禁可捕获回归。
