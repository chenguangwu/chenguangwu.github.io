# 第 17 批 · IT-N406 · base64-file MIME → 标准文件扩展名

- 日期：2026-11-08
- 页面：`tools/it/base64-file.html`
- 条目：IT-N406（中，确认缺陷）
- 类型：真实缺陷修复（含文案 / i18n / 用例同批）

## 一、缺陷

还原下载的文件名直接取 `mime.split('/')[1]` 当扩展名，**MIME 子类型并不等于文件扩展名**：

| data URI 的 MIME | 修复前文件名 | 修复后 |
|---|---|---|
| `text/plain` | `decoded.plain` | `decoded.txt` |
| `image/svg+xml` | `decoded.svg+xml` | `decoded.svg` |
| `image/jpeg` | `decoded.jpeg` | `decoded.jpg` |
| `application/vnd.openxmlformats-officedocument.wordprocessingml.document` | `decoded.document`（取末段）| `decoded.docx` |
| 无 data URI 前缀 → `application/octet-stream` | `decoded.octet-stream` | `decoded.bin` |

两个调用点都错：`b64ToFile()`（`:323`，粘贴 Base64 还原）与 `downloadB64()`（`:303`，b64Out 还原）。后果：下载文件双击打不开 / 被错误程序关联，Office、XML 类型尤其明显。

## 二、修复

在页面脚本顶层（`var lastFile=null,lastB64='';` 之后）新增：

- `MIME_EXT` 映射表（约 60 条）：text/*、application/*（含 pdf/zip/gzip/7z/rar/wasm、OOXML 三件套、旧版 Office、ODF）、image/*（jpeg→jpg、svg+xml→svg、ico…）、audio/*、video/*、font/*、`application/octet-stream`→bin。
- `extFromMime(mime)`：① 小写、去掉 `;charset=…` 参数；② 查表命中直接返回；③ 未命中则截掉 `+` 结构化语法后缀（`svg+xml`→`svg`）、去掉 `x-` / `vnd.` 前缀、取点分末段、只留 `[a-z0-9]`；④ 全空回落 `bin`。

两个调用点改接：

```js
a.download = lastFile ? ('b64-'+lastFile.name) : ('file.'+extFromMime(mime));   // downloadB64
var fname='decoded.'+extFromMime(mime); a.download=fname;                       // b64ToFile
```

`b64ToFile()` 成功提示补回显实际文件名：`✅ 已还原 5 B 字节文件并触发下载（text/plain → decoded.txt）` —— 既是用户可见信息，也是可断言的行为契约。新增片段里的文件名是纯 ASCII，英文态无中文泄漏。

**文案/i18n 同批**：`formula-eq` 从「以 decoded. 加类型后缀（取不到后缀时用 bin）」改写为「按媒体类型查表得到标准扩展名…未收录类型先清洗 + 语法后缀与厂商前缀…输出实际文件名」，并同步 `i18n/tools/en/it/base64-file.json` 的 `map`（中文原文作 key，用 `html.unescape(页面 textContent)` 取真实 key，避免把 HTML 片段当 key）。`node scripts/_en_i18n_probe.mjs --check it/base64-file` → 有残留 0 页。
