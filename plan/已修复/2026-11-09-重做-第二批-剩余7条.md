## 1. IT-N492 / IT-N493 Codabar 深度解析示例仍错误

- 根因：deepdive 示例套用条码族通用模板，未按 Codabar 的实际字符集与起止符约束改写；此前只修了公式区与输入校验，未动内容源。
- 修复位点：三处同步 —— ① `i18n/tools/content_deepdive.json` 的 `it/barcode-codabar.examples[0].body`；② `i18n/tools/en/it/barcode-codabar.json` 的中文键与英文译文（英文态不会漏译 / 不会残留旧键）；③ 构建后页面 `tools/it/barcode-codabar.html` 的 `dd-ex-body`。新文案给出可用示例 `A12345678B`、首尾 A/B/C/D 起止符、数据位仅 0–9 与 `- $ : / . +`、明确「标准 Codabar 不含校验位，无需额外补校验位」。

## 2. D-N21 SVG 过期回调提前退出导致对象 URL 泄漏
- 失败点：`generate()` 的旧 `img.onload` / `img.onerror` 在 token mismatch 时先 `return`，`URL.revokeObjectURL(url)` 永不执行；连续转换累积 blob URL 占用内存。
- 根因：上一轮修复把过期守卫放在释放动作之前，只考虑了「旧结果不写回」，没考虑「资源仍需释放」。
- 修复位点：`tools/design/svg-to-png.html` — 两个回调统一改为 `try { if(myToken !== __genToken) return; … } finally { URL.revokeObjectURL(url); }`；过期回调走 finally 释放，且不改写 `lastDataURL` / `preview`，最新回调仍正常出图。
- 证据：新增用例用 URL/Image/canvas 桩连续 `generate()` 三次创建 `blob:1/2/3`，触发过期 `onload`（第 1 次）与过期 `onerror`（第 2 次）后命中 `D21REV=blob:1,blob:2 STALE=Y LATEST=Y ALL=blob:1,blob:2,blob:3`；同时证明旧回调不写回预览、`lastDataURL` 保持空，最新 onload 仍能写入 `PNG_OK` 并释放 `blob:3`。原有 D-N21「旧结果不回写」用例与 design 分类 273 条用例保持通过。

## 3. IT-N421 标签去重跨越扩展与私有段导致合法标签被拒
- 失败点：`en-u-ca-gregory-x-gregory`、`en-US-x-1-1` 被判非法，而 `Intl.getCanonicalLocales()` 接受。
- 根因：旧 `__lcValid()` 对全 `parts` 扫描，5–8 位子标签一律当 variant、单字符一律当扩展 singleton，不区分所处语法段；私有用途 `x` 之后的子标签也被纳入判重。
- 修复位点：`tools/it/locale-lookup.html` — 按 RFC 5646 固定次序推进 `language → extlang* → script → region → variant* → extension* → privateuse`；只在 variant 段收集 variant，只在扩展段收集 singleton；遇到 `x` 立即停止判重；扩展属性子标签不再计为 variant。
- 证据：新增用例命中 `LC=YYNNYY` —— 跨段同名合法、私有段重复合法、重复 variant `en-US-1901-1901` 与重复 singleton `en-u-ca-u-ca` 仍拒绝、多 variant `sl-rozaj-biske-1994` 与 4 位数字 variant `de-DE-1996` 仍合法。原有 IT-N421 / N422 共 14 条 locale 用例保持通过。

## 4. IT-N555 CJK 扩展块末尾未分配码位仍伪造名称
- 失败点：`lookupName(0x2B73F)`、`0x2B81F`、`0x2CEAF`、`0x2EBEF`、`0x3134F` 返回 `CJK UNIFIED IDEOGRAPH-…`，Unicode 15.1 中这些码位 UNASSIGNED。
- 根因：`isCjkAssigned()` 直接拿 block 边界（如 `0x3134F`）当已分配末码位。
- 修复位点：`tools/it/unicode-lookup.html` — 用 `UL_CJK_RANGES` 明确列出 Unicode 15.1.0 `unicodedata.name()` 逐码位扫描得到的 10 段连续已分配区间（Ext A、基本区、Ext B–I），`isCjkAssigned()` 改为区间表查询并加 `Number.isFinite` 守卫。**本轮全量重算还补回此前侦查遗漏的 Ext I `2EBF0–2EE5D`（Unicode 15.1 新增）与 Ext H `31350–323AF`（Unicode 15.0）**，否则这两个区的真实汉字会被误标「名称未收录」。
- 证据：新增用例逐点命中 `UL=YNYNYNYNYNYYNYYNN`：5 个原失败尾码位 + `2EE5E`/`323B0`/`3FFFF` 均为 N，5 个区首尾已分配码位与 Ext I/H 首尾均为 Y。原有 5 条 unicode-lookup 用例保持通过。

## 5. IT-N355 单键嵌套序列仍生成多个或零个 XML 根
- 失败点：`items:\n  -\n    - a\n    - b` 输出 `<items>a</items><items>b</items>` 两个并列根；`jsonToXml({items:[[]]}, '', false)` 输出空串、零个根。
- 根因：顶层唯一根判断只看外层数组长度，`ser()` 会递归把内部数组展平成多个或零个元素。
- 修复位点：`tools/it/yaml-to-xml.html` — 新增 `countTop(val)`，按与 `ser()` 相同的递归展开规则统计顶层元素数（数组求和、空数组计 0）；`total===1` 时直接输出该唯一元素（保持单键标量/单元素数组的既有形态），否则（含 `total===0`）统一包一层 `<root>`，空 body 输出 `<root></root>`。
- 证据：新增 5 条页面真实输入用例 —— 嵌套序列命中 `&lt;root&gt; &lt;items&gt;a&lt;/items&gt;&lt;items&gt;b&lt;/items&gt; &lt;/root&gt;`；两层嵌套 3 元素命中同形态 3 个 `<items>`；单元素 `items: - only` 仍命中 `&lt;items&gt;only&lt;/items&gt;`（未被误包 root）；多键映射与 `items: []` 空态近似回归均单根。原有 8 条 yaml-to-xml 用例保持通过。零元素分支（页面简易 YAML 解析器无法构造 `[[]]`）由源码层 `countTop([[]])=0 → <root></root>` 保证，供复核方独立调用验证。

## 6. IT-N549 长词库后缀突破最大长度
- 失败点：种子 x、创意、古风、maxLen=6、词库后缀、30 条，输出含 `G Collective`(12)、`I Studio`(8)。
- 根因：`Math.max(1, maxLen - suffix.length)` 在 suffix 本身长于 maxLen 时至少保留 1 字符 base，再拼上完整后缀必然超限。
- 修复位点：`tools/it/team-name-generator.html` — 词库后缀先筛出「`' '+s` 长度 + 至少 1 字符 base ≤ maxLen」的可用候选，仍用一次 `pick()` 取用（随机调用次数不变，种子复现契约不破）；一个都放不下则本条不加词库后缀；任何类型后缀若 `length>=maxLen` 一律丢弃；末尾加 `name.slice(0,maxLen)` 硬约束保险丝。
- 证据：新增 2 例 —— 复现原失败参数命中 `TN=Y LONG=0 WORD=Y`（30 条全 ≤6、无 Collective/Studio、仍有可用的 Team/Crew 短后缀）；词库/数字/符号三类后缀在 maxLen=6 各 30 条命中 `TNMODE=YYY`。原有 3 条 IT-N549 种子/风格/长度/后缀用例保持通过。

## 7. IT-N358 多行数组注释仍破坏引号内内容
- 失败点：合法 TOML `dependencies = [ # ] note\n  'a#b',\n  'tokio',\n]` 只得到错误字符串 `"'a\n'tokio'"`；双引号串末尾成对转义反斜杠后接注释也误判引号状态。
- 根因：`stripComment()` 只识别双引号且仅看引号前一个字符是否为 `\`；`tSplitTop()` / `tDepth()` 同样不认 TOML 字面字符串；`tVal()` 不解析单引号标量。
- 修复位点：`tools/it/toml-to-yaml.html` — ① `stripComment()` 改状态机，区分串外 / 基本串 / 字面串 / 三引号基本串 / 三引号字面串，成对吞掉 `\` 转义序列；② `tSplitTop()` / `tDepth()` 的引号状态由布尔改为 0/1/2，字面串内 `, [ ] #` 一律按内容处理；③ `tVal()` 新增 `'…'` 字面串解析（不转义）。`parseToml()` 的「先剥注释再判括号深度再合并多行」链路保持不变。
- 证据：新增 5 条页面真实输入用例 —— `dependencies: - "a#b" - tokio`（字面串 # 保留、注释里的 ] 不当闭合）、`note: "a\\"`（成对反斜杠 + 注释）、`items: - x - y`（注释里连续两个 ]）、`v: "a#b"`（双引号内 # 是数据）、`x: - "a,b" - "c,d"`（字面串内逗号不切分）。原有 6 条 toml-to-yaml 用例保持通过。
