# 第 433 批：FAQPage 结构化数据与可见问答同步

日期：2026-11-22
类型：SEO / 结构化数据
状态：已修复并本地提交（未 push）

## 一、原问题

全站 1,306 个工具页带 `FAQPage` JSON-LD，但其中 **236 页**的结构化问答仍是旧模板，与页面底部 `dl.dd-faq` 的可见问答不一致。例如：

- `tools/edu/calc-2.html`：LD 有 4 条旧问（“标准分Z分数是做什么的？”等），页面可见 5 条新问（“Z=0 含义？”“标准差未知？”等）；
- `tools/agriculture/assessor-1.html`：LD 问“机收损失率的参考值是多少？”，可见问“机收损失率多少算合格？”。

Google 要求 FAQ 结构化数据必须与页面可见内容一致，否则可能判定为欺骗性标记并取消富结果资格。

## 二、修复内容

修改 `_build.py`，新增 `_sync_faq_ld()` 并在每页写回前调用：

1. 只读取页面内 `<dl class="dd-faq">` 的可见 `<dt>/<dd>` 问答；
2. 去掉 HTML 标签、还原实体、归一空白；
3. 逐个 `<script type="application/ld+json">` 块判断是否为 `FAQPage`（**严禁跨 script 块正则匹配**）；
4. 仅当现有 `mainEntity` 与可见问答不一致时才替换，内容已一致的页面保持原字节不变；
5. 输出 `@context / @type / mainEntity` 标准结构，`</` 转义为 `<\/`，防止提前闭合 script。

## 三、验证证据

  - 缺 `<body>` 的页面：**0**。

- 静态门禁：**4,626 passed / 0 failed / 0 warnings**。

## 四、过程事故与修复（必须记录）

首次实现时用了一个跨 `<script>` 的贪婪正则匹配 `FAQPage`，把 `WebApplication` 块到 `FAQPage` 块之间的整个 `<body>` 一并吞掉，构建后 **416 页被截断成仅剩 head 的死壳**（`tools/agriculture/calc-38.html` 从 28KB 降到 4.5KB）。发现后立即：

1. `git checkout -- tools json i18n sitemap.xml sitemap_lastmod.json` 回滚全部页面到第 432 批提交状态；
2. 将匹配改为逐个 `<script>` 块解析 `json.loads` 判断 `@type`，禁止跨块；
3. 重建后复核 `缺 <body>` 页面为 **0**，历史内容完整。
