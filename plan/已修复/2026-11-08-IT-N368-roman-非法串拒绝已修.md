# IT-N368 roman-numeral 非法罗马串拒绝（已修复 · 申请复核）

- **分类**：it / 编码转换
- **原缺陷**：`fromRoman()` 先 `replace(/[^IVXLCDM]/g,'')` 剔除所有非法字符，再按「右到左、小减大加」累加；既不校验剩余串是否符合减法/重复规则，也不校验结果是否落在 1–3999。表现：`ABC` → `C`=100、`IL` → 49、`IC` → 99、`IIII` → 4、`VV` → 10、`MMMM` → 4000（超出页面声明的 1~3999）；乱码/拼写错误被当成合法数值，用户无法察觉。
- **证据（修复前）**：`tools/it/roman-numeral-converter.html` `fromRoman`（原 :216）、`calcTool` else 分支（原 :223-225）非空即直接输出。
- **根因**：缺少标准罗马数字构成校验，且页面公式区自己写明「不能出现 IL/IC」「范围 1~3999」却未执行。
- **修复位点**：
  1. `fromRoman()`：先 `toUpperCase().trim()`，再用标准正则 `^(M{0,3})(CM|CD|D?C{0,3})(XC|XL|L?X{0,3})(IX|IV|V?I{0,3})$` 校验，不通过返回 `null`；
  2. `calcTool` else 分支：`fromRoman` 返回 `null` 时输出「⚠️ 不是有效的罗马数字：仅可含 I/V/X/L/C/D/M，且须符合构成规则（范围 1–3999）」，合法串照常还原。
- **判别力实测**：
  - 修复前：`IL` → `49`、`MMMM` → `4000`、`ABC` → `100`、`1\n2\n3` → `0`。
  - 修复后：`IL` / `MMMM` / `ABC` / `1 2 3` 均输出无效提示；合法 `MCMLXXXIV` → `1984`、`CCXLVIII`/`248` 不变。
  - 门禁：新增 3 条 N368 回归用例（有效 MCMLXXXIV→1984、非法 IL、非法 MMMM）+ 同步修正既有 B 类自动补强用例 expect；`verify_it_calc.js` 1072/1072 通过；`discriminate_check.js` 单文件版 1071 正确变红、0 逃生项。
- **结论**：工具逻辑修复，回归用例锁定行为；非逃生、强判别。
