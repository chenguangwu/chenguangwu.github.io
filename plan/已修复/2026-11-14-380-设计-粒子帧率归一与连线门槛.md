# 380 设计 · 粒子特效：帧率归一 + 连线门槛放宽（D-N216 / D-N217）

- **分类**：04-设计创意
- **工具页**：`tools/design/particle-effect-generator.html`
- **日期**：2026-11-14
- **缺陷编号**：D-N216（高）、D-N217（中）

## 缺陷与根因

### D-N216：按「每帧」积分，速度与寿命随刷新率漂移

`updateParticles()` 内 `p.vy += gravity*0.1`、`p.x += p.vx`、`p.life--` 全部无时间差，`opts.lifetime = Math.round(lifeVal*60)` 又把「秒」硬换算成 60fps 帧数，动画循环 `animate(ts)` 只把 `ts` 用于 FPS 统计，从未做时间归一。

后果：同一「速度 2、寿命 1.5s」在 120Hz 屏上位移约为 60Hz 的 2 倍、寿命只有一半；UI 标注「1.5s」与实测不符。

### D-N217：连线在粒子 ≥300 时被静默禁用

`drawParticles()` 中 `if (opts.linkDist > 0 && particles.length < 300)`，而「星空」预设恰好 300 粒子 + linkDist 60、「星云」400 + 100 ⇒ 两个预设的核心连线视觉效果**恒不出现**，用户拖动 linkDist 也毫无反馈。

## 修复

### 1. 时间归一（dtFactor）

`animate()` 计算以 60fps 为 1.0 的归一因子：

```js
var __dtMs = prevTs ? Math.min(100, Math.max(1, timestamp - prevTs)) : 16.7;
prevTs = timestamp;
var dtFactor = __dtMs / 16.6667;
```

- `dt` 上限 100ms：切回后台标签页时不会出现粒子瞬移；
- 首帧按 16.7ms 基准，避免 dt=0 导致首帧静止。

`updateParticles(dtFactor)` 内全部运动量按因子缩放：

| 项 | 修复前 | 修复后 |
|---|---|---|
| 重力 | `p.vy += gravity*0.1` | `* dtFactor` |
| 鼠标力 | `p.vx += (dx/dist)*force` | `* dtFactor` |
| 阻力 | `p.vx *= 0.99` | `p.vx *= Math.pow(0.99, dtFactor)`（时间指数衰减） |
| 位移 | `p.x += p.vx` | `p.x += p.vx * dtFactor` |
| 寿命 | `p.life--` | `p.life -= dtFactor` |

寿命单位仍是「60fps 帧」（`lifetime*60`），除以因子后对应真实秒数恒定；死判由 `p.life === 0` 改为 `p.maxLife > 0 && p.life <= 0`（小数递减不会精确命中等号）。

### 2. 连线门槛 300 → `LINK_MAX = 500`

覆盖星空（300）/ 星云（400）两个预设；500 粒子约 12.5 万对连线仍可维持流畅。超出时**不再静默**，在画布信息条追加提示（中英按 `TBKit.util.isEn()` 三元）：

`| 连线已停用（粒子 > 500）` / `| link lines off (particles > 500)`
