### IT-N62 CSS 历史恢复后输出仍是旧值（中，已修复）
- 原问题：`loadH()` 仅回填输入、不重新计算或清除输出 ⇒ 恢复另一条历史后输入已更新、输出仍是上一次的结果，用户可能复制到错的 CSS。旧 localStorage 记录只有 60 字符截断摘要，回填后无法还原完整输入。
- 2026-11-06 复核（前半段已修）：`tools/it/css-minifier.html:492-510` 新历史保存完整输入并转义时间、操作和摘要，原「截断 + 摘要注入」问题已修。Node 执行页面实际函数确认新记录可完整回填，标签转为 `&lt;` 等实体。
- 修复（2026-11-06，后半段）：`addToHistory(action, input, op)` 新增 `op` 字段记录原操作（`beautify`/`minify`），`loadH(i)` 回填输入后按 `h[i].op`（旧记录回退按 `action` 含「美化」推断）调 `beautify()` / `minify()` 重算，结果区不再残留上一次输出。
- 证据位点：`tools/it/css-minifier.html` `addToHistory`（`:493-499`）、`loadH`（`:508-515`）、两处调用点（`:410`、`:428`）。
- 门禁回归用例（`scripts/verify_it_calc.js`，3 条）：① 历史存完整输入，长 111 字符的输入经 `loadH(0)` 恢复后尾部 token `x;background:#fff;border:1px solid #ccc;}` 仍在；② `op='minify'` 的历史恢复后重算，输出出现只在压缩形态存在的拼接串 `n62x{color:#abc}`（预置 `OLDOUT` 被覆盖）；③ `op='beautify'` 的历史恢复后走美化分支，输出 `#n62y {`（紧凑输入回显不含该串）。单跑 8/8 通过，全量门禁 229/229。

### IT-N65 User-Agent 解析器：Windows Phone 系统标记优先级误判（中，已修复）
- 原问题：`parseOS()` 把 `Windows NT 10/6.x/5.1` 各版本判断全部放在 `Windows Phone` 之前 ⇒ UA 同时含 `Windows Phone 10.0` 与 `Windows NT 10.0` 时输出「Windows 10/11」（桌面系统），未识别 Windows Phone。
- 2026-11-06 独立复核（前半段已修）：Node 执行页面实际 `parseBrowser()`、`parseOS()`，`Windows Phone 10.0 … Chrome/52.0 … Edge/15.15254` 已正确识别为 Microsoft Edge 15.15254 / Windows Phone；legacy `Edge/` 先于 `Chrome/` 判定亦正常。
- 修复（2026-11-06，后半段）：`parseOS()` 首行前置 `if(/Windows Phone/.test(ua)) return {name:'Windows Phone', icon:'📱'};`，其余 Windows 分支顺序不变。
- 证据位点：`tools/it/user-agent-parser.html:385-388`。
- 门禁回归用例（`scripts/verify_it_calc.js`）：混合 UA（含 `Windows Phone 10.0` + 末尾 `Windows NT 10.0`）经 `parse()` 后识别结果区出现「系统：Windows Phone」；修复前该串不存在（为「系统：Windows 10/11」）。单跑 5/5 通过，全量门禁 229/229。
