# 549 批：A/B 检验零转化、区间校验与深解 z 值（MS-N59 / MS-N60）

日期：2026-11-15　页面：`tools/marketing/marketing-ab-test-significance.html`

## 问题

- **MS-N59（高）**：深解算例「A 200/2000、B 260/2000 → z≈2.45，p≈0.014」与池化 z 检验不符。实算 `p̂=0.115`、`se=0.010088`、`z=2.9737`、双侧 `p=0.00294`。
- **MS-N60（高）**：输入守卫 `__D={"conversionsA":"conversionsA"}` 把 A 组转化数当成「分母不能为 0」，0 转化（冷启动常见）整页被拒绝，且文案把转化数说成分母。
- **区间校验缺口**：转化数未限制在 0 与访客数之间，150/100 会让合并比例 >1、标准误 NaN，结果被替换为「—」仍给「尚不显著」；两组合并率 0%/100% 时标准误为 0，`0/0` 同样无解释。

## 修复

1. **移除零值误判**：`__D` 置空，转化数 0 不再拦截；真正无定义的只有相对提升与标准误为 0 的情形。
2. **区间校验**：`cA<0 || cA>vA || cB<0 || cB>vB` → 「转化数须介于 0 与对应访客数之间」。
3. **标准误为 0**：`p̂=0%` 或 `100%` 时提示「两组合并转化率为 0% 或 100%，标准误为 0，无法进行 z 检验（两组转化率相同）」。
4. **相对提升**：`pA===0` 显示「不适用（A 组转化率为 0）」，z 检验与显著性照常输出。
5. **结果补充**：新增「z 值：2.974」一行；p 值 <0.0001 显示「<0.0001」，避免 0.0000 误导。
6. **深解重算**（`i18n/tools/content_deepdive.json`）：示例改为 `z≈2.974 / p≈0.003`；新增「A 组 0 转化 → z≈4.49 / p<0.0001 / 相对提升不适用」示例与 FAQ。
7. **英文态**：结果卡全部按 `isEn()` 三元化，并监听 `toolbox:langchange` 重算；EN 字典同步示例与 FAQ，补 term-link 碎片键「合并 / 转化率 / 为 0% 或 100%…」。
