# 第1239批交接：参观流线历史快照可回放通道数据

## 本批条目
- RL-K53（参观流线：历史快照只存有 id 的控件，通道距离/端点无法回放）

## 根因
`__visitor_routeSnap()` 仅采集 `input[id]/select[id]/textarea[id]`，通道行控件只有 `data-i/data-k` 无 id ⇒ 历史记录不含任何边数据；回放只按 id 回填展厅/起终点，`compute()` 读的全局 `edges` 仍是当前值 ⇒ 历史「回放/对比」失真。

## 改动（tools/museum/visitor-route.html）
- `__visitor_routeSnap()` 新增内部键 `__vrEdges = JSON.stringify(edges)`，把通道端点+距离纳入快照。
- 新增顶层 `__visitor_routeApplySnap(rec,rk)`：先解析 `__vrEdges` 恢复全局 `edges`（校验数组结构、过滤坏项）并 `renderEdges()`，再回填带 id 控件，最后 `compute()` 用恢复后数据重算；mount 回调改为调用此函数（便于 verify 共用取证）。
- `__visitor_routeExtras()`：`__vrEdges` 不作为展示列（从 keys 过滤），但 rec 携带它供回放；same 去重比较纳入 `__vrEdges`，杜绝「只改通道距离被误判为相同记录」。
- `__visitor_routeExport()`：`Object.keys(snap)` 同样过滤 `__vrEdges`，避免导出表格多出 JSON 内部列。
