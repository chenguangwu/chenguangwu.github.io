## 修复内容

### 1. 参数签名拦截（防「改参数后仍导旧图」）
两个页面均注入参数签名拦截三件套：
- `__xxxLastSig`（上次生成签名）、`__xxxSig()`（取输入拼签名）、`__xxxStale()`（签名不一致则返回提示串）
- 输入 id：text 页 `text/bgColor/textColor/size/radius`；emoji 页 `emoji/bgColor/size/radius`
- `downloadImg()` / `copyResult()` 开头先调 `__xxxStale()`，过期则清空 `lastURL` 并提示、直接 return
- `generate()` 末尾写 `__xxxLastSig = __xxxSig()`，确保签名与产物同步

> emoji 页曾因 `let lastURL` 与 `generate` 间夹了 `__exportFail` 函数，导致 apply326.py 的注入替换 MISS；已用 Edit 手动在 `__exportFail` 前补入三函数定义，避免下载/复制时 `__favEmojiStale` 未定义崩溃。

### 2. 文案名实不符「多尺寸 ICO/PNG」→「PNG」
工具实际只导出**单张 PNG**（`a.download='favicon.png'`、`canvas.toDataURL('image/png')`），所有「.ico / 多尺寸 ICO」均为虚假承诺。

- **text 页**：按钮「下载 ICO/PNG」→「下载 PNG」；formula-desc「导出多尺寸 PNG / ICO」→「导出 PNG」；deep-dive「多尺寸 favicon 可下载」→「PNG favicon 可下载」。
- **emoji 页**：
  - HTML 内联 meta/OG/Twitter/JSON-LD 三处「并导出多尺寸 ICO/PNG」→「并导出 PNG」（replace_all）
  - 深度解析示例 body 真源在 `i18n/tools/content_deepdive.json`（line 16462），改源后 `_build.py` 重建注入
  - intro 真源 `i18n/tools/design.json:1717`、`json/industry-design.json:692`、`json/tools.json:73066`「并导出多尺寸 ICO/PNG」→「并导出 PNG」
