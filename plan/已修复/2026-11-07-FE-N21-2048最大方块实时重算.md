# FE-N21 2048「最大方块」实时重算（新局重置 / 悔棋回退 / 不再被存档播种）

**分类**：11-文娱爱好 / 游戏 (fun/2048-game.html)
**类型**：功能缺陷（状态变量只增不减）→ 已修复
**处理日期**：2026-11-07
**复核方**：待复核

## 失败点（原缺陷）
`maxTile`（顶部「最大方块」、scores 标签页 `maxTile2`、终局弹窗 `finalMax`）只在合并成功时
`if(mergedVal > maxTile) maxTile = mergedVal` 刷新；`newGame()` 不重置、`undoMove()` 不回退、
`loadBest()` 用存档 `data.maxTile` 播种。导致：合并出 4 后撤销 → 仍显示 4；存档 1024 刷新开新局 →
顶部仍 1024；终局统计沿用历史值。

## 根因
`maxTile` 未与棋盘状态绑定，等于「只增不减的历史峰值」却无独立 best 语义，且新局/悔棋/读档三条路径都没
把它拉回当前棋盘。

## 修复位点
`tools/fun/2048-game.html`：
- 新增 `computeMaxTile()`：双重循环扫描 `board` 取最大值。
- `updateScore()` 每帧 `maxTile = computeMaxTile();` 再写 `#maxTile` / `maxTile2`（顶部分数、scores 页、
  终局 `finalMax` 全走此值，天然随当前棋盘变化）。
- `newGame()`：`maxTile = 0;` 防御性重置（随后 `updateScore` 按新棋盘重算为 2/4）。
- `loadBest()`：移除 `maxTile = data.maxTile || 0;` 与对应 DOM 写入，只读 `bestScore`，新局不再被历史存档污染。

## 证据 / 验证
- `scripts/_verify_fun_batch_fe_n21.mjs` JSDOM 两态锁：
  - 设含 4 棋盘 → updateScore → `#maxTile=4` ✅
  - 压全 2 历史 → undoMove → `#maxTile=2`（整棋盘回退）✅
  - newGame → `#maxTile` 为当前棋盘最大块（非 0）✅
  - localStorage 存档 maxTile:1024 → loadBest+newGame → 非 1024 ✅
  - **修复后 4/4 通过；HEAD 旧版 4/4 全 FAIL**（含 4 棋盘显示 0、undo 后停 0、newGame 停 0、loadBest 播种 1024），
    证明 bug 真实存在且本次修复可判别。
- 页面无输入框、harness 无法驱动键盘落子，故用 JSDOM 两态锁（同 FE-N18/N19），不强行塞 harness 逃生用例。
