## 根因与要点

- D-N59 是四层叠加：色块 `<input type="color">` 无 id ⇒ 历史快照只收 `overlay/cssOutput`；`#output` 只有预览 div ⇒ ResText 恒空 ⇒ 历史/数据表/CSV 全空；`__mesh_gradientPresets()` 是空函数 ⇒ 预设页签无按钮；恢复回调只写 input.value 后调 `generate()`，而 `generate()` 读的是全局 `colors` 数组 ⇒ 恢复不改配色。本批逐层补齐。
- 恢复回调从记录里按 `color0..color9` 顺序读取合法 HEX，≥2 个才重建 `colors`，再 `renderColors()` + `generate()`；`generate()` 内部会按新长度重算 `pos`，无需额外处理。
- 预设回调从 `color0..color2` 读回值后重建 `colors` 并 `renderColors()`，避免"预设只改输入框、主图不变"。
- D-N170 旧实现 `parseInt(value)||5` 把 `0`/空串静默当 5，且 `oninput` 每次按键重掷整批。现非法直接 return 并给出「请输入 1–50 之间的整数」，合法时清空提示并生成。

## 两条验证方法学教训（已同步 memory）

1. **元素存在性不能写进 verify 强锁**：`runCase` 的桩 DOM `getEl` 对找不到的 id 会造「游离桩」，`document.getElementById('x')?1:0` 恒真。本批最初为 D-N173 写了这类用例，旧码差分时它假绿（旧码 316/318 而非 315/318），已删除，改由 JSDOM 真实 DOM 解析验证。
2. **分次 `win.eval` 会割裂跨 script 的 `let` 作用域**：页面主体脚本与注入的 toolkit 脚本是两个 `<script>`，真机共享全局词法环境，但 JSDOM 分次 eval 时各自独立，导致探针改不到页面真实的 `colors`、恢复回调也写不到，出现"假失败"。改为把全部脚本拼成一次 eval 后，修好版 8/8 全过。后续验证跨 script 顶层 `let` 的页面一律用合并 eval。
