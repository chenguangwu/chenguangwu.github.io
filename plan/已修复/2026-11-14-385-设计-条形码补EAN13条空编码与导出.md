## 一、问题

页面宣称「输入数字生成 EAN-13 条形码**图片**」「可下载条码」，实际 `gen()` 只用 `genEAN13()` 造 12 位随机数 + 校验位，拼成一行等宽文本：

- 没有 EAN-13 的 95 位条空编码（L / G / R 码表、首位奇偶模式、护线）
- 没有 canvas / SVG 绘制，没有图片下载
- 没有数字输入框，用户无法指定要生成哪一条码

校验位算法本身是对的，但输出物不是条形码，无法用于商品标签。

## 二、修复

### 1. 真实 EAN-13 编码（ISO/IEC 15420）

```js
const EAN_L = {...};  // 左侧奇码 10 组 7 位
const EAN_G = {...};  // 左侧偶码 10 组 7 位
const EAN_R = {...};  // 右侧码 10 组 7 位
const EAN_PARITY = ['000000','001011','001101','001110','010011','011001','011100','010101','010110','011010'];  // 首位 → 左半区奇偶模式

function ean13Bits(code) {
  const parity = EAN_PARITY[+code[0]];
  let bits = '101';                                   // 起始护线
  for (let i = 1; i <= 6; i++) bits += (parity[i-1] === '1' ? EAN_G[code[i]] : EAN_L[code[i]]);
  bits += '01010';                                    // 中间护线
  for (let j = 7; j <= 12; j++) bits += EAN_R[code[j]];
  return bits + '101';                                // 终止护线，合计 95 模块
}
```

### 2. SVG 绘制 + 双格式导出

- `barcodeSvg(code, mw, h)`：把 95 位按连续 `1` 合并成 `<rect>`（左侧 11 模块静区），下方按「首位 / 左 6 位 / 右 6 位」三段定位 `<text>`；带 `role="img"` 与 `aria-label`。
- `saveBarcode(code, fmt)`：SVG 走 `Blob` + `URL.createObjectURL`；PNG 走 `Image` 载入 SVG data URI → canvas → `toBlob`。
- 下载按钮用事件委托（`data-dl` / `data-fmt`）绑定，不用内联 `onclick`。

### 3. 数字输入与校验位

- 新增 `#bcode` 输入框：12 位自动补校验位；13 位必须校验位自洽，否则**报错不静默改数**；留空保持原「批量随机」行为（此时数量固定 1 条）。
- `ean13CheckDigit` / `ean13Bits` / `barcodeSvg` 全部加参数防御（长度不符返回 `null` / `''`），顺带清掉了 harness 零参探针产生的 `errs`。

| 用例 | expect | 判别力 |
|---|---|---|
| 固定条码 | `完整数字: 6901234567892 \| 校验位: 2` | 旧码无输入框、只出随机数，永不命中 |
