## 失败点（原缺陷）

「对音频做变速处理，支持实时试听与微调」，但页面仅做 BPM/时长纯算术转换，无任何 `audio` / `AudioContext` /
`playbackRate` / 文件读取代码 —— 属能力虚标。

## 根因
页面定位为「BPM 与新时长换算器」，文案却按「音频处理工具」撰写；参考表虽列了速度比→音高 cents 关系，但
未对用户输入做计算，不能作为「已实现音频功能」的依据。按项目「不虚标、不对齐真实能力即收敛」原则处理。

## 修复位点（真源层 · 关键）
**meta/og/twitter/JSON-LD 描述与卡片描述由构建从 i18n 源注入，直接改 HTML 的 `<meta>` 是错层、会被 `_build.py` 每次重建还原。**
真源：`i18n/tools/music.json` 的 `convert-speed.zh-CN.intro`：
```
输入原曲BPM与目标BPM，计算速度比例并对音频做变速处理，支持实时试听与微调，用于翻唱移调、练琴跟拍等音乐创作与练习场景。
```
→
```
输入原曲BPM与目标BPM，计算速度比例与新时长，给出提速/降速百分比，用于翻唱移调、练琴跟拍等音乐创作与练习场景。
```
构建后该 intro 自动传播到：convert-speed.html 的 meta/og/twitter/JSON-LD 四处描述、`json/tools.json` 的 `d` 字段、`tools/music/index.html` 的 convert-speed 卡片描述（已 grep 确认三处均收敛，0 处「对音频做变速处理/实时试听」残留）。

页面 `<body>` 内简介 `<p>`（行 251，已是「用于 BPM 与新时长换算」）、功能特点/使用场景为 HTML 硬编码、不被构建重写，直接改 HTML 有效且与 i18n 文案口径一致。
