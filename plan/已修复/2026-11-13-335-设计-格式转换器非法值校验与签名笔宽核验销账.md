## D-N38 图片格式转换器非法值静默兜底（真修）

### 根因
`tools/design/image-format-converter.html` 的 `convertAll()`（约 996 行起）对尺寸输入采用静默兜底：
- 比例模式 `pct = parseInt(...) || 100`：0 / 空 / 非数字一律回落 100%；负值直透传，`w,h` 变负后被 `Math.max(1, w)` 夹成 1×1，无任何报错。
- 自定义模式 `if (cw > 0) w = cw`：0 / 负 / 空 / 非数字静默忽略，用户以为设置了自定义尺寸，实际按原图尺寸导出。
- 无上界校验，超范围值直接透传。

### 改动
在 `state.files.forEach` **之前**新增集中校验块（合法值路径与原码等价）：
```js
var cw = 0, ch = 0, pct = 0;
if (mode === 'custom') {
  cw = parseInt(document.getElementById('customWidth').value, 10);
  ch = parseInt(document.getElementById('customHeight').value, 10);
  if (!isFinite(cw) || !isFinite(ch) || cw < 1 || ch < 1 || cw > 10000 || ch > 10000) {
    ToolBox.showToast(__ifcT('自定义宽高需为 1–10000 的整数', 'Custom width and height must be integers between 1 and 10000'), 'error');
    return;
  }
} else if (mode === 'percent') {
  pct = parseInt(document.getElementById('percentScale').value, 10);
  if (!isFinite(pct) || pct < 1 || pct > 1000) {
    ToolBox.showToast(__ifcT('缩放比例需为 1–1000 的整数', 'Scale percent must be an integer between 1 and 1000'), 'error');
    return;
  }
}
```
循环体内改为直接用已校验的 `cw/ch/pct`，删除 `|| 100` 与 `if (cw > 0)` 静默兜底。校验在循环外一次完成，避免多文件重复弹提示。
- 范围与 HTML 控件一致：`customWidth/customHeight` min=1 max=10000、`percentScale` min=1 max=1000。
- 报错文案走页面既有 `__ifcT(zh,en)` 双语 helper（1279/1294 行），英文态零 CJK；`js/common.js` 的 `canvasExportError(w,h)` 仍保留做 canvas 面积上限兜底，与输入合法性校验互补。
- 改动仅在 `convertAll()` 内（点击「转换」才执行），不触及 verify 用例的输出区渲染路径。

## D-N148 signature-pad 笔宽核验销账（核心断言已失效）

### 核验结论：不新增修复代码
台账断言「滑杆 `oninput` 只改文本、不写 `strokeWidth`，画笔恒定 3px」在当前源码**已不成立**，属历史批次修复后未销账。证据链（静态源码核验 6/6 ✓）：
1. `id="strokeWidth" ... oninput="__spSetWidth(this.value)"`（158 行）— 滑杆绑定写值函数。
2. `window.__spSetWidth`（322-329 行）内 `strokeWidth = Math.max(1, Math.min(20, w));`，同步更新 `#widthVal` 并调用 `__spRenderInfo()`。
3. `startDraw`（404-410 行）以 `width:strokeWidth` 落笔，与 305 行 `let strokeWidth=3` 同属 298 起的 script 块，作用域贯通。
4. `__spApply`（674-676 行）设滑杆 value 后 `dispatchEvent(new Event('input',{bubbles:true}))`，会触发上述 `oninput` → `__spSetWidth` 写变量，工具栏预设同样生效。
5. `__spStrokePreset`（337-357 行）直接写 `strokeWidth` 并同步控件/标签。

### 顺手收口残留（唯一改动）
台账附带提到「1.5 对 `step=1` 还会被取整」：`SP_PRESETS` 中「钢笔细」预设 `strokeWidth:'1.5'`，而滑杆 `step="1"` 会把 1.5 规范化为 2，设置值与生效值不一致。改为 `'2'`，使名实相符（标签本身不含数值，无文案同步需求）。
