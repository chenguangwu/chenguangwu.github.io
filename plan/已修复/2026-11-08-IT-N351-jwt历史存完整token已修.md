# IT-N351 jwt-debugger 解析历史只存前 60 字符 —— 已修复，申请复核

## 缺陷原文要点

`addToHistory(token.substring(0, 60) + '...')` 只保存截断串，`loadHist()` 却把它当完整 token 回填给 `decodeJwt()`。任何长度 > 60 的真实 token 点历史后输入框得到残缺串，`token.split('.')` 段数错乱 ⇒ 恒显示「❌ JWT格式错误：应该包含3个用点分隔的部分」。解析历史功能整体不可用，且原始 token 从未落库。

## 修复位点

文件 `tools/it/jwt-debugger.html`：

1. `decodeJwt()` 末尾：`addToHistory(token.substring(0, 60) + '...')` → `addToHistory(token)`（历史存完整 token）。
2. `renderHistory()`：展示层再截断，`escapeHtml(x.token.length > 60 ? x.token.substring(0, 60) + '...' : x.token)` —— UI 观感不变（仍 60 字符 + 省略号），但存储完整。

`loadHist(i)` 无需改动：它本来就把 `h[i].token` 完整回填，只是过去拿到的是截断串。

## 判别力实测（jsdom 真机，非 harness）

harness 无法断言本条：该页 `token-input` 在「首屏自跑 / 兜底循环」阶段会被内置样例加载函数重置，且完整 token 只存在 JS 内存与输入框，DOM 里只以截断形式出现。改用 jsdom 加载真实页面执行：

```
[1] history[0].token is FULL  : true (len=129, 原长=129)
[2] 展示文本截断为 60+…       : true | "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiIxMjM0NTY3ODk..."
[3] loadHist 回填完整 token   : true
[4] 回填后解析结果            : ""（无 exp/iat 时无告警条目，属正常）
[5] 声明表含自定义字段        : true   ← 说明用完整 token 重新解析成功
[6] 声明表无裸 <img 标签      : true   ← 顺带验证 IT-N350 转义
```

修复前 [1]/[3] 均为 false（历史只存 60 字符 + '...'）。
