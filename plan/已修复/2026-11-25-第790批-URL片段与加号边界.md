# 第 790 批：URL 片段结构、查询加号边界与基础地址脱敏

- 受影响工具：`tools/it/url-params.html`、`tools/it/url-encode.html`、`tools/it/url-encoder-advanced.html`
- 关闭任务：
  - `URL参数编辑-片段标识被改写进查询参数.md`
  - `URL编码-完整地址空格转换.md`
  - `URL编解码-基础地址未纳入历史脱敏.md`
  - `高级URL编码-查询解码破坏参数边界.md`

## 修复内容

### 1. URL 参数编辑保留片段
- 新增 `splitUrlParts(raw)`：先按首个 `#` 切出片段，再在片段之前按首个 `?` 切出查询串，返回 `{base,query,hash}`。
- `calcTool()` 只解析 `parts.query`，不再把 `1#top` 当作参数值。
- `renderUrl()` 从当前输入重新拆分，重建 `base + '?' + query + hash`；无查询串时新增参数放在 `#` 之前，片段内的 `?` 原样保留，不编码成 `%23`。

### 2. 完整地址的空格/加号上下文
- `url-encode.html` 新增 `__urlQuerySlice(s, fn)`：只对 `?` 与 `#` 之间的查询串应用转换，路径与片段不动。
- 编码：完整 URL + 查询串空格转 `+` 时，先把查询串中的字面 `+` 转成 `%2B`，再把 `%20` 转成 `+`；路径/片段空格保持 `%20`，字面 `+` 保持原样。
- 解码：只把查询串的 `+` 还原为 `%20`，路径/片段中的字面 `+` 不当空格；`%2B` 解码回字面 `+`，可往返。
- 界面文案改为「空格在查询参数中编码为 +」，并补英文键 `Encode spaces as + in the query only`。

### 3. 基础地址历史脱敏
- `__url_encodeSnap()` 的 `__tbPrivate` 增加 `baseUrl` → `基础URL长度`，只记录字符数，不落盘原文。
- 历史清理增加 `baseUrl` / `基础URL长度` 旧记录的迁移：已存在的明文替换为「已清理（原基础地址未保留）」。
- 原有 `input` / `parseInput` / `builtUrl` / `output` 规则不变。

### 4. 高级查询解码保留参数边界
- `url-encoder-advanced.html` 的 Query 解码改为先按 `&` 切分、每项按首个 `=` 切键值，再分别 `decodeURIComponent`（`+` 先还原空格）。
- 新增 `#queryDecoded` 表格，逐行展示解码后的键和值；任一键/值解码后含 `&` 或 `=` 时显示警告：输出文本不再保留可安全重新解析的边界，以表格为准或重新编码。
- 编码模式或非 Query 解码会清空该表格，避免残留上次结果。
- 补英文键：`Query key` / `Query value` / 边界警告。
