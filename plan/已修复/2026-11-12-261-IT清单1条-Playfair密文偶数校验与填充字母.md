## 处理结果

### IT-N157 Playfair 密文未校验偶数长度，非字母输入会中断（高）— 真改

- 解密分支 `process()` 原先直接对清洗后的密文做 `.match(/.{1,2}/g).map(...)`：
  - 输入 `Z`（奇数长度）时第二个字符是 `undefined`，`processPair()` 拼出 `Tundefined` 写进结果区，步骤数与分组面板也照旧渲染；
  - 输入 `123`（清洗后为空）时 `.match()` 返回 `null`，`.map()` 抛 `TypeError: Cannot read properties of null (reading 'map')`，页面脚本中断。
- 现在解密前先清洗并显式校验：
  ```js
  const cleaned = text.toUpperCase().replace(/[^A-Z]/g, '').replace(/J/g, 'I');
  if(!cleaned || cleaned.length % 2 !== 0){
    const __msg = ((typeof TBKit!=='undefined'&&TBKit.util.isEn())
      ? 'Ciphertext must contain an even number of letters (Playfair works on 2-letter pairs).'
      : '密文需为偶数个字母（Playfair 按 2 字母分组），请检查输入。');
    // 清空 output / stepData / totalSteps / stepTotal，pairList 显示错误，showToast('error')
    return;
  }
  pairs = cleaned.match(/.{2}/g).map(s => s.split(''));
  ```
  关键点是**非法输入必须清空上一轮残留结果**，否则用户会误把旧密文结果当成新输入的解。
- `prepareText()` 的填充字母：明文两字母相同且为 `X` 时，旧实现仍补 `X` 生成 `XX` 同字母对（Playfair 规则不允许，且解密无法还原）。改为 `a === 'X' ? 'Q' : 'X'`，`prepareText('XX')` 由 `[['X','X'],['X','X']]` 变 `[['X','Q'],['X','Q']]`，加密输出由 `ZZZZ` 变 `VSVS`。
- 中英文错误提示走 `TBKit.util.isEn()` 三元 helper，无需进 `js/tool-i18n-en.js` 的 GEN_UI_MAP（非按钮标签）。
- 清单要求的「明确说明解密保留填充字符」已由页面 FAQ `为什么加密结果长度是偶数？` 中的「解密后需自行去掉这些填充并恢复断词」覆盖，本批未改 deep-dive 权威源。
