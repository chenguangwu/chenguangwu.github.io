## IRR 多根现金流仍误报区间无解

**失败点（原复核记录）**
- 页面：`tools/investment/irr-calc.html` 的 `calcTool()` / `irrVerdict`。
- 复现：五期现金流 `-100, 230, -132, 0, 0` 令 NPV=0 的根有两个（10% 与 20%），页面给出 IRR 10.00% 却同时显示「搜索区间内无 IRR 零点，下值无意义」，自相矛盾。

**根因**
- `noRoot` 仅用 `npv(-0.99,cfs)*npv(10,cfs)>0` 判断（两端点同号即判无解）。多根时两端点同号但区间内部存在根，导致误判无解，而 `irr()` 扫描实际已求得 10%。

**修复位点**
- `tools/investment/irr-calc.html` `calcTool()`：改为先取 `irrVal=irr(cfs)`，以 `noRoot=isNaN(irrVal)` 判定（无解即 `irr()` 返回 NaN）；`irrVerdict` 据此区分「无解」/「多根」/「唯一根」三态；结果行改用 `irrVal*100`。

**验证证据**
- `env -u NODE_OPTIONS node scripts/verify_it_calc.js irr-calc` 全绿（含新增用例）。
- 新增回归用例：注入 `-100,230,-132,0,0` → expect `可能存在多重 IRR`（修复前该串不出现、只配「无零点」提示）。默认 `-1000,300,400,500,200` 给 15.32% 与「解唯一」，不命中。

**判别力实测**
- 单文件判别器 `node scripts/discriminate_check.js verify_it_calc.js`：1333 用例已检、正确变红 1333、逃生项 0。本用例锚多根提示串，依赖注入的非常规现金流，默认态不含该串，强判别、零逃生；回退源码（noRoot 用端点乘积）后转红，确认门禁可捕获回归。
