# 第942批：默认值/预设精度高于 step 的字段细化步长

## 问题
沿用 929–941 批预设栏治理的思路继续扫描，发现一类真实的表单校验缺陷：
部分数字输入的**默认值或预设档小数精度高于 `step` 步长网格**，浏览器会判定
`stepMismatch`（原生 validity 校验不过），也说明 `step` 设置与字段实际取值精度不匹配。

典型：`astronomy/humidity-calculator` 大气压 `value=1013.25`，`step=0.1`，
预设 `1013.25 / 506.63 / 2026.5 / 3039.75` 均不在 0.1 网格上。

## 修复
按字段语义把 `step` 细化到能容纳默认值与全部预设档的最小十进制精度（不改变任何计算逻辑，
计算仍走 `parseFloat(value)`；仅影响箭头步长与原生校验网格）：

| 页面 | 字段 | 原 step | 新 step |
|---|---|---|---|
| astronomy/humidity-calculator | pAtm | 0.1 | 0.01 |
| meteorology/temp-pressure | pres | 0.1 | 0.01 |
| general/calc-stats-1 | x | 0.1 | 0.01 |
| chemistry/empirical-formula | a2 | 0.01 | 0.001 |
| forex/cross-rate | quoteUsd | 0.0001 | 0.00001 |
| automotive/voltage-2 | area | 0.5 | 0.1 |
| automotive/container-loading | pl | 0.05 | 0.01 |
| automotive/container-loading | pw | 0.05 | 0.01 |
| automotive/container-loading | ph | 0.05 | 0.01 |
| math/geometry-calculator | d | 0.1 | 0.001 |
| math/geometry-calculator | l | 0.1 | 0.001 |
| glass/snell-refraction | n1 | 0.001 | 0.0001 |
| food-processing/blanching-conditions | Dref | 0.01 | 0.001 |
| hydraulic/dam-stability | inF | 0.05 | 0.01 |
| hydraulic/flow-velocity | inNu | 0.01 | 0.001 |

共 12 页、15 字段。

## 不修（浮点误报，已验证）

  `119904200.00000001` 是 IEEE754 浮点误差（偏差 1.49e-08），非真实不合网格，跳过不改。
