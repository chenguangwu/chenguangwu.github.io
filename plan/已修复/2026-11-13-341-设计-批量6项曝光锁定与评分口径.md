## 1. D-N118 exposure-triangle：重复卡片 + 「锁定曝光」空按钮

**根因**
- 重复卡片：光圈分支 clamp 到 `na=0`（f/1.4）后 `neededSi = si + (na−ai)` 对 `da=−2` 与 `da=−1` 完全相同，两个分支各 push 一张同内容卡片。
- 空按钮：`🔒 锁定曝光` 只绑 `calc()`，无任何锁定状态。

**改动**（`tools/design/exposure-triangle-calculator.html`）
1. 两个循环（等效卡片 + CSV 行）各加 `Set` 按档位去重：`!__usedA.has(na)` / `!__usedI.has(niso)`。
2. 新增锁定状态与补偿：
```js
var __lockEv=null;                       // 顶层 var（页面作用域，clicks 可读写）
function __curIdx(){ ... }               // 统一按 value 反查三档位（与 calc 同口径）
function __syncLockEv(){ ... }           // 锁定期间 ±EV / 套预设时同步基准，避免补偿把操作抵消
function toggleLock(){ ... }             // 锁定/解锁 + 按钮文案（🔒 锁定曝光 / 🔓 解锁曝光 (EV x.x)）
```
3. `calc()` 开头锁定分支按 `t = N² / 2^(EV + log2(ISO/100))` 反推最近快门档，写回 `shutter.value`（不是 `selectedIndex`，与页面既有 `value` 反查口径一致）。
4. `changeExp()` / `applyExpPreset()` 在 `calc()` 前调 `__syncLockEv()`。

**验证**：默认 f/4·1/60·ISO200 锁 EV 8.9 → 改 f/8 后快门自动 1/15；锁定后 −1EV 快门索引 −1、+1EV 复原；光圈 f/2 时 `#equiv` 只出现 1 张 f/1.4 卡片。

## 5. D-N213 generator-38：完整度评分下限 60 与文档「全空 20」不符

**根因**：任务类型/输出格式是两个 `<select>`，恒有值恒 `ok:true`，故最低 3/5=60。
**改动**
1. 两个 select 首项加空值占位（`<option value="">请选择…</option>`）。
2. `prompt` 拼接加防护：任务为空时输出 `【请补充任务类型】`、格式为空时 `【请补充输出格式】`。
3. 算例文案同步（**改 JSON 源，不改 HTML 产物**）：`i18n/tools/content_deepdive.json` 与 `i18n/tools/en/design/generator-38.json` 中「目标对象留空时完整度降为 60」改为「降为 80（缺上下文）；若任务与输出格式也未选，仅角色计入已填、降为 20」，`_build.py` 重建后中文页 / 繁中页均生效、旧文案 0 处。

## 踩坑记录（供后续同类修复参考）

1. **harness 下 `selectedIndex` 与 `value` 不同步**：页面既有 `calc()` 早就改成「按 value 反查档位」，锁定逻辑若读 `selectedIndex` 会拿到错误档位（实测 EV 被算成 10.0 而非 8.9）。凡新增档位换算一律走 `value` + `idxOfNum`。
2. **顶层状态必须 `var`**：`let __lockEv` 在页面作用域 eval 下不可见（`idxOfNum: Cannot read properties of undefined`），改 `var` 后正常。
3. **失败输出只截前 300 字**：`__tbProbe` 常在截断区外，诊断时把探针串临时写进首个采集元素（如 `#aperture.value`）才看得到真实值。
