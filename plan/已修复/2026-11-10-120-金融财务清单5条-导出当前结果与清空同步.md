## 二、失败点 → 根因 → 修复位点

### 1. F-N102 / F-N106：导出的是历史表，不是结果明细

两页的 `__*Export()` 都是同一模板：先 `__*Extras(true)`，再 `TBKit.util.exportTable('#<page>Table', ...)`，而 `#<page>Table` 是 TBKit 自动历史表（首次使用为空），结果区 `#resultBox` 里的「每年取息现金流」「分档计算明细」完全没进 CSV。

**裁断**：清单建议「新增 `#<page>Detail` 表再导出该表」。本批选择**导出当前结果区的逐行明细**而非新增表，理由：① 不改任何可见输出 ⇒ verify 零漂移、无需重算/重复实现；② 对 `simple-interest` 的 annual / simple 两种模式、`tax-bracket` 的任意档位都成立，不存在「某些模式没有 Detail 表」的空洞；③ 结构化拆分（各档金额/税率、各年现金流）本就在结果区，逐行导出等价且不引入第二份数据源。

```js
var box=document.getElementById('resultBox');
var rows=[['序号','结果明细']];
var nodes=box.querySelectorAll('p, tr');   // p 段落 + 表格行
// TR 的 th/td 用 ' | ' 拼成一行；p 取 textContent
if(rows.length>1) TBKit.export.csv('<page>-detail.csv', rows);
```

导出前仍 `__*Extras(true)`，保证节流中的最后一次输入同步进历史。文件名由 `<page>.csv` 改为 `<page>-detail.csv`，与「历史表」语义划清。

### 2. F-N103：清空动作与可见状态不一致

`clearAll()` 原只清 3 个输入与 `#resultBox`，不清 `#simple_interestTable` / `#simple_interestDiff` / `#simple_interestChart` / `#simple_interestHist`，也不清 TBKit 历史 ⇒ 结果区已显示「请输入数据」，下方仍是上一次计算记录（复核方八类退回根因「清空残留」同源）。

修：一并清空四个容器，并调 `TBKit.history.clear()`（try/catch 保护，harness 无 TBKit 时跳过）。**不改结果区占位文案**，避免既有用例漂移。

## 五、踩坑

1. **第 3 次踩「前缀重复 `__`」**：容器 id 是 `simple_interestTable`，函数前缀是 `__simple_interest`；用同一个变量拼 `#{prefix}Table` 会生成 `#__simple_interestTable`，补丁 count=0。取来的前缀先看内容再决定是否补下划线。
2. **harness 没有 TBKit 实例**：`verify_*.js` 是自研 stub，页面所有 `typeof TBKit === 'undefined'` 守卫都会跳过；涉及导出/历史/趋势的行为必须交给真机 JSDOM，别在 harness 里硬造。
3. **「导出明细」类缺陷不要急着新增第二份数据源**：优先导出结果区已有的结构，既不改可见输出、也不重复计算，verify 零漂移；清单里的「新增 #Detail 表」只是方案之一。
4. **清空要连历史一起清**：只清可见容器，下次 `Extras` 重绘又会把旧记录带回来。
