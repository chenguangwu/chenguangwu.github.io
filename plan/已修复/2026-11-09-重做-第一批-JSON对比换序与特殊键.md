## 失败点 → 根因 → 修复位点 → 证据

### IT-N396：完全逆序数组被误报多条修改

- 失败点：勾选「数组按内容匹配」，`{"tags":["a","b","c"]}` 对 `{"tags":["c","b","a"]}` 实测产生 2 条 mod，但两侧内容多重集完全相同，应为 0 处差异。
- 根因：`deepDiff()` 的 arrayMatch 分支先用 `jdLcsPairs()` 对齐「顺序也能对齐」的相同元素；完全逆序时 LCS 长度只有 1，剩余元素虽内容相同却被 `restA[t]` / `restB[t]` 按下标硬配对递归，报成 mod。
- 修复位点（`tools/it/json-diff.html` `deepDiff()` arrayMatch 分支）：LCS 配对后，先用 `Map<规范键, 下标桶>` 对 `restB` 建池，遍历 `restA` 按 `jdKey` 做**多重集抵消**（相同内容一一配对、双方都不再进入差异列表）；只有配不上的 `pendingA` / `pendingB` 才按顺序递归比对，多出的报 del / add。规模保护（LCS 返回 null 时退回按下标对齐）保持不变。

### IT-N397：`__proto__` 自有键在规范化时丢失导致漏报

- 失败点：`{"a":{"__proto__":{"a":1}}}` 与同处值为 2 的对象在简单模式输出「无差异」；数组元素中的同类变化也漏报；顶层 `__proto__` 键同样漏报。
- 根因（三处同类问题）：
  1. `jdCanon()` 用 `const o = {}`，`o['__proto__'] = jdCanon(v[k])` 触发原型 setter，该键不会成为自有属性，`JSON.stringify` 直接丢键 ⇒ 比较键恒为 `{}`；
  2. `simpleDiff()` 的去重表 `const seen = {}`，`seen['__proto__']` 命中 `Object.prototype` 为 truthy ⇒ 该顶层键被去重逻辑整个跳过；
  3. `countSame()` 用 `k in b` 走原型链，与既已修过的 `deepDiff` 的 `hasOwnProperty` 口径不一致。
- 修复位点：
  1. `jdCanon()` 改用 `Object.create(null)`；
  2. `simpleDiff()` 的 `seen` 改用 `Object.create(null)`；
  3. `countSame()` 改 `Object.prototype.hasOwnProperty.call(b, k)`。
  `Object.create(null)` 仍按键名 `sort()` 排序，键序不同的等价对象依旧判为相同（用例 6/6 护栏验证）。
