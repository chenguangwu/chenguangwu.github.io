## 一、IT-N418 10 位一律判「✅ 标准 10 位 NANP 号码」

**缺陷**：`digits.length===10` 分支无条件追加 `✅ 标准 10 位 NANP 号码`，前面算出的 `AREA_CODES[areaCode]` 结果完全没进判定；`999 / 000 / 111` 这类区号照样通过，与「地区：未知/非 NANP 区号」自相矛盾。

**修复**：新增 `__aeNpaErr(npa)` / `__aeNxxErr(nxx)` 两条结构校验（与第 21 批 msisdn-lookup 的 NANP 口径一致）：

```js
if(!/^[2-9]\d\d$/.test(npa))  → ❌ 区号 NPA 首位须为 2–9
if(/^\d11$/.test(npa))        → ❌ N11 是保留服务码，不能作区号
if(npa[1]==='9'&&npa[2]==='9')→ ❌ N99 是保留未分配区号
if(NPA_RESERVED.has(npa))     → ❌ 该码是保留 / 非地理区号
// NXX 同样校验 [2-9]XX 与 N11
```

10 位分支改为**三层结论**，查表结果真正参与判定：

| 条件 | 结论 |
|---|---|
| NPA/NXX 结构错误 | ❌ 具体错误，不给有效结论 |
| 结构合法、区号未收录或为保留码 | ⚠️ 结构合法但归属地未收录，**不判标准有效** |
| 结构合法且区号已收录 | ✅ 标准 10 位 NANP 号码 |

「区号表不全」与「号码结构非法」分开处理，不把未收录误升级成无效，也不把结构非法放行。

## 二、IT-N419 `+1` 国际号码被当成区号 121

**缺陷**：`raw.replace(/\D/g,'')` 保留全部数字后直接取前 3 位。`+1 212-555-0100` → `12125550100`（11 位）→ 区号 `121`、提示「⚠️ 通常为 10 位」，排查方向被带偏。

**修复**：

```js
let digits=raw.replace(/\D/g,'');
let stripped=false;
if(digits.length===11&&digits.charAt(0)==='1'){ digits=digits.substring(1); stripped=true; }
```

判据用「11 位且首位 1」而非是否含 `+`：NANP 本地号首位必为 2–9，因此这种形态必是国家码，不会误剥合法的 10 位号码；不带 `+` 的 `1 212 555 0100` 同样正确。结果区新增「国家码：+1（已剥离，按 10 位 NANP 号码解析）」一行，让剥离动作可见、可断言。

## 三、IT-N420 `456 Reserved` 被判「✅ 区号有效」

**缺陷**：3 位分支只做 `if(AREA_CODES[areaCode])` 存在性检查，`'456':'Reserved'` 也算命中。

**修复**：不止删一条数据，改为**规则化**拦截，防止后续再加入同类 Reserved 条目时复发：

```js
const NPA_RESERVED = new Set([
  '456','800','833','844','855','866','877','888','900',   // 保留 / 免费 / 付费非地理 NPA
  '211','311','411','511','611','711','811','911'          // N11 服务码
]);
const reserved = NPA_RESERVED.has(areaCode) || /reserved/i.test(String(hit||''));
```

3 位输入的判定顺序：`__aeNpaErr` → `reserved` → 已收录 → 未知。`456` 现输出「❌ 未知区号（456 是保留 / 非地理区号，未分配为地理区号）」；`800` 与 FAQ「800/888 为非地理区号」口径对齐。
