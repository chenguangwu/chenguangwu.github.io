## 根因（真实功能回归，非噪声）
`_build.py::normalize_tool_h1()` 用全局正则
`_H1_BLOCK_RE = re.compile(r'(<h1\b[^>]*>)([\s\S]*?)(</h1>)')`
扫描**整个 HTML 文本，包含 `<script>` 内容**。markdown-editor 的渲染器在 script 里写了字符串字面量 `'<h1>$1</h1>'`（第211批 N290 把 `#` 改渲染 h1 时引入）：
- 该字面量被当成一个真实 h1 块，`inner` = `$1`；
- `_h1_text('$1')` 无中文 → 命中「h1 无中文，替换为中文工具名」分支（606-608 行）；
- 被替换成 `esc_html_py(cand)` = `Markdown编辑器`。

**后果**：所有 markdown 一级标题会渲染成固定的「Markdown编辑器」，`$1` 捕获组丢失；且每次 build 都会重现，HEAD 源码与线上产物不一致。第211批的 N290 修复在 build 后被静默破坏。

## 改动（根因修复，仅 `_build.py`）
在 `normalize_tool_h1()` 入口标记 `<script>/<style>` 块区间，① 错配闭标签与 ②③④ h1 块处理一律跳过落在其中的匹配：
```python
    skip_spans = [(m.start(), m.end()) for m in
                  re.finditer(r'<(script|style)\b[^>]*>[\s\S]*?</\1>', html_str, re.I)]

    def _h1_in_skip(pos):
        return any(s <= pos < e for s, e in skip_spans)
```
- ① 循环：`if _h1_in_skip(m.start()): i = m.end(); continue`
- ②③④ 循环：`if _h1_in_skip(b.start()): continue`

真实页面里的 h1 都不在 script/style 块内，故对既有 5000+ 页的 h1 规范化行为**零影响**；只拦下把 JS/CSS 字符串字面量误当标题的误伤。全站仅 `markdown-editor.html` 一处 script 含 `<h1>` 字面量（grep 确认 1 个页面）。
