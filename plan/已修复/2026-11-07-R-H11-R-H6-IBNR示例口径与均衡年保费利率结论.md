# 2026-11-07 · 金融-保险（R-H11 + R-H6）：IBNR 深挖示例口径、均衡年保费利率结论

## 条目（`plan/categories/02-金融财务/insurance.md:171 / :132`）
- **R-H11**（中）：`tools/insurance/ibnr-reserve.html` 主计算只接受「已报案赔款 + 发展因子」，按 `IBNR = 已报案 ×(因子 − 1)` 计算；深度解析与指南却用「已发生 400 万、已报告 320 万 → IBNR = 400−320 = 80 万」举例，引入本页不存在的「已发生」输入。默认 400 万 / 1.25 的页面结果为 IBNR 100 万、最终赔款 500 万，示例相差 20 万且无法复核。
- **R-H6**（中）：`tools/insurance/level-premium-life.html` 公式框写「利率越高年金现值系数越小、均衡年保费越高」，`计算说明` 第 2 条却写「年保费随利率上升而下降」，两句方向相反。实跑（净趸缴 85000、n=20）：i=3% → P=5,713.34，i=6% → P=7,410.69，实际随利率**上升**。同页图表标题写「随缴费年数反比下降」，数学上也不准确（年金因子对 n 非线性，曲线递减并趋饱和）。

## 根因
1. 深挖示例不是页面手写的：`_build.py` 从 `i18n/tools/content_deepdive.json` 重建工具页 deep-dive 段；guide 页由 `scripts/gen_industry_guides.py` 读同一真源生成，但**当前 guide 静态产物不由 `_build.py` 重建**。只改 HTML 会被构建回退，只改 JSON 则 guide 静态页残留旧文。
2. 英文态靠「键 = 中文源串」查表：`i18n/tools/en/insurance/ibnr-reserve.json` 与 `i18n/guides/ibnr-reserve-guide.json`（正文键带前导「：」）必须**逐字**同步，否则英文态会泄漏中文。
3. 历史生成脚本 `scripts/apply_insurance.py`（深挖真源）、`scripts/gen_insurance_tools.py`（notes）仍存旧串，重跑会把修复写回；`i18n/tools/insurance.json` 的 `note` 数组（zh-CN 与顶层各一份）也是同一份元数据的副本。
4. `计算说明` 的 note 是页面静态 `<li>`，行业 JSON / 生成脚本 / 英文 map 各存一份，属于典型的「多源副本不同步」。
