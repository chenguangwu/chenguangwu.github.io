## 1. SF-N62 零体重变化被称为增重、错误提示与输入矛盾
- 失败点：70→70 kg、饮水 500 mL 同时称「净增重」与「净减轻 0.00 kg」；70→69 kg、排尿 2000 mL 时页面反称「运动后体重不低于运动前」。
- 根因：`netLoss<=0` 把「未变」与「增重」合并；`sweatKgRaw<=0` 分支提示文案写死增重，未区分体重实际下降但补液/排尿记录不自洽。
- 修复位点：`tools/sports/estimate-35.html` — ① 错误提示按 post/pre 三分支生成准确描述并列出修正出汗量；② zone 增 `netLoss===0` 分支「体重未变」；③ 明细体重差三分支；④ 补液建议区补「体重未变」分支。
- 证据：`verify_sports_calc.js` 新增两例，expect「体重未变 / 0.00 kg（体重未变）」与「实际体重已下降 / 修正出汗量为 -1000 ml」，均通过且单文件判别力 0 逃生（默认态不含）。

## 2. SF-N120 总 ACE 被错误限定为一发得分
- 失败点：ACE 8、一发得分 0、二发得分 8 被「一发得分应不少于 ACE」误拦。
- 根因：把总 ACE 全部强行计入一发得分，忽略 ACE 可来自二发。
- 修复位点：`tools/sports/wangqiudefenlvfenxi.html` — 校验改为 `p1w+p2w >= ace`（总 ACE 不超过一发+二发得分之和），info-box 口径同步改为「ACE 计入发球得分、可来自一发或二发」。
- 证据：新增正向用例（p1w=0/p2w=8 → 一发得分率 0.0%、二发得分率 20.0%）与负向用例（p1w=p2w=0/ace=8 → 新错误提示）；旧用例 expect 同步改为仍生效的「二发得分不能超过二发數减去双误数」越界锚。sports 228/228 通过。

## 3. SF-N34 末次剂量浮点噪声及补液时程自相矛盾
- 失败点：3 kg×1.3 末次显示 `150.00000000000045 mL`；250 mL×16 次仍标「间隔 15–20 分钟」，与页面「2 小时内补齐」冲突。
- 根因：`A*B*1000` IEEE754 尾数未归一；次数/时长与固定时程硬断言并置，未做自洽性核对。
- 修复位点：`tools/sports/jianzhong-tuoshui-buye-kongzhi.html` — 总量与末次剂量按 0.001 mL 归一；label 去掉「间隔 15–20 分钟」硬断言；结果区新增排程自洽性提示（16 次按 15–20 分钟间隔至少 225–300 分钟，明确声明不构成补液方案、须运动医学专业人士确认）。同步改静态 formula-desc、dd-example 及 `i18n/tools/content_deepdive.json` + `i18n/tools/en/sports/jianzhong-tuoshui-buye-kongzhi.json` 英文映射，删去「2 小时内补齐/2 小时内补回」的绝对表述。
- 证据：新增用例 expect「末次 150 mL（共 16 次）」「225–300 分钟」；原 3.90 L / 3900 mL 用例保持通过。**专业阈值未擅自改动**，仅按复核要求消除自相矛盾并标注需专业裁断。

## 4. SF-N35 两分命中仍可大于两分出手
- 失败点：总命中 10、总出手 10、三分出手 10、三分命中 0 仍输出 FG%=TS%=1.000「顶级高效」。
- 根因：守卫只比各分项命中/出手，缺 `fgm−tpm <= fga−tpa`。
- 修复位点：`tools/sports/lanqiumingzhonglv-lanbanxiaolv.html` — 守卫补该不等式（含 1e-9 容差），错误文案补两分口径。
- 证据：新增用例 expect「两分命中（总命中−三分命中）」，默认态不含；原「⚠ 命中数不能大于对应出手数」用例仍通过。

## 5. SF-N17 正数最终体重四舍五入为零
- 失败点：30 kg、目标 29.99 kg ⇒ 0.01 kg 显示为「预计最终体重 0.0 kg」。
- 根因：`(w-target).toFixed(1)` 对 <0.1 的正数归零。
- 修复位点：`tools/fitness/jianzhinengliangquekoujisuan.html` — `0<最终体重<0.1` 时用三位小数并注明「正值按三位小数显示，避免四舍五入成 0.0 kg」。安全阈值未擅自裁断。
- 证据：新增用例 expect「0.010 kg（正值按三位小数显示」，fitness 98/98 通过、判别力 0 逃生。

## 6. SF-N75 以数字开头的附注或数字姓名被当作成绩
- 失败点：`张 三,88,2次测试` 被解析为姓名「张 三 88」/成绩 2；`007,缺考` 把姓名 007 当作成绩 7。
- 根因：`parseFloat` 接受数字前缀；成绩列允许落在第 1 列。
- 修复位点：`tools/sports/stats-11.html` — 引入完整数字字段正则 `NUM_FIELD`，成绩取第 2 列及之后的最后一个完整数字字段；成绩列之后若仍有完整数字字段则判歧义；无成绩列（如 `007,缺考`）记为待人工核对行，结果区明确列出「格式不明确、未纳入统计」及示例，不静默纳入。
- 证据：新增两例 — `张 三,88,2次测试 / 李四,90` expect「平均分： 89.00」（旧实现 46.00）；`007,缺考 / 张三,88` expect 歧义提示串。既有含空格姓名/末尾附注用例保持通过。

## 7. 目标配速的配速字段仍显示 60 秒
- 失败点：目标 4:12:50、全马匀速，平均与分段配速显示 `5'60"/km`。
- 根因：`fmtPace()` 仍先取余再四舍五入，与已修的 `fmtTime()` 口径不一致。
- 修复位点：`tools/fitness/pace-calculator.html` — `fmtPace` 先 `Math.round(secPerUnit)` 整体取整再分解，并拦截非有限值返回 `—`。
- 证据：新增用例 clicks 注入 4:12:50，expect「所需平均配速 6'00」（避开默认态 4'59 的裸串 `6'00` 逃生，首轮曾判逃生并已收紧）；fitness 判别力复跑 0 逃生。
