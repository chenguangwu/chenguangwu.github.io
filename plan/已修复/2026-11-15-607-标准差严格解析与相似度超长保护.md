# 607 批 · 标准差严格解析与文本相似度超长保护（2026-11-15）

## 修复清单（2 页 / 2 个真缺陷）

### `tools/it/standard-deviation.html` — IT-N433 非法数据被静默吞掉
- 旧 `parseData()` 是 `split → parseFloat → filter(!isNaN)`：`12abc` 被截成 `12`、`abc`/表头整段丢弃，n 少算但结果照常输出，用户误信。
- 新实现：整串十进制正则校验（含科学计数法、正负号、小数点），非法 token 收集为 `bad`；`calculate()` 发现 `bad` 即在结果区列出并早退。token 经 `__sdEsc()` 转义后才进 `innerHTML`（用户输入永不直接拼接），文案中英双态走 `SD_EN`。

### `tools/it/text-similarity.html` — IT-N366 长文本逐键重建全尺寸 DP 矩阵
- `levenshtein()` / `computeDiff()` 各分配 `(m+1)×(n+1)` 矩阵，且 `autoCalc()` 绑在 `oninput`；8000×8000 字符约 1.6GB，低内存设备直接 OOM。
- 新实现：`calculate()` 开头对 `lenA × lenB > 1000000` 提前返回，隐藏旧结果避免残留误导，并给出中英明确的「文本过长」提示。
- 说明：本批采用「上限 + 明确提示」而非重写成线性空间 Myers；彻底的内存优化（滚动数组 + ops 栈）留后续专门批次，届时同步移除上限。

## 验证
- `verify_it_calc.js` 新增 2 条判别性用例：非法 token `12abc` 必须出现在结果区提示里；超长文本必须触发「文本过长」toast。
- 轻量门禁：单页 verify + 全量 IT verify + `_build.py` + `_test_static.py`。

## 复核要点
- 真机：标准差输入 `1, 12abc, 3` 应显示非法数据提示且不出 σ；输入 `0x10` 同样报错（旧实现会当成 16）。
- 真机：文本相似度两段各 1100 字符，应明确提示过长、旧结果不残留；短文本计算不受影响。
- 既有用例（`1,2,3,4` → 1.291/1.118、`1,3,5,7,9` → σ=2.828、`1\n2\n3` → σ=0.816）全部保持通过。
