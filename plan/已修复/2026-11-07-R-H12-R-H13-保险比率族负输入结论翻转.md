# 2026-11-07 · 金融-保险（R-H12 + R-H13）：费用率页 10⁻⁹ 兜底伪倍数、综合成本率页负赔款判「承保盈利」

## 条目
- **R-H12**（中，`plan/categories/02-金融财务/insurance.md:164`）
  `tools/insurance/expense-ratio.html` 只用 `max(费用, 1e-9)` 防除零，未拦截负费用。保费 1000 万、费用 −250 万时费用率 −25.00%，而「保费与费用比」因分母被换成 1e-9 输出 **10000000000000000.000**，两个指标方向完全冲突。
- **R-H13**（高，同文件 `:169`）
  `tools/insurance/combined-ratio.html` 的输入守卫只判空与分母为 0，未限制赔款/费用非负。保费 1000 万、费用 250 万、赔款 −650 万时 CR = **−40.00%**，页面仍按 `CR<100` 判「承保盈利」，承保利润率 **140.00%**，承保结论被完全翻转。
- **顺带修（同文件「留存优化」）**：两页「示例 2× / 示例 0.5×」预设对分子分母同比例缩放，三档结果完全相同（费用率恒 25.00%、综合成本率恒 90.00%），用户点击看不到任何变化。

## 根因
1. 两页 `calcTool()` 都在 `__tbInputGuard`（只判空 / 分母为 0）之后直接代入 `num()`，而 `num()` 是 `parseFloat(...) || 0` —— 负数是合法有限值，一路照算；没有任何业务符号约束。
2. `expense-ratio` 的 `Math.max(e, 1e-9)` / `Math.max(p, 1e-9)` 把「分母无定义」伪装成「分母极小」，于是负费用同时产出负费用率与 1e16 量级的正倍数；费用恰为 0 时同样产出 1e16。
3. `combined-ratio` 把「承保结论」写成 `cr<100?'承保盈利':'承保亏损'` 的裸比较，没有前置有效性门槛，负输入可直接把结论翻转为盈利。
4. 两页 `__*Extras()` 的早退条件是 `!isFinite(num(...))` —— 负数是有限值，**不会早退**，于是旧明细表被刷新成非法结果、历史照记；导出又固定 `exportTable('#…Table')`（历史摘要表），错误态仍可导出。
5. 预设是模板统一生成的「2× / 0.5×」同比例缩放，对该页的**比值型**结果天然无影响。
