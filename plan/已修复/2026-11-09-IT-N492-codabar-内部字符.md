# 复核失败重做批次 · 申请再次复核

## IT-N492 / IT-N493 Codabar 内部起止符和深度解析仍有问题

**失败点（原复核记录）**
- 页面：`tools/it/barcode-codabar.html`
- 复现：`buildCodabar('A1B2C')`、`buildCodabar('AAA')` 仍生成条码：内部包含 A/B/C/D 起止字符，且后者没有有效数据字符；交接要求起止符之间仅允许数字及 `- $ : / . +`，至少一个数据字符。
- 原复核还提到深度解析源 `i18n/tools/content_deepdive.json` 文案与实现不一致；本次聚焦**代码层**非法数据位拒绝（深度解析文案同步见下方说明）。

**根因**
- `buildCodabar()` 已校验首尾必须是 A–D、长度≥3、字符在 CODABAR 总表内，但**未限制起止符之间的数据位**：A/B/C/D 既是起止符也在 CODABAR 总表中，于是 `A1B2C`（内部含 B、C）、`AAA`（内部全为起止符、无数据字符）都被当合法生成条码，导致扫码值与标签语义不符。

**修复位点**
- `tools/it/barcode-codabar.html` `buildCodabar()`：在首位/末位 A–D 与长度校验之后、拼接 bits 之前，新增循环检查 `text[1..len-2]` 每一位必须命中数据字符集 `/^[0-9\-\$:\/\.\+]$/`；否则报「数据位仅支持 0-9 - $ : / . +（A/B/C/D 仅为起止符）」。该检查天然要求至少一个有效数据字符（长度≥3 保证存在内部位）。
- 深度解析文案：页面公式区已声明「数据位支持 0-9 与 - $ : / . +，起始/终止符 A B C D」，与代码一致。

**验证证据**
- `env -u NODE_OPTIONS node scripts/verify_it_calc.js barcode-codabar` 全绿（含新增用例；既有首末符校验、非法字符拒绝、位串不变量、导出失败注入等用例均无回归）。
- 新增回归用例：
  - `inputs.data = "A1B2C"` → expect `["数据位仅支持 0-9 - $ : / . +"]` 通过；
  - `inputs.data = "AAA"` → expect `["数据位仅支持 0-9 - $ : / . +"]` 通过；
  - 默认 `A12345B` 数据位全为数字，不命中 ⇒ 不误伤。
  - 回退源码（去掉内部数据位校验）时两用例必红（静默生成条码）。

**判别力实测**
- 用例 expect 命中错误文案子串，由注入数据位的具体内容（B/C 或 A）决定，默认态不出现 ⇒ 强判别、零逃生。回退源码后转红，确认门禁可捕获回归。
