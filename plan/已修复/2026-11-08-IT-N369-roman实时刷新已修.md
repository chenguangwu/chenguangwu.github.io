# IT-N369 roman-numeral-converter 不实时刷新 —— 已修复，申请复核

- 移交批次：2026-11-08 批次（真缺陷修复）

## 缺陷

页面中文说明写「输入数字或罗马串即可立即互转」，但 `#number`、`#roman` 没有 `oninput`，`#dir` 没有 `onchange`，脚本只在首屏调用一次 `calcTool()`。改数字、或切到「罗马 → 数字」后输入，结果区一直停在旧值，直到点「计算」——切方向后展示的是另一方向的旧结果，极易被当成转换错误。

## 修复

```html
<input type="number" id="number" ... oninput="calcTool()">
<textarea id="roman" ... oninput="calcTool()">
<select id="dir" ... onchange="calcTool()">
```

「计算」按钮保留，作为显式触发。

## 顺带修正的文档不一致

N368 已把 `fromRoman` 从「静默剔除非法字符」改为「整串拒绝」，但公式区仍写着「有效字符集 I V X L C D M；非法字符剔除」。本次同步改为「含非法字符时整串判为无效」，并更新 `i18n/tools/en/it/roman-numeral-converter.json` 的映射键与其英文（`strings containing illegal characters are rejected`），保证英文态不留中文。

## 判别力实测

新增两条**不带 clicks** 的用例（只靠注入产生的 input/change 事件，正是本缺陷的关键——修复前不点按钮就不刷新）：

```
1) inputs: { number: "2024", roman: "1" }        expect: ["2024 = MMXXIV"]
2) inputs: { dir: "from", roman: "MMXXIV" }      expect: ["MMXXIV → 2024"]
```

- 修复前结果区恒为 `1984 = MCMLXXXIV`，两条都不命中；
- 默认态（1984/MCMLXXXIV、dir=to）也不命中，非逃生项；
- 覆盖了两个不同的事件源：`oninput`（文本框）与 `onchange`（下拉方向）。

`node scripts/verify_it_calc.js` → **1082/1082 通过**；`discriminate_check.js verify_it_calc.js` → **逃生 0**。
