## 修复位点

### T-N3 未超限时出现负的「超出限额部分」（中）
- **文件**：`tools/tax/foreign-tax-credit.html`（`calcTool()`、`__foreign_tax_creditExtras()`）、`i18n/tools/en/tax/foreign-tax-credit.json`（formula-eq 英文键值）
- **缺陷**：两处输出（结果卡片 + 明细表）都写死 `ft − lim`，境外已纳税低于抵免限额时直接输出负数。境外已纳税 1200 / 限额 1500 ⇒ 「超出限额部分 −300.00」；台账要求应为 `max(已纳税-限额, 0)` 且另列未使用限额。
- **修复**：
  1. 主计算引入 `const over = Math.max(ft-lim, 0), unused = Math.max(lim-ft, 0);`，结果卡片「超出限额部分」改用 `over`；
  2. 新增一行「未使用限额 (元)」= `unused`，让「未抵完的限额」有显式出口（原来这一信息只能靠用户自己做减法猜到）；
  3. `__foreign_tax_creditExtras()` 的 `TBKit.matrix.table` 明细表同步：`over` / `unused` 两行，导出 CSV 随之带上正确口径；
  4. 「计算说明」`formula-eq` 文案由「超出限额部分 = 已纳税额 − 抵免限额」改为「超出限额部分 = max(已纳税额 − 抵免限额, 0)、未使用限额 = max(抵免限额 − 已纳税额, 0)」，并同步英文 map（键即中文源串，旧键删除、新键新增，文本级替换，未重排 JSON）；
  5. 补金额非负守卫：`ft<0 || lim<0` ⇒ 提示「⚠ 境外已纳税额与抵免限额都不能为负数（当前输入 X / Y）」并拒绝计算（负数已纳税额会让 `min()` 与钳零同时失去意义）。
- **根因**：把「差额」当成「超额」，未区分正负两种经济含义——超出限额的部分可结转，未用完的限额是本年度作废的额度，二者方向相反。

### T-N5 营业周期为零时构造伪比例（中）
- **文件**：`tools/accounting/cash-conversion-cycle.html`（`calcTool()`、`__cash_conversion_cycleExtras()`）
- **缺陷**：应付占营业周期比写死 `DPO / (DSO+DIO||1) * 100`；`DSO+DIO = 0` 时 `||1` 把分母抬成 1，DSO=0 / DIO=0 / DPO=30 会输出 **3000.00%**。此输入并非全零，`__tbInputGuard` 的「全零拒算」拦不住，属真实可达路径。
- **修复**：
  1. 抽出 `const opCycle = DSO+DIO;` 与 `const payRatio = opCycle>0 ? (DPO/opCycle*100) : null;`，删掉 `||1` 伪分母；
  2. `payRatio === null` 时结果卡片显示 `—`，标签改为「应付占营业周期比 (%) · 营业周期为 0，占比无定义」；明细表同步显示 `—（营业周期为 0，占比无定义）`；
  3. CCC 与营业周期本身保持原样（0 / 0 / 30 时 CCC = −30.00 天仍照常给出，负现金周期是有业务含义的正常结果，按台账要求不拦）；
  4. 补非负天数校验：`__tbInputGuard` 的 `__N` 表填入 DSO/DIO/DPO（原为空表），负数天数 ⇒ 「⚠ 「应收天数 DSO」不能为负值。」并标记 `input-error`；空值仍由该守卫首段区分（不落成 0）。
- **根因**：用 `||1` 兜底除零，把「无定义」悄悄变成「除以 1」，制造了一个看起来精确、实际无意义的百分比。
