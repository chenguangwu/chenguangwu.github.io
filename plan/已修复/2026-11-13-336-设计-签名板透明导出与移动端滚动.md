## D-N149 白色/网格背景下「导出 PNG」仍带背景（真修）

### 根因
`drawBackground()` 把白底/网格直接烘焙进主画布 `canvas`；`exportPNG()`（无参「⬇ 导出 PNG」）创建透明 tmp 后直接 `tctx.drawImage(canvas,0,0)` 复制整个主画布，因此背景选白色/网格时导出图仍带白底/网格线，与 meta「导出 PNG 透明背景」及按钮语义不符。仅背景选「透明」时才碰巧正确。

### 改动
- `drawStroke(stroke, targetCtx)` 增加可选目标上下文（默认主 `ctx`），并对 `stroke.points` 缺失做防御（兼容历史 verify 的 `strokes.push({})` 空笔画）。
- **`redraw()` 同步改为包装调用** `strokes.forEach(function(s){drawStroke(s);})` —— 关键坑：若保留 `strokes.forEach(drawStroke)`，forEach 会把 `index` 当作第二参数 `targetCtx` 传入，导致主画布笔画被画到数字上、绘制失效。
- `exportPNG()` 不再 `drawImage(canvas)`，改为在 tmp 上按笔画层重绘：`tctx.scale(dpr,dpr)` 复用主画布 DPR 变换（`resizeCanvas` 用 `ctx.scale(dpr,dpr)`，笔画坐标为 CSS 像素，不复用会导出错位/变小），再逐笔 `drawStroke(s,tctx)` + `currentStroke`。
- 行为：`exportPNG()` → 透明底（无 fillRect）；`exportPNG('#ffffff')` → 白底 + 笔画；`bg-options` 的白/网格仅影响**画布预览所见**，不再污染导出。

### 验证（JSDOM 真机 `/tmp/jsdom336.js`，14/14 ✓）
- 透明导出：`drawImage=0`（背景不混入）、多点笔画 `stroke=1`、单点 `arc=1`、`fillRect=0`、`scale(2,2)=1`、绘制集中在单一临时 context。
- 白底导出：`fillRect=1`、`drawImage=0`、笔画仍重绘。
- 兼容：`strokes.push({})` 后导出不抛错；`redraw()` 主画布仍画出笔画（stroke+arc=2，证明 forEach 包装未误伤）。
- `verify_design_calc.js` 335/335 ✓（含 `entry:"strokes.push({});exportPNG();"` 的 toDataURL 失败注入用例）；`check_inline_js_syntax.js` 12141/12141 ✓。

## D-N150 预设条与建议表在 touch-action:none 容器内无法滚动（真修）

### 根因
`.canvas-wrap{...overflow:hidden;touch-action:none;}` 同时包住 `<canvas>`、`#spPresets`、`#spRefTbl`。`touch-action:none` 作用在整块容器上，手指在预设条/建议表区域上下滑动时浏览器不接管页面滚动，形成移动端滚动死区。

### 改动（最小，不动 DOM 结构）
把 `touch-action:none` 从 `.canvas-wrap` 移到 `#canvas`：
```css
.canvas-wrap{...;overflow:hidden;}          /* 去掉 touch-action:none */
#canvas{...;touch-action:none;}             /* 仅画布禁用手势，保证签名绘制 */
```
画布仍需禁浏览器手势以正常绘制；预设条/建议表恢复页面滚动（表格自身 `overflow-x:auto` 保留横向能力）。

### 验证
JSDOM `getComputedStyle`：`.canvas-wrap.touchAction !== 'none'`、`#canvas.touchAction === 'none'` ✓。
