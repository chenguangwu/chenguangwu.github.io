# 第180批 · IT 清单 1 条 · short-link-generator 短码与 URL 无函数关系（IT-N468）

- 来源：`plan/categories/01-IT开发/it.md` → IT-N468（整条删除；覆盖清单 `short-link-generator` 行同步改为无剩余缺陷）
- 修复日期：2026-11-11
- 类型：承诺未实现（页面宣称 Base62 编码，实际是随机字符串生成器）

## 失败点
`generate()` 的短码循环只用 `crypto.getRandomValues` 抽字符，URL 仅被显示、不参与任何运算：同一 URL 连点两次得到完全不同的短码，任意两条 URL 的短码分布也无差别。页面 `formula-eq` / 英文 intro 却宣称 "base62 / using Base62 encoding"。

## 根因
随机源替代了映射函数：缺少「长链 → 短码」的确定性计算，批量生成也只是重复抽随机数，没有序号参与。

## 修复位点
- `tools/it/short-link-generator.html` 新增顶层 `urlHash62(input, len, chars)`：
  - FNV-1a 双通道（不同 offset basis，字符高低字节分别进入 h1/h2）；
  - 每位输出前用 xorshift32 + mulberry 混合，再按 `chars.length` 取模映射到当前字符集，保证任意长度每一位都随哈希变化；
  - `generate()` 改为 `urlHash62(url + '#' + i, len, chars)` —— 同链同设置稳定，批量序号参与哈希故逐条不同。
- 中文 `formula-eq` / `formula-desc` 改为如实描述哈希映射与「同链稳定、仍有碰撞可能、本工具不提供服务端跳转」；FAQ 新增「同一条长链会生成不同短码吗？」条目。
- `i18n/tools/en/it/short-link-generator.json` 同步替换两条公式文案英译，并新增 FAQ 问答英译（英文态零 CJK）。
- 自定义 slug 分支、空 URL 提示、`escapeHtml` 输出路径均未改动。
