### IT-N409 UUID v5 命名空间校验和实际生成不一致

- 失败点：合法命名空间 ` 6ba7b810-…-00c04fd430c8 ` 首尾带空格，入口 trim 校验通过但生成时传入未 trim 值 ⇒ `generateUuidV5` 抛 `Invalid namespace UUID`，异步异常未捕获；`6ba7b810----9dad11d180b400c04fd430c8` 去掉所有 `-` 后恰 32 位 hex 被接受，与错误提示宣称的 8-4-4-4-12 格式不符。
- 根因：`isValidUuid()` 只查去符号后的 32 位 hex；校验与 SHA-1 输入分别读取 `namespace`，一个 trim 一个不 trim。
- 修复位点：`tools/it/uuid-generator.html` —— `isValidUuid()` 改为严格接受 8-4-4-4-12 或 32 位连续 hex（含首尾空格与花括号）；`normalizeUuid()` 统一产出标准串，入口校验与 `generateUuidV5()` 共用它；生成入口加 try/catch 并补全提示文案（明示也接受 32 位连续 hex）。
- 证据：`UU=YNYYY NORM=6ba7b810-9dad-11d1-80b4-00c04fd430c8`（五种书写逐一判定）；错位连字符得到「命名空间 UUID 格式非法…」；带空格 DNS 命名空间产出 `2ed6657d-e927-568b-95e1-2665a8aea6a2`，与 RFC 4122 / Python `uuid5(NAMESPACE_DNS,"www.example.com")` 标准向量一致。

### IT-N411 邀请码校验位的通用检错承诺不成立

- 失败点：`AB7`→`KB7`（单字符替换）、`AK9`→`KA9`（相邻换位）都通过校验，页面却宣称「可检出单字符错填与相邻换位」。
- 根因：1 位十进制校验位只有 10 种取值，而字符集有 36 个符号（鸽巢原理），不可能保证全检出。
- 修复位点：保留兼容既有已发码的 Luhn 变体（不擅自更换校验方案、避免已发码全部失效），改为如实标注能力边界：`tools/it/invite-code-generator.html` 的功能说明、公式注释、校验入口提示，及 `i18n/tools/en/it/invite-code-generator.json` 的中文键 + 英文值四处同步改为「拦截部分错填」「无法保证检出所有单字符错填与相邻换位（举出 AB7→KB7、AK9→KA9 两个反例）」「高可靠场景请用服务端查表或更长校验位」。
- 证据：`IC=YYYYN`（两个漏检反例通过、改错校验位 `AB8` 被拒），把漏检事实固化为回归护栏而非掩盖。

### IT-N370 矩阵求逆的大尺度消元阈值错误

- 失败点：`[[1e13,1e13],[1e13,2e13]]` 输出 `[[1e-13,0],[-1e-13,1e-13]]`，`A×A⁻¹=[[0,1],[-1,2]]`。
- 根因：相对主元判据 `tol≈20` 被继续用于**归一化之后**的消元因子 `f≈1`，应执行的消元被跳过。
- 修复位点：`tools/it/matrix-inverter.html` 消元循环把 `Math.abs(f)<tol` 改为仅 `f===0` 才跳过（主元选 piv 仍用 tol）。
- 证据：`MI=1,0,0,1 INV=2.0e-13,-1.0e-13|-1.0e-13,1.0e-13`，以矩阵乘积验证逆矩阵自洽。

### IT-N392 TOML 转 XML 的元素名清洗仍产生非法标签

- 失败点：合法 TOML 键 `"a　b"`（U+3000）输出 `<a　b>`；U+0301 组合音标作首字符被原样放行，XML 解析器报非法标签。
- 根因：`xmlName()` 粗略放行整个 `\u00c0–\uffff`，而 XML NameStartChar / NameChar 并不覆盖其中所有码位。
- 修复位点：`tools/it/toml-to-xml.html` 新增 `xmlStartCp()` / `xmlCharCp()` 按 XML 1.0 (5th ed) 逐码点判定；`xmlName()` 逐码点清洗，首字符非法时补前导 `_`：**数字保留**（`"123"`→`<_123>`）、不可见组合标记替换为 `_`（`́x`→`<_x>`），连续 `_` 合并。
- ⚠️ 本批同时修掉上批自己引入的回归：初版 `xmlName()` 首字符非法时只补 `_` 却吞掉原字符，`"123"` 变成 `<_123>`→`<_23>`，导致既有用例 `IT-N392` 红灯。本次已修正并把该契约写进新用例的 ref，避免再次退化。
- 证据：`&lt;a_b&gt;1&lt;/a_b&gt;`、`&lt;_x&gt;1&lt;/_x&gt;`；既有用例 `it/toml-to-xml` 分类 **7/7 通过**（含 `"123"`→`&lt;_123&gt;`）。

### IT-N398 / N400 JSON Schema 对象与数组约束和联合类型处理错误

- 失败点：`{"required":["x"],"items":{"type":"number"}}` 配 `["bad"]` 判通过；`{"type":["object","array"],…}` 配 `[1]` 误报「不是对象」；`{"type":["array","string"]}` 配 `"hello"` 误报「不是数组」。
- 根因：`walk()` 用 `hasObjKw` / `hasArrKw` **猜** schema 角色，且联合类型被当成需同时满足的多重约束。
- 修复位点：`tools/it/json-schema-validator.html` 的 `walk()` —— 关键字按**实例类型**应用（`required`/`properties` 只对对象、`items` 只对数组），`typeOK` 只校验允许类型集合。
- 证据：`JSV=FAIL:类型不匹配 root[0]: 期望 number N=required,items`、`JSV=PASS N=type,items`、`JSV=PASS N=type`，覆盖对象/数组/标量三类实例。

### IT-N385 / N386 TOML 多行字符串转义和闭合判断仍有误

- 失败点：`p = """C:\\temp"""` 解析出「反斜杠 + TAB」；合法混合引号 `m = """a ''' b"""` 后另起一行 `x = 1` 只保留 m。
- 根因：单行串链式 `replace` 先解 `\t` 再解 `\\`；`tOpenTriple()` 分别数 `"""` 与 `'''` 的奇偶，把双引号串内的三个单引号误判为另一种多行串开头。
- 修复位点：`tools/it/toml-to-json.html` —— 单行/多行基本串统一走单遍 `tUnescape()`；`tOpenTriple()` 按当前打开的三引号定界符类型判断闭合。
- 证据：`JSON 输出 { "p": "C:\\temp" }`、`JSON 输出 { "m": "a ''' b", "x": 1 }`、`JSON 输出 { "v": "C:\\temp", "s": "a\tb" }`（输出侧为 JSON.stringify 转义形态）。
