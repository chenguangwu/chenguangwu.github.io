## 一、IT-N410 批量生成无去重

**缺陷**：原理框承诺「批量生成自动去重保证唯一」，`generate()` 却只是 `for(count)` 随机拼接后直接 `html+=`，全程无 Set。最短码长 4、字符集「仅数字 + 排除易混」只有 8 个字符（空间 4096），30 条约 9.71% 概率出现重复 ⇒ 邀请码/白名单「唯一」假设不成立。

**修复**：
```js
const seen=new Set(),codes=[];
const maxAttempts=Math.max(count*50,1000);
while(codes.length<count && attempts<maxAttempts){
  ...生成 body（含校验位）→ 拼前缀得到最终码...
  if(seen.has(code))continue;      // 碰撞重抽
  seen.add(code);codes.push(code);
}
if(codes.length<count){ /* 明确报「组合空间不足」，绝不交付少于请求数量的码 */ return; }
```
去重对象是**最终码**（含前缀与校验位），尝试上限 `max(count*50,1000)` 防止组合空间不足时死循环。

## 二、IT-N411 校验位是求和取模、且无校验入口

**缺陷**：原理框写「可附加校验位（Luhn 变体或 CRC）以拦截错填」，实现却是 `sum += c.charCodeAt(0); code += sum % 10` —— 纯加法校验，`AB` 与 `BA` 的校验位都是 1，最常见的相邻换位完全检不出；页面也没有任何校验输入框/按钮，所谓「拦截错填」根本无从使用。

**修复**（三件事一起做）：
1. `luhnValue(ch)`：数字 0-9 用自身、字母 A-Z 映射 10-35；
2. `luhnCheckDigit(body)`：从右往左隔位乘 2（>9 减 9）求和，校验位 `(10 - sum%10)%10`；`AB→7`、`BA→8`，换位可检出；
3. `verifyLuhn(code)` + `verifyCode()`：新增「校验邀请码」输入区（`#verifyInput` + 校验按钮），支持剥 `XXX-` 前缀、判格式非法、给通过/失败结论，结果追加到结果区（沿用被采集的 `#output` 容器，不用 `insertAdjacentHTML`）。

生成侧把 `sum%10` 换成 `luhnCheckDigit(body)`，与校验侧**同源可逆**。

**噪声治理**：harness 会兜底无参调用页面所有顶层函数，新函数 `luhnValue(undefined)` / `luhnCheckDigit(undefined)` / `verifyLuhn(undefined)` 会抛错并污染 `errs`；给四个函数（含既有 `escapeHtml`）加 `String(x==null?'':x)` 守卫，兜底不再抛错。这是测试桩适配，不改变正常调用语义。

**文案/i18n**：原理框第 3 条去掉未实现的「或 CRC」，写明「Luhn 变体 + 下方校验入口 + Set 去重」；`js/tool-i18n-en.js` 的 `GEN_UI_MAP` 补 `'校验':'Verify'`；`i18n/tools/en/it/invite-code-generator.json` 同步 10 条 map（含新 UI 文案与运行时中英双语文案）。`--check` 0 残留。

## 六、说明

- 短码碰撞是概率事件，直接跑 30 条赌重复的用例不可靠；用确定性随机桩把「必然碰撞」变成可断言的固定场景，这是本批用例能稳定判别的关键。
- 校验位只保证「抄错/换位能被发现」，不是密码学完整性校验，页面文案未夸大该能力。
