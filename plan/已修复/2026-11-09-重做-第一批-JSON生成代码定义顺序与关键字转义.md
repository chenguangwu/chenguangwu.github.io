## 失败点 → 根因 → 修复位点 → 证据

### IT-N380：Python 子类型定义在根类型之后，执行即 NameError

- 失败点：`{"u":{"aa":1}}` 生成 `class Root(BaseModel): u: RootU` 在前、`class RootU` 在后；对象数组 `{"orders":[{"id":1}]}` 与根数组 `[{"id":1}]` 分别先引用 `RootOrders` / `RootItem`。Python 类注解在类体执行时立即求值，实际运行报 `NameError`。
- 根因：`toPython()` 把 `head`（根定义）放进 `out` 后，才 `subs.forEach` 追加子类型；而 `jcSubs()` 是前序收集（父的子 → 孙），顺序正好与依赖方向相反。
- 修复位点（`tools/it/json-to-code.html` `toPython()`）：改为先输出 `subs.slice().reverse().map(pyBody)`，最后才 `out.push(head)`。前序逆序即「最深的子类型先定义」，对树形 JSON 天然满足拓扑序；根数组的类型别名 `Root = List[RootItem]` 也因此落在 `class RootItem` 之后。其他语言（TS/Go/C#/Java/Kotlin/Rust/Proto）允许前向引用，输出顺序保持不变。

### IT-N382：目标语言保留字未规避

- 失败点：`{"class":1,"type":"x"}` 生成 Python `class: int`（SyntaxError）、Rust `pub type: String`；Java / Kotlin 的 `class` 字段同样非法。
- 根因：各 `xxxBody()` 直接用 `jcIdent(k, style)` 当字段名，没有任何保留字检查。
- 修复位点：新增 `JC_KW`（py / rust / java / kotlin 四张保留字表）与 `jcSafe(name, lang)`（命中则加 `_` 后缀），八个生成器统一 `jcUniq(jcSafe(jcIdent(k, style), lang), used)`。Go / C# 用 PascalCase 不撞小写保留字、TS / Proto 允许关键字作属性名，故这四张表不含它们（调用 `jcSafe` 只是统一形态，零行为变化）。改名后 `jcNote` / `#[serde(rename=...)]` / Go json tag / C# JsonProperty 仍指回原键。

### IT-N384：映射字符串未转义 + Go backtick tag 被截断

- 失败点：键含双引号时，Rust `#[serde(rename = "a"b")]`、C# `[JsonProperty("a"b")]`、Go `` `json:"a"b"` `` 全部裸拼、目标语言无法编译；键含反引号时 Go 的 backtick 原始字符串会被提前闭合。
- 根因：三处都直接 `'...' + k + '...'`，没有字符串字面量转义。
- 修复位点：新增 `jcStr(s)`（转义 `\`、`"`、CR/LF/TAB），用于 Rust serde rename、C# JsonProperty、Go struct tag；Go 额外在键含反引号/真实换行时把 tag 从 backtick 字面量退成 `JSON.stringify(tag)` 的普通字符串字面量。`jcNote()` 里的原键注释也把 CR/LF 换成空格，避免注释注入换行。
