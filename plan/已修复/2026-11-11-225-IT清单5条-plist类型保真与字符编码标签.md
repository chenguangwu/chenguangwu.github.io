## 一、进批探测结论

清单 5 条全标「确认缺陷」，真机复算后确认 5 条均为当前源码真缺陷（本批无漏销账）：

- **N202**：`plistNode()` 的 real 走 `parseFloat`、`date`/`data` 只取 textContent，`toPlistNode()` 靠 `Number.isInteger` 猜标签 ⇒ `<real>1.0</real>` 往返成 `<integer>1</integer>`、`<date>`/`<data>` 往返成 `<string>`。
- **N203**：`<integer>` 用 `parseInt`，`9007199254740993` → `9007199254740992` 静默丢精度。
- **N204**：`escapeXml` 只替 `& < >`，JSON 里的 `U+0001` 直写 XML ⇒ 产物自己都解析不了（命中 parsererror）。
- **N205**：char-encoder 的 ASCII 行用 `bytes.length <= 1` 判定，`Hello` 被误标「多字节序列」且与下一行 UTF-8 字节重复。
- **N206**：`clearAll()` 只清 input/results，不清 `#byteViewBox`，清空后字节表残留旧文本。
- **顺带发现**：plist-parser 尾部重复注入了一组同名函数（`setOut`/`setErr`/`clearAll`/`loadSample`），后定义的 `setErr` 用 `e.className='err'+(s?'':' ok')`（有内容反而红）覆盖前面正确的实现 ⇒ 连「✅ 转换成功」都显示红色。

```javascript
// plist 类型保型核心
case 'real': return plistTyped('real', String(node.textContent).trim());
case 'integer': {
  const raw = String(node.textContent).trim();
  if(/^-?\d+$/.test(raw)){
    const bi = BigInt(raw);
    if(bi > BigInt(Number.MAX_SAFE_INTEGER) || bi < BigInt(Number.MIN_SAFE_INTEGER)) return plistTyped('integer', raw);
  }
  return parseInt(raw, 10);
}
function isPlistTyped(v){
  return !!(v && typeof v === 'object' && !Array.isArray(v) &&
    typeof v.__plistType === 'string' && Object.keys(v).length === 2 &&
    /^(real|date|data|integer)$/.test(v.__plistType));
}
```

**设计取舍**：JSON 没有 plist 的 real/date/data 原生类型，也无法无损表示 `1.0` 与超安全整数，故用 `__plistType` 标记对象在 JSON 中间态保真，回写时按标记还原；`isPlistTyped()` 用「恰好两个键 + 合法标记值」收窄，避免把普通 dict 误判为类型包装。控制字符按 XML 1.0 合法码点过滤（`\t\n\r` 保留），计数在提示中显式告知用户。

## 四、踩坑（记死）

1. **harness blob 剥标签**：`collectStrings` 采集输出元素时会把 `<real>1.0</real>` 剥成纯文本 `1.0`，expect 里带标签永不命中。plist 这类「输出就是 XML 标签」的用例，必须在 clicks 里读 `output.textContent` 判断标签存在性，再把结论写进 `__tbProbe`（纯文本哨兵），不能把标签直接写进 expect。
2. **harness 无 DOMParser**：plistToJson 方向在 verify harness 里会报 `DOMParser is not defined`，故 plist 的 verify 锁只能走 `jsonToPlist()` 回写方向；解析侧（real/date/data→标记对象、大整数 BigInt、控制字符可再解析）由 JSDOM 真机脚本覆盖。
3. **真机 CJK 断言必须排除输入回显**：用 `A中` 测 EN 态会命中用户输入里那个「中」字，误判 i18n 泄漏；改用纯 ASCII 输入 `AZ` 复验才是干净的判据。
4. **`__plistType` 标记对象要收窄**：必须用「恰好 2 键 + 标记值白名单」判定，否则普通 dict 若碰巧含 `__plistType` 键会被误还原成标签。
5. **控制字符计数要每次重置**：`__plistDropped` 是模块级累计，若不在每次 `jsonToPlist()`/`doMinify()` 开头清零，第二轮干净输入会残留上一轮的「已剔除 N 个」提示。
