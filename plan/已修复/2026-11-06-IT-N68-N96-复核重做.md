## IT-N68：摘要未算完时复制会把占位符 `—` 一起复制（复核失败 → 已重做）

- 复核失败点：`hash-multi` 的异步竞态已修，但 SHA 计算完成前 `copyAll()` 仍把占位符 `—` 纳入剪贴板，`copyItem()` 也会把 `—` 复制走，且无禁用或提示。
- 修复（`tools/it/hash-multi.html`）：
  - 新增 `__hmPending(v)`：空值 / `—` / `--` / `-` 一律判定为「尚未算完」。
  - `copyItem(btn)`（`:390`）：读到的是占位符时**拒绝复制**并 toast「摘要尚未计算完成，请稍候再复制」（EN 同步）。
  - `copyAll()`（`:399`）：只复制已就绪条目；全部未就绪时拒绝并提示；部分就绪时复制 N 条并告知「另有 M 条仍在计算」，不再静默混入占位符。
  - 顺带把条目里写死的「复制」按钮改成 `__hmEn()?'Copy':'复制'`，`_verify_en_cjk --container=outBox` 由 `CJK_LEAK` 转 `OK_EN`。
- 门禁回归用例（`scripts/verify_it_calc.js`，新增 1 条）：勾选 MD5/CRC32/SHA-1/SHA-256 后对 `n68probe` 调 `calc()`，再拦截 `ToolBox.copyText` 调 `copyAll()`，断言 `CAP lines=2 dash=0 total=4`——4 对里 2 对已就绪、0 个占位符。修复前该串为 `lines=4 dash=2`，不命中。`it/hash-multi` 7/7 通过。

## IT-N71：非法 CIDR 前缀回退并显示旧结果（复核失败 → 已重做）

- 复核失败点：`parseCidr()` 拒绝非法前缀后，主计算回退到 `#ipOnly`/`#maskInput` 里的上一次有效值并照常出结果——浏览器实测 `10.20.30.40/16` 得 `10.20.0.0`，改成 `192.168.1.1/24abc` 仍显示旧网络且零提示，历史里还写入了这次非法输入。
- 根因：`calculateV4()` 用「`parseCidr()` 返回 null」同时表示「输入里没有斜杠」和「斜杠后前缀非法」两种完全不同的状态。
- 修复（`tools/it/ip-calculator.html`）：
  - `calculateV4()`（`:543`）改为先判 `input.indexOf('/') !== -1`：带斜杠即走 CIDR 单一入口，解析失败**直接报错返回**，不再回退旧值；无斜杠才走「IP + 掩码」两栏输入（这是页面设计的第二种输入方式，保留）。
  - 新增 `showInvalidV4()`（`:521`）：统一无效态出口，同时清空 `#v4Result` 与 `#binaryBox`，避免二进制区残留上一次的位图。
  - 文案走新增 `__ipEn()`（TBKit 未就绪时按 `?lang=en-US` / `html[lang]` 兜底），`_verify_en_cjk --container=v4Result --container=binaryBox` → `OK_EN`。
- 门禁回归用例（新增 2 条，`it/ip-calculator` 11/11 通过）：`192.168.1.1/24abc` 与 `10.20.30.40/` 均须出现「无效的 IP 或前缀」；修复前两者都会渲染上一轮的完整结果卡片。
- 同批修正过期用例：自动补强用例（`scripts/verify_it_calc.js:5797` 附近）原断言是把整段 blob 拼成超长串（含输入回显 `abc123测试`/`42`，零判别力且任何合法改动都会失配），改为断言计算结论「无效的 IP 或前缀」。

## IT-N83：Base32 尾部等号数量未校验（复核失败 → 已重做）

- 复核失败点：非法字符与非零填充位会报错，但 `base32Decode()` 无条件 `replace(/=+$/,'')` 剥掉全部尾部等号 ⇒ `MY=`、`MY=====`、`MY=========` 与标准 `MY======` 全部解出同一个字节 `f`，无法发现传输中被截断或补错的串。
- 修复（`tools/it/base64-converter.html:467`）：按 RFC 4648 §6 校验——
  - 等号只允许出现在末尾（`=+$`），中间出现即报错；
  - 填充最多 6 个；
  - 有填充时，去填充后的长度必须使 `8 - (len % 8)` 与填充数**精确相等**，否则报「Base32 填充数量无效（应为 N 个等号）」；
  - 无填充形式（`MZXW6YTBOI`）继续接受，不破坏既有用法。
- 证据脚本：新增 `scripts/_verify_encoding_runtime.mjs`（从源文件按行抽取真实函数体在 Node 里跑，`__b64L` 桩返回中文），9/9 通过：`MY=` → 「填充数量无效（应为 6 个等号）」、`MY=========` → 「填充无效（最多 6 个等号）」、`MY=A====` → 「等号只能出现在末尾」、`MZXW6YTB0I` → 「第 9 位含非法字符「0」」；`MY======` → `f`、`MZXW6YTBOI` → `foobar`、编码→解码往返均正常。
- 判别力实测：回退 `base64-converter.html` 后同一脚本 6/9（三条填充断言全红），恢复后 9/9。
- 说明：该页编解码函数包在页内 IIFE 里，`verify_it_calc.js` 的 `__pageEval` 取不到（实测 `typeof base32Decode === 'undefined'`），故以独立运行期脚本作为门禁外证据。

## IT-N87：AES 关闭填充时非整块密文仍被静默接受（复核失败 → 已重做）

- 复核失败点：加密侧已拒绝非整块明文，但 `decrypt()` 解码密文后无长度检查——ECB + 关填充 + `abcdef1234`（5 字节）会输出 5 个 NUL 并提示成功。
- 修复（`tools/it/aes-encryptor.html:968`）：`decrypt()` 在解码密文后、派生密钥前增加分组长度校验——`mode ∈ {ECB, CBC}` 且 `ciphertext.length % 16 !== 0` 时拒绝并提示「密文长度无效：ECB/CBC 模式要求密文为 16 字节的整数倍（当前 N 字节）」（EN 同步），结果区不改写。
- 验证（`scripts/_verify_aes_runtime.mjs`，新增脚本）：非法长度被拒且结果区不变；反向校验合法 16 字节密文仍能正常解出，未过度拦截。

## IT-N88：AES ECB 元数据在盐已存在时未剥离；Base64 盐解析口径不一致（复核失败 → 已重做）

- 复核失败点：① ECB 只有盐框为空才剥离 `salt:ciphertext`，盐框有值时把盐当密文前缀，同页往返解出乱码前缀 + 原文；② Base64 输出把盐写成 Base64，解密侧却把该串直接写进盐字段，而 `getKeyAndSalt()` 恒按 hex 解析。
- 修复（`tools/it/aes-encryptor.html`）：
  - 新增 `parseSaltBytes(str)`（`:738`）：32 位 hex 走 `hexToBytes`，否则试 Base64 且要求解出 16 字节，仍失败才回落 hex——盐字段同时接受两种编码。`getKeyAndSalt()` 改用该函数（`:783`）。
  - 解密元数据解析（`:927` / `:941`）改为按**段数**判定而非按「盐框是否为空」：非 ECB 的 `salt:iv:cipher` 三段式、ECB 的 `salt:cipher` 两段式，只要首段能解析成 16 字节盐就剥离，并把盐**规范化成 hex** 写回盐框；不是 16 字节的首段不当作盐，避免把用户用 `:` 分组的十六进制密文误切。
- 验证（`_verify_aes_runtime.mjs`）：ECB + 盐框有值 + 元数据 → 解回「中文」；Base64 输出 + 盐框非空 → 解回「hello」；CBC 三段 meta → 解回「CBC往返测试」。

## IT-N90：AES 趋势图未正确表达密文；历史/导出含密码明文（复核失败 → 已重做）

- 复核失败点：① 趋势图对结果列 `parseFloat`，把 `1234ab…` 读成 `1234`，画出与安全无关的假趋势；② `__aes_encryptorSnap()` 收集密码输入框，历史与 CSV 导出含口令/密钥明文。
- 修复（`tools/it/aes-encryptor.html`）：
  - 趋势图（`:1146`）改画**输出字节数**：加密记录密文字节、解密记录明文字节（`__aes_encryptorLastBytes`，`:903` / `:1015`），存于记录的隐藏字段 `__bytes`（不进表格、不进 CSV），无量值时不出图。
  - 快照脱敏（`:1098`）：`#password` 字段一律写 `••••` 后跳过，不落盘、不导出；其余字段照旧。
- 验证（`_verify_aes_runtime.mjs`）：`__aes_encryptorSnap().password === '••••'` 且整份快照不含 `SUPERSECRETPW`。
- 说明：历史条目仍保留 `keyType`（用了哪种密钥形态）与 `keySize`，便于回溯配置，但不含任何可还原密钥的内容。

## IT-N92：AES 加密输入字节数显示的是填充后长度（复核失败 → 已重做）

- 复核失败点：`updateInfo(plaintext.length, ciphertext.length)` 在 PKCS7 填充之后调用，输入「中文」（UTF-8 6 字节）在 ECB+PKCS7 下显示 `16 B`。
- 修复（`tools/it/aes-encryptor.html:858`）：填充前先存 `inputBytes = plaintext.length`，`updateInfo(inputBytes, ciphertext.length)`。
- 验证（`_verify_aes_runtime.mjs`）：输入「中文」→ 信息栏 `6 B`，密文 `16 B`，hex 密文 32 字符。

## IT-N96：RSA 签名/验签不写历史（复核失败 → 已重做）

- 复核失败点：`__rsaExtras()` 只被 `downloadKeys()` 的包装调用，`doSign()` / `doVerify()`（以及 `doEncrypt()` / `doDecrypt()`）完成后没有任何记录逻辑，只签名/验签不产生历史。
- 修复（`tools/it/rsa.html`）：
  - 四个操作成功分支各加一行 `__rsaExtras(true)`（`:468` 加密、`:485` 解密、`:508` 签名、`:531` 验签）；`__rsaExtras(force)` 新增 `force` 参数，显式操作不受原有 1 秒节流限制。
  - **顺带修安全面**：`__rsaSnap()` 增加密钥字段黑名单 `__rsaKeyFields`（`:573`：`privKeyOut`/`pubKeyOut`/`encPrivKey`/`encPubKey`/`signPrivKey`/`signPubKey`）——历史会导出成 CSV，私钥一旦落盘即泄漏；且历史点击回填会把快照值写回输入框，密钥字段根本不参与快照才安全。
  - 趋势图同 N90 口径：改画输出字节数（`__bytes`），不再对签名字符串 `parseFloat`。
- 验证（`scripts/_verify_rsa_runtime.mjs`，新增脚本，7/7）：签名后历史 +1 且结果列含「签名已生成」；记录里不含任何 `BEGIN … KEY`；签名字节数 256（2048 位）；验签后历史 +1 且结果列为验签结论；加密后历史 +1；趋势图数据为数值型输出字节数。
- 判别力实测：回退 `rsa.html` 后同一脚本 1/7（六条全红），恢复后 7/7。
