# 第985批：摩尔质量明细改为元素组成导出

## 问题

`tools/science/molar-mass-calculator.html` 与 `tools/science/calc-cycle.html` 的「导出明细 CSV」实际调用 `TBKit.util.exportTable('#…Table',…)`，导出的是历史记录表；结果列只保存结果区文本前 80 个字符。多元素化学式和水合物的完整元素计数、原子量、分项质量、占比全部被截断，导出名称与用户预期不符。

## 修改

### 两页主按钮

- 「导出明细 CSV」改为「导出元素组成 CSV」，直接从当前化学式重新解析，不再读历史表。
- CSV 列（中文 / 英文）：
  - 化学式 / Chemical formula
  - 总摩尔质量 (g/mol) / Molar mass (g/mol)
  - 元素 / Element
  - 原子个数 / Atom count
  - 原子量 (g/mol) / Atomic weight (g/mol)
  - 分项质量 (g/mol) / Element mass (g/mol)
  - 质量占比 (%) / Mass fraction (%)
- 首行合计记录 `合计 / Total`、总质量、`100.00`；随后每元素一行，计数来自解析结果，分项质量 = 原子量 × 计数，占比 = 分项质量 ÷ 总质量 × 100。
- 调用 `TBKit.util.exportCsv()`（复用公共 CSV 转义、公式注入防护与 BOM）。
- 空化学式、括号错误、未知元素时先经 `calc()` 显示错误，直接 return，不下载上一次的旧表。

### 历史导出

- 新增独立按钮「导出历史记录 CSV」及独立函数：
  - `__molar_mass_calculatorExportHistory()` → `molar-mass-calculator-history.csv`
  - `__calc_cycleExportHistory()` → `calc-cycle-history.csv`
- 历史导出仍走原 `exportTable`，名称和文件都明确标注为历史，不再与当前元素明细混用。

## 真机验证

Chrome headless，两页中英文态，拦截 `exportCsv` / `exportTable` 读取实际 rows：

| 化学式 | 结果 |
|---|---|
| `H2O` | 4 行 × 7 列：合计 18.015；H 2×1.008=2.016、11.19%；O 15.999、88.81% |
| `C6H12O6` | 4 行：C 6×12.011=72.066、40.00%；H 12.096、6.71%；O 95.994、53.28% |
| `CuSO4·5H2O` | 5 行：合计 249.677（calc-cycle 249.68）；Cu1/S1/O9/H10 全部保留 |
| `H2(O` | 无 `exportCsv` 调用，仅显示括号错误 |
| 空化学式 | 无 `exportCsv` 调用 |

- 英文态列名为 `Chemical formula` / `Molar mass (g/mol)` / `Element` / `Atom count` / `Atomic weight (g/mol)` / `Element mass (g/mol)` / `Mass fraction (%)`。
- 历史按钮分别传 `molar-mass-calculator-history.csv` / `calc-cycle-history.csv`，selector 为各自历史表。
- 两页无 `pageerror`。
