# 第693批：AA 账单边界与合同金额大写

## 修复项

### 1. AA 账单简单模式：空总额仍输出分摊结论

`tools/life/bill-splitter.html` 原先把空总金额按 0 元计算，并输出“合计已对齐”，与“空值不产生计算结论”的规则冲突。

修复：总金额为空时只提示“请先填写账单总金额；如需分摊 0 元账单，请输入 0”，不输出分摊表；数字 `0` 仍按合法金额正常计算。

### 2. AA 账单简单模式：极大金额导致余数分配失控

原逻辑直接 `Math.round(totalWithTip * 100)` 后进入余数循环，`1e100` 等输入会得到巨大或 `NaN` 的余数，可能长时间占用主线程。

修复：

- 总金额限制为 `0–100,000,000,000` 元，小费比例限制为 `0–100%`。
- 分摊前校验含小费总额、分值均为有限且安全整数，并限制分值不超过 `1e13`。
- 份额占比先算 `s / totalShare` 再乘总额，避免中间乘积溢出。
- 超出范围时清空旧导出快照并显示可理解的上限提示。

### 3. 合同生成：十万及以上金额大写出现无效单位

`tools/life/generator-price.html` 的 `numberToChinese()` 单位只到“万”，十万位会访问 `undefined`；合同总额没有上限。

修复：

- 重写人民币大写转换，按四位分组处理“万 / 亿”，正确补零，支持 `0–999,999,999,999` 元。
- 合同总额超出该范围时停止生成并提示降低单价、数量或税率。
- 保留 `0` 元合法输入，输出“零元整”。

### 4. 合同生成：说明与实际生成顺序不一致

页面 FAQ、结构化数据和深度解析原写“随机组合生成、可再挑选条目拼接”，实际按内置服务项固定顺序循环生成。

修复：

- 统一改为“按输入金额与固定顺序生成合同草案，服务项按内置列表循环使用；暂不支持锁定指定条款”。
- 同步工具页 FAQ、FAQPage 结构化数据、使用指南和第三层英文词典。
- 指南中“生成数量超出范围按边界取值”的旧说法改为“提示输入有误”，与页面校验一致。

## 验证

本地 Chromium 实测：

- AA 账单空总额 → 仅提示补填，无分摊结论。
- `0` 元 → 四人各 `¥0.00`，合计 `¥0.00`。
- `1000` 元 + 10% 小费 → 每人 `¥275.00`，合计 `¥1100.00`。
- `1e100` 与 `1e12` → 显示金额上限提示，无页面异常、无冻结。
- 合同大写：`10001 → 壹万零壹`、`100000 → 壹拾万`、`100010001 → 壹亿零壹万零壹`、`999999999999` → 完整十二位大写。
- 合同总额超限 → 显示范围提示，不生成带 `undefined` 的草案。
- 合同正常输入 `50000 × 2`、折扣 10%、税率 6% → 总额 `95,400`，大写“玖万伍仟肆佰元整”。

## 规则

- 空串与数字 `0` 区分处理，`0` 元不作为空值拦截。
- 金额上限仅在无法精确计算时触发，正常账单不受影响。
