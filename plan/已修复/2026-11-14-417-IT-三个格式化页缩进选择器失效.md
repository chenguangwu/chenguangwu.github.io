# 417 批：三个格式化页的缩进选择器此前完全无效

日期：2026-11-14
范围：`tools/it/graphql-formatter.html`、`tools/it/xml-formatter.html`、`tools/it/json-to-yaml.html`

## 一、问题

三个页面都有 `#indent` 下拉（2 空格 / 4 空格 / Tab），预设按钮也会写入 `indent` 值，
但输出始终固定为 2 空格：

- `graphql-formatter.html`：`const pad = () => '  '.repeat(depth)` 写死 2 空格；
- `xml-formatter.html`：`serializeNode()` 的 `pad` 写死 `'  '`，`getIndent()` 从未调用；
- `json-to-yaml.html`：`toYaml()` 用 `'  '.repeat(indent)`，且文件里有两份 `getIndent()`
  （前一份固定返回 `'  '`，后一份才是读下拉，函数声明提升后后者生效但从未被调用）。

结果是用户切换「4 空格 / Tab」、或点「4 空格」「Tab 缩进」预设，输出完全不变，
与页面「可自定义缩进」的说明不符。

## 二、修复

- `graphql-formatter.html`：`pad()` 改为 `getIndent().repeat(depth)`；
- `xml-formatter.html`：区分布局/压缩两种模式，格式化模式下
  `const pad = indent ? getIndent().repeat(depth) : ''`；
- `json-to-yaml.html`：`toYaml()` 改为 `getIndent().repeat(indent)`，并删除固定返回两空格的
  重复 `getIndent()` 定义，只保留读取 `#indent` 的一份。

未改动各页的解析/格式化算法与按钮行为。

## 三、验证

- `node --check`：3/3 通过。
- Node + 假 DOM 运行时验证：
  - GraphQL 选 4 空格 → 每层 4 空格；选 Tab → 每层制表符；
  - JSON→YAML 选 2 / 4 / Tab → 分别输出 2 空格、4 空格、制表符缩进。
- XML 页为单行 `pad` 取值改动，格式化仍走原 `formatXml(..., true)` 分支；
  压缩分支 `indent=false` 不受影响。
- `python3 _build.py` 连续两次幂等；`python3 _test_static.py`：**4714/4714 通过**。
