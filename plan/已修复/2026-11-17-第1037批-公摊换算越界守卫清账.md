# 第 1037 批 · RE-N1 公摊换算越界守卫清账

## 问题与根因
`tools/realestate/convert-area-shared.html` 的 `calc()` 用 `+value||0` 取值后直接算 `shared=inner×ratio/100`、`gross=inner+shared`、`rate=inner/gross×100`，没有面积/系数的正负与区间校验：

- 套内 0、系数 20% → `gross=0`、`rate=0/0=NaN`，仍渲染「得房率 = NaN %」；
- 套内 100、系数 −50% → 公摊 −50㎡、建面 50㎡、得房率 200%，且判「优秀」；
- 系数 −100% → `gross=0`、`rate=Infinity`。

页面公式说明还明写「校验：无强校验，空值按 0 兜底」，与数值风险相矛盾。

## 修复
`calc()` 入口增加守卫：要求 `inner > 0` 且 `0 <= ratio <= 100`，否则只渲染错误提示并 `return`，不再产出 NaN/负数/超 100% 得房率。提示按 `TBKit.util.isEn()` 中英分流，避免英文态新增硬中文。

两处公式说明的「校验」口径同步改为「套内面积须大于 0、公摊系数须在 0–100 之间，否则提示并中止」；`i18n/tools/en/realestate/convert-area-shared.json` 的中文键与英文值同步更新，防止整段映射失配导致英文态残留。

## verify 用例
新增两条 `realestate/convert-area-shared` 判别用例，注入后显式 `calc()` 并把结果区覆盖成哨兵：

- `inner=0 / ratio=20`：断言提示存在且不含 `NaN`；
- `inner=100 / ratio=-50`：断言提示存在且不含 `-50.00` 与「优秀」。

默认态 100/20 合法，不命中哨兵 ⇒ 零逃生。
