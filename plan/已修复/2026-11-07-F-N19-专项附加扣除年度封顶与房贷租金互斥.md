## 2. F-N19：专项附加扣除明细未校验年度上限与互斥（真缺陷）

### 失败点
`__sdSum()` 把 7 项明细直接累加：`sum += (id === 'sd4') ? v / 12 : v;`

- **大病医疗（sd4）**：按年填，旧实现直接 `v/12` 摊月，**无 80000 元/年上限**。填 100000 ⇒ 计入 8333.33/月，专项附加多扣、税额被低估到 ¥156.67。
- **住房贷款利息（sd5）与住房租金（sd6）**：一个纳税年度内依法不可同时扣除，旧实现**直加**，页面只有 placeholder 文字提示、无互斥逻辑。房贷 1000 + 租金 1500 ⇒ 扣 2500、税 ¥740（仅租金 1500 时应为 ¥840）。
- 公式框仍声明「校验：无强校验，空值按 0 兜底」，与实际应有口径不符；明细合计与税额同屏却给出偏乐观结论。

### 根因
7 项明细共用一个「逐项累加」循环，未把「年度限额」与「法定互斥」这两条口径编码进计算链；`sdTotal` / `bonusBox` 只显示一个合计数字，用户无法看出哪项被截断或忽略。

### 修复位点（只改工具页 + 英文 map + 门禁用例）

**`tools/finance/tax-calculator.html`**
1. 新增 `__SD_ILLNESS_CAP = 80000`、`__sdFmt()` 与 **`__sdAudit()`** 作为专项附加口径单一真源：
   - 每项先读值、负值按 0 兜底；
   - sd4 = `Math.min(illnessRaw, 80000)` 后 `/12` 摊月，`illnessCap` 标记是否触顶；
   - sd5/sd6 同时 >0 时 `housingExclusive = true`，仅取 `Math.max(loan, rent)`，并记录 `housingUsed` 与被忽略项；
   - 其余四项照旧相加，返回 `{sum, v, illnessRaw, illnessMonthly, illnessCap, loan, rent, housing, housingExclusive, housingUsed}`。
2. `__sdSum()` 改为调 `__sdAudit()`，仍只返回数值（保持 `__sdApply()` 兼容），并把合计写进 `sdTotal`。
3. `renderBonus()` 改调 `__sdAudit()`，在 `sdLine` 后**把「实际采用值 / 未计入项 / 未封顶对照值」写进被采集的结果容器 `bonusBox`**；动态串用 `en ? English : 中文`，EN 态零 CJK。
4. 公式框「校验：无强校验，空值按 0 兜底。」→「校验：大病医疗按 80000 元/年封顶后摊到 12 个月；住房贷款利息与住房租金不可同时扣除，同时填写时仅按较大者计入；其余项负值按 0 兜底。」
5. 明细区 `<details>` 内补一行 `p[data-zh]` 静态规则说明（英文态显示英文，中文态由 `js/tool-i18n.js` 的 `p[data-zh]` 还原机制写回中文）。

**`i18n/tools/en/finance/tax-calculator.json`**：formula-eq 的键即中文原串，采用**文本级精确 replace** 同步删旧键片段、加新键片段，英文值同步 `Validation: serious illness is capped at 80000 yuan/year …`；`json.load` 校验通过，并用 `html.unescape` 断言 HTML 公式框文本与 map 键**逐字一致**（避免整档 `json.dumps` 重排）。

**关键取舍**：台账原方案写「置灰另一项」。本批改为「提示 + 自动按较大者计入」，不新增 radio/select 控件、不改禁用态，避免新增控件改变输出元素拼接顺序而触发大面积用例漂移；按较大者也符合纳税人利益最大化，且说明行明确写出被忽略项，口径可复核。
