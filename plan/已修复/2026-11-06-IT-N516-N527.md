### IT-N520 · email-qr「伪二维码」
- 审计原文：`:262-282` `renderQR` 只画三个定位符与时序线，其余 29×29 模块由 FNV 种子伪随机填充；无数据编码 / Reed-Solomon / 格式信息，扫码得不到 `mailto:`。
- 当前源码（`tools/it/email-qr.html:253-272`）：已 `<script src="../../js/qrcode.js">`，`drawQR(text)` 走 `qrcode(0,'M') → addData(text) → make()`，按 `qr.getModuleCount()` 逐模块 `isDark()` 绘制并留 4 模块静区；`generate()` 把 canvas 挂到 `.qr-wrap`。**固定 29×29 噪点实现已不存在**。
- 既有回归：`it/email-qr` 主用例（mailto 百分号编码）+ 自动补强用例（`abc123测试` → `mailto:abc123%E6%B5%8B%E8%AF%95...`）均通过。
- 结论：审计证据为旧快照，归档不改码。

### IT-N521 · location-qr「伪二维码」
- 审计原文：`renderQR()` 固定 25×25、仅定位角 + 定时线 + `strHash`/LCG 噪点。
- 当前源码（`tools/it/location-qr.html:255-274`）：与 email-qr 同构，已改用 `js/qrcode.js` 真实编码 `geo:` 载荷。`strHash`/LCG 已不存在。
- 既有回归：`it/location-qr` 主用例（`geo:31.2,121.4?q=P`）+ 自动补强用例（非数值 → 纬度范围提示）均通过。

### IT-N522 · location-qr「经纬度不校验范围」
- 审计原文：`buildGeo()` 仅 `parseFloat(v)||0`，输入 `999` 会生成 `geo:999,999`，非数字静默变 `geo:0,0`。
- 当前源码（`buildGeo()`）：逐项 `if(!latRaw||!lngRaw) return {error:...}`、`isFinite()` + `lat<-90||lat>90` / `lng<-180||lng>180` 范围校验；`generate()` 遇 `built.error` 直接显示「⚠ …」并 return，不再渲染二维码。
- **本批补锁定用例 1 条**：`it/location-qr` 注入 `lat/lng=999` → 断言「⚠ 纬度需在 -90 ~ 90 之间」。与既有 NaN 补强用例互补（范围校验 vs 非数值校验），防后续回退。
- 结论：审计证据为旧快照，归档不改码，仅补回归护栏。

## 二、本批真实修复（9 条）

### IT-N516 · docker-cheatsheet 命令尾 `-- 注解` 破坏命令（中）
- 根因：bash 注释符是 `#`，`--` 在 `docker ps -q  -- 仅 ID`、`docker stop $(docker ps -q)  -- 停所有`、`docker rm -f $(docker ps -aq)  -- 删所有` 中会被当作参数 / 容器名，复制即执行失败。
- 修复：`tools/it/docker-cheatsheet.html` 三处 `  -- 中文` → `  # 中文`（shell 合法注释）；同步 `i18n/tools/en/it/docker-cheatsheet.json` 的 3 个 example 整句键与英文值。

### IT-N517 · docker build 语法字段错误（中）
- 根因：`"docker build [options] -t name:path"` 把镜像 tag 与构建上下文混为一谈，且漏掉必需的上下文 PATH。
- 修复：改为 `docker build [options] -t name:tag PATH`；EN map 无此键（纯 ASCII，英文态不受影响）。

### IT-N518 · emacs-cheatsheet 启动命令 `-- 注解` 被当文件名（中）
- 根因：`emacs -nw file.txt  -- 终端模式` / `emacsclient -t file.txt  -- 连接守护进程` 是真实 shell 命令，`--` 后中文会被当作文件名分别打开。
- 修复：两处改 `  # 中文`；同步 EN map 的 example 整句键与英文值。表格内其余 `C-x …  -- 说明` 属键位速查分隔符、非 shell 命令，审计未点名，保持原样。

### IT-N519 · emacs 撤销条目 params 自相矛盾（中）
- 根因：`"params": "C-/ 重做"`，但同条 example 与 `:170` 说明均标 `C-/` 为撤销，重做需 `C-g C-/`。
- 修复：改为 `C-x u / C-/ 撤销；C-g C-/ 重做`；EN map 键同步为 `C-x u / C-/ undo; C-g C-/ redo`。

### IT-N523 · lorem 数量不精确 / 负数输出空串（中）
- 根因：`parseInt(...)||1` 不拦负数；words + `startLorem` 分支固定塞 `['lorem','ipsum']` ⇒ `count=1` 输出 2 词；`count=-5` 时循环不执行输出空串。
- 修复（`tools/it/lorem.html:generate()`）：`parseInt(...,10)` → `isFinite` 兜底 → `Math.max(1,Math.min(100,raw))` 钳制并**回写输入框**；words 分支首词固定 `lorem`，`count>=2` 才追加 `ipsum`，再补到恰好 `count` 个。
- 证据：`scripts/_verify_lorem_runtime.mjs` 5 条（1 词 / 2 词 / 5 词 / -5 钳制回写 1 / 1000 钳制回写 100 且 100 段）。

### IT-N524 · lorem 预设 / 历史回调只下载不重算（中）
- 根因：`__loremPresets()` 的预设回调与 `TBKit.history.mount()` 的历史恢复回调都接 `downloadTxt()`。
- 修复：两处改为 `generate()`（页面已有 `generate` 包装会触发 `__loremExtras()`；历史回调期间 `__lorem_skip=true` 不会重复记历史）。
- 证据：运行期脚本 3 条源码断言（两处 `generate()` 落地 + 两处 `downloadTxt()` 已消除）。

### IT-N525 · lorem 中文占位 / 句长范围承诺未实现（中）
- 根因：页面承诺「支持中文占位文本」「可指定句长范围」，但 `chineseTexts` 与 `randomChineseSentence` 是死代码，无任何控件。
- 修复：新增「中文」类型按钮（`data-type="chinese"`，输出 count 行中文占位句，按换行连接）；新增 `minWords` / `maxWords` 两个数字控件与 `sentenceRange()`，句 / 段模式句长由区间决定；`formula-eq` 同步改为四种模式 + 钳制 + 句长说明。
- **兼容性**：`sentenceRange()` 缺省值取 `[8,19]`，与原 `8 + floor(random()*12)` 完全同分布，既有 `it/lorem` 自动补强用例（依赖固定随机序列）17/17 中保持通过，无需改写。
- i18n：EN map 新增 `中文` / `句长（词数）:` / `作用于句子 / 段落模式` 三条键 + 新 formula-eq 整句键。
- 证据：运行期脚本 5 条（chinese 3 行、句长 3–3 每句 3 词、chinese 分支源码、控件与公式同步、默认区间 8–19）。

### IT-N526 · markdown-lint 检查项承诺未实现（中）

- 修复（`tools/it/markdown-lint.html`）：补齐 **MD009**（`/[ \t]+$/` 行尾多余空格）、**MD013**（行宽 > 80 列）、**MD040**（首个围栏 ``` / ~~~ 未标注语言）三条检查；检查项、规则集、`formula-eq` 文案与实现逐条对齐（MD007 / MD041 明确标注「留给团队规范」，不再含糊承诺）；三处文案的 EN map 键同步。

### IT-N527 · markdown-lint 强调语法误报 + 代码块内误判（中）
- 根因：`/^\s*[-*]\S/` 把 `*斜体*`、`**加粗**` 当成列表缺空格；循环不识别围栏，代码块内 `# 注释` 参与标题层级 / 重复计数。
