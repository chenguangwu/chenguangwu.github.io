### IT-N236 "错误格式"示例非法 JSON + 未引 RFC 9457（低，真修）
- 修复：COMMANDS 中「错误格式」的 syntax 补全为合法 JSON `{"error":{"code":"ERROR_CODE","message":"human readable message","details":{"field":"name"}}}`；params 增 `另见 RFC 9457 application/problem+json：{type/title/status/detail/instance}`；引据表新增「错误响应格式 / RFC 9457」行（中英 data-zh 齐全）；英文映射补 params 新串。
- 证据：JSDOM `JSON.parse(e.syntax)` 成功且 code/message/details 齐全、params 含 problem+json；旧源码 syntax 缺冒号值、JSON.parse 抛错 ⇒ RACERR BAD。

### IT-N237 deep-dive 把 POST 建指向 /users/{id}（低，真修）
- 修复：deep-dive「命名」示例改为集合与实例分开：`POST /users` 建、`GET /users/{id}` 查单个、`PATCH/DELETE /users/{id}` 改删，明确创建 POST 到集合而非带 id 实例地址。权威源 `content_deepdive.json` + 页面 + 英文映射三源同步。
- 证据：JSDOM 读 rawHTML 断言无旧串「GET 查、POST 建、PATCH 改」、含新集合/实例区分；deepdive source sync audit 4573 页 0 不一致。该条为静态文案，靠真机脚本 + audit 覆盖（harness stub 不采集 deep-dive 静态块，故未加 verify 用例）。

### IT-N238 HMAC 长密钥 TypeError（高，其他 agent 已修好，本批复核补证据）
- 进批探测：清单描述的行号（`k=md51(k)` 后 `charCodeAt`）与当前源码不符——当前 `hmacMd5` 已按 RFC 2104 把超长密钥先取 MD5 原始 16 字节（小端）再补块，中文长密钥不再抛 TypeError。
- 复核：用 node crypto 按「文本 UTF-8 语义」（本工具密钥/消息均 UTF-8 编码）算 5 组参考值（含 68 字节长密钥、40 中文 120 字节），页面 hmacMd5 逐字一致 5/5；中文长密钥返回合法 32 位 hex。注意 RFC 2202 原始字节向量不适用于文本工具（会把 key 当原始字节，UI 输入会被 UTF-8 编码），已按正确语义核对。
- 结论：缺陷已修复，本批确认并销账，无新增改动。

### IT-N239 UTF-16 码元非标准摘要（中，真修）
- 修复：删除「UTF-8编码」勾选框（含 preset 中 3 处 utf8 字段与 data-tb-presets 一处），`md5()` 恒按 UTF-8 字节串计算（与文件哈希/HMAC/主流实现一致），不再提供会产出非标准摘要的码元模式。
- 证据：JSDOM 中文 `密码学哈希函数测试` 结果 = `0069fbe6a5a50eaf7315ee7eda065ac2` = crypto md5(utf8)（旧取消勾选得 `c2981cdd…` 非标准值）；verify 原 checkIds 去掉失效的 `utf8` 并更新 ref（a7bac... 大写锚仍成立）。

### IT-N240 虚假"批量生成/碰撞检测"宣称（中，其他 agent 已修好，本批复核补证据）
- 进批探测：JSON-LD description 与 intro 已改为「逐行批量计算与大小写切换」，碰撞检测宣称已删；`lineMode`/`lineResults` 逐行批量为真实功能。
- 复核：JSDOM 开启 lineMode 注入 `abc\ndef`，逐行表产出 2 行且含 `abc` 的正确摘要 `90015098…`；无旧虚假宣称串。
- 结论：缺陷已修复，本批确认并销账，无新增改动。
