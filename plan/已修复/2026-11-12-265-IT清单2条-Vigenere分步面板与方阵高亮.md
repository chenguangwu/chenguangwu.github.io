## 处理结果

### IT-N164 解密分步面板 P/C 标签与公式整体反转（中）— 真改

- 根因：`vigenere()` 解密时 `step.plain = ch`（其实是输入的密文）、`step.plainIdx = p`（密文下标）、`step.cipherIdx = c`（解出的明文下标），而 `updateStepDisplay()` 固定按「明文字母 / 结果」渲染，并写公式 `(cipherIdx - keyIdx + 26) mod 26 = plainIdx`，代入后左右不相等。清单复现（解密 `LXFOPVEFRNHR`/`LEMON` 第 1 步）在旧源码上实测为：`明文字母: L (位置 11)`、`(0 - 11 + 26) mod 26 = 11`。
- 采用清单方案：给每个 step 增加**语义无关的输入/输出角色字段** `inLetter / inIdx / outLetter / outIdx`（大写、小写两个分支都补），原有 `plain/plainIdx/cipher/cipherIdx` 保持不变以兼容可视化表、历史与高亮逻辑，避免大范围重构引入回归。
- `updateStepDisplay()` 改为按模式渲染：
  - 加密：标题「加密第 N 个字符」、`明文字母: inLetter (位置 inIdx)`、公式 `(inIdx + keyIdx) mod 26 = outIdx`、`结果: outLetter (位置 outIdx)`；
  - 解密：标题「解密第 N 个字符」、`密文字母: inLetter (位置 inIdx)`、公式 `(inIdx - keyIdx + 26) mod 26 = outIdx`、`结果: outLetter (位置 outIdx)`；
  - 公式两侧现在恒等（第 1 步 `(11 - 11 + 26) mod 26 = 0`，输入密文 L/11 → 输出明文 A/0）。
- 动态文案全部走 `TBKit.util.isEn()` 三元 helper，英文态为 `Decrypt step 1 / Ciphertext letter / Key letter / index / Result`；顺手把「点击"下一步"开始分步演示」默认提示也做了中英双态（原文是硬编码中文，EN 态会残留 CJK）。

### IT-N165 解密时方阵高亮行列互换（低）— 真改

- 方阵定义是「行 = 密钥字母、列 = 明文字母，交叉点 = 密文字母」（见页面 meta 与表格说明）。旧 `highlightVigenereTable()` 解密分支取 `rowIdx = step.cipherIdx`（明文下标）、`colIdx = step.keyIdx`，行列对调；因加法可交换，格子里的字母仍恰好是密文，但行列标题指向错字母，用户对照方阵会读错。
- 改为 `rowIdx = step.keyIdx`（两模式一致）、`colIdx = encrypt ? step.plainIdx : step.cipherIdx`。解密第 1 步由旧 `row-0 / col-11` 改为 `row-11 / col-0`，交叉格 `cell-11-0` 值仍是 L；加密保持 `row-10 / col-0`（值 K）不变。
