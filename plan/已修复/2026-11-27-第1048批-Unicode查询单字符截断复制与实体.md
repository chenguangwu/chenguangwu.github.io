1. **名称搜索结果截断未告知**
   - 名称检索改为先统计全部匹配数，再按单次上限（200）收集结果；不再一达到 200 就静默停止。
   - 结果区增加名称表覆盖说明；超过上限时显示「已显示前 N / 共 M 条匹配；可继续加载」并提供「再显示 200 条」按钮。

2. **单个英文字母被当作名称检索**
   - 在码点解析之后、名称检索之前增加单字符精确查询：`A` → U+0041，`a` → U+0061，单个 emoji/汉字同样直接成格。
   - 码点输入（`U+2603` / `0x2603`）优先级保持不变；含空格的输入才按名称检索。
   - 含空格的名称查不到时明确显示「未找到匹配」，不再把名称拆成 N/O/T 等单字卡片；普通无空格文本仍保留逐字符展示。
   - 新增搜索模式提示（用 `div` 而非 `<p>`，避免被构建首段预渲染覆盖）：单个字符优先精确查询，含空格按名称检索。
   - 回归 `ULSINGLE` / `ULSINGLE2` / `ULNO` 覆盖大写、小写与无名称结果；Chrome 实测 A/a 各只显示 1 格。

3. **复制失败没有反馈**
   - `copy()` 统一处理：优先 `navigator.clipboard.writeText`，拒绝时回退到 `ToolBox.copyText`（统一复制能力，含权限失败提示）；两者均不可用时按钮显示「复制失败，请手动选择」。
   - 成功显示 `✅`，失败保留可手动选择的详情文本；按钮文案按语言恢复。
   - Chrome 实测拒绝 `clipboard.writeText` 且移除 `ToolBox.copyText` 后按钮文案为「复制失败，请手动选择」。

4. **详情未展示 HTML 实体写法**
   - HTML 实体改为 `escapeHtml(htmlEntity)` 以文本方式显示：U+0041 显示 `&#65;`，不再被浏览器解析成 `A`。
   - 新增「复制 HTML 实体」按钮，通过数字码点生成实体文本，避免 HTML 属性解析。
   - 增加边界说明：代理码点可能被替换为 U+FFFD；U+0000 可能被替换或忽略；C1（U+0080–U+009F）可能按 Windows-1252 重映射；普通字符按十进制实体源码显示。
