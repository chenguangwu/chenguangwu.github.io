# 第980批：XML 转换工具合法非 ASCII 标签

## 问题

`xml-to-json` / `xml-to-toml` / `xml-to-yaml` 三页共用的 `xmlWellFormed()` 结构预检使用 `[A-Za-z_][\w:.-]*` 匹配标签名，只允许 ASCII 字母/下划线开头。合法的 `<根><名字>张三</名字></根>` 因标签名无法匹配，被 `s.replace(re,'').indexOf('<')>=0` 判为 XML 解析错误；命名空间形式 `<ns:根>` 因 ASCII 前缀可绕过，行为不一致。

## 修改

三页统一把标签名匹配从 `[A-Za-z_][\w:.-]*` 放宽为 `[^\s<>/]+`：

- 接受中文、日文假名、组合附加符等 Unicode 名称，也接受 `ns:根` 这类命名空间前缀。
- 仍保留结构预检：标签开闭配对、未闭合栈、文本区裸 `<` 继续拒绝；最终合法性仍由 `DOMParser` + `xmlParseFailed()` 判定。
- 未引入自定义 XML 解析器，实体、CDATA、属性引号、命名空间继续由浏览器解析器处理。

## 真机验证

Chrome headless 三页逐项：

| 输入 | JSON | TOML | YAML |
|---|---|---|---|
| `<根><名字>张三</名字></根>` | `{"根":{"名字":"张三"}}` | `["根"]` + `"名字" = "张三"` | `根: / 名字: 张三` |
| `<ns:根 xmlns:ns="urn:x">…` | 成功，保留 `@xmlns:ns` | 成功，附命名空间提示 | 成功，附命名空间提示 |
| `<a><b></a>` | 拒绝 | 拒绝 | 拒绝 |
| `<a>` | 拒绝 | 拒绝 | 拒绝 |
| `<a></b>` | 拒绝 | 拒绝 | 拒绝 |
| `<a title="1>2">x</a>` | 成功 | 成功 | 成功 |
