# 2026-11-07 · 金融-保险（R-H7）：四页历史/差异框改用核心结果键

## 条目（`plan/categories/02-金融财务/insurance.md:147`）

  - `tools/insurance/level-premium-life.html` 记 `{..., v:v}`（折现因子 0.970874），差异框比较 `v`；
  - `tools/insurance/ibnr-reserve.html` 记 `{..., r:r}`（已报案赔款 4,000,000），差异框比较 `r`；
  - `tools/insurance/expense-ratio.html` 记 `{..., e:e}`（营运费用 2,500,000），差异框比较 `e`；
  - `tools/insurance/combined-ratio.html` 记 `{..., c:c}`（赔款支出 6,500,000），差异框比较 `c`。
  用户回看历史、差异对比和导出结果列时看到的是「输入额/中间量」，而非均衡年保费 5,713.34 / IBNR 1,000,000 / 费用率 25% / 综合成本率 90%。

## 根因
1. 四页 `__*Extras()` 里 `TBKit.history.record({...})` 的最后一个键随手写成计算过程中已存在的局部变量（`v` / `r` / `e` / `c`），没有与结果区的核心指标对齐。
2. `TBKit.util.diffBox(host, fields)` 的 `fields` 直接沿用同一个错误键，差异框因而展示「上次计算的折现因子/输入额变化」，与用户关心的指标无关。
3. `TBKit.history.mount` 会把 `rec` 的所有键原样渲染成历史表列名，`TBKit.util.diffBox` 也把键名直接拼进文本（`k + ' ' + from + ' → ' + to`，`js/tool-kit.js:251`）——键名既是数据键又是展示标签，所以不能只改数值、必须换键名。
4. `level-premium-life` 依旧 `exportTable('#level_premium_lifeTable')` 读历史摘要表，导出结果列同样受错误键影响，且缺单位标注。
