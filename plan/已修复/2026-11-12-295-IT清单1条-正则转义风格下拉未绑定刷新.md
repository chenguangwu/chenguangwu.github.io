# 第295批 · IT 清单 IT-N59：正则转义风格下拉未绑定变更刷新

## 清单来源
`plan/categories/01-IT开发/it.md` →「正则转义 IT-N58 已于第246批真机复核销账…IT-N59 的额外元字符集合仍在，风格下拉也未绑定变更刷新」。

- 额外元字符集合：第246批已修 `VERBOSE_META` 剔除 `=,;:<>@#&~` 等非正则元字符，现有集合为 `\\^$*+?.()|{}[]/`（含斜杠，配合「转义 /」开关），属正确实现，无残留。
- 风格下拉：`tools/it/regex-escape.html` 的 `<select id="flavor">` 无 `onchange`，而 `#slash` 复选框和 `#input` 输入框都绑了 `__escLive()`。手动切换「通用 (JS) / 含 / 括号」时结果不刷新（预设路径会显式调 `esc()`，故预设切换正常，掩盖了该 bug）。

## 修复
给 `#flavor` 添加 `onchange="__escLive()"`，与 `#slash`、`#input` 一致。

## 验证
- 新增 `scripts/_verify_regex_flavor.mjs`（JSDOM）：5/5——脚本无异常、下拉存在、onchange 绑定 `__escLive`、切换风格后重算生效（`default=a\.b/c` → `verbose=a\.b\/c`）、与斜杠开关绑定一致。
- **旧源码差分 4/5**（`onchange=""` 绑定用例变红），恢复后 5/5。
- **真机（Playwright selectOption）**：默认 `a\.b/c` → verbose `a\.b\/c`（`/` 被转义）→ 切回 `a\.b/c`，零 pageerror。
- 新增门禁 `regex flavor change binding`，同步 `scripts/gates_manifest.txt`。

## 坑
- verify stub DOM 的 `getAttribute` 不返回内联 `onchange`，且 select 事件不建模 ⇒ 该绑定类用例不能放 `verify_it_calc.js`，须用 JSDOM 独立脚本（能读真实属性 + 派发事件）。
- JSDOM `runScripts:'outside-only'` 不执行内联 handler；验证重算链路改为直接调用与 onchange 绑定的同一函数 `__escLive()`（末尾显式导出引用）。
- 输出元素 `#output` 是 textarea，读 `.value` 而非 `.textContent`。
