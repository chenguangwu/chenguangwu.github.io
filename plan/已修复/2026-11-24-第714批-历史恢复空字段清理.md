# 第714批：历史恢复补空字段清理

## 背景

`plan/历史恢复遗漏空字段.md`：页面 `Snap()` 只保存非空字段，恢复时只遍历 record 已有键，旧记录中原本为空的字段不会被清空。KDIGO 尿量页已实测：保存 `uo12` 为空的有效记录，随后填入 0，恢复旧记录后仍为 0，分期结果改变。静态筛选出 3043 个候选页，全部使用 `TBKit.history.mount` + `history.record`。

## 修复（共享层，一次覆盖全部候选）

`js/tool-kit.js`：

- `history.record(obj)` 写入前扫描本页 `input[id] / select[id] / textarea[id]`，排除 button/submit/hidden/disabled：
  - 未勾选 checkbox/radio 记为空字段；
  - 其他控件 `value.trim()===''` 记为空字段；
  - 空字段 id 列表存入 `obj.__tbEmpty`（数组），只作恢复元数据。
- `history.mount()` 恢复前：
  - 新记录有 `__tbEmpty`：只清空这些字段，再回填旧值，避免误清未参与快照的控件。
  - 旧记录无 `__tbEmpty`：清空本页所有可编辑控件（跳过 search 等）作为兼容路径，并 toast 明确提示“该历史记录版本较旧，恢复前已清空本页输入”。
- 历史面板展示与 `diffLast` 跳过 `__` 前缀元字段，不把 `__tbEmpty` / `__tbScore` 显示成字段。
- 已有页面自带的显式清空逻辑（如 KDIGO）保留，不冲突。

## 验证

代表页 `tools/accounting/calc-2.html`：

- 保存记录 A：收入 500000、成本 300000、`loss` 为空；record 的 `__tbEmpty` 包含 `loss`。
- 修改 `loss=100000` 生成 B，再点击 A：`loss` 恢复为空，结果与保存 A 时一致。
- 历史面板不显示 `__tbEmpty`。
- 删除 A 的 `__tbEmpty` 模拟旧记录，恢复时 `loss` 被清空，并出现“该历史记录版本较旧，恢复前已清空本页输入”提示。
- 已有 KDIGO 显式清空逻辑未回归；`verify_nephrology_calc` 40/40、`verify_accounting_calc` 82/82。
- 静态测试 0 失败 0 告警。
- 全量 `run_gates.py` 结果见提交前验证。

## 备注

`__tbEmpty` 只保存控件 id，不含用户输入内容；随历史记录保存在本机 localStorage，不上传。旧记录兼容路径会清空本页可编辑控件，已有提示，避免旧空值污染新计算。
