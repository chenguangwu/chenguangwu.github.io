# 第 457 批：社交分享图尺寸声明补齐

## 问题

全站社交分享图统一为 `https://chenguangwu.github.io/og-image.png`（1200×630），但大量页面只有 `og:image`，没有 `og:image:width` / `og:image:height`。Facebook、LinkedIn、Slack、飞书等平台在抓取分享卡片时，如果缺少尺寸声明，需要先下载图片才能确定宽高比，首屏卡片可能延迟渲染、被裁切或降级为小图。

只读审计（2026-11-22）：

- 2,673 个页面有 `og:image` 但缺 `og:image:width` / `height`；
- 其中 `guides/**` 2,640 页、`tools/it/**` 30 页、根页 `about.html` / `chains.html` / `search.html` 3 页；
- `og:image:alt` 已由第 446 批补齐，全站 0 缺失，无需重复处理。

## 修复

在 `_build.py` 新增 `ensure_og_image_dimensions()`，放在全站页面生成完成、繁体站生成之前：

- 扫描所有源 HTML（排除 `zh-tw/`、`_en-i18n/`、`node_modules`）；
- 跳过 `TOOLBOX-REDIRECT` 迁移存根和 `meta refresh` 跳转页；
- 仅处理含 `property="og:image"` 的页面；
- 缺少 `og:image:width` 时补 `content="1200"`，缺少 `og:image:height` 时补 `content="630"`；
- 已存在任意一个尺寸字段时只补另一个，已完整则完全不动，保证幂等；
- 新字段紧跟 `og:image` 标签插入，不改变原有属性、顺序和其他社交标签。

繁体站随后由 OpenCC 复制源页面，自动继承尺寸声明。

## 结果

- 构建输出：`OG image dimensions: 2673 pages updated`；
- 全站复核：16,152 个带 `og:image` 的 HTML（源页 8,065 + `zh-tw/` 8,087）全部具备 width/height，缺失 0；
- 数值复核：全部为 `1200` / `630`，错误 0，重复声明 0；
- 二次构建：`OG image dimensions: 0 pages updated`，工作区状态数量不变，幂等通过；
- 静态测试：4,626 passed / 0 failed / 0 warnings（4,606 个工具）；
- 死链门禁：16,743 文件 / 160,344 内链，0 死链；
- 资产完整性：0 资产死链 / 0 `lang` 缺失 / 0 重复 id；
- 内联标记位置审计：4,921 页，0 处加固片段违规。

## 变更规模

- `_build.py` +2,673 个页面：2,640 指南、30 个 `tools/it` 页、3 个根页；
- 每页新增 2 行 meta，无正文、脚本、样式变化。
