# 复核失败重做批次 · 申请再次复核 — IT-N509

> 来源：`plan/复核失败/2026-11-09-第一批.md` 的「IT-N509 Code 39 仍允许内部起止哨兵」条目，重做后重新移交。

## 复核失败点原文
`buildCode39('A*B', false)` 返回有效位串，内部 `*` 是起止哨兵，不属于页面列出的数据字符，可能导致扫描提前终止。

## 根因
`buildCode39()` 未校验数据字符中是否含起止哨兵 `*`，哨兵只应由编码器在首尾添加；数据内出现 `*` 会破坏条码结构，使扫描器提前终止。

## 修复位点
- `tools/it/barcode-code39.html:267`：`buildCode39` 开头 `if(text.includes('*')) return {error:'*'};`；`generate()` 据此输出「⚠ 不支持字符「*」，Code 39 仅支持 A–Z、0–9、空格与 - . $ / + %。」

## 验证证据
- node 复算：`buildCode39('A*B', false)` 返回 `{error:'*'}`；合法 `HELLO` 仍输出 `*HELLO*`。
- `scripts/verify_it_calc.js` 新增 `data:"A*B"` 用例（expect 含「不支持字符「*」」），整 slug 回归 12/12 通过；既有字符集校验（`abc123测试`）用例同绿。

## 判别力实测（回退源码应转红）
回退该 `if` 守卫 → `A*B` 被当作正常数据编码为 `*A*B*`（多哨兵），新用例转红；合法样例不受影响。
