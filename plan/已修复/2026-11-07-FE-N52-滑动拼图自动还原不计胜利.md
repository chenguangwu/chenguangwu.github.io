# 2026-11-07 FE-N52 滑动拼图「自动还原」不记为胜利

- 分类：11-文娱爱好 / fun
- 页面：`tools/fun/sliding-puzzle.html`
- 缺陷：自动还原被记为胜利，写入 0 步最佳纪录并污染完成局数统计
- 严重度：高（确认源码缺陷，非陈旧快照误报）

## 失败点
`solveAnimation()` 反向回放结束后直接 `won=true; celebrateWin()`；而 `celebrateWin()` 在 `:1004-1005` 被包裹为「写最佳 `saveBest(moves,elapsed)` + 记完成局数 `__spRecord()`」。自动还原不增加 `moves`、也不重置计时，于是以玩家当前步数/用时（刚开局时为 0/0）记为「新纪录」，并计入完成局数；该尺寸/模式的最佳此后无法再被正常刷新（步数最小为优，0 步恒最优）。

## 根因
演示路径与胜利路径未解耦：自动还原复用了胜利结算（含成绩写入），但演示不应产生成绩。

## 修复位点
文件 `tools/fun/sliding-puzzle.html`（`solveAnimation()` 内 `doStep` 完成分支，约 900 行）：
- 改为独立演示路径：`won = true; playing = false; stopTimer(); ToolBox.showToast(spT('演示完成，不计入对局成绩', 'Demo finished — not counted as a win'), 'info');`
- 不再调用 `celebrateWin()`（不写最佳、不计完成局数、不弹胜利弹窗）。

## 证据
1. `python3 _build.py` 重建成功（BUILD_EXIT=0），A 级率 100%（4700 页）。
2. `node scripts/verify_fun_calc.js` 35/35 全过。
3. `scripts/_verify_fun_batch_fe_n52.mjs` JSDOM 两态锁：清 localStorage → `startGame()` → `solveAnimation()`，轮询 `puzzle_games_v1`：
   - 当前（修复后）：自动还原完成不写入任何完成记录，localStorage 键数 0→0 → **PASS (exit 0)**。
   - HEAD（修复前）：自动还原完成写入 1 条完成记录（localStorage 键数 0→2）→ **FAIL (exit 1)**，确认 bug 真实且已修。
