## 踩坑与教训

1. **锁着旧错误行为的补强用例必须同批升级**：`data=42` 的自动补强用例 expect 是 n=1 时显示「—」的旧输出，修复后必然变红。类似 617 批线性回归用例，须同批改 expect 与 ref，不能拖到全量红。
2. **stub DOM 不建模子节点删除，容器嵌套缺陷只能真机发现**：`sample-variance` 四面板嵌在 `#result` 内，verify 桩里节点始终存在、全绿，jsdom 里首次计算后 `svTable` 直接为 null。故此类缺陷须靠 jsdom 全链路 + 源码结构 grep 双证。
3. **多层包装器会在清空后重绘**：`calcTool` 被 `__itExtras()` 与 `__itChart()` 两层包装调用，主算 `__itClear()` 清空后 `__itChart()` 仍画参考曲线。停算守卫必须一路同步到所有包装层，不能只改主算。
4. **保真检查不能按裸词断言**：旧用例升级后 ref 里仍保留旧输出串作为说明，检查脚本按「文件不含该串」判定会误报失败，改为检查新 expect 与升级标记。

## 复核要点

- 真机切页签时样本方差「数据表」页能同时看到明细与差异；n=1 与恢复合法输入的状态链无残留。
- 独立 t 检验在 n=1 / s=0 / 非整数 n / 恢复合法值四态下主结果、明细、历史、参考曲线一致；不等样本量时表格 t 与主结果同为合并口径。
- 相关系数 X 或 Y 恒定、恢复合法、清空输入三种状态下不出现强度结论与「—」并存。
