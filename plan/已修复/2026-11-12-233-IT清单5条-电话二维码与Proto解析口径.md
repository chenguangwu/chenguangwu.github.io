### IT-N276 map<> 解析（高，主路径其他 agent 已修，oneof 内本批补修）
- 进批探测：`parseField` 已支持 map<>（message 内），但 `parseOneof` 仍把 map 当普通类型、`<` 当字段名。
- 修复：parseOneof 内联 map<> 消费（`<` + keyType + `,` + valueType + `>`，支持限定名 `.`），输出字段带 mapKey/mapValue。
- 证据：JSDOM 输入 `message Outer { oneof pick { map<string,string> opts=1; } }` → 解析成功含 `"map<string, string>"`/`opts`（旧「期望 ;」）；verify 增 oneof map 强锁。

### IT-N277 校验只数括号（高，其他 agent 已修主体，本批补未知顶层文本漏洞）
- 进批探测：`doValidate` 已真正调用 parseProto（不再是括号计数），但 `message X { int32 a }` 已报失败；然而 `not proto at all` 仍报「✅ 校验通过」——主循环 `else { next(); }` 把未知顶层 token 静默跳过。
- 修复：顶层未知 name token 抛「无法识别的顶层内容「X」」；允许顶层空语句 `;`；保留 `extend {…}` 块跳过（兼容）。
- 证据：JSDOM 三类输入：非法字段 → 失败、任意文本 → 失败（含「无法识别的顶层内容」）、合法 proto → 通过；verify 增强锁。
