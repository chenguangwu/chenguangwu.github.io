# 第 1373 批：预设数据与页面字段错位修复（一）

## 根因
`TBKit.preset.bar` 的 `values` 键按「字段 id」写入。历史模板换代（字段改名 / 控件从输入框改为单选）后，
预设仍用旧键名或旧取值范围，导致：① 写入落空（点预设无效果）；② 写入非法下拉值（结果出现 `undefined`/`—`）；
③ 预设语义与页面功能完全不符（沿用其它工具模板的「5/12/30 条数量」）。

## 本批修复（4 页）
| 页面 | 缺陷 | 修复 |
|---|---|---|
| tools/tunnel/lining-thickness.html | 「极端工况」设 `inGrade=8`，但下拉只有 1–7 级 → 结果全为 `undefined` | 改为 `inGrade=7` 并把跨度提到 16 m |
| tools/tunnel/support-design.html | 同上 | 同上 |
| tools/hr/generator-36.html | 预设为「5/12/30 个员工编号」，与页面「制度文本生成」毫不相干，且 `cnt` 字段不存在 | 改为「员工手册 / 请假流程 / 离职交接单」三个真实场景，写 `docType`/`company`/`ver` |
| tools/nutrition/generator-nutrition-label.html | 预设为「3/10/20 例批量生成」，页面实际是单产品营养成分表；`cnt` 不存在 | 改为「原味酸奶 / 苏打饼干 / 混合坚果 / 无糖气泡水」四组真实营养数据（含份重） |

## 验证
`verify_tunnel_calc.js` 9/9、`verify_hr_calc.js` 48/48、`verify_nutrition_calc.js` 25/25；
