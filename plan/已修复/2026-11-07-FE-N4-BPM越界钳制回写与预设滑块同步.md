# FE-N4 · BPM 越界钳制后输入框/滑块不同步（已修复 · 待复核）

- 分类：11-文娱爱好 / fun-entertainment
- 工具页：`tools/music/bpm-converter.html`
- 移交日期：2026-11-07
- 来源条目：`plan/categories/11-文娱爱好/fun-entertainment.md` → FE-N4

## 失败点（用户可见缺陷）
1. 用户在 BPM 输入框键入超出 40–300 的值（如 `500`）后，计算按钳制后的 300 进行（四分音符 = `200.00ms`），但输入框仍显示原始 `500`，所见数值与实际计算值不一致，误差可达 4 倍以上。
2. 点击预设「小规模/大规模/极端工况」时只写入 `bpmInput`，不写 `bpmSlider`，滑块拇指仍停留在上一位置（如默认 120），视觉与输入值不符。

## 根因
- `getBpm()`（行 495-500）已做内部钳制 `[40,300]` 供计算使用；但 `onBpmChange`（行 503-508）仅 `bpmSlider.value = val` 同步滑块，**未把钳制后的 `val` 回写 `bpmInput`**，导致输入框保留越界原值。
- 预设定义（行 836）仅 `小规模/大规模/极端工况` 只设 `bpmInput`，缺 `bpmSlider` 字段。

## 修复位点
- `tools/music/bpm-converter.html`
  - `onBpmChange`（约 503-515）：解析 `raw = parseFloat(bpmInput.value)`；按与 `getBpm` 一致的规则钳制得到 `val`；**仅当 `!isNaN(raw) && raw !== val`（输入了数字但越界）时回写 `bpmInput.value = val`**，正常范围内输入（如正在键入 120）不回写以免打断键入；滑块 `bpmSlider.value = val` 始终同步。
  - 预设（约 836）：`小规模`→`{'bpmInput':'60','bpmSlider':'60'}`、`大规模`→`{'bpmInput':'180','bpmSlider':'180'}`、`极端工况`→`{'bpmInput':'240','bpmSlider':'240'}`（默认参数预设本就双写，无需改）。

## 证据（判别力实测）
- `scripts/verify_fun_calc.js` 新增用例：
  - `slug:"music/bpm-converter", inputs:{bpmInput:"500"}, expect:["200.00"]` —— 注入 500 → 钳到 300 计算，四分音符 `200.00ms`；若未钳制则按 500 算得 `120.00ms`。
  - 默认 `bpmInput=120` → 四分音符 `500.00ms`、其余音符时长均不为 `200.00` ⇒ 零逃生。
- `env -u NODE_OPTIONS node scripts/verify_fun_calc.js music/bpm-converter` → `fun calc 1/1` PASS。
- `env -u NODE_OPTIONS node scripts/discriminate_check.js scripts/verify_fun_calc.js` → 全量 **29/29 正确变红、0 逃生项**。
- 整份 `env -u NODE_OPTIONS node scripts/verify_fun_calc.js` → **29/29** 通过（无回归）。

## 复核要点（供复核方）
- 边界：输入 `40`/`300` 正常范围内不回写；输入 `500`/`10` 回写钳制值；清空输入（NaN）不强制回写。
- 预设点「小规模」后滑块应落到 60、「大规模」180、「极端工况」240，且与输入框一致。
- 注：本工具计算本身早已按钳制值进行（getBpm 内部钳制），本次修复的是「显示与计算不一致」的 UX 一致性问题，非计算错误。
