# 第288批 · 13 个新 telecom 工具 C→A（老板点名）

## 诉求
第284批拆分的 13 个独立 telecom 工具页质量为 C。老板要求「把刚才新增的工具从 C 升到 A」。

## 根因
`_build.py::classify_quality`：`A = (rich && own_len>=800) or own_len>=6000 or (own_len>=3000 && inputs>=3)`。
13 页 `rich=True`（formula-box 正文达标），但核心逻辑在共享 `js/network-toolbox.js`（跨页共享 md5 去重，不计入 `own_len`），每页 `own_len=388` < 800 ⇒ C。

## 方案（坚持真升质，不改规则、不复制共享 JS 骗分级）
给每页增加**本工具独有、真实有价值**的「结果速读」能力：
1. 共享 JS `render()` 在 `state==='ok'` 后调用 `window.__ntAnalyze(id, display, isEn())`，结果写入 `#analysis-{id}`；失败/无 hook 时清空。T1 的 IPv6 异步追加后也重算。
2. 每页内联脚本定义独有解读器（`scripts/_net_analyze.py` 的 `ANALYZE` 字典，模板注入）：纯本地解析 `display` 文本并给出专业判断——
   - T1 公网 IP：IPv4/IPv6、公网 vs 私有/保留、数据源、时区、IPv6 探测
   - T2 IP 归属：公网/内网、归属地是否为空、ASN 可得性
   - T3 本机 IP：地址数、mDNS 混淆、多网卡
   - T4 可达性：可达比例 + 全通/部分/全断判断
   - T5 URL 可达：结果、探测方式、耗时分级、无状态码提示
   - T6 WebRTC：公网 IP 一致性、内网暴露数、泄露风险
   - T7 NAT：类型、有效映射数、对 P2P 的影响
   - T8 DNS 出口：需配置状态、配置步骤、诚实降级说明
   - T9 CDN：边缘头是否可读、RTT 区间、缓存命中
   - T10 代理分流：推断模式、国内/国外通过数、启发式提示
   - T11 测速：下行等级、延迟、抖动、估算提示
   - T12 指纹：哈希算法、特征维度、隐私与唯一性提示
   - T13 服务状态：正常/降级/故障/未知统计 + 整体健康度
   - 全部不发请求、不伪造；空/失败返回空串，解析失败不影响主结果。
3. 模板加 `.nt-analysis-wrap` 区与 CSS；「💡 结果速读」等静态文案进 `_gen_net_en.py::COMMON`，英文态预渲染、中文态还原。

## 结果
- 13 页 `own_len` 388 → 1398~2329，全部判 A；build 后 A 级 4713（100%），C 级仅 1（其它分类遗留项）。
- 全站 `verify_it_calc.js` 1696/1696。
- 新增门禁项 `telecom net tools analysis`（`scripts/_verify_net_tools.mjs`），专项 **98/98**：13 页结构/解读器/容器 + T1 公网判定强验证 + 解读器判别力（不同输入不同判断、空输入不臆测、英文态零 CJK）。
- 真机（Playwright，13 页×中英双语）：解读器生成≥2 项、预期锚点正确、英文解读输出零 CJK、页面可见 CJK 仅语言选项、1280/375 无横向溢出、无 JS 错误——全过。
- `gates_manifest.txt` 同步新增门禁项，门禁棘轮通过。

## 坑（复用）
- 新增 `run_gates.py` 门禁项必须同步 `scripts/gates_manifest.txt`，否则「清单外多出 1 条门禁」失败（棘轮机制）。
- 解读器输出值若直接取结果文本：英文态喂中文结果文本会残留中文；真实场景结果文本由共享 JS `t()` 在英文态生成即英文，无问题，测试须喂对应英文文本。
- 真机统计可见 CJK 要排除 `<option>`（「繁體中文」语言选项基线 2 处 8 字）。
- `scripts/_net_analyze.py` 的 JS 片段作为 `TPL.format(analyze_js=...)` 的参数值注入，花括号不会被 format 再解析，安全；但模板本身新增的 CSS 花括号须写 `{{ }}`。
