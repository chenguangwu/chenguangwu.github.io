# 2026-11-07 FE-N34 眨眼测试进行中禁改时长

- 分类：11-文娱爱好 / fun
- 页面：`tools/fun/blink-counter.html`
- 缺陷：测试进行中修改「时长」会改写 remain/total，最终速率算错
- 严重度：中（确认源码缺陷，非陈旧快照误报）

## 失败点
时长下拉 `onchange` 直接调 `updateRing()`，该函数无条件 `total=新值; remain=total`，不判断 `running`；正在跑的倒计时被中途换标尺，导致 `elapsed` 与 `remain` 口径错乱、速率误算、评级误判。

## 根因
`updateRing()` 缺少 `running` 守卫，且进行中未禁用时长控件。

## 修复位点
文件 `tools/fun/blink-counter.html`：
- `updateRing()` 开头加 `if(running)return;`（测试进行中忽略时长改动）
- `startTest()` 内 `running=true;` 之后加 `document.getElementById('duration').disabled=true;`
- `stopTest()` / `resetTest()` 内加 `document.getElementById('duration').disabled=false;`（进行中禁用选择，双重保险）

## 证据
1. `python3 _build.py` 重建成功（BUILD_EXIT=0），A 级率 100%（4700 页）。
2. `node scripts/verify_fun_calc.js` 35/35 全过。
3. `scripts/_verify_fun_batch_fe_n34.mjs` JSDOM 两态锁：
   - 当前（修复后）：设 60 秒 → startTest → 改 duration=30 并调 updateRing()（模拟中途改时长）→ #tNum 保持 60 → **PASS (exit 0)**。
   - HEAD（修复前）：同流程 → remain 被改写为 30（#tNum=30）→ **FAIL (exit 1)**，确认 bug 真实且已修。
