# 第667批：默认空态异常值扫描与修复

## 背景

第664–666批已完成工具页、指南页、分类/入口页的真机冒烟，页面无脚本异常。但“能打开”不等于“输出正确”，本批转为扫描**默认空态可见文本**中的异常值，目标是把 `NaN` / `undefined` / `Infinity` / `[object Object]` / `null` 这类会直接暴露给用户的脏输出找出来。

## 扫描方式

- Chrome 无头真机，4 worker 复用页面，遍历 `json/tools.json` 全部 **4,634** 个工具页。
- 默认空态（不注入任何输入）加载后，只取首个 `.card` 的 `innerText`，匹配上述五类关键词。
- 初扫日志：`/tmp/b667_badvalues.log`，命中 46 条。

命中里绝大多数是**正常文案**，不是缺陷，例如：

- JSON 系列工具说明中的 `null` 类型、`JSON.stringify(x, null, 2)` 示例；
- 公式说明里的 `Math.max.apply(null, counts)`、`分母 ≤0 时记 Infinity`；
- 页面明确写“结果含 NaN 时提示”“n<2 时除零得 NaN，页面显示「—」”等防御说明。

逐条过滤后，确认 **4 个真实缺陷**：

1. `tools/gardening/balcony-sunlight.html`：历史记录显示 `sunTab [object Object]`，因为把整张朝向光照配置表 `sunTab` 传给了 `TBKit.history.record`。
2. `tools/it/usb-version.html`：历史记录显示 `info [object Object]`，因为把 `USB_INFO` 整表传给了历史。
3. `tools/it/bluetooth-version.html`：同型，`BT_INFO` 整表进入历史记录。
4. `tools/geometry/pyramid-volume.html`：著名金字塔对照表每行显示 `×NaN`，实际是数据行只有 `[名称, 底边, 高]` 三个元素，却按 `p[2]` 取底边、`p[3]` 取高，导致底面积 `NaN`。

## 修复

### 1. 历史记录组件（系统性）

`js/tool-kit.js::history.mount()` 原先只跳过 `null` / `undefined` / 非有限数字，对象字段会被 `String()` 成 `[object Object]` 直接展示。改为：对象与函数字段只保留在数据中供“恢复历史”使用，不参与列表展示。

```js
if (typeof v === 'object' || typeof v === 'function') continue;
```

这样即使其他页面未来把配置对象存档，也不会再出现 `[object Object]`；历史点击恢复仍能拿到完整对象。

### 2. 三个页面不再把整表写入历史

- `balcony-sunlight.html`：`sunTab:sunTab` → `hours:Number(hours.toFixed(1))`，历史显示每日光照小时数，恢复只依赖 dir/floor/season。
- `usb-version.html`：`info:info` → `rate:row[0]`，历史显示所选版本的最大速率。
- `bluetooth-version.html`：`info:info` → `rate:row[0]`，同上。

### 3. 金字塔对照表索引修正

```js
var A2=p[1]*p[1], V2=A2*p[2]/3;
return [p[0], p[1], p[2], +A2.toFixed(1), __pvFmt(V2), ...];
```

底边取 `p[1]`、高取 `p[2]`，底面积与体积恢复正常；默认 9 m² / 4 m 输入下，胡夫金字塔体积 2,598,551.5 m³、与当前棱锥比 ×216545.95，不再出现 `×NaN`。

## 核验

- 四个页面中/英态真机复测：**0 脚本异常、0 `[object Object]`、0 `NaN`**。
- 历史记录显示：
  - `dir south · floor mid · season spring · hours 6`
  - `v 3.2 · v2 2.0 · conn usbc · rate 20 Gbps`
  - `v 5.3 · v2 5.0 · scene audio · rate 2 Mbps`
- 金字塔表四行均输出正常底边、高、底面积、体积、比值。
- `python3 _build.py` 后修复存活（构建未还原）。
- 全量门禁 **274/274 通过**。
- 修复后全站 4,634 页复扫，确认不再出现 `[object Object]` / `×NaN` 类真实缺陷（剩余命中均为说明文案中的正常关键词）。

## 结论

本批把“页面可打开”推进到“默认输出无脏值”，并修掉一个公共历史组件的对象展示缺陷。后续新增工具若需要历史存档对象字段，展示层已自动跳过，不会再把 `[object Object]` 弹给用户。
