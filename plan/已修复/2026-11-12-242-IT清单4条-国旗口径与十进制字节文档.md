- 根因：参考资料表写"国家码 1-3 位 / E.164 / Dialing code"，但 `COUNTRIES` 数据无 `dial` 字段、详情面板也不显示，属空承诺。
- 修复：选择"删空承诺"而非"补数据"路线——引据行改为 ISO 3166-1 口径（`alpha-2/alpha-3/数字码`），SEO intro（it.json）从"国旗 emoji、国际区号与顶级域"改为"国旗 emoji 与 ISO 代码"，meta/og/twitter 三处由 build 注入同步。
- 证据：JSDOM 断言页面无「国际区号/E.164/顶级域/Dialing code」字样、无 `dial:` 字段、含 ISO 3166-1。

## N309 · 仅收录 48 国且无"未收录"提示（中）
- 根因：`COUNTRIES` 仅 48 条，搜"巴基斯坦"等返回"共 0 个国家/地区"却不说明数据不完整，用户误判为故障。
- 修复：采用短期方案（清单方案允许）——`render()` 无结果且 q 非空时在 grid 输出"未找到匹配项。当前仅收录 48 个常用国家/地区；可尝试 ISO 两位或三位代码。"，count 追加"（仅收录 48 个常用国家/地区）"；英文态走 `TBKit.util.isEn()` 输出全英文（零 CJK），顺带修正上一版英文态仍拼中文前缀的 i18n 缺陷。
- 证据：JSDOM 中文态空结果/有结果两分支、英文态零 CJK，`enc` 与 count 双处锚点。

## N311 · 文档说"Unicode 码点"实际是 UTF-8 字节（中）
- 根因：formula-box 与 FAQ 写"取 Unicode 码点""'中'=20013"，但实现先 `TextEncoder` 再逐字节输出，`中` 实为 `228 184 173`，按 20013 解码会被拒。
- 修复：统一为 UTF-8 字节口径三源同步——
  - 页面静态：`tools/it/decimal-encode.html` 的 formula-box 原理/范围/解码、英文 p 段落；
  - deep-dive 权威源：`i18n/tools/content_deepdive.json` 的 scenarios + FAQ（build 会重注入页面，故必须改源）；
  - 英文映射：`i18n/tools/en/it/decimal-encode.json` 对应 key/value 全改；
  - FAQ 给出 `中` → `228 184 173` 的字节示例并说明码点 20013 不成立。
- 证据：JSDOM 断言页面无旧码点说法、含字节示例、`enc('中',' ')` 实出 `228 184 173`；另直接读 JSON 两源校验口径。
