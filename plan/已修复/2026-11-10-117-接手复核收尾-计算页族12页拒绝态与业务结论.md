## 六、verify 用例契约同步（1 条，重要）

`finance/position-size-calculator` 的 `MARTHIST` 用例原是 F-N189 旧契约：

```js
!localStorage.getItem(HISTORY_KEY) && records===0 && exports===0
```

去掉 `currentResult` 守卫后，`Export()` 会调用 `exportTable` ⇒ `exports=1`，旧断言必然变红（实测 `564/565`）。按「改功能必须同批同步测试」铁律，**同批改写该用例**，锁住 harness 可判别的三个真实行为：

1. 原生 `saveHistory()` 不得写 localStorage（防旧结果残留）；
2. `Export()` 不得再被守卫吞掉（`exports>0`）——旧源码首行 return ⇒ 不命中；
3. Score 按业务输入判定：错误文案判 0、`k-capital=0` 时即使文案正常也判 0——旧 Score 纯词表对「一切正常」返回 1 ⇒ 不命中。

⚠️ **harness 盲区如实记录**：自研 stub DOM 的 `innerHTML` 不派生 `textContent`（实测 `html=[❌ 跌幅须…]` 而 `txt=[]`），`ResText()` 恒空 ⇒ 在 harness 里 `Extras()` 保守 return，**无法覆盖「拒绝态入历史」**。该链路改由真机 JSDOM 脚本全链路覆盖，不塞假 expect、不把盲区伪装成已验证。

**用例差分实测**：`position-size-calculator.html` 写回 `HEAD` → 该 slug `9/10` FAIL；恢复 → `10/10` PASS。判别器亦确认该用例**正确变红**（非逃生项）。

## 八、踩坑

1. **页面改动撞上旧测试契约时，先判「真 bug」还是「测试过期」**：本批 `MARTHIST` 是行为契约变更（复核方要求拒绝态入历史/可导出），不是页面 bug；但绝不能靠删 expect 或塞静态串蒙混，必须换成对旧源码仍会变红的行为锁。
2. **harness 与 JSDOM 的 textContent 语义不同**：`ResText()` 读 `textContent`，在自研 stub 里恒空；把「拒绝态写历史」交给真机脚本，harness 只锁它测得到的部分。
3. **`❌ / ⚠️` 不等于失败**：退休金页「资金不足」是有效结论，批量词表替换必然误判（复核方生成源护栏同源）。
4. **按钮触发页的测试桩要每次点**：只在历史为空时点按钮会让快速连续输入的后两次完全不落到页面，造成大面积假失败。
5. 内联脚本语法自检须过滤 `<script type="application/ld+json">`，否则 JSON-LD 会被当成 JS 报 `Unexpected token ':'`。
