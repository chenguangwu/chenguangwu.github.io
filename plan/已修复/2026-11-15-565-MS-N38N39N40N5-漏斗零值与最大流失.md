# 565 批：漏斗零值口径、最大流失定位与引据表口径（MS-N38 / N39 / N40 / N5）

日期：2026-11-15
范围：`tools/marketing/funnel-calculator.html`、`tools/marketing/marketing-sales-funnel.html`、`i18n/tools/content_deepdive.json`

## MS-N38 上一级为 0 时三处出口结论相反

### 问题
- 汇总表对 `prevVal=0` 兜底为 100%，漏斗图与 CSV 兜底为 0%；同一环节同时出现 100% 与 0%。
- 首级为 0 时整体转化率固定 0%，没有「不可计算」提示。

### 修复
- 抽出 `rateOf(prev,val)`，`prev<=0` 返回 `null`；汇总表、漏斗图、CSV 三个出口统一显示「—」。
- 首级为 0 时整体转化率也显示「—」。
- 结果区提示「第 X 级的上一级人数为 0，环比转化率无法计算，已显示「—」」。
- 另加「第 X 级人数高于上一级」提示，避免漏斗填反产出的负流失被当成正常结果。

### 验收
- 将第 2 级改为 0 → 提示零值，第三级环比与可视化均显示「—」，CSV 同为「—」。
- 首级改为 0 → 整体转化率显示「—」，各级总体转化率同样为「—」。

## MS-N39 未计算流失人数与最大流失环节

### 问题
- 只有环比标红，没有 `prev-val` 流失人数，也没有最大流失定位；与 meta「定位流失瓶颈」的承诺不符。

### 修复
- 汇总表新增「流失人数」列，数值为 `上一级人数 − 本级人数`；上一级为 0 时显示「—」。
- 遍历所有相邻级，取流失人数最大者，结果区输出「最大流失：A → B，流失 N 人（环比 Z%）」，并在表格中高亮该行。
- CSV 导出同步增加「流失人数」列。

### 验收
- 默认 100,000 → 25,000 → 20,000 → 4,000 → 800 → 输出「最大流失：曝光 → 点击，流失 75,000 人（环比 25.0%）」，对应行高亮。
- CSV 表头为「步骤,人数,环比转化率,流失人数,总体转化率」。

## MS-N40 深解把转化率写成掉单率

### 修复
- 深解示例改为「逐级转化 50%/20%/10%，对应掉单率 50%/80%/90%。支付环节转化率仅 10%、掉单 90%，最严重」。
- FAQ「各级乘客单价」改为「各级以客单价」。
