# 第178批 · IT 清单 1 条 · url-params「值解码显示：开/关」假控件

- 来源：`plan/categories/01-IT开发/it.md` → IT-N466（整条删除，覆盖清单 `url-params` 行同步移除该项）
- 修复日期：2026-11-11
- 类型：假功能（开关声明与实际计算逻辑脱钩）

## 失败点
`toggleEncoding()` 只翻转 `_decMode` 并改按钮文案，而 `calcTool()` 解析查询串时恒做 `decodeURIComponent`，从不读取 `_decMode`。点「关」后参数框仍显示解码后的 `toolbox` / `手`，用户无法看到原始编码形态。

## 根因
解码分支与开关状态没有数据通路：`_decMode` 是全局标志，但解析代码把它当不存在；同时解码函数 `decPart` 是 `calcTool()` 局部函数，渲染 URL 的 `renderUrl()` 无法复用。

## 修复位点（`tools/it/url-params.html`）
- 顶层新增 `urlParamsDec(s)`：`+` → 空格后 `decodeURIComponent`，非法百分号按字面回落（不抛错）。
- 顶层新增 `parseQueryPairs(qs, decode)`：按 `&` / 首个 `=` 拆键值，依 `decode` 决定是否解码；`calcTool()` 改为 `parseQueryPairs(qs, _decMode)`。
- `renderUrl()` 关闭解码时用 `urlParamsDec` 先还原参数框里的原始编码值再 `encodeURIComponent`，避免 `%` 被二次编码成 `%25`。**同时修掉了上一轮调试引入的 `decPart is not defined`**（局部函数跨作用域引用）。
