## 1. 失败点

台账 F-N18（中，确认）记录三个相互关联的失败点，只读复核后**全部仍成立**：

1. **四个主输入无下限**：`salary` / `insurance` / `special` / `threshold` 的 `<input type="number">` 均无 `min="0"`。`calculate()` 只对 `taxableIncome` 做 `Math.max(0, …)` 兜底，负值被当成合法数值进入计算链。
2. **负社保虚增应税所得**：`insurance = −2000` 时 `salary − (−2000)` 反而放大应税所得，税额被高估。台账独立复算（专项附加 0）：12000 → 17000、税 990 → 1990；页面默认 `special=2000` 下为 10000 → 15000、税 790 → 1590（JSDOM HEAD 态精确复现 `¥1,590.00`）。
3. **负税后收入直接展示**：`const afterTax = salary - insurance - tax` 无下限，月薪 2000 / 社保 3000（均合法非负）时显示 `¥-1,000.00`。
4. **导出与主页不同口径**：`__taxExport()` 独立复写一套计算，既没有负值校验，`afterTax` 也没有 0 下限 ⇒ 错误输入下仍可导出一份含负到手工资的「明细表」。

## 2. 根因

该页存在**两条并行的计算链**（`calculate()` 与 `__taxExport()`），输入合法性没有收敛成单一真源；`Math.max(0, …)` 只兜住「应纳税所得额」这一个中间量，没有守住最终展示量。负值既无浏览器端 `min`、也无字段级运行时校验，错误态还会残留上一轮的结果/明细表/级距列表，形成「提示与旧结果同屏」的误导。

## 3. 修复位点

**`tools/finance/tax-calculator.html`**

1. 四个主输入统一加 `min="0"`（浏览器端下限，不替代运行时校验）。
2. 新增 `__taxCheck()` 作为**单一真源**：按 `['salary','insurance','special','threshold']` 顺序逐项 `parseFloat`，负值立即返回 `{ok:false, msg}`，`msg` 带字段名并用 `__tbIsEn()` 动态双语（中文「社保公积金不能为负数，请填写 ≥ 0 的数值。」/ 英文 `Social insurance & housing fund must not be negative; enter a value >= 0.`）。空值仍按 0 兜底，与公式框口径一致。
3. 新增 `__taxBlock(msg)`：`calculate()` 校验失败时把 7 个结果元素（`taxAmount`/`afterTax`/`taxRate`/`taxableIncome`/`actualTax`/`effectiveRate`/`annualTax`）统一清成 `—`，清空 `bracketList` 与 `taxResultTable`，覆写 `bonusBox` 为字段名错误提示，然后**早退不参与计算**。
   - `if (!msg) return;` 是必要的免疫守卫：harness 兜底阶段会无参调用顶层函数，否则会把正确提示覆盖成 `⚠ undefined`。
4. `calculate()`：`const afterTaxRaw = salary - insurance - tax; const afterTax = Math.max(0, afterTaxRaw);`；当 `afterTaxRaw < 0` 时，向**被采集的结果容器 `bonusBox`** 追加归因说明（中英动态双语），明确「原始差额为负、请核对填写」。用 `innerHTML = String(innerHTML) + html` 追加（harness stub DOM 不支持 `insertAdjacentHTML`）。
5. `__taxExport()`：开头复用 `__taxCheck()`，负值态用 `ToolBox.showToast(msg,'error')` 提示并 `return`，不写表、不调 `exportTable`；导出明细的 `afterTax` 同样改 `Math.max(0, salary-insurance-tax)`，保证主计算与导出同口径。
6. 公式框静态中文改为明确口径：「…其余明细负值按 0 兜底；月薪、社保公积金、专项附加扣除与起征点均须 ≥ 0，负值字段级拒绝且不参与计算；税后收入下限 0。判据：…」。

**`i18n/tools/en/finance/tax-calculator.json`**：公式框中文原串即 en map 键，做**文本级**键值替换（删旧键 `其余项负值按 0 兜底。判据：…`、加新键），英文值同步 `negative values are rejected at field level` 与 `after-tax income is floored at 0`。`json.load` 通过（map 42 键），`html.unescape` 校验 HTML 公式框与 map 键逐字一致、旧键零残留。

**`scripts/verify_finance_calc.js`**：同批新增 5 条用例（老板 2026-11-07 强调「改工具必须同批改用例」）。

**刻意不动**：第 35 批的 `__sdAudit()` 明细负值 0 兜底逻辑保持原样 —— 明细七项按 0 兜底、四个**主输入**负值则整页拒绝，两层口径分层且都在公式框写明；年终奖/专项附加明细渲染链不改，避免新增控件改变输出元素拼接顺序引发大面积 auto 用例漂移（本批因此**无需重采任何 auto 锚点**）。
