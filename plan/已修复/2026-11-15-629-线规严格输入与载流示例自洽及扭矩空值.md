## 缺陷与根因

| 页面 | 根因 | 表现 |
|---|---|---|
| 线规 | `calcFromAwg` 用 `parseInt` | 输入 12.5 → 按 12 计算：线径 2.053（真值 1.937）、载流 16.5（真值 14.7）；历史里保存的小数 AWG 恢复后被截断，结果与保存值不同 |
| 线规 | `calcFromMm/Mm2` 用 `parseFloat` 且 `if(isNaN||<=0) return` | 清空或填 0 时静默返回，**上一组结果留在页面上**，用户误以为是本次输入的结果 |
| 线规 | 深挖示例写「AWG 20 载流约 5 A」 | 同页 5 A/mm² 规则与对照表给 2.59 A，自相矛盾约 2 倍 |
| 扭矩 | `parseFloat(...)||0` | 清空扭矩值后按 0 换算，输出一整列 0 且 `lastResult` 写成有效结果，可被保存进历史 |

## 修复内容

### 线规页
1. `calcFromAwg / calcFromMm / calcFromMm2` 全部改为 `String(value).trim()` + `Number()`；空值、非数字、反算越界分别提示，**不再静默 return 保留旧值**。
2. 新增 `__wgClear()`：清空 `resAwg/resDmm/resDmil/resArea/resRes/resAmp` 为 `—`、`detailTable` 显示提示、`lastResult=null`。
3. `calcAll()` 入口加 `!isFinite(awg)||awg<0||awg>40` 守卫（双保险）。
4. AWG 输入 `step="1"` → `step="0.01"`，使反算得到的小数线规可原样回填；历史恢复经 `calcFromAwg` 走 `Number`，与保存值一致。
5. 载流示例改为「截面积 ≈0.518 mm²，按本页 5 A/mm² 估算载流约 2.6 A，每千米铜电阻约 33.2 Ω」，并注明实际载流随绝缘与敷设降额。
6. 提示串走 `__wgMsg(kind)` + `TBKit.util.isEn()`，EN 态零 CJK。

### 扭矩页
1. `convert()` 改 `String(value).trim()` + `Number()`，空值/非有限值 → `__tqClear()` 清空 `convGrid` 并提示，`lastResult=null`，**不再写 0 结果**。
2. 提示串走 `__tqMsg()`，EN 态零 CJK。

## 新增判别用例（写入 `const CASES = [...]` 字面量）

1. `awg=12.5` → 期望 `1.937`（旧 `parseInt` 给 2.053）
2. `awg=""` → 期望「请输入 AWG 线规号（0–40）」
3. `mm=0` → 期望「请输入大于 0 的线径（mm）」
4. `val=""`（扭矩）→ 期望「请输入有效的扭矩数值」

## 复核要点

- AWG 填 12.5：线径应为 1.937 mm，结果卡 AWG 显示 12.5。
- 清空 AWG / 线径填 0：结果卡应全变 `—` 并有红色提示，**不再留着上次的数字**。
- 从线径 0.9 mm 反算 → 保存历史 → 点历史恢复：AWG 仍为 19.11 量级，不被截成 19。
- 扭矩页清空数值：结果格显示提示，不再出现 `0.000000e+0` 一整列。
