# 第293批 · IT 清单：TypeScript 编译器加载失败诊断抛错 + 防抖旧输出

## 清单来源
`plan/categories/01-IT开发/it.md` →「TypeScript 编译器加载失败时诊断自身可能抛错（中，代码确认）」两个子问题：
1. `showDiagnostics()` 直接调 `ts.flattenDiagnosticMessageText`；`init()` 轮询 60 次（12s）超时后缺库场景调用它，`ts` 未定义 ⇒ 抛错，失败提示写不进界面，卡在「加载中」。
2. 输入变化后防抖 300ms 才编译，期间复制/下载仍读上次 `jsOutput`。

## 修复（`tools/it/typescript-compiler.html`）
- `showDiagnostics()` 的 msg 计算改为本地 `flattenMsg()`：支持字符串、`DiagnosticMessageChain`（`messageText`/`next`）与数组，完全不依赖 `ts` 全局。缺库时超时分支可直接显示「TypeScript 编译器加载失败…」。
- `setupLiveCompile()` 的 input 监听：输入变化**立即**清空 `jsOutput` 并 `updateStats(0,0,0)`，再 300ms 防抖编译；诊断面板保留上次结果避免闪烁。复制/下载判空走既有 warning 分支，不再取旧输出。

## 验证
- 新增 `scripts/_verify_ts_compiler.mjs`（JSDOM 执行主脚本块，跳过 `text/plain` 的 TS 示例块；导出 `__showDiagnostics` 引用供断言；派发 DOMContentLoaded 触发 init 绑定）：9/9。
- **旧源码差分 2/9**（7 条全红：`ts is not defined`、`value="OLD-JS"`、`statSize=-`），恢复后 9/9。
- **真机（Playwright）**：① 拦截 CDN 缺库 → 直接调诊断分支显示「加载失败」、count=1、零 pageerror；② 正常加载 → 输入变化 jsOutput 立即空、statSize=0，600ms 后重编译产出；零 JS 错误。
- 新增门禁 `typescript compiler guards`，同步 `scripts/gates_manifest.txt`。

## 坑
- 页面 `<script type="text/plain" id="sampleTs">` 里是 TypeScript 源码；verify harness 的 `inlineScripts` 会当 JS 执行 ⇒ `Unexpected identifier 'User'` 初始化失败，无法加常规用例 ⇒ 改用独立 JSDOM 脚本按 `<script>` 无 type/src 属性提取主脚本块。
- JSDOM `eval` 里的 `const`/`function` 不挂 window：脚本块末尾追加 `window.__showDiagnostics = showDiagnostics` 才能从外部调用；`w.eval` 后须派发 DOMContentLoaded，否则 init 不绑定 input 事件。
