# 第 1019 批：BPM 主计算与反向计算分别记录、导出

- 影响页面：`tools/music/bpm-converter.html`
- 对应任务：`plan/music/BPM转换-反向时长为空阻断主结果导出.md`

## 问题

历史/CSV 胶水层先读取反向时长 `reverseMs`，为空或非法时直接 `return`；导出按钮也要求反向时长有效。结果主 BPM 与音符时长已正常显示时，清空反向时长会阻断主结果的历史记录与 CSV 导出，并要求填写无关模块。

## 修复

- 新增 `__bpm_converterMainValid()`（BPM 40–300、非空）与 `__bpm_converterReverseValid()`（时长 > 0、非空）。
- `__bpm_converterResText()` 改为分别采集：
  - 主结果取 `noteGrid` 前三个 `.note-val`（全音符 / 二分 / 四分），前缀“主结果”；
  - 反向结果取 `reverseResult`，前缀“反向”；
  - 两者都无效时返回空，不记录。
- `__bpm_converterExtras()` 只在主、反向都无效时返回；快照按有效模块裁剪：主无效时去掉 `bpmInput/bpmSlider/sampleRate`，反向无效时去掉 `reverseMs/reverseNote`。
- `__bpm_converterExport()` 改为“主或反向任一有效即可导出”，都无效才提示“请先输入有效的 BPM 或时长值”。

## 验证

- Chrome 真机（清空 localStorage）：
  - `bpmInput=120`、`reverseMs=''`：历史表仅含 `bpmInput/bpmSlider/sampleRate`，结果“主结果 2000.0 ms / 1000.0 ms / 500.00 ms”，不含 `reverseMs`；`__bpm_converterExport()` 成功调用 `exportTable`。
  - `bpmInput=''`、`reverseMs=500`：历史表仅含 `reverseMs/reverseNote`，结果“反向 120.00 BPM”，不含 `bpmInput`；导出成功。
  - 无 `pageerror`。
- `node scripts/verify_music_calc.js`：82/82；新增静态守卫覆盖两个有效性函数、快照裁剪与导出条件。
