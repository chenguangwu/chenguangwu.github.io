## 二、失败点 → 根因 → 修复位点

### 1. `word-wrap` 折行核心（`wrap()` / `visualLen()` / `takeByLen()`）

- **F-N160**：`prefix` 只在 `mode==='soft'` 分支算（原 `:322/:329`），`hard/word/chinese` 三模式完全不读 `indent`/`hanging`；预设「英文条款按单词折行 50」正是 `mode:'word', hanging:true`，勾了毫无效果。
  - 修：把 `prefixFor(first)` 提到 `paragraphs.forEach` 内，四种模式共用 `pushLine()`；**前缀计入可用行宽** `avail = width - visualLen(prefix)`（不是最后补空格），soft/hard 的循环条件也改成 `visualLen(prefix)+visualLen(rest) > width`，避免末行超宽。
- **F-N161**：旧实现只把 `[\u4e00-\u9fff\uff00-\uffef]` 记 2 字节，emoji 与 CJK 扩展 B 记 1；控件写「中文 2 字节」、deep-dive/FAQ 写「UTF-8 占 3 字节」。
  - 修：新增 `utf8Bytes(ch)` 按码点判 1/2/3/4 字节；`visualLen`/`takeByLen` 改按 `for(const ch of s)` 码点迭代，不拆代理项，宽度连一个字符都放不下时按码点强取一个防死循环。控件标签与 opt-guide 参数说明同步改「按字节（UTF-8，中文 3 字节）」，与 deep-dive/FAQ 口径一致。**选 UTF-8 而非 GBK 双字节**，因为改计数只动页面 JS，改三处文案会牵动全站生成源。
- **F-N162**：`chinese` 分支只有「放得下就接、放不下整段换行」，单 token 长于 width 时整段压成一行。
  - 修：word/chinese 共用「按 token 装行 + `hardSplit()` 逐段强折」；无标点 45 字长句在宽 20 下应至少 3 行、每行 ≤20 且不丢字。

### 2. `word-wrap` 导出与静态文案（F-N163）

- **导出**：`__word_wrapExport()` 原导出 `#word_wrapTable`（TBKit 历史表，首次为空），不含换行结果。改用 `TBKit.export.csv('word-wrap-result.csv', rows)` 导出**当前折行结果的逐行明细**（行号 / 折行后文本 / 字符数 / UTF-8 字节数），占位态不导出；开头仍 `__word_wrapExtras(true)` 保证最后一次输入同步。
- **套话**：opt-guide 的「点击『计算』或『生成』按钮」改为「点击『换行』按钮」；FAQ 答案改为写明粘贴文本、设宽度与模式、点「换行」；适用场景由「个人或家庭的理财规划、贷款与投资收益测算…」改为「报表备注与合同条款按固定宽度排版、固定宽度文本字段对齐、中英文混排窄栏折行」，同步 opt-guide / opt-faq / FAQPage JSON-LD 三处。
- **页签**：`P` 映射里 `pre → #word_wrapPresets`，而预设栏本来就在输入卡片内常显，点「预设」只是把结果区藏掉、没有任何新面板。删除 `data-pane="pre"` 按钮与 `P.pre` 映射，预设栏保持常显。
- ⚠️ **范围边界（如实记录）**：`meta description` / `og:description` / `twitter:description` / WebApplication JSON-LD 里仍是旧的理财套话，属 **SEO 元数据**，需走 i18n 源另批统一处理，本批不动以免构建覆盖成半新半旧。`scripts/opt_content.py` 是历史一次性生成脚本，**不进 `_build.py` / `run_gates.py` 流程**，故可见 guide/faq 段改页面不会被覆盖。英文态：原套话本就不在 `js/tool-i18n-en.js` 词表里，静态 guide/faq 属项目明确不扫的「页面结构中文」；本批未新增 JS 运行时中文模块、未引入中文 aria-label ⇒ 英文态状态未变差，全量翻译属既有 i18n 专项。

### 3. `swift-bic-validator`（F-N146）

- 入口只 `trim().toUpperCase()`，`DEUT DE FF 500` 被当 14 字符直接命中长度分支。
- 修：新增 `rawInput` 保留原始输入、`raw = rawInput.replace(/[\s-]/g,'')`、`ignored` 计数；长度行注明「已忽略 N 个空格/连字符分隔符」（仅当输入字符合法时显示，避免对 XSS 输入也给分隔符提示）。
- **顺带修（用户「专项任务顺带修 bug」指令）**：该页原本没有 `esc()`，`${raw}` 直接插进 `innerHTML` ⇒ 非法输入回显 XSS。新增 `esc()` 并对输入回显转义；`re.test` 失败时先做 `/^[A-Z0-9]*$/` 白名单分支，明确拒绝非法字符。

### 4. `aadhaar-validator`（F-N152）

- 首位 0/1 分支 `return` 前只写一句「❌ Aadhaar 不能以 0 或 1 开头」，与常规分支（输入/格式化/长度/校验和）结构不一致。
- 修：该分支在既有 `html`（已含输入行）后追加「格式化」「长度」两行，再追加错误行；`00-0000-0000-00` 现在能看到 `0000 0000 0000 / 12 位`。

## 五、踩坑

1. **改页面输出必先跑单分类 verify**：本批一处 swift 文案变更立刻让 `564/565` 变红，先判「测试过期 ≠ 页面 bug」再同批同步，别等门禁炸。
2. **同一 expect 文案在多个 slug 用例里重复**：Edit 精确替换时报 2 处匹配，必须带 `"slug": ...` 上下文定位，避免改错页。
3. **harness blob 折叠空白**：`1\n2\n3` 在 `expect` 里写成 `1 2 3`；真机断言不能直接 `includes('1 2 3')`，要先 `replace(/\s+/g,' ')`。
4. **分隔符计数别凭感觉**：`DEUT DE FF 500` 是 3 个空格不是 4；`toUpperCase()` 后 XSS 输入变成 `&lt;IMG`，断言需大小写不敏感。
5. **静态文案有两类来源**：可见 `opt-guide`/`opt-faq` 由历史一次性脚本生成、改页面安全；`meta/og/twitter` description 走 SEO i18n 源，本批不动，避免半新半旧。
