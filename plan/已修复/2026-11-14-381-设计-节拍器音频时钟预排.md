# 381 设计 · 节拍器改用音频时钟预排（D-N215）

- **分类**：04-设计创意
- **工具页**：`tools/design/web-audio-metronome.html`
- **日期**：2026-11-14
- **缺陷编号**：D-N215（高，确认源码缺陷）

## 缺陷与根因

原调度是 `setTimeout` 链式自调用：

```js
function scheduler(){
  const interval=60000/bpm;
  playClick(currentBeat===0);     // 回调时立即发声
  ...
  timer=setTimeout(scheduler,interval);   // 下一拍基准 = 本次回调的实际执行时刻
}
```

两个问题叠加：

1. **基准漂移**：每拍的下一拍时间以上一次回调的**实际执行时刻**为起点，`setTimeout` 的回调延迟逐拍累加，节拍持续变慢；
2. **无 lookahead**：`playClick` 用 `audioCtx.currentTime` 即时发声，音频事件没有提前排入音频时钟，JS 主线程抖动直接表现为发声抖动；页面自身注释宣称"预排音频事件、避免定时器漂移"，实现与之相反。

复现：120 BPM、每拍回调平均晚 1ms，连播 600 拍（10 分钟）累计慢约 0.6s。

## 修复

采用标准 Web Audio 节拍器架构（lookahead scheduler）：

1. **新增音频时钟基准**：`nextNoteTime`（下一拍的绝对音频时刻）+ `scheduledBeat`（已排拍号），`LOOKAHEAD_MS=25`、`SCHEDULE_AHEAD_S=0.1`。
2. **`playClick(isAccent, when)`** 支持指定发声时刻：`gain.setValueAtTime(vol, t)`、`osc.start(t)`、`osc.stop(t+0.05)`，无参时回退 `currentTime`（兼容旧调用）。
3. **`scheduler()` 改为预排循环**：

```js
while (nextNoteTime < audioCtx.currentTime + SCHEDULE_AHEAD_S) {
  playClick(beatIndex === 0, nextNoteTime);
  /* 仅视觉高亮用 setTimeout 对齐音频时刻，不参与计时基准 */
  nextNoteTime += secondsPerBeat;       // 严格累加，回调延迟不进入基准
  scheduledBeat = (scheduledBeat + 1) % beats;
}
timer = setTimeout(scheduler, LOOKAHEAD_MS);
```

4. **`toggle()` 启动时**以 `audioCtx.currentTime + 0.06` 为基准，避免首拍排到过去时刻；`scheduledBeat` 归零。

拍号切换（`beats` 变更）与 BPM 变更自动生效：下一拍间隔按新的 `60/bpm` 计算，拍号取 `scheduledBeat % beats`。
