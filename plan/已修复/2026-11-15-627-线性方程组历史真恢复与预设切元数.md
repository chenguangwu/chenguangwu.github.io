### SMS-161 · 历史为假恢复（高优）
- 根因：`restoreHistory(mode)` 只按元数写入固定默认系数（d2/d3 常量表），`item.vals` 从未被读；点任意记录得到默认示例。且 `oninput` 每次按键都 `saveHistory`，5 条上限内全是中间态。
- 修正：
  ```js
  function restoreHistory(idx){
    var list=JSON.parse(localStorage.getItem(historyKey())||'[]');
    var h=list[idx]; if(!h)return;
    var ids=h.mode===2?['a1','b1','c1','a2','b2','c2']:['a1_3',...,'d3_3'];
    var vals=h.vals||[];
    ids.forEach(function(id,i){ var e=document.getElementById(id); if(e&&i<vals.length&&isFinite(vals[i])) e.value=vals[i]; });
    ids.forEach(function(id){setInvalid(id,false);});
    setMode(h.mode);
  }
  ```
- `renderHistory` 的 onclick 由传 `h.mode` 改为传索引 `i`；三元签名由写死「系数矩阵已记录」改为显示实际 12 个系数（`[2, 1, -1, 8] [...] [...]`）。
- `saveHistory` 改 600ms 防抖 + 与最新一条完全相同则跳过，杜绝中间态刷屏：
  ```js
  if(list.length&&list[0].mode===mode&&JSON.stringify(list[0].vals)===JSON.stringify(vals)){renderHistory();return;}
  ```

### SMS-162 · 预设不切元数 + 默认参数不完整
- 根因：所有预设回调只调 `calc()`，3 元态点「2 元」预设只改隐藏字段、界面无变化；「默认参数」只写到 `b2_3`，缺 6 项。
- 修正：

  - 「默认参数」补全 `c2_3/d2_3/a3_3/b3_3/c3_3/d3_3`，共 12 项。

## 三、教训

1. **假恢复类缺陷要用"可区分值"验证**：注入系数必须与页面默认表不同（本例 2/1/5 vs 默认 1/2/5），否则真机断言会误判通过。
2. `TBKit.preset.bar` 的 after 回调**不带参数**，无法知道哪个预设被点；用隐藏 input 承载目标模式（`__xhMode`），`setValue` 会一并写入并派发事件，after 再读它，是最小侵入方案。
3. 隐藏 input 会被页面自己的 `Snap()` 采集函数跳过（已排除 `type==='hidden'`），不影响快照/verify 注入。
4. 防抖保存用 `typeof setTimeout==='function'` 兜底，harness/无定时器环境自动退化为同步保存。
