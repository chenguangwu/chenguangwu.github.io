## 一、IT-N407（高）v1 时间字段全错 —— 改为 BigInt 取位

**根因（两重叠加）**：
1. `Date.now()*10000 + 0x01b21dd213814000 ≈ 1.4×10¹⁷` 超过 `Number.MAX_SAFE_INTEGER`，100ns 精度已经丢失；
2. **更致命**：JS 位运算的移位数按 32 取模，`t >>> 32` 等于「不移位」、`t >>> 48` 等于 `>>> 16`，于是 `time_mid` / `time_hi` 写入的全是低 32 位里的片段，按 RFC 4122 拼回时间戳会解出 2780 年 / 4538 年。

**修复**：
```js
const UUID_GREG_OFFSET = 122192928000000000n; // 0x01b21dd213814000
var __v1LastMs = -1, __v1Seq = 0;
function uuidV1Timestamp() {
  const ms = Date.now();
  if (ms === __v1LastMs) __v1Seq = Math.min(__v1Seq + 1, 9999);
  else { __v1LastMs = ms; __v1Seq = 0; }
  return BigInt(ms) * 10000n + BigInt(__v1Seq) + UUID_GREG_OFFSET;
}
// timeLow / timeMid / timeHi 分别用 (t & 0xffffffffn)、(t >> 32n) & 0xffffn、
// (t >> 48n) & 0x0fffn 取位后再转 Number
```
顺带补齐条目里点名的「同一毫秒内多条 v1 时间字段完全相同」：同一毫秒用 100ns 序号（0–9999）递增，保证时间有序性卖点成立。

jsdom 真机：`b2de00b0-db7b-11f1-9a43-…` 解码得 `2026-11-08T13:52:55.355Z`（= 生成时刻）；连续两次 `time_low` 由 `b2de27c0 → b2de27c1` 递增。

## 二、IT-N408 声称支持 v7 但下拉没有 —— 补齐 v7 全链路

- `<select id="version">` 新增 `<option value="v7">Version 7（时间有序随机）</option>`；
- 新增 `generateUuidV7()`：RFC 9562，前 48 位写 Unix 毫秒（BigInt 取位，避免同样超精度问题），其余随机数，版本位 `0111`、变体位 `10`；
- `generateUuid()` 分发加 `else if (version === 'v7') raw = generateUuidV7();`（原来会落到 else 的 v4）；
- `parseUuid()` 的 `versionName` 补 `7 → 时间有序随机`；`formula-eq` 的版本号解析列表补 7；
- 版本说明区加 v7 stat-card + 说明条；`formula-list` 补 v7 与 BigInt 两条；
- `i18n/tools/en/it/uuid-generator.json` 同步 7 条新 map（含 formula-eq 新 key 用 `html.unescape(页面 textContent)` 取真实原文），英文态 `--check` 0 残留、`--roundtrip` 0 不一致。

jsdom 真机：下拉 `v1,v4,v5,v7`；v7 前 48 位 = `Date.now()`、版本位 7；真入口产出 `01a1bb6e-fc3f-753f-…`；解析 v7 UUID 显示「时间有序随机」。

## 三、IT-N409 v5 命名空间非法输入静默产出错误 UUID —— 加格式校验

**根因**：`uuidToBytes()` 只用正则剔除非十六进制字符，不校验长度；`namespace='abc'` 会被解成 `[0xab,0x0c,0,0,…]` 后照常 SHA-1，产出一个格式合法但与约定命名空间完全不同的 UUID（幂等键全漂移，且看不出异常）。

**修复**：
- `generateUuid()` 在循环前对 `version === 'v5'` 调既有 `isValidUuid(ns)`，失败时用 i18n helper 输出「命名空间 UUID 格式非法：请填写 8-4-4-4-12…」并 `return`（同步路径，用户立刻可见）；
- `generateUuidV5()` 开头再抛 `Error('Invalid namespace UUID')` 作双保险，防止其它调用点绕过。

jsdom 真机：`abc` → 明确报错；合法 DNS 命名空间 `6ba7b810-9dad-11d1-80b4-00c04fd430c8` + `example.com` → `cfbff0d1-9375-5685-968c-48ce8b15ae17`（与 Node 独立 SHA-1 复算逐字节一致，主路径未误伤）。
