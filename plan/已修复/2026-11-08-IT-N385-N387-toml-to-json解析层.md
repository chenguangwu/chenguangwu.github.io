## 一、缺陷与修复

### IT-N385 内联表 / 字面量字符串 / 数字下划线全被降级成字符串（高）
- 失败点：`tVal` 只认双引号串、`true/false`、空串、`^-?\d+$`、`^-?\d+\.\d+$`、`[ ]`，其余原样返回字符串：
  - `point = { x = 1, y = 2 }` → `"point": "{ x = 1, y = 2 }"`
  - `a = 1_000` → `"a": "1_000"`
  - `c = 'lit'` → `"c": "'lit'"`（单引号被当内容）
  - 而页面注意事项写着「字符串、整数、浮点、布尔、数组、内联表都会被正确解析」⇒ 承诺未兑现。
- 根因：解析器缺 `{}` 分支、缺单引号 literal 分支、数字正则不接受 `_` 与进制前缀。
- 修复位点：`tVal()`（:270 起）重写 —— 新增 `{}` 内联表递归（按顶层逗号切键值对）、`'...'` 字面量串（不转义）、`"""..."""`/`'''...'''` 多行串、数字去下划线 + `0x/0o/0b` 前缀 + 科学计数；双引号串转义改为「先保护 `\\` 再解 `\n \t \r \"`」，修掉原先 `"\\\\n"` 被误当换行的连带问题。新增 `tKeyName()` 处理内联表里带引号的键。
- 证据：`point = { x = 1, y = 2 }` → `{ "point": { "x": 1, "y": 2 } }`；`a = 1_000`/`h = 0xFF` → `1000`/`255`；`m = { a = { b = 1 }, c = [1,2] }` → 正确嵌套。

### IT-N386 数组按逗号硬切 + 逐行解析，引号内逗号 / 嵌套数组 / 多行数组全错（中）
- 失败点：`inner.split(',')` 无视引号与嵌套；`parseToml` 逐行处理 ⇒ `ports = [` 当行即得空数组，后续 `8000,`/`8001` 行无 `=` 被跳过，结尾 `]` 行还会建空键。
- 根因：没有「顶层分隔」概念（state machine），也没有「值可以跨行」的概念。
- 修复位点：新增 `tSplitTop(s, sep)`（:232，引号/转义/`[]{}` 深度感知的顶层切分，数组与内联表共用）；新增 `tDepth()`（:255）与 `tOpenTriple()`（:250），`parseToml`（:345）在取值时循环吞并后续行直到括号闭合/三引号配对（guard 5000 行），每行都先过 `stripComment()`（:330，`#` 只在引号外才算注释，引号支持单/双）。
- 证据：`list = ["a,b", "c"]` → `["a,b","c"]`；`ports = [\n 8000,\n 8001\n]` → `[8000,8001]`；数组内 `1, # one` 注释行也正确剥离。

### IT-N387 「Tab 缩进」输出字面反斜杠 + t（中）
- 失败点：`JSON.stringify(obj, null, indent==='tab' ? '\\t' : n)` —— 源码里写的是 `'\\t'`，运行时值是**两个字符**（`\` 和 `t`），复制到编辑器就成了可见的 `\t` 文本。
- 根因：JS 字符串转义层级写错（多写了一个反斜杠）。
- 修复位点：改为 `'\t'`（真 0x09），并把 `parseInt` 兜底补上（`indent` 取不到值时回落 2，原来会是 NaN ⇒ JSON.stringify 退化成无缩进）。
- 证据：`a = 1` + `[b] c = 2` + indent=tab → 输出串 `charCodeAt` 含 9（用例用 `String.fromCharCode(9)` 在 clicks 里直接查 innerHTML）。

## 四、已知限制（勿当漏测）

- **日期时间保留原字符串**：JSON 无 datetime 类型，TOML `1979-05-27T07:32:00Z` 输出成字符串（与主流转换器一致）；若下游需要时间戳应由消费者自行解析。
- **`inf` / `nan` 保留原文字符串**：JSON 无法表达非有限数，`JSON.stringify(NaN)` 会变 `null`（信息丢失），故不转数字。
- **点号键歧义**：`[a.b]` 与 `a.b = 1` 都按点号建嵌套；TOML 规范中的「带引号含点号键」（`"a.b" = 1`）已通过 `tKeyName()` 保留为单键，但键与表头混用同一路径时的重复定义合并策略仍按「先到先得」，属骨架级简化。
