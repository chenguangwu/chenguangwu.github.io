# 第963批：prime-number 严格整数解析与筛法上限（SMS-134/135）

## 来源
`plan/categories/09-自然科学/science-math-statistics.md` 原审统计节两条待修真缺陷（SMS-134 输入 parseInt 静默截断、SMS-135 区间筛/单值试除无上限），判据清晰、可自判，本批修复并真机销账。

## 缺陷（旧版真机回放，5 FAIL 实证）
- `tools/science/prime-number.html` 五个分支全用 `parseInt(value)`：
  - num=97.9 → 截成 97 → 判「97 是素数」；
  - num=1e3（number 框 value 保留原串）→ 截成 1 → 判「1 不是素数」；
  - num=1e18 → 截成 1 → 判「1 不是素数」（若填纯整数大数才真正冻结）；
  - from=1/to=1e9 → `new Uint8Array(1e9+1)` 约 1GB 分配风险；
  - 质因数 num=360.5 → 截成 360 → 输出「360 分解」。

## 修复
- 新增 `parsePositiveInt(raw)`：`Number(s)` + `Number.isSafeInteger(n) && n>=1`，支持科学计数（1e3→1000）、拒绝小数/空串/NaN/超安全整数；五处 `parseInt` 全部替换，去冗余 `n<1` 判断。
- case1 范围筛加 `to<=10000000` 上限，超限提示走 `__rangeTooLarge()` helper（中英双语）；从根上杜绝 1GB 分配。
- case2/case3 原有 100000/1000000 上限保留。
