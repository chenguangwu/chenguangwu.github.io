## 一、缺陷与修复

### IT-N392 TOML 键名直接当 XML 元素名，含空格/数字开头的键产出非法 XML
- 失败点：`ser` 用 `'<'+name+...` 原样拼接键名，不做 XML Name 合法性转换；页面注意事项却写「XML 元素名不能以数字开头或含空格，非法名称需做转换」。
- 根因：生成器缺「名字规范化」这一层，键名被当成合法的 XML 标识符。
- 修复位点：新增 `xmlName(k)`——非 `[A-Za-z0-9_.\-\u00c0-\uffff]` 的字符转 `_`、连续 `_` 合并、空串→`_`、非字母/下划线开头补 `_`；`ser` 开头 `var nm=xmlName(name);`，标签拼接全部改用 `nm`。
- 证据：`[cfg]\n"user name" = "x"` → `<user_name>x</user_name>`；`"123" = "y"` → `<_123>y</_123>`（此前分别是 `<user name>`、`<123>`，两者都不是 well-formed）。

### IT-N393 `#text` 原样拼接未转义、空数组整键丢失
- 失败点：`ser` 对 `#text` 走 `inner += val[k]`，不经过 `escXml`；数组分支对内层遍历，空数组时循环 0 次 ⇒ 键被整体省略。
- 根因：元素文本走的是「字符串直拼」路径，绕过了所有转义；空集合没有兜底分支。
- 修复位点：`ser` 内 `#text` / `@attr` 分流——`@attr` 走 `escAttr`、`#text` 走 `escXml`；`Array.isArray(val) && !val.length` 时直接返回 `<nm></nm>`。
- 证据：`[cfg]\n"#text" = "<b>&</b>"` → `<cfg>&lt;b&gt;&amp;&lt;/b&gt;</cfg>`（此前未转义）；`[cfg]\nports = []` → `<cfg><ports></ports></cfg>`（此前提 `<cfg></cfg>`，`ports` 整键消失）。

### IT-N391（toml-to-xml 侧）：缩进下拉与「按键名排序」均未接线
- 失败点：页面提供「缩进：2 空格 / 4 空格 / Tab」和「按键名排序输出」，但 `calcTool` 只调用 `jsonToXml(obj)`，两个控件的值从未被读取 ⇒ 输出恒为单行无缩进、顺序恒为输入顺序。
- 根因：`jsonToXml` 只签名一个参数，没有 pad / sort 选项，控件是纯摆设。
- 修复位点：`jsonToXml(obj, opt)` 新增 `opt.pad`（缩进单位）与 `opt.sort`（键遍历前 `keys.sort()`）；`calcTool` 里接线：
  ```js
  var iv=document.getElementById('indent').value||'2';
  var pad= iv==='tab' ? '\t' : (' ').repeat(parseInt(iv,10)||2);
  var xml=jsonToXml(obj,{pad:pad,sort:document.getElementById('top_1').checked});
  ```
  同批把「同名兄弟元素」加 `_2/_3` 后缀去重（此前同名会产出重复标签，XML 语义上无法回读成数组）。
- 证据：jsdom 实测 2 空格 / 4 空格 / Tab（真 `\t`）三态缩进宽度分别正确；勾选排序后 `b,a` 输入输出为 `a,b`；多根自动 `<root>` 包裹并换行缩进。

## 二、判别力实测（关键：harness 断不了「缩进宽度」）

`collectStrings()` 对 `innerHTML`/`textContent` 做 `replace(/\s+/g,' ')`，**空白宽度在 blob 里完全不可区分**，所以「缩进 = 4 空格」不可能靠 expect 直接断言。本批用三种手段补齐：

1. **换行/缩进**：`clicks` 里读 `document.getElementById('result').innerHTML`，用 `indexOf(String.fromCharCode(10)+'    &lt;')` 判「换行 + 4 空格 + 转义后的 `<`」，把布尔结果写回结果区再断言 `N391 i4=1 k=1`（`k` 绑入参键名 `zzq`，避免判定串与输入无关）。入参刻意只留一层，防止嵌套层级凑出 4 空格。
   - 坑：第一次读 `textContent` 判 `\n    <` 恒 0——结果区是「`XML 输出` 标签 + `<pre>`」结构，`textContent` 不聚合子节点；且 innerHTML 里是真转义形态 `&lt;`，不是 `<`。
2. **排序**：断言相邻串 `&lt;a&gt;2&lt;/a&gt; &lt;b&gt;1&lt;/b&gt;`。输入顺序是 b 在前 a 在后，只有排序生效才出现 a→b 相邻；不勾选时是 `&lt;b&gt;1&lt;/b&gt; &lt;a&gt;2&lt;/a&gt;`，互不命中。
3. **`#text` 转义**：结果区用 textContent 写入，最终 blob 是**二次转义**形态——XML 里的 `&lt;b&gt;&amp;&lt;/b&gt;` 在 innerHTML 里读作 `&amp;lt;b&amp;gt;&amp;amp;...`，故 expect 写 `&amp;lt;b&amp;gt;&amp;amp;&amp;lt;/b&amp;gt;`。修复前输出里没有 `&lt;` 这层实体，`&amp;lt;b` 只可能来自转义路径。

**逃生项自查（本批实际踩到）**：空数组用例首版 expect 写成 `["&lt;cfg&gt;", "&lt;ports&gt;&lt;/ports&gt;"]`，因 expect 是 OR 语义、`&lt;cfg&gt;` 在修复前也成立 ⇒ 负向对照里这一条照绿。删掉 `&lt;cfg&gt;` 只留 `&lt;ports&gt;&lt;/ports&gt;` 后，负向对照从 5 红变成 6 红。
