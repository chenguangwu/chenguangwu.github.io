# 2026-11-11 第186批 · IT-N461 api-sign MD5 名实不符修复

## 清单项
- **IT-N461**："MD5" 选项实为 SHA-256 取前 32 位，签名与任何 MD5 服务端都不匹配（高，算错）

## 根因
- `md5Hex()` 走 `crypto.subtle.digest('SHA-256', …).slice(0,32)`——Web Crypto 不提供 MD5，旧实现拿 SHA-256 前缀冒充；下拉文案也写明"兼容：SHA-256 取前 32 位"，与 formula 承诺的真 MD5 矛盾。

## 改动
1. `tools/it/api-sign-generator.html`：
   - 内联 RFC 1321 纯 JS MD5（`_md5Cmn/_md5Ff/Gg/Hh/Ii` + `_md5Cycle` + `_md5Bytes`，与 `tools/it/md5.html` 同源算法），`md5Hex(s)` 改为 `_md5Bytes(new TextEncoder().encode(s))`，按 UTF-8 字节摘要、输出 32 位小写十六进制，保持 async 签名兼容调用方；
   - 下拉文案改「MD5（RFC 1321，输出 32 位小写十六进制）」；
   - 摘要说明改「MD5 模式按 RFC 1321 输出 32 位小写十六进制；HMAC-SHA256 模式输出 64 位小写十六进制」（原"转大写"也与输出不符）。
2. `i18n/tools/en/it/api-sign-generator.json`：对应两条中英 map 同步更新（下拉 + 摘要说明）。
3. `scripts/verify_it_calc.js`：更新 MD5 用例 expect 为真 MD5 `9b211a5b174da8c32c0c361b39155597`（node crypto 权威源），ref 注明旧假值来源。
