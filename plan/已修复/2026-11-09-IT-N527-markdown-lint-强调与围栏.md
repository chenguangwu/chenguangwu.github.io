> 来源：`plan/复核失败/2026-11-09-第一批.md` 的「IT-N527 Markdown 行首强调误判及不同围栏混淆」条目，重做后重新移交。

## 复核失败点原文
`*斜体* 后面是说明` 是合法强调文本，却被报列表符号后缺空格；以三个反引号加语言开始的围栏内出现 `~~~`，被错误当作闭围栏，后续代码参与检查且真正的反引号结尾又被报缺语言。

## 根因
1. 列表误判：`calcTool()` 用 `/^\s*(\*[^*\s][^*]*\*|…)\s*$/` 要求**整行**都是成对强调才豁免 listBad；行首强调后接正文时不匹配，仍判为列表缺空格。
2. 围栏混淆：`/^\s*(```+|~~~+)/` 任意围栏行都翻转 `inFence`，不区分定界符类型与长度；`~~~` 会提前闭围栏，末尾 ```` ``` ```` 被当成无语言新围栏报 MD040。

## 修复位点
- `tools/it/markdown-lint.html:219`：新增 `fenceChar`/`fenceLen` 记录开围栏定界符。
- `tools/it/markdown-lint.html:222-233`：开围栏记录定界符类型与长度，仅当**同类型且长度≥开围栏**的行才闭围栏，跨类型（如 `~~~` 在 ```` ``` ```` 内）不再误闭。
- `tools/it/markdown-lint.html:241`：listBad 豁免改为「行首以成对强调开头即豁免」（去掉行尾 `\s*$` 约束）。

## 验证证据
- node 逻辑复算：`*斜体* 后面是说明` 行首匹配强调 → 不报列表；` ```python / ~~~ / code / ``` ` 整块仅一个带语言围栏 → 无 MD040。
- `scripts/verify_it_calc.js` 新增 2 条 IT-N527 用例（行首强调后接正文、跨类型围栏），整 slug 回归 9/9 通过；既有整行强调/同类型围栏用例同绿。
