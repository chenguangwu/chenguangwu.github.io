# 第 519 批：示例预设零值 / 越界值与空态提示修复

日期：2026-11-23

## 根因

`scripts/_ux_wire.py` 批量生成预设时用 `round(float(v)*f, 4)` 缩放默认值：

- `1.2e-5 × 2 = 2.4e-5`，四舍五入到 4 位小数后变成 `0`；
- 所有科学计数法默认值（衰变常数、热膨胀系数、电阻率、电容、跨导面积等）的「示例 2× / 0.5×」因此被写成 0；
- 下拉框没有 `value` 属性，生成器取不到默认值，预设把下拉写成空字符串。

点击这些「示例」会直接得到 0、空结果或守卫报错，属于批量脚本误插的真实功能缺陷。

## 修复

### 1. 科学计数法预设（29 个页面 / 64 个值）

按默认预设逐项恢复：默认值非零、示例值为 `'0'` 的字段，用 `默认值 × 2` 或 `× 0.5` 回填，保留 12 位有效数字（如 `2.4e-05`）。

涉及行业：materials、nuclear、chemistry、electromagnetism、thermodynamics、aerospace、structural、signal、optics、quantum、fluid 等。

### 2. 约束越界预设（7 个页面）

| 页面 | 问题 | 修复 |
| --- | --- | --- |
| accounting/depreciation-syd | 年序 `yr=0.5`，要求 1–5 整数 | 改 `yr=1` |
| civil/rock-mass-rating | 五项评分整体翻倍后超出各自上限 | 2× 改为各上限内的最高分组合 |
| math/exponent-solve | 底数 `a=1`，1 的任何次幂都无法得到 b=4 | 改 `a=2, b=4` |
| economics/spending-multiplier | MPC `1.6`，要求 0–1 且不含 1 | 改 `0.9` |
| economics/tax-multiplier | 同上 | 改 `0.9` |
| quantum/spin-magnetic-moment | `m_l=0.5`，要求整数 | 改 `0` |
| quantum/bohr-orbit-radius | 主量子数 `n=0.5`，要求 ≥1 | 改 `1` |

### 3. 下拉预设空值（6 个页面）

bbq-portion、hotpot-portion、steel-profile-weight、wedding-banquet、meditation-timer 的预设下拉都写了空字符串。已回填页面首个有效选项（烤串类型、火锅风格/食量、钢材类型、桌型/备桌、冥想方式）。desk-dimensions 的 `scene` 由页面动态填充，保持不动。

### 4. 生成器防复发

`scripts/_ux_wire.py`：

- `scale()` 改为 `format(float(v) * f, '.12g')`，不再四舍五入到 4 位小数；
- 默认值提取增加 `<select>` 分支：优先取 `selected` 的 option，否则取首个 option。

### 5. 空态提示

- `meteorology/heat-index`：三项任一为空时原先直接清空结果，改为显示「⚠ 请填写气温、相对湿度与风速后再计算。」；
- `wedding/wedding-car-route`：`departTime` 原先不在必填列表，清空后静默回退 `07:00` 并保留旧结果；已加入 `_REQ`，清空即提示。

### 6. 英文动态提示

`js/tool-i18n.js` 的动态节点翻译增加三条带变量的守卫句式兜底：

- `请填写「…」后再计算。` → `Please fill in the required field and calculate again.`
- `⚠ 「…」是本计算的分母，不能为 0。` → 英文分母提示
- `⚠ 输入不能全为 0…` → 英文全零提示

并在 `i18n/tools/en/meteorology/heat-index.json` 补了新空态提示的英文。

## 验证

- 预设输出扫描：754 个含「示例 2×」页面、1,504 个预设，修复后仅剩 4 条为合法业务结论（基础压力不满足、边坡欠稳定、冲调说明），无空结果/NaN/Infinity/守卫错误；
- 真机英文态：婚车页清空出发时间显示英文守卫；体感温度页清空湿度显示英文提示；
- `python3 _build.py` 成功，改动在构建后存活；
- `python3 -m py_compile scripts/_ux_wire.py`、`node --check js/tool-i18n.js` 通过。

## 判定为非缺陷

`_audit_stale_result.mjs` 抽 120 页报出的另外 3 条为审计口径误报：

- `film/aspect-ratio`：审计会依次执行所有 `oninput` 入口，`calcByWidth` 写提示后又被 `calcByHeight` 用另一字段重算覆盖；真实用户只触发当前字段，清空仍会提示；
- `structural/ss-point-deflection`：审计把「重置」按钮的 `resetForm` 当计算入口，改值后先重置再算，故看到旧结果；真实清空后点计算会提示；
- `meteorology/heat-index`：审计只取 `#detail`，空态提示写在 `#grid`，故判为「结果未变」；真机提示正常。
