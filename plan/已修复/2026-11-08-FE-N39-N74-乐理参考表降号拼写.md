# FE-N39 / FE-N74 乐理参考表降号拼写修复（2026-11-08 移交）

## 一、FE-N74（tools/music/sheet-music.html）—— 早已修复，本会话确认

- **失败点**：旧 `NOTE_NAMES` 仅升号，`renderStaff`/`__staffExport` 用 `NOTE_NAMES[(offset+semitone)%12]`，降号调音名错拼（Bb 调主音显 A# 等）。
- **根因**：缺按调号的 ♭/♯ 拼写表。
- **修复位点（已在代码中，非本会话）**：文件已新增 `KEY_SPELLINGS`（`:289-302`）按 12 调给出正确 ♭/♯ 拼写，`renderStaff`（`:360`）与 `__staffExport`（`:399`）均改用 `KEY_SPELLINGS[currentKey][i]`，旧 `NOTE_NAMES[` 取音名逻辑已无残留。
- **证据**：本会话 `grep "NOTE_NAMES\[" tools/music/sheet-music.html` 零命中，确认旧逻辑已移除；`KEY_SPELLINGS` 含 `F:['F','G','A','Bb',...]`、`Bb:['Bb','C','D','Eb',...]` 等正确拼写。
- **判别力实测**：参考表为页面默认静态内容，A/B 态一致 ⇒ 直接断言会成逃生项；且 `KEY_SPELLINGS` 是数组常量，harness 无法触发差异化输出。按铁律⑤不另加门禁用例，以源码读取 + grep 证据替代。

## 二、FE-N39（tools/music/ear-trainer.html）—— 本会话修复

- **失败点**：`NOTE_NAMES` 仅升号，参考对照表用 `NOTE_NAMES[topNote%12]`（音程）、`NOTE_NAMES[s]`（和弦）拼示例，小三度写成 `C → D#`、小三和弦 `C D#-G`，与同页深度解析（`:575` `C-E♭-G`）自相矛盾。
- **根因**：缺以 C 为根音的正确音级拼写。
- **修复位点**：
  - 新增 `DEGREE_SPELL = ['C','D♭','D','E♭','E','F','F#','G','A♭','A','B♭','B','C']`（原 `NOTE_NAMES` 后，`:662` 附近）。
  - `renderRefTable()` 音程分支 `:787` `NOTE_NAMES[topNote%12]` → `DEGREE_SPELL[topNote]`。
  - 和弦分支 `:796` `NOTE_NAMES[s]` → `DEGREE_SPELL[s]`。
  - 修正后：小三度 `C → E♭`、小六度 `C → A♭`、小七度 `C → B♭`；小三和弦 `C-E♭-G`、大三 `C-E-G`、增三 `C-E-G#`、减三 `C-E♭-G♭`。
- **证据**：harness 加载该页（默认 interval 模式）渲染的参考表实测含 `小三度 m3 3 C → E♭`、`小六度 m6 8 C → A♭`、`小七度 m7 10 C → B♭` ⇒ 修复已生效；和弦表同机制（DEGREE_SPELL[s]）经源码核对正确。
- **判别力实测**：参考对照表为页面默认静态内容，**interval 表在默认态即渲染 ⇒ 断言其拼写会 A/B 态一致 → 逃生项**；chord 表仅 `setMode('chord')` 后渲染，但 harness 桩缺 `playStyleGroup`/`difficultyGroup`（`document.getElementById` 返回 undefined）、且 `document.createElement`/`body` 不可用 ⇒ `setMode('chord')` 抛错、和弦表无法在 harness 内渲染。故**无法构造可判别门禁用例**（同 binomial `__bpPmf` 下溢类 harness 盲区），按铁律⑤**不加逃生用例**。修复以「源码读取 + harness interval 表实测渲染」双重验证，不写 verify 用例。
