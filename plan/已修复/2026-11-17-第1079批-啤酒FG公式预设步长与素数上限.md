# 第 1079 批复修交接（2026-11-17）

本批处理 3 条复核失败：934 啤酒 FG 公式、937 两页预设步长、963 素数单值工作量上限。均为真实逻辑缺陷，不涉及 P2 裁断项。

## 934 啤酒 FG 公式错误
- **根因**：`fg=1-(og-1)*atten` 违反表观发酵度恒等式 `(OG−FG)/(OG−1)=atten`，正确为 `FG=OG−(OG−1)×atten`。页面自身算例（OG=1.050、atten=80%→FG=1.010）也支持正确式。旧 expect 把 0.931/21.3% 当有效业务结果，绿灯掩盖错误。
- **改动**：`tools/food/beer-gravity-estimator.html` 计算式、公式框、FAQ、`i18n/tools/content_deepdive.json` deep-dive 源、`i18n/tools/en/food/beer-gravity-estimator.json` 三处映射全部改为正确式并补表观发酵度定义。
- **用例**：`scripts/verify_food_calc.js` 三组——8 kg/75% FG=1.023、10 kg/23 L/50% FG=1.048、ABV 联动哨兵（9.1% 且旧错值消失）。
- **判别**：旧版差分 32/35（三条新用例全红）；判别器 35/35 零逃生；反模式/僵尸输入 0 异常；EN check+roundtrip 0 残留。
- **教训**：expect 为 some 语义，禁止混入不受被测因子影响的锚（如 OG/Plato 与 FG 公式无关）；须锚唯一受控输出或用 DOM 联动哨兵。

## 937 两页预设不合默认步长
- **根因**：`dishQty`（份数）与 detector-30 三项评分 `type=number` 无 step，浏览器默认步长 1，而预设 1.5/3.5 触发 stepMismatch。
- **改动**：`tools/restaurant/dish-cost-card.html` 份数加 `step=0.5`（半份业务语义）；`tools/logistics/detector-30.html` 外观/气味/质地统一 `step=0.5`；dish placeholder 中文补 EN 映射。
- **用例**：两页各加一条 step 属性 + 小数输入参与计算的一体化哨兵。
- **判别**：旧版差分 restaurant 14/15、logistics 21/22；判别器零逃生；EN check+roundtrip 0 残留。

## 963 素数单值试除无工作量上限
- **根因**：case 0/4 仅 `Number.isSafeInteger` 校验，安全整数范围内的难分解数（如 9e15 附近）同步试除可长时间阻塞页面。
- **改动**：`tools/science/prime-number.html` 加 `MAX_SINGLE=1e12`（√1e12=1e6 次循环秒级返回），超限 `__singleTooLarge()` 中英提示；公式框与 EN 映射同步。
- **用例**：`scripts/_verify_prime_number_963.mjs` 真机专项扩至 14/14——9e15 秒级拦截（<3s）、边界 1e12 可判定/可分解、英文态单值上限提示零 CJK、无脚本异常。
- **判别**：新增用例在旧版（无上限）会因长时间试除/不拦截而失败；专项真机 Chrome 验证。
