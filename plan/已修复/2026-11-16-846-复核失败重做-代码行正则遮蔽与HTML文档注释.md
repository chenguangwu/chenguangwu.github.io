## 1. 代码行统计未遮蔽正则字面量（604）

- **复核失败点原文**：`tools/it/code-line-counter.html` 的 `__maskLiterals()` 仅处理引号和模板字符串；有效 JS `const x = /[/*]/;` 中的 `/*` 会启动块注释状态，后续代码行被误计为注释，且无回归用例。
- **根因**：遮蔽层只按「引号字符」进入遮蔽态，没把正则字面量当作独立词法单元；正则内容里的 `/*`、`//` 直接参与注释判定。
- **修复位点**：`tools/it/code-line-counter.html`
  - 新增 `__prevWordAt(line,pos)`（向左跳空白再取词）与 `__regexAllowed(prev,word)`（`return/typeof/instanceof/…` 关键字后必为新表达式，否则看前一字符是否表达式结束符）。
  - `__maskLiterals(line, st, lang)` 增加 `lang` 形参；对 `js`/`c` 系语言，满足上下文时按正则字面量扫描到未转义、非字符类内的闭合 `/`，把整段（含修饰符）替换为空格，`lastSig` 记为值结束。
  - 字符串/模板串起始处同步把 `lastSig` 记为值结束，避免 `"…" / 2` 被误认为正则；调用点补传 `lang`。
- **验证证据**：新增门禁 `CLRX`——输入 `const x = /[/*]/; return /[/*]/.test(s); var y = a / b; // note`，断言结果区依次为 `4 总行数 → 3 代码行 → 1 注释行 → 0 空行`。`node scripts/verify_it_calc.js code-line-counter` ⇒ 6/6（既有 IT-N445/N446/N447 全部保留通过）。
- **判别力实测**：撤掉正则分支后回到「1 代码 / 2 注释」，`CLRX` 转红；把 `return` 从关键字白名单移除后，`return /[/*]/` 一行重新触发 inBlock，同样转红。

## 2. 摩斯增强版英文态三处中文残留（605）

- **复核失败点原文**：`node scripts/_en_i18n_probe.mjs --check it/morse-decode-advanced` 失败，报告 3 段残留：「按空白与斜杠分隔的」「摩斯电码」「文本互转。」
- **根因**：深解列表项 `按空白与斜杠分隔的<a class="term-link">摩斯电码</a>文本互转。` 中的内链把整句切成 3 个文本节点；字典里只有整句键 `按空白与斜杠分隔的摩斯电码文本互转。`，运行时按节点精确匹配，三个片段全部落空。
- **修复位点**：`i18n/tools/en/it/morse-decode-advanced.json` 的 `map` 增补三条与节点同形的键：`按空白与斜杠分隔的` → `Whitespace- and slash-separated `、`摩斯电码` → `Morse code`、`文本互转。` → ` text conversion.`（首尾空格用于拼接后保持英文词距），整句旧键保留不动。
- **验证证据**：`node scripts/_en_i18n_probe.mjs --check it/morse-decode-advanced` ⇒ `共 1 页，有残留 0 页`；英文态渲染为 `Whitespace- and slash-separated Morse code text conversion.`。
- **判别力实测**：删除三条片段键后探针立即回到 3 段残留 ⇒ 断言确实依赖新增键。

## 3. 大小写转换清空输入后仍保留旧结果（609）

- **复核失败点原文**：`tools/biz/text-case-advanced.html` 的 `updatePreview()` 仅在 `lastMode && input && input.value` 为真时重算；`abc`→`ABC` 后手动清空输入会跳过重算，预览仍为 `ABC`，`copyResult()` 仍可复制旧值。
- **根因**：空输入被当作「不处理」而不是「结果失效」，预览态与输入态脱钩。
- **修复位点**：`updatePreview()` 改为——有 `lastMode` 时一律重算：输入非空走 `convert(lastMode)`，输入为空则把预览写回「请输入文本 / Enter text」；`copyResult()` 原有守卫据此拦截复制。
- **验证证据**：新增门禁 `TCCLR`——先 `convert('upper')` 再清空输入并 `updatePreview()`，断言预览为「请输入文本」且 `navigator.clipboard.writeText` 未被调用。`node scripts/verify_biz_calc.js text-case-advanced` 随套件 13/13 通过（既有 TCUP/缩写保护用例保留）。
- **判别力实测**：还原旧 `if(lastMode && input && input.value)` 后预览停在 `ABC`、`copied` 变 true ⇒ `TCCLR` 转红。

## 4. HTML 文档注释未闭合（610）

- **复核失败点原文**：`tools/biz/comment-generator.html` 的 `doc` 分支把 HTML 落入通用路径 `cfg.line + ' ' + l`，而 HTML 的 `cfg.line` 是 `<!--`，产出 `<!-- hello` 不闭合；23/23 专项只覆盖 HTML 的 line/frame，没有 doc。
- **根因**：`doc` 分支只对 JS/C/Java/CSS 与 Python 做了专门处理，HTML 落到 else 的「行注释前缀」兜底，而 `<!--` 不能单行闭合。
- **修复位点**：`generate()` 的 `doc` 分支新增 HTML 前置判断，输出 `<!--` + 逐行两空格缩进 + `-->` 的多行包裹（与 block 分支同形态但独立保语义）。
- **验证证据**：新增门禁 `CMHTMLDOC`——`currentLang='html'`、`currentStyle='doc'`、内容 `hello`，断言输出以 `<!--` 开头、`-->` 出现在正文之后。`node scripts/verify_biz_calc.js comment-generator` 随套件 13/13 通过（既有 CMHTMLLINE/CMCSSLINE 等保留）。
- **判别力实测**：把 HTML 分支移出 `doc` 后输出退回 `<!-- hello`（无 `-->`）⇒ `CMHTMLDOC` 转红。
