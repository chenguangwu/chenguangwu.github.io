## 一、问题

`getNoiseLevel()` 在**等效 ISO**（`iso / mult`）上与 `cleanMax` / `usableMax` 比较；但统计卡直接把 `cleanMax` / `usableMax` 当「纯净上限 / 可用上限」展示，进度条也用 `val / usableMax` 作分母。两套口径相差 `1/mult` 倍：

| 画幅 | mult | cleanMax | usableMax | 判定用等效阈值 | 页面旧展示 | 差 |
|---|---|---|---|---|---|---|
| 手机 | 0.3 | 400 | 1600 | 400 / 1600 | 400 / 1600 | 3.3× |
| M4/3 | 0.5 | 800 | 3200 | 800 / 3200 | 800 / 3200 | 2× |
| APS-C | 0.7 | 1600 | 6400 | 1600 / 6400 | 1600 / 6400 | 1.43× |
| 全画幅 | 1 | 3200 | 12800 | 3200 / 12800 | 3200 / 12800 | 1× |
| 中画幅 | 1.5 | 6400 | 25600 | 6400 / 25600 | 6400 / 25600 | 0.67× |

复现（APS-C，mult=0.7）：ISO 5000 → 等效 7143 > 6400 ⇒ 判「较重」，页面却标「可用上限 6400」，用户按标称选 ISO 会拿到更低一档的评级；进度条以 6400 为满格，与「较重」判定直接矛盾。

## 二、修复

新增 `sensorLimits(sensorType)`，把内部阈值折算回**机身 ISO**，统计卡与进度条全部改用它，判定逻辑保持「等效 ISO」不变（`mult` 的物理含义就是小画幅同机身 ISO 噪点更重）：

```js
function sensorLimits(sensorType) {
  const s = sensorMultiplier[sensorType];
  return {
    clean: Math.round(s.cleanMax * s.mult),
    usable: Math.round(s.usableMax * s.mult)
  };
}
```

- 统计卡：`${lim.clean}` / `${lim.usable}`（原 `${s.cleanMax}` / `${s.usableMax}`）
- 进度条：`Math.min(100, (val / lim.usable) * 100)`
- `getNoiseLevel()` 补注释说明「阈值恒以机身 ISO 表达，展示侧必须 ×mult」
- `formula-desc` 补口径说明并列出五档折算值：手机 120/480、M4/3 400/1600、APS-C 1120/4480、全画幅 3200/12800、中画幅 9600/38400；EN 字典整段 key + value 同步

五档折算后（判定仍用等效 ISO，二者现已一致）：

| 画幅 | 纯净上限（机身 ISO） | 可用上限（机身 ISO） |
|---|---|---|
| 手机 | 120 | 480 |
| M4/3 | 400 | 1,600 |
| APS-C | 1,120 | 4,480 |
| 全画幅 | 3,200 | 12,800 |
| 中画幅 | 9,600 | 38,400 |
