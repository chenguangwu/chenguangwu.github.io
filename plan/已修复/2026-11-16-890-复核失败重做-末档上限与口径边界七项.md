## 逐项修复

### 558 末档上限输入被静默忽略（`sales/commission-calculator`）
- 根因：末档上限框可编辑，`getTiers()` 却无条件把末档替换成 `Infinity`；提示写「留空表示无穷」，填有限值/负数仍按无穷算。
- 修复：`resetTiers()` 末档输入直接 `disabled` 并标 `title="Last tier is fixed at infinity"`；`addTier()`、`delTier()` 重排后同步给新末档加 `disabled`，非末档上限框保持可编辑。
- 验证：`scripts/verify_sales_calc.js` 新增 `commissionStaticChecks()`，断言末档分支带 `disabled`、两条重排路径都设 `disabled`、非末档未误禁。sales 3/3，判别力 21/21。

### 581 纸卷长度复制漏校验层数（`paper/roll-length`）
- 根因：`calcLen()` 有 `layers < 1` 守卫，`copyResult()` 只查三个参数；外径 100.5、芯径 100、厚 1 时页面报无法成卷，复制仍生成长度。
- 修复：`copyResult()` 补齐与 `calcLen()` 同口径的 `Math.round((D - d) / (2 * t)) < 1` 守卫，并给出同一句提示后 `return`。
- 验证：`scripts/verify_paper_calc.js` 新增 `rollLengthStaticChecks()`，分别抽取 `calcLen()`、`copyResult()` 函数体，要求计算侧 `layers` 守卫与复制侧内联守卫并存。paper 5/5，判别力 16/16。

### 614 草莓文字英文态深解残留（`biz/strawberry-text`）
- 根因：深解正文被 `<a class="term-link">Unicode</a>` 拆成多个文本节点，原 EN 映射是整句键，运行时按整串匹配失败，探针报 3 段 CJK 残留。
- 修复：按实际文本节点拆成三段精确键（`输入「hello」，工具按`、`码点逐字在原字符前后（或包夹）插入所选 emoji...`、`装饰依赖 Unicode emoji 字符...`），删除失效的整句键。
- 验证：`node scripts/_en_i18n_probe.mjs --check biz/strawberry-text` → 残留 0。

### 640 非法目标覆盖与批量维护未留痕（`metalwork/recorder-9`、`hydraulic/cycle-19`）
- 根因 1：`calcSoaking()` 用 `+targetTemp.value || 0` 覆盖 `current.target`，清空/非法目标会把有效目标改成 0，偏差、记录、导出继续用无效值。
- 修复 1：读取原串并 `trim()`，仅当非空、有限且 `>0` 时才写 `current.target`；非法态保持上一次有效目标，与 `syncTargetTemp()` 只标红不落值的口径一致。
- 根因 2：`markAllDone()` 只写 `last` 并持久化，绕过单次维护的 `log` 留痕。
- 修复 2：批量入口为每台设备 `unshift({date, done:[], note:'批量标记完成'})`，上限 20 条后 `persist();render();`。
- 验证：`scripts/verify_metalwork_calc.js` / `verify_hydraulic_calc.js` 各加源码守卫；metalwork 4/4、hydraulic 1/1，判别力分别 83/83、108/108。顺手收紧 `analysis-35` 存量逃生锚（「问题类型数： 2」默认态命中，已删，只留依赖注入的总数 8）。

### 642 零成本与硬度下界不一致（`geology/soil-sample`、`geology/mineral-hardness`）
- 根因：土壤采样以 `cost<=0` 拒绝 0 元（免费采样是合法金额）；莫氏硬度把负值钳到 0 却提示「有效范围 1–10，已按 0 级计算」。
- 修复：成本只拒绝空串、非有限值与负数，错误文案统一为「每点成本（≥0，免费采样填 0）」；硬度下界统一钳到 1，0 与负值提示「已按 1 级计算」。
- 修复附带：中英文公式说明同步 0 元口径；莫氏硬度页英文映射键「铜币约3」与页面「铜币约3.5」不一致造成存量 CJK 残留，已逐字对齐。
- 验证：`scripts/verify_geology_calc.js` 新增 cost=0、cost 空串、h=0、h=-3 四条用例。geology 10/10，判别力 68/68。
  - 判别器实测：短锚「0 估算成本 (元)」被默认 cost=80 的结果 `6400` 尾零命中，已改为绑定 `dens=9` 的组合锚「9.00 密度 (点/km²) 0 估算成本 (元)」。

### 648 DTD 实体空白与照片 CSV 真假值（`design/svg-minifier`、`design/photo-print-size`）
- 根因 1：含内部子集的 DOCTYPE 虽整体保留，但随后 `/\s{2,}/g` 仍把 `<!ENTITY x "A  B">` 压成单空格，实体值改变。
- 修复 1：空白压缩前先把整段 DOCTYPE 内部子集抽到 `preserved`，同 `xml:space="preserve"` 分支一起原样回填。
- 根因 2：CSV 导出函数算出 `ok` 却在 `addRow` 恒写「是/Yes」，1×1 像素对较大尺寸明显不合格仍导出合格。
- 修复 2：`addRow(..., ok?(en?'Yes':'是'):(en?'No':'否'))`。
- 验证：`scripts/verify_design_calc.js` 新增 `designRework648StaticChecks()`，锚定 DOCTYPE 抽出语句在空白压缩语句之前、以及 `ok` 三元分支；design 9/9，判别力 401/401。

### 534 NPF 深览仍是旧公式（`photo/photo-4`）
- 根因：深解权威源写旧式 `35×像元/焦距`、24mm/4µm 得 5.8s，与页面现行 `(35×光圈+30×像元)/(焦距×裁切系数)` 不一致；直接改页面会被构建还原。
- 修复：`i18n/tools/content_deepdive.json` 的 `photo/photo-4.examples[1].body` 改为 24mm、f/2.8、6000 万像素级长边（p≈6µm）→ ≈11.6s，对比 500 法则 20.8s；`_build.py` 重建后页面第 161 行已同步。EN 映射中的陈旧旧键同步删除。
- 验证：`audit_deepdive_source_sync.py --check` → 扫描 4547 页、不一致 0；`_en_i18n_probe.mjs --check photo/photo-4` → 残留 0。
