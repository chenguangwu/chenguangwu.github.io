# 第700批：照明计算的自定义灯具、层高说明与无效图表

## 修复项

`tools/home/lighting-calculator.html`

### 1. 单只光通量只校验不使用

原 `calc()` 读取 `lumens` 但只做合法性校验，实际灯具数量全部来自 `BULB_TYPES` 固定参数，用户改“灯具单只光通量”结果不变。

现在：

- 固定型号方案明确标“（内置）”，仍使用内置单灯流明与功率。
- 新增“自定义单灯”卡片，数量 = `ceil(总光通量 / 输入流明)`；改 800→2000 lm 时同一客厅方案由 6 只变 3 只。
- 导出 CSV 增加“自定义单灯（输入）”行，同时给内置型号标注“（内置）”。

### 2. 层高未参与计算但文案声称按层高估算

页面没有可靠的层高-利用系数模型，选择不伪造影响：

- 输入标签改为“高度（m，安装参考）”，下方说明“层高只作安装参考，不参与光通量公式”。
- SEO description / og / twitter / JSON-LD / 页面简介统一改为“按房间面积与推荐照度估算”，删除“按层高估算”。
- 深度解析算例删除“层高 2.8m”条件，避免暗示层高进入公式。
- 新增说明带 `data-zh`，英文态显示英文。

### 3. 无效输入仍重绘图表

包装函数原先无条件调用 `__lightExtras()`，其内部用 `0.6 / 0.8` 兜底 CU/MF，只要面积有效就会画出一张图。

现在：

- `calc()` 成功时返回统一结果对象，失败返回 `null`，并调用 `__lightClearOutputs()` 清空总光通量、灯具卡片、图表、导出隐藏表。
- `__lightExtras(result)` 只消费结果对象，无结果或非法时清空图表，不再使用默认系数。
- 导出仍以 `#total-lumens` 是否有值为准；清空后提示先计算。

## 验证

本地 Chromium：

- 默认客厅 5×4m、100 lux、CU .6、MF .8 → 4167 lm，7 个内置方案 + 1 个自定义单灯。
- 单灯 800 → 自定义 6 只；改 2000 → 3 只，总光通量不变。
- 层高 2.8 → 5，结果与图表完全不变。
- 清空 CU：总光通量 `—`、卡片 0、图表 innerHTML 长度 0，提示“请填写 利用系数 后再计算”。
- CU=1.5：同样清空并提示范围错误。
- 恢复 CU=.6 / 800lm 后结果与图表恢复。
- 无 `pageerror`。

## 规则

输入框存在就必须参与结果或明确说明不参与，不做“看起来能用”的装饰参数；图表只消费主计算的合法结果，不在包装层用默认值补算。
