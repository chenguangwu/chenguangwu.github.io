# 第293批：朗读时长空态与交互扫描口径校准

## 真实缺陷：`tools/advertising/copy-duration.html`

- 清空文案后点「⚡ 计算时长」，结果区输出「0秒朗读时长 / 0中文字数 / 0等效字数」，属于无输入伪结果。
- 修复：`calc()` 开头判断 `!text.trim()`，结果区改为「请输入文案内容后再计算朗读时长。」（英文态 `Enter copy text before calculating.`），同时清空数据表，不再输出 0 统计。
- 新增 verify 用例：`content=""` + `calc()` → 断言提示串；默认欢迎文案不含该提示。

## 交互扫描器口径校准（`scripts/runtime_scan.js`）

300 页复扫过程中继续修正三类误报来源：

1. **重定向存根不应作为独立工具页扫描**：`TOOLBOX-REDIRECT` /Meta refresh 页会被跳到目标页，导致 `calc-2.html` 等存根被记成「重置无效」。改为在加载前读源文件，识别 `TOOLBOX-REDIRECT` 或 `http-equiv=refresh` 即标记 `kind=redirect` 跳过。
2. **重置探针选错控件**：语言/主题/隐藏控件不归 `resetForm()` 管理，旧探针拿它们做差异必然误报；改为选择「HTML 默认值非空」的业务字段（input/textarea/select），改成另一个合法值后点重置，再判断是否回到默认值。
3. **清空列表类按钮的「有内容」判定**：旧逻辑把静态参考表 `tbody` 行和空态提示节点算成动态行，导致空清单页也报「清空无效」；改为只统计 `.item-row / .list-item / .dynamic-row / .record-item` 显式动态行。

300 页复扫结果：`reset_dead` 从 2 降到 1，剩余 1 页为“确认框 + 空态后添加示例记录”的扫描时序问题，真机手动操作正常；另一条 `no_effect` 是倒计时页「开始孵化」在 300ms 快照窗口内尚未刷新，属低置信度线索，非页面缺陷。报告档案仍保留原历史版本，未用 300 页快照覆盖。
