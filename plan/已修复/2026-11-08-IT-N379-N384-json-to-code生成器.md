## 一、缺陷与修复

### IT-N379 TS 只引用嵌套类型名，从不生成对应 interface（高）
- 失败点：`toTS` 只输出根 `interface`，`tsType` 对对象字段返回裸类型名 `capitalize(k)`，全函数无递归生成子类型；默认样例即产出 `user: User` / `orders: OrdersItem[]`，`tsc` 报 `Cannot find name 'User'`。
- 根因：TS 侧缺少 Go/C#/Java 已有的 `collect*Subs` 子类型收集器 —— 六个生成器各写一套逻辑，TS 这套从来没写。
- 修复位点：新增统一收集器 `jcSubs()`（:355，比旧的 `collect*Subs` 多两件事：按类型名去重、数组元素下钻 `jcElem()`），`toTS`（:390）改为「根类型 + 收集到的子类型」两段输出，`tsBody()`（:381）负责单个 interface 体。
- 证据：`{"u":{"aa":1}}` → `interface Root { u: RootU; }` + `interface RootU { aa: number; }`。

### IT-N380 数组对象字段类型名与子类型定义名不一致（高，六种语言）
- 失败点：字段类型由 `*Type(v, capitalize(name)+capitalize(k))` 算，数组得 `[]RootOrders` / `List<RootOrders>` / `Vec<RootOrders>`；子类型定义却统一拼 `subName + 'Item'` = `RootOrdersItem` ⇒ 引用名 ≠ 定义名，六种语言全部「未定义类型」。
- 根因：命名有两套规则——「字段引用」走 type 函数内部，**命名层再加 `Item` 的只有定义侧**。
- 修复位点：类型名统一由 `jcSubName(parent, k)`（:346）产生，字段引用与类型定义同源；数组元素**不再**二次加 `Item` 后缀（只有「根节点是数组」的元素类型仍叫 `<Root>Item`，因为那里 `<Root>` 已被根别名占用）。落到 `toGo`(:433)/`toCSharp`(:476)/`toJava`(:521)/`toKotlin`(:563)/`toRust`(:604)/`toPython`(:646)/`toTS`(:390)。
- 证据：`{"orders":[{"id":7}]}` → `Orders []RootOrders` + `type RootOrders struct`；C#/Java/Kotlin/Rust/Python 同理（`RootZz` 全语言一致）。

### IT-N381 Go 子结构体重复 `package main`、Proto 重复 `syntax`（高）
- 失败点：`toGo` 递归时每次都从 `package main` 开头；`toProto` 每个嵌套 message 都重写 `syntax = "proto3";` ⇒ 单文件多份声明，语法错误。
- 根因：文件头（`package` / `syntax` / `using` / `import`）和类型体混在同一个生成函数里，递归即重复。
- 修复位点：拆成 `<lang>Body()`（只产类型体：`goBody`:424、`csBody`:466、`javaBody`:509、`kotlinBody`:554、`rustBody`:594、`pyBody`:637、`protoBody`:678）+ `to<Lang>()`（只产一次文件头，再拼 subs：:433/:476/:521/:563/:604/:646/:688）。
- 证据：`{"zz":{"k":1}}` → Go 只有一处 `package main`，Proto 只有一处 `syntax`；根 struct 的 `}` 后紧跟 `type RootZz struct` / `message RootZz`。

### IT-N382 根节点为数组 / 标量 / null 时产出非法字段名或直接抛异常（中）
- 失败点：六个生成器一律 `Object.entries(obj)`；数组根被当对象 ⇒ 字段名 `0`/`1`（非法标识符）；`null` 根 ⇒ `Object.entries(null)` 抛 TypeError；`convert()` 只捕 `JSON.parse`，生成期异常后结果区**保留上一次内容**（静默失败，用户以为生成成功）。
- 根因：生成器入口没有根形态判据；`convert()` 缺生成期 try/catch。
- 修复位点：`to*()` 首段按 `null` / `Array` / 标量 / 对象四态分派（`jcNull()`:351 统一提示）；数组根 → 切片或别名（`type Root []RootItem`、`public class Root : List<RootItem> { }`、`typealias Root = List<RootItem>`、`pub type Root = Vec<RootItem>;`、`Root = List[RootItem]`、`message Root { repeated RootItem items = 1; }`）；标量根 → 类型别名（类语言用单字段类包装并注明）；对象根走 `<lang>Body()`。`convert()`（:283-306）新增生成期 `try/catch`，异常渲染成 `// 生成失败: …` 并新增 `default` 分支。
- 证据：`[{"zz":1}]` → `type Root []RootItem` + `type RootItem struct`；`null` → `// 输入是 null，无法推断类型：请提供对象或数组样例`。

### IT-N383 Python 用 `Any` 但未 import（中）
- 失败点：`toPython` 头部写死 `from typing import List, Optional`，而 `pyType` 对 null 字段返回 `Optional[Any] = None`、空数组返回 `List[Any] = []` ⇒ pydantic 求值注解即 `NameError: name 'Any' is not defined`。
- 根因：类型映射（`py*Type`）与 import 清单分处两地，新增 `Any` 形态时没回头补 import。
- 修复位点：`toPython`（:646）头部改为 `from typing import Any, List, Optional`。
- 证据：`{"qnote":null,"qlist":[]}` → 导入行含 `Any`，且字段渲染出 `Optional[Any] = None`。

### IT-N384 承诺「键名按目标语言惯例转换」，实际只做首字母大写（中）
- 失败点：参考表写「convert keys to target naming conventions」，代码只有 `capitalize()`；`user_name` / `api-key` 原样输出，后者根本不是合法 TS 字段名。
- 根因：命名层只有 `capitalize`，没有分词（snake/kebab/camel 边界）+ 目标语言风格 + 合法性兜底。
- 修复位点：新增 `jcWords()`（:317，camel 边界切分 + 非 `[0-9A-Za-z\u00c0-\uffff]` 分隔 + 全大写词降为小写）与 `jcIdent(k, style)`（:324，`camel`/`pascal`/`snake`/`raw` 四种风格，数字开头补前缀，`raw` 优先保留合法原键）；`jcUniq()`（:335）在同一结构体内去重（`user_name` 与 `userName` 撞名时后者加 `_2`）。
  - 各语言风格：TS/Java/Kotlin `camel`；Go/C#/Rust-**类型名** `pascal`；Rust 字段/Python/Proto `snake`；Python 字段用 `raw`（合法键**保留原样**，pydantic 是按字段名对 JSON 键的，无 serde 式的 rename 能力，乱改造会造成解码失配，只有非法键才降级成 snake 并加 `# 原键:` 注释）。
  - 无损映射：Go 沿用既有 `json:"k"` tag、C# 沿用既有 `[JsonProperty("k")]`；Rust 在改名时补 `#[serde(rename = "k")]`；TS/Java/Kotlin 改名时在行尾补 `// 原键: k`。
- 证据：`{"user_name":1,"api-key":"x"}` → `userName: number; // 原键: user_name`、`apiKey: string; // 原键: api-key`；`{"2fa":true}` → `f_2fa`（数字开头兜底）。

## 三、判别力实测与取证方法（后人务必按此口径复跑）

- 用例：`scripts/verify_it_calc.js` 新增 14 条（`slug: it/json-to-code`），覆盖 N379×1、N380×7（TS + 六语言）、N381×2（Go/Proto）、N382×2（根数组/null）、N383×1、N384×1。
- **踩到的坑 1（OR 语义）**：`expect` 是「任一命中即通过」。首版对六语言写了 `["public class RootZz {", "List<RootZz> Zz"]` —— 第二个串（字段引用）**修复前就成立**，于是整例在修复前照样变绿、判别力为零。负向对照当场暴露，已改成**只断言定义名**（`public class RootZz {` / `data class RootZz(` / `pub struct RootZz {` / `class RootZz(BaseModel):` / `type RootOrders struct`），并在 `ref` 里写明「字段引用串修复前已存在，故不入 expect」。
- **踩到的坑 2（高亮剥标签）**：`#output` 的 `innerHTML` 经 `highlight()` 上色，harness 的 `replace(/<[^>]+>/g,' ')` 会在被包成 `<span>` 的 token 两侧**插入空格** ⇒ 实际串是 `number ;`、`json: "zz" `、`syntax = "proto3" ;`；且 `<`/`>` 已被 `escapeHtml` 转成 `&lt;`/`&gt;`（想断言 `List<X>` 必须写 `&lt;X&gt;`）。断言一律取「无分号、无尖括号」的片段。
- **踩到的坑 3（多空格 indexOf）**：`Any` 那例要在 clicks 里比对导入行，`replace(/<[^>]+>/g,' ')` 会留下连续多个空格（`Any  ,  List`），`indexOf('Any , List')` 恒 -1。改为 `...split(' ').join('')` 后再查 `importAny,List`（该串只可能来自 `from typing import Any, List, Optional`）。同时避开 `\s`/`\"` 转义（长 clicks 里的转义引号会让 `extractCases()` 误吞括号）。
- **坑 4（harness 只能断言「存在」）**：N381 是「重复声明」类缺陷，无法断言「只出现一次」，改为断言「根类型体的 `}` 后面紧跟子类型定义」（`} type RootZz struct {` / `} message RootZz {`）—— 这段在修复前被 `package main` / `syntax` 隔开，天然不存在。
- 离线取证（harness 外的双保险）：用 `node -e` 从页面截取 `let lang=…` 到 `function copyResult(` 的整段生成器，注入 `document.getElementById` 桩后直接调 `toTS/toGo/…`，把 8 种语言 × 根形态四态 × 命名用例的输出全部打印核对（含 `[[{b:1}]]` 数组套数组、中文键、空对象、`for(const k in …)` 的 `__proto__` 无关性）。

## 四、已知限制（非缺陷，勿当漏测）

- **harness 无法断言「只出现一次」**：`collectStrings()` 只做包含判断，IT-N381 的「重复声明」只能反向断言（见坑 4）。
- **Python 字段名保留原键**（`raw` 风格）：pydantic 没有 serde 式 rename 注解，改名即解码失配；因此只对**非法标识符**（kebab/空格/数字开头）降级成 snake 并加 `# 原键:` 注释，这是有意的取舍，不是 N384 未修完。
- **Proto 字段名恒 snake_case**：protobuf 规范要求 small_snake；JSON 侧映射依赖 `json_name`（本工具暂不生成），属骨架层面的固有简化，与 N384 的「按目标语言惯例」一致。
- **类型名去重按名字**：`{"a":{"b":1},"a_b":{}}` 这类「不同形状、同名类型」只保留先出现的定义（避免重复定义直接编译失败）。极端歧义输入下可能合并类型，属可接受的骨架行为。
