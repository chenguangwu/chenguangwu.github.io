# 复核失败重做批次 · 申请再次复核

## 条目

- 来源：`plan/复核失败/2026-11-09-第七批.md` → `## SF-N10 增肌预设仍被自定义系数覆盖`
- 失败点：预设「增肌 80kg 高强度」的上轮修复只把 `goal` 由 0.2 改成 0.4，但同一条预设仍带 `customFactor:2.2`。`calculate()` 中 `custom || (activityFactor+goalAdd)` 让自定义系数优先，点击预设实际得 2.2 g/kg / 160–192 g，而非交接期望的 2.4 g/kg / 176–208 g。既有回归手工把 `customFactor` 置空再测，未覆盖真实预设路径。
- 根因：预设数据与计算优先级冲突；预设数组内联在 `__calc_5Presets()` 函数内，回归用例无法直接调用真实预设。

## 修复位点

- `tools/fitness/calc-5.html`：预设数据提为顶层 `CALC5_PRESETS`，四项预设全部把 `customFactor` 置为空串（包括「默认参数」补上该键，避免先填自定义系数后点默认预设时残留覆盖）；新增真实预设入口 `applyCalc5PresetAt(i)`，逐个写入输入框后调用 `calculate()`；`TBKit.preset.bar` 改用同一份数组，按钮组件与回归用例共用同一数据源。
- 同文件 `calculate()`：`custom || (activityFactor+goalAdd)` → `(isFinite(custom) && custom > 0) ? custom : (activityFactor+goalAdd)`，顺手消除 `custom=0` 或负数时的静默回退。
- 可见说明核对：`i18n/tools/content_deepdive.json` 与 `tools/fitness/calc-5.html` 内联 deep-dive 本回合均已是「增肌 +0.4」「70 kg 算例 126–154 g」，页面与数据源一致（上轮构建产物已同步）。

## 证据

- `env -u NODE_OPTIONS node scripts/verify_fitness_calc.js` → `==== fitness calc 96/96 ====`。
- 新增真实预设用例：`inputs:{}` + `clicks:["applyCalc5PresetAt(2);"]`，期望 `176-208g` 与 `2.4g/kg`（factor=2.0+0.4=2.4，区间 [2.2,2.6]×80）。既有的手工置空用例与 `customFactor:42` 自定义系数用例同批回归通过。
