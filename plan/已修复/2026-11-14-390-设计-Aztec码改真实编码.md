## 一、原缺陷（确认）

1. **D-N177（高）**：`generate()` 只对文本做 32 位 hash 当 LCG 种子填格，再画 3×3 靶心、两侧环与 4 个角点。没有高电平编码、没有 Reed-Solomon 纠错码字、没有模式消息、没有层/版本选择、没有参考网格 —— 输出不是合法 Aztec 码字，任何解码器都读不出。而 meta/deep-dive 写着「用于票据与物流信息的移动端识读」「扫码即得原文」。
2. **D-N178（中）**：矩阵尺寸只取滑杆（夹 11–25、偶数 +1），文本只影响 hash，10 字符与 200 字符同尺寸；预设 `size:10`/`8` 写进 `min=11` 的 number input 后显示 8/10，实际被夹成 11，UI 与实际不符；FAQ「过长会超出容量无法生成」与引据「compact/full by payload size」都不成立。

## 二、修法（补真实编码，不降级改名）

项目内无 Aztec 库，故按项目既有做法（`js/barcode-lib.js` 按标准自写、`js/qrcode.js` 引 MIT 库）新增 `js/aztec-lib.js`：**移植 ZXing Aztec 编码器（Apache-2.0）到 ES5 零依赖实现**，保留版权声明与来源说明。

- 高电平编码：UPPER / LOWER / DIGIT / MIXED / PUNCT 五张码表 + LATCH/SHIFT 表 + 动态规划取最短位串（含 BINARY 移位、`. ``, ``, `: ``, CRLF` 四个 PUNCT 双字符特例）
- 位填充：全 1 / 全 0 码字插隔位（`mask = (1<<wordSize)-2`）
- Reed-Solomon：GF(16) 模式消息、GF(64) 紧凑型、GF(256) 全尺寸、GF(1024)/GF(4096) 全尺寸大层，长除法求余
- 布点：数据位按层螺旋写入四边 → 模式消息 → 同心方靶心（紧凑 5 / 全尺寸 7 级）→ 全尺寸参考网格
- 文本：纯 ASCII 走 Latin-1 字节；含非 ASCII 走 UTF-8 字节并写 ECI 26，避免解码端猜错字符集

页面侧：
- 引入 `<script src="../../js/aztec-lib.js">`；输入改为 文本 / 纠错比例（23% · 33% · 50%）/ 每模块像素（4–40）/ 前景 / 背景
- 尺寸语义彻底改正：**矩阵边长由编码结果决定**，滑杆只控制缩放；夹取后的值回写输入框（显示值 = 实际值）
- 结果区新增信息行（层数 · 紧凑/全尺寸 · 边长 · 数据码字 · 纠错占比 · 字节数），并新增 **SVG 矢量导出**（PNG 仍保留）
- SVG 在 PNG 之前生成：画布被污染导致 `toDataURL` 失败时不连带丢掉矢量
- 文案全量重写：公式框写真实容量/纠错/边长公式，deep-dive / FAQ / 引据表 / 介绍块 / 注意事项全部改为规范内表述，删掉「简化版」「仅供演示」「不可被识别」等旧口径

## 五、顺带修掉的 harness 回归（第 389 批遗留）

第 389 批为了让 QR 页在门禁里能真实编码，把 `qrcode` 作为 `new Function` **形参**注入。形参会遮蔽用例内 `globalThis.qrcode=...` 的桩，导致 3 条既有 IT 用例与 1 条 design 用例由绿转红（它们原本依赖「harness 不加载外部脚本 ⇒ qrcode 未定义 ⇒ 走失败/异常分支」）：

- `it/url-qr`（mock 编码器探测）：形参遮蔽后桩不生效 ⇒ `QRAPI NA|NA|N|N`
- `it/text-qr`（异常作废画布）：真库可用 ⇒ 生成成功 ⇒ `ERR=STALE`
- `it/qr-beautify`（自动补强弱用例）：anchor 是旧环境报错串 ` defined`
- `design/qr-code-styled`（失败分支清 lastURL）：真库可用 ⇒ 生成成功 ⇒ URL 非空

修法：
1. **注入方式改回全局**：`globalThis.qrcode / globalThis.Aztec` 每页无条件赋值（未引用该库的页面拿到 undefined，跨页不残留）。页面内联脚本对未声明标识符本就是查全局，与浏览器一致，且用例桩可覆盖。
2. 三处**依赖「库未加载」的隐式前提**改为**显式注入必抛异常的编码器**（`globalThis.qrcode=function(){throw new Error('boom')}`），被测的失败分支不变，判别力不降。
3. `it/qr-beautify` 的自动补强弱用例重写为锚真实派生量「✅ 已生成 29 × 29 模块 · 容错 H · 232px」（20 字节 ASCII + H 级 ⇒ 比默认样例更大的版本）。
