## 一、D-N4 font-preview 英文态残留中文（功能修复）

**问题**：`render()` 把卡片提示「点击复制」、计数「N / M 种字体」以及三个中文分类标题（中文字体 / 英文字体 / 通用字体族）硬编码进 HTML 字符串；`isEn` 只在 `__fpChart()` 里用于图表标题。`toolbox:langchange` 回调也只重画图表、不重跑 `render()`，所以即使补了词典，切换语言后列表仍停在旧语言。

**修复**（`tools/design/font-preview.html` 5 处）：

1. `render()` 开头取语言，带完整能力守卫，TBKit 未加载或不支持 `isEn` 时按中文态渲染、不中断脚本：
   ```js
   var isEn = (typeof TBKit !== 'undefined' && TBKit.util && typeof TBKit.util.isEn === 'function' && TBKit.util.isEn());
   ```
2. 卡片提示：`'<span class="fp-copy-hint">' + (isEn ? 'Click to copy' : '点击复制') + '</span>'`。
3. 分类标题复用页面已有的 `fpCatEn`（Chinese / Latin / Generic families）：`escHtml(isEn ? (fpCatEn[sectionName] || sectionName) : sectionName)`。`fpCatEn` 是 `var` 且在 `render()` 首次调用前已赋值，安全。
4. 计数：`totalVisible + ' / ' + getTotalFontCount() + (isEn ? ' fonts' : ' 种字体')`。
5. 语言切换：抽出 `window.__fpOnLangChange = function () { try { render(); } catch (e) {} };`，挂到 `toolbox:langchange`；`__fpChart()` 已由 `render()` 末尾调用，不再单独重画。

**为什么没走「补第三层词典」**：这些串是 JS 动态拼进 `innerHTML` 的，词典替换按「整节点 `textContent` 精确匹配」工作，对逐个卡片内的 `<span>` 与动态计数都不可靠；直接在生成处按 `isEn` 分支更彻底，也顺手修好了切换语言不刷新的根因。
