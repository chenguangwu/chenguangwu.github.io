# 复核失败重做批次 · 申请再次复核 — IT-N489

> 来源：`plan/复核失败/2026-11-09-第一批.md` 的「IT-N489 JSONPath 负步长的起止边界颠倒」条目，重做后重新移交。

## 复核失败点原文
JSON `{"a":[1,2,3,4,5]}`，查询 `$.a[4:0:-1]` 实得 `[]`，期望 `[5,4,3,2]`；查询 `$.a[0:5:-1]` 实得 `[5,4,3,2,1]`，期望 `[]`。负步长分支从 `end - 1` 向 `start` 迭代，交换了起止语义；省略起点时也提前固定为 0，无法按步长方向处理默认值。

## 根因
1. `jsonPath()` slice 分支负步长写成 `for(i=e0-1; i>=s0; i+=step)`，起止语义颠倒；
2. `parseTokens()` 把省略的 `start` 兜底成 `0`（`st===null?0:st`），使负步长「省略起点默认 len-1」无法生效，`$.a[::-1]` 反转错误。

## 修复位点
- `tools/it/json-path.html:383-391`：负步长按步长方向从 `start` 向 `end`（不含）迭代；`s0`/`e0` 按方向收敛——负步长省略 `start`→`len-1`、省略 `end`→`-1`，正步长沿用原 `norm`。
- `tools/it/json-path.html:478`：`parseTokens` 切片 token 改为保留 `start: st`（不再兜底 0），使执行层 `token.start===null` 判断生效。

## 验证证据
- node 独立复算：`$.a[4:0:-1]`=[5,4,3,2]、`$.a[0:5:-1]`=[]、`$.a[::-1]`=[5,4,3,2,1]、`$.a[0:5:2]`=[1,3,5]、`$.a[-1:]`=[5]。
- `scripts/verify_it_calc.js` 新增 2 条用例（`[4:0:-1]` / `[::-1]`），整 slug 回归 40/40 通过；既有 `[-1:]` / `[0:5:2]` 用例同绿。

## 判别力实测（回退源码应转红）
回退至颠倒循环 + `start` 兜底 0 后：`$.a[4:0:-1]` 得 `[]`、`$.a[::-1]` 得 `[1]` → 新用例转红；正步长用例不受影响。
