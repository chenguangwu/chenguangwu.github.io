## 二、本批真修

1. **F-N33 终值公式统一 + 0% 边界**（`calcFV` / `calcFVAt` / IRR 反解三处复用）
   - 旧：`calcFV` 与绘图 `calcFVAt` 各写一遍 `((1+r)^t−1)/r`，`r=0` 得 `0/0=NaN`。
   - 修：抽出全局 `roiFutureValue(p,t,r)`，`r≈0` 走 `add*t` 加性分支；并用 `Math.expm1(t*Math.log1p(r)) / Math.expm1(Math.log1p(r))` 消除 `r→1e-13` 时的灾难性抵消（否则 0% 附近 IRR 反解会假报「无法确定」）。
   - 0% 真机实测：两方案终值 **15,000 / 15,000**、年化 **0.00% / 0.00%**、判持平，无 `--` / `NaN` / `−100.00%`；0% vs 5% ⇒ 0.00% / 5.00% 判方案 B；极小利率 `1e-10%` 不假报无解。

2. **F-N34 判优改按资金加权年化（IRR）**
   - 新增 `roiMoneyWeightedIrr(p, fv)`：按「初始投入 t=0、每年期初追加、期末一次收回终值」的现金流口径，以与终值公式同源的函数二分反解年化利率；与 `calcRegular` 的定投现金流 IRR 同口径，期限含小数仍自洽。
   - `calcCompare()` 不再用 `(1+累计ROI)^(1/年数)−1`；`winner` 按 IRR 判，结果卡新增「资金加权年化（IRR）」双列 + 一段依赖输入的口径说明（累计投入只用于展示成本，终值差额不代表收益率高低）。
   - **复核方判据「未检出当无解 → 保守无法确定」**：端点同号或残差不过关返回 `null`，判优显示「无法确定」而非把求解失败当成「持平」或伪造上限（`aRate=100000%` 实测）。
   - 清单原例修复后 **9.00% / 10.00% / 方案B**；既有契约 A@10% vs B@3% 仍判方案A；同利率不同追加判持平；小数期限 2.5 年仍自洽。

3. **真机发现的真 bug：拒绝态静默 return + 残留**（复核方八类退回根因之一）
   - 旧 `calcCompare()` 对 `a.cost<=0 / b.cost<=0 / years<=0` 直接 `return`：不给任何提示、不清结果区，上一次合法方案的终值仍挂在屏上，历史却按新输入判 0 ⇒ 同屏自相矛盾且可导出旧报价。
   - 修：抽出 `__roiReject(zh,en)` 统一出口，写明字段级原因并 `clearRect` 图表；第一个守卫与「负追加」分支都走它；NaN 守卫分支也补清图表。

4. **顺带修 `isFinite(null)` 误判**：`calcRegular` 的 `hasIrr = isFinite(irrPer)` 会把 `irrFromCashFlows` 求解失败返回的 `null` 当成 0（`isFinite(null)===true`），显示 0.00% 而不是「—」；改为 `irrPer !== null && isFinite(irrPer)`。

5. **同页机制层补修（复核方「真实入口漏包装 / 快照错配 / 容器错配」判据）**
   - 旧：`__investment_roiExtras` 只包装 `calcSimple`；`Snap()` 全表抓 17 键再截断到 12 ⇒ `bCost/bRate/bAdd` 永远进不了历史；`ResText/FullResText/Score` 恒读 `#simpleStats` 与 `cost/years`；历史回放只调 `calcSimple()`。
   - 修：三个真实入口全部包装；`Snap()` 按活动 tab 收窄（compare tab 恰好 8 键）；结果容器按 tab 选 `simpleStats / regularStats / compareStats`；`Score()` 按各 tab 自己的业务输入判定；记录写 `__tbTab`，回放时切回对应 tab 并调对应计算函数；preset 回调先切回 simple tab；新增/改动的运行时动态串全部走 `__roiTx(zh,en)`，EN 态 `compareStats` 零 CJK。

## 四、踩坑（写进记忆，防复发）

1. **通用回归桩会兜底无参调用新顶层函数**：新加 `roiFutureValue()` 被 harness 无参调用，抛 `Cannot read properties of undefined (reading 'cost')`，首次 verify 出现附带异常。修法不是删函数，而是给入口加 `if(!p || !isFinite(t) || !isFinite(r)) return 0;` 防御；`roiMoneyWeightedIrr` 同理。
2. **0% 不只是「除零」**：直接改成 `add*t` 后，`roiMoneyWeightedIrr` 在 `r≈1e-13` 仍因 `(1+r)^t−1` 浮点抵消使残差校验失败、假报「无法确定」。`expm1/log1p` + 0% 快速路径才彻底收口。
3. **`isFinite(null)===true`**：JS 全局 `isFinite` 会先做数值转换，判 `null` 结果时务必显式 `!== null`。
4. **真机断言自身三处写错（非页面 bug）**：① `compare()` 每次展开默认参数，状态链三态必须显式带同一 `aAdd/bAdd`；② 加 `tick()` 重置节流后，「历史回放」点的最新一条已变成刚写入的新值，应按「点最新一条即回填该记录值」断言，不要硬编码旧值；③ `JSON.stringify(undefined).slice(...)` 让诊断输出在旧源码下直接抛错、差分脚本提前退出，统一加 `|| {} / || []`。
5. **节流与 Score 断言**：连续两次 fire 落在 1 秒节流窗口内时，第二次不会立即入历史；机制层逐项断言前用 `tick()` 模拟跨秒，节流行为本身单独用「快速连续输入 + 等 1180ms」验证。
