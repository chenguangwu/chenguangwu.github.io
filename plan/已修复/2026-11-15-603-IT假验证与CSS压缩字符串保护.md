# 603 批 · IT 假验证按钮与 CSS 压缩字符串保护（2026-11-15）

## 修复清单（2 页 / 2 组真缺陷）

### 1. `tools/it/json-schema-generator.html` — 「✅ 验证」是走过场
- 旧实现 `validateSchema()` 只做 `JSON.stringify(lastSchema)`；`lastSchema` 是内部生成对象，对普通对象永不抛错 ⇒ 按钮永远报「Schema 格式有效」，不校验任何内容。
- 新实现：
  - 读取**输出区当前 Schema 文本**（用户可编辑/粘贴），`JSON.parse` 失败直接报 `❌ JSON: …`；输出区为空才回退内部 `lastSchema`。
  - 新增 `__schemaIssues()` 递归结构校验：合法 `type` 白名单、`$schema` 字符串、`enum` 数组、`properties` 对象及子项、`required` 字符串数组且**每项必须在 properties 中定义**、`items` / `anyOf` 递归（深度上限 12）。
  - 结果写入 `#statusText`（中英双语文案走 helper）并同步 toast，用户可见具体错误项。
- 同批核验已修：`isIPv4` 逐段 0–255 + 拒前导零、`mergeSchemas` 保留共有 `required` ⇒ 清单该行整条销账。

### 2. `tools/it/css-minify.html` — 引号串内 CSS 被静默改义（IT-N431）
- 旧 `minify()` 是 4 条全局正则：`content:"a: b"` → `content:"a:b"`、`content:"A  B"` → `content:"A B"`、属性选择器 `[title="a, b"]` → `[title="a,b"]`，压缩结果看似正常但上线后文案/匹配错。
- 新实现逐字符 tokenizer：注释剔除，引号串与 `url(…)`（含引号内括号）作为 `raw` 段原样保留，仅对 `code` 段做空白/符号压缩。
- 另修：`escH()` 与结果写入层的 `replace(/Infinity|NaN/g,'—')` 会把 `.NaN` 选择器改写成 `.—`；改为仅对**纯值** `NaN`/`Infinity` 做守卫，CSS 文本不再被误伤。

### 3. 过时结论销账（核验后删除，避免后续 agent 按旧证据改坏页面）
