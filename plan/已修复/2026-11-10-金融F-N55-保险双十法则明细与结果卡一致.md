# F-N55 保险页双十法则明细金额与结果卡不一致、年支出输入无效（真修）

- 分类：金融财务 / `tools/finance/insurance-calculator.html`
- 优先级：中（确认缺陷）
- 批次：2026-11-10 分类线第 77 批（本地提交，未 push）

## 失败点（原清单）
- 结果卡 `lifeInsurance = max(income*10 + debt − existing, 0)`，明细行却硬写 `income*10 + '万 (年收入×10)'`，同屏出现两个不同的寿险保额。
- `dt_expense`（年支出）读入后从未参与任何公式，输入形同装饰。
- 复现：年收入 20 / 负债 80 / 已有 10 → 结果卡 270 万、明细 200 万；改年支出 12→0 或 100 万所有结果不变。

## 根因
明细行在写死文案时未按结果卡的完整算式渲染；年支出读入变量后无下游消费，也没说明它在双十法则中的口径。

## 修复位点
`tools/finance/insurance-calculator.html` dual-ten 分支 details：
- 寿险明细行改为 `value: lifeInsurance + '万'`，desc 展示完整算式 `年收入X万×10 + 负债Y万 − 已有保障Z万 = lifeInsurance万（不为负）`，与结果卡同源。
- 年支出改为「年支出（参考）」明细行，desc 诚实标注：**双十法则按收入估算，年支出不进入本法则公式；需按支出测算请用「需求分析法」**。
  - 说明：双十法则（10×收入寿保 / 5×收入重疾 / 10% 收入保费）是通行经验法则，年支出并非其标准输入；不自造「收入−支出×N」类无权威公式以免误导，改为显式标注口径边界，并把有权威依据的支出缺口法留在同页「需求分析法」（`nd_expense` 已真实参与 `生活支出缺口 = max((开支−配偶收入)×年限, 0)`）。

## 证据
- 专用判别锁：年收入 28 / 支出 15 / 负债 90 / 已有 33 → 寿险 = 280+90−33 = **337 万**，明细行须有 `年收入28万×10 + 负债90万 − 已有保障33万 = 337万`。旧实现明细硬写 `280万 (年收入×10)` ⇒ 本串不命中。
- 同步两条旧例 expect（原 `360万 (年收入×10)` / `100万 (年收入×10)` 文案已消失）：改为带输入号的完整算式串。
