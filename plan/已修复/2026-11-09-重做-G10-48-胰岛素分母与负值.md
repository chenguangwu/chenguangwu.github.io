# 复核失败重做批次 · 申请再次复核

## 条目

- 来源：`plan/复核失败/2026-11-09-第七批.md` → `## G10-48 胰岛素零分母及负输入仍产生剂量`
- 失败点：`icr=0` 或 `isf=0` 时主结果显示「—」、明细含「—U」，但 `__insulin_dose_ok` 仍为 true，错误态仍可写入历史；碳水 −10、活性胰岛素 −2 也继续输出剂量。
- 根因：上轮只把 `!carbs` 改成 `!isFinite(carbs)` 以保留合法 0，却未校验分母必须为正、未校验负值、未校验 `activeIns`/`exercise` 的非有限值；`parseFloat(activeIns)||0` 还会把空串与非法值混为一谈。

## 修复位点

- `tools/health/insulin-dose.html` `calc()`：
  - `activeIns` 改为显式区分空串（合法 0）与 `parseFloat` 结果；把 `exercise`、`active` 一并纳入 `isFinite` 校验。
  - 三级校验：① 任一非有限 → 「请填写有效的血糖、碳水系数、敏感系数与碳水摄入数值」；② `icr<=0 || isf<=0` → 「碳水系数（ICR）与胰岛素敏感系数（ISF）须大于 0，不能为 0 或负数」；③ `cur/tgt/carbs/active/exercise<0` → 「血糖、碳水摄入、活性胰岛素与运动系数不能为负，请核对输入」。
  - 任一无效即置 `__insulin_dose_ok=false`，把 `doseVal` 置 `--`、`doseMarker` 复位 `0%`，并把 `breakdown` 三张卡整体替换为「输入无效 + 具体原因」的中英双态提示，不再残留 `—U` 明细；`__insulin_doseResText()` 依据 `__insulin_dose_ok=false` 返回空串，历史与评分不再记录错误态。
- 保留合法 0 碳水（上轮修复成果）与本轮新增的合法边界不变。
