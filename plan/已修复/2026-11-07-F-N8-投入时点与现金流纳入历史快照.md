## 2. F-N8：历史恢复不可靠（真残留）

### 失败点
两页的通用 `TBKit.history` 机制只扫描 `input[id] / select[id] / textarea[id]` 生成快照，恢复时把记录里的键逐個回填同名控件再 `calc()`：

- `dca-calculator.html`：投入时点只存于 JS 变量 `timing`（由两个 `<button>` 切换），**不在任何 input 里** ⇒ 历史记录不含时点；恢复后沿用当前 `timing`，期初/期末结果被混算。
- `irr-calculator.html`：`renderFlows()` 动态生成的现金流行 `<input>` **没有 id**（只有 `oninput="updateAmount(idx,...)"`）⇒ 快照漏掉全部期号与金额；恢复后仍用当前 `cashFlows`，IRR/NPV 无法重现。该页虽有 `CF_STORE_KEY` 的 localStorage 持久化，但那是「刷新恢复」，不等于「点历史记录恢复」。

### 根因
页面状态与「带 id 的表单控件」不同构。通用快照器无法观测纯 JS 变量与无 id 的动态控件。

### 修复位点（只改工具页 + 门禁用例，不动构建真源）

**`tools/finance/dca-calculator.html`**
1. 新增只读输入 `id="dcaTiming"`（`begin` / `end`），label 用页面既有 `data-zh` 双语模式。
2. `switchTiming(t)` 同步写入该输入。
3. 新增 `__dcaSyncTiming()`：以快照输入为准同步 `timing` 变量与两个按钮的 `active`。
4. 在 `__dca_calculatorRender` 的 `history.mount` 回填回调里，**先** `__dcaSyncTiming()` **再** `calc()`。

**`tools/finance/irr-calculator.html`**
1. 新增只读输入 `id="irrCashflowSnapshot"`，值为紧凑序列 `T期号:金额`（如 `T0:-100,T1:115`）。
2. 新增 `__irrEncodeFlows / __irrDecodeFlows / __irrWriteFlowSnapshot / __irrRestoreFromSnapshot`。
3. `renderFlows()` 末尾写快照并 `saveFlows()`；`updateAmount()` 改金额时同步写快照并落库；`addPeriod` / `removePeriod` / `loadPreset` 经 `renderFlows()` 统一落库（顺带修掉「新增/删除期数刷新后丢失」）。
4. 在 `__irr_calculatorRender` 的 `history.mount` 回填回调里，**先** `__irrRestoreFromSnapshot()` **再** `calc()`。

**关键设计取舍（踩过一次坑）**：首版把「以快照为准重建」放进了 `calc()` 开头，结果 `verify_finance_calc.js` 立刻从 356/356 掉到 354/361 —— 既有用例通过 `clicks` 直接赋 `cashFlows` 或 `switchTiming()` 无参切换，会被隐式的快照读回覆盖。**恢复逻辑必须由历史 mount 回调显式触发，不能放进每次 calc()**。改为显式调用后全量恢复 361/361。
