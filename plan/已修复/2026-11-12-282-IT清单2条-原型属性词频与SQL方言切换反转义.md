# 第282批 · IT 静态续审 2 条（原型属性词频 / SQL 方言切换与反转义空白）

## 移交范围（一个整体）
1. `tools/it/text-statistics.html`：词频对象 `wordFreq = {}` 遇到 `constructor` 等原型属性名时，读到 `Object.prototype.constructor`（函数），`函数+1` 得字符串，下游百分比 NaN ⇒ 整个词频区被替换成「计算结果含无效值」。
2. `tools/it/sql-escape.html`：① `select#dialect` 未绑定 change，切换方言不重算输出；② `unesc()` 无条件 `trim()`，`  abc  ` 反esc 成 `abc`，首尾空格丢失。

## 根因与改动
- text-statistics：`const wordFreq = Object.create(null)` 消除原型链继承；`Object.entries/keys` 兼容无原型对象，显示逻辑不变。
- sql-escape：`<select id="dialect">` 加 `onchange="__escLive()"`（与 quote 复选框、输入框一致，切换方言即重算当前转义方向）；`unesc()` 改为仅当 trim 后呈配对引号字面量才按边界 slice，未加引号纯文本原样保留首尾空格。

## 证据（真机 + 差分）
- 原型属性词频：JSDOM 旧源码输入 `constructor constructor hello` ⇒ 词频区「⚠ 计算结果含无效值」；修后 ⇒ `constructor 2 hello 1`。verify 强锁 `expect: ["constructor 2 hello 1"]`，旧源码跑该 slug 4/5（新用例正确变红），新源码 1689/1689。
- SQL 方言：独立脚本 `scripts/_verify_sql_dialect.mjs`（verify harness stub DOM 不解析 onchange 属性，故用 JSDOM 真机）——新源码 4/4，旧源码 2/4（onchange 探针 + change 重算两判别点变红）。MySQL `It\'s fine` → 切 PostgreSQL 自动变 `It''s fine` → 切回 MySQL 复原。
- 反转义空白：`  abc  ` 旧 ⇒ `abc`，新 ⇒ `  abc  `（含首尾空格）；verify 强锁 `expect: ['TRIM " abc "']`（collectStrings 折叠连续空白为单空格），旧源码该用例变红。

## 判据说明
- 方言切换未纳入 verify 主库的原因：自研 stub DOM 对 select 的 onchange 属性既不进 attribute 也不进 property（`getAttribute('onchange')=null`、`outerHTML` 无该属性），无法构造可判别用例；在 clicks 里手动调 `__escLive()` 会绕过绑定导致旧版误绿（已弃用）。改用 JSDOM 真机脚本锁，判别明确。
