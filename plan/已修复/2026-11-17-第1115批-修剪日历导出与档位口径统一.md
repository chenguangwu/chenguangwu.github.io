# 第1115批 修剪日历导出与档位口径统一（12-N225 / 12-N226）

## 问题
`gardening/pruning-calendar` 的「导出明细 CSV」读取的是搜索历史表，首屏无历史时点导出无文件，有历史时导出的也是搜索词与截断结果，不是修剪日历；同时杜鹃秋季、栀子花春季标「可以」却分别写着「秋后勿修剪」「冬春勿剪」，月季冬季按公式框应重剪却只标「可以」。

## 改动
- `tools/gardening/pruning-calendar.html`：`__pruning_calendarExport()` 改为从 `PLANTS × SEASONS` 直接生成「植物 / 季节 / 档位 / 推荐时机 / 说明」五行矩阵（16×4=64 行），经 `TBKit.util.exportCsv` 下载，不再依赖搜索历史表。
- 档位纠偏：杜鹃 `autumn: ok → avoid`、栀子花 `spring: ok → avoid`、月季 `winter: ok → best`（同步月季说明为「冬季休眠期重剪骨架、去除枯弱枝」），并顺手修正栀子花图标占位 `icon:' white'` → `🌼`。
- `i18n/tools/content_deepdive.json` 与 `i18n/tools/en/gardening/pruning-calendar.json`：算例改为「月季：春冬 best（冬季休眠期重剪）、夏秋 ok」，构建回写页面与英译。
- `scripts/verify_gardening_calc.js`：新增 `PRUNECAL` 用例，注入秋季并同时校验秋季「不宜修剪 5 种」、导出函数形态、三处档位数据及深解算例口径。
- 计划清单删除 N225、N226 整条。
