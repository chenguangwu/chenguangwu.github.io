## 归档判据（三条满足其一即可）

1. **改了源**：`tools/**`、`i18n/**`、`json/**`、`scripts/**` 已改，且有验证证据（Node 复算 / 门禁回归用例 / 官方测试向量）。
2. **复核确认线上无需改码**：实读当前源码 + 复算，证明审计描述基于旧快照（陈旧证据）。
3. **口径/文档类**：说明文案、示例数值、引据已改正（含 deep-dive 的 i18n 源）。

**不归档**：`部分修复`、`仍待处理`、`待复核`、`已修声明未独立复验` 的条目——这些继续留在 `plan/categories/**`，直到真正闭环。

## 归档格式

```md
## 来源：<分类目录>/<文件>.md

### <原条目标题>（原严重度，已修复）
- 问题：…（原描述，保留以便回溯）
- 证据：…（原证据 + 修复后的源码位点）
- 修复（YYYY-MM-DD）：<改了什么 + 怎么验证的>
```

条目级（原条目仍是待办、只修掉了其中一个子问题）用：

```md
- 原条目：<所属条目标题>
- <复核/修复结论>
```

## 维护流程（每批修完必做）

1. 改源 → 跑该分类 `node scripts/verify_<cat>_calc.js` 清零 → 跑 `scripts/run_gates.py` 全绿；
2. 把该条从 `plan/categories/**` **整段删掉**（不是复制）；
3. 在 `plan/已修复/` **新建本批文件**（`YYYY-MM-DD-<NN-分类>-<主题>.md`），把移出的条目按「归档格式」写进去；**不要追加到既有分类文件**；
4. commit（与修复代码同一批），标题写明归档的分类与本批文件。

> 铁律：**本目录只存已修复项，不登记待办**；`plan/categories/**` 只留未闭环项。两边不允许同一条目同时出现。
