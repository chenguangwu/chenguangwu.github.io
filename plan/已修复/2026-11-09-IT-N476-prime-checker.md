## 一、缺陷：判定对象被静默替换

`num(id)` 只 `parseFloat`，`calcTool()` 再 `Math.floor`，输入框虽有 `step="1"` 却不校验。`isPrime` 与因式分解都基于被改写后的 `n`。`node vm` 抽取页面真实脚本对照：

| 输入 | 修复前 | 修复后 |
|---|---|---|
| `2.5` | `判定结果 2 是质数 ✅` | `请输入整数：不支持小数、科学计数法、负号或其它字符。` |
| `9007199254740993`（=3 × 3002399751580331） | `9007199254740992 是合数，最小质因数 2，因数分解 53 个 2` | `9007199254740993 是合数，最小质因数 3，= 3 × 3002399751580331（余项仍可分解）` |
| `1e21` | `1e+21 是合数` + 伪分解 `2×…×5×…` | 明确拒绝非十进制整数 |
| `2^61−1 = 2305843009213693951` | 按浮点判错 | `2305843009213693951 是质数 ✅` |

## 二、修复

`calcTool()` 重构为四段，新增 4 个顶层函数（`__pcL` / `__pcModPow` / `__pcMillerRabin` / `__pcBigFactor`），均带无参守卫（harness 兜底会遍历调用顶层函数）：

1. **严格校验**：`raw = String(n.value).trim()`；空值 → 「请输入一个正整数。」；非 `/^\d+$/`（小数、科学计数、负号、`0x10`、`97.0`）→ 明确拒绝，不再 `floor`。
2. **精确解析**：`const big = BigInt(raw)`，避免 `parseFloat` 精度损失；`big < 2n` 仍走原有「小于 2 的数既不是质数也不是合数」。
3. **≤ 2^53−1**：`Number(big)` 走原试除路径，**输出 HTML 逐字不变**（只把中文常量包 `__pcL` helper）。vm 对照 HEAD 版 10 组合法输入（97/2/91/89/42/0/1/104729/999999999999989/9007199254740991）**10/10 逐字一致** ⇒ 既有 5 条用例零漂移。
4. **> 2^53−1**：BigInt + 确定性 Miller-Rabin（12 个素数基）判质数；合数用**有界试除**（小素数 + 到 200000）找最小质因数，输出 `n = p × rest`，余项为合数时标注「余项仍可分解」，避免对大合数做 √n 试除把页面挂死。输入原串 `raw` 直接进输出，不再被浮点改写。

### 公式说明同步

`formula-eq` 是**按 `<br>` 分段**做 en json map key 的（不是整段一个 key），故末尾追加第 6 段「输入校验：仅接受十进制正整数；≤ 2^53−1 用试除精确分解，更大整数改用 BigInt + Miller-Rabin 判定并做有界试除…」，`i18n/tools/en/it/prime-checker.json` 同批新增该段中英映射。静态断言：6 段全部精确命中 map。

### 顺带修：动态结果区英文态

`#result` 由脚本重建，`--check` 只扫静态 DOM。新增 `__pcL(zh,en)` 包住全部动态串（判定结果 / 是质数 / 是合数 / 最小质因数 / 因数分解 / 小于 2 / 两条新错误提示 / 大数余项标注），中文态逐字不变。

## 三、两个 harness 坑（本批新增经验）

1. **stub DOM 元素创建顺序会改变 blob**：初版把 `const box=getElementById('result')` 放在读 `n` 之前，harness 按首次 `getElementById` 顺序收集输出 ⇒ 既有自动补强用例的 expect `"42\n判定结果 42 是合数 …"` 变成 `判定结果 …\n42`，整条红。改回**先 `n` 后 `result`**（与旧实现 `num('n')` 一致）后立即恢复。**改函数开头取元素顺序前，先查该页有没有锚定「输入回显 + 结果」的自动补强用例。**
2. **`String(fn)` 源码契约在本页失效**：该页被 harness 自动包装成 `__prime_checker_f0`，`String(calcTool)` 实际是 `function(){ var __r=__prime_checker_f0.apply(null, … }`，`indexOf('BigInt(raw)')` 恒 −1。改用**行为契约**：直接调用 `__pcMillerRabin(2305843009213693951n)===true && __pcMillerRabin(9007199254740993n)===false`，以及 `__pcL('判定结果','Result')==='判定结果'`；HEAD 页面无这两个函数 ⇒ 短路输出 0 ⇒ 负向变红。
