## 一、本批真实修复（9 条，全部改源）

### IT-N536 · password-strength 破解耗时三档标签与除数不一致（高，算错）
- **失败点**：`check()` 用 `seconds = combos/(1e10*2)`（实际 2×10¹⁰ 次/秒）作基准，却把三档标成「10 亿 / 1000 亿 / 1 万亿 次每秒」，并用 `/100`、`/100000` 换算，真实速率变成 2×10¹² 与 2×10¹⁵ 次/秒。
- **根因**：标签、除数、基准值三处各自为政，从未做一致性复算；默认 `ToolBox@2026`（78 bit）首行显示 479 千年（按 10 亿/秒应约 1000 万年）。
- **修复位点**：`tools/it/password-strength.html:check()` —— 统一 `seconds = 2^entropy / 1e9`；离线 GPU `/100`（=1e11）、超算 `/1000`（=1e12），与标签逐档对齐；三档标签改走 `pwQ()` 双语。
- **顺带修（同页真 bug）**：`formatTime()` 原只把「秒 / 分钟」两档做了英文，长单位「小时 / 天 / 个月 / 年 / 千年 / 百万年 / 十亿年 / 瞬间 / 宇宙级」全为中文硬编码；英文态结果区必然漏中文。现全部改走 `pwQ()`（中文态返回逐字相同的原串）。另把 14 条 `fbs` 反馈串、6 档 `label` 等级串一并改双语，`pwEn()` 加 `TBKit.util && isEn` 防御。
- **证据**：新增 verify 用例 `pwd=abc123测试`（48 bit）断言「在线破解（10亿次/秒）： 3 天」；运行期脚本另断言离线 46 分钟 / 超算 4 分钟与英文态 `3 days`。回退后该用例转红（HEAD 为「3 小时」）。

### IT-N537 · 公式承诺的熵判读从未输出（中，承诺未实现）
- **失败点**：`formula-eq` 写「判读：<40 弱｜40~60 中｜60~120 强｜≥120 极强」，但 `check()` 只用 6 项清单得分映射等级；32 个 `a` 熵 150 bit（公式应判「极强」）却只得 3 分 →「一般」。
- **修复位点**：`check()` 新增独立一行「熵判读（N bits）： 等级」，等级由熵值单独计算，**不替换** 6 项清单等级；公式框改为如实说明「熵判读（单列）…；强度等级由 6 项清单得分映射」，消除两套口径混淆；`i18n/tools/en/it/password-strength.json` 同步换键。
- **证据**：新增 verify 用例 `pwd=32×a` 断言「熵判读（150 bits）： 极强」；运行期脚本同时锁英文态 `Entropy verdict (150 bits): Very strong`。回退后转红。

### IT-N538 · 键盘序列正则 `^` 锚定漏判中段（中，错误结果）
- **失败点**：`xxqwe123`、`Tq7!abc123` 这类序列在中间或后段时，风险提示与反馈清单都不命中。
- **根因**：`check()` 与 `__pwdExtras()` 两处同一正则均以 `^` 开头。
- **修复位点**：两处去掉 `^`，字符串任意位置命中即提示（中文态文案逐字不变）。
- **证据**：新增 verify 用例 `pwd=xxqwe123` 断言「⚠️ 包含键盘连续序列（如123、abc、qwe）」；英文态另断言 `Keyboard sequence (e.g. 123, abc, qwe)`。回退后 2 条均转红。

### IT-N539 · python-cheatsheet 15 条示例 32 处 `--` 行内注释（中，复制即 SyntaxError）
- **修复位点**：`tools/it/python-cheatsheet.html` 全部 15 条 `example` 改 `#` 注释（Python 无 `--`）；裸 `raise` 补 `try/except ValueError` 上下文，不再是「函数外 bare raise」。
- **EN 键同步**：原本在 map 中的 8 条 example 全部同步换键与译文；另修两条「键先改 `#`、HTML 又改成 try/except 与 `import helper`」造成的漏键（批量改后务必用「改动字段 × 新 map」复核，本批实测揪出 2 条）。
- **证据**：`_verify_cheatsheet_syntax.mjs` 断言 `-- 计数 0`、`#` 存在、`except ValueError:` 存在。

### IT-N540 · python-cheatsheet 装饰器与相对导入不可执行（中）
- **修复位点**：`syntax` 字段 `@dataclass class C:` → `@dataclass\nclass C:`（装饰器必须独立成行）；`from . import helper` → `import helper  # 同目录模块（相对导入需包内）`（独立脚本复制后可运行）。
- **证据**：语法脚本 2 条断言 + EN 键同步。

### IT-N541 / IT-N542 · rust-cheatsheet 注释符与占位表达式（中）
- **N541**：7 处 `--` 改 `//`（Rust 无 `--` 运算符），5 条 example 全部改为可编译形态。
- **N542**：`if x > 0 { ... }` / `while cond { ... }` 的 `...` 占位换成真实表达式；`let n = parse("1")?;` 从顶层移入 `fn demo() -> Result<(), ParseIntError>` 并补 `use std::num::ParseIntError;`，同时去掉未定义的 `r.unwrap_or(0)` 改为 `parse("x").unwrap_or(0)`。

### IT-N543 · redis-cheatsheet 行内注解被当成命令参数（中）
- **失败点**：`PING  -- 返回 PONG`、`TYPE mykey  -- …`、`EXEC  -- …`、`OBJECT ENCODING mykey  -- …` 共 4 条；redis-cli 不支持行内注释，粘贴即 `wrong number of arguments`。
- **修复位点**：4 条 `example` 里的 `  -- 注解` 整体删除，只留纯命令（PING / TYPE / EXEC / OBJECT ENCODING）。`PING`、`WATCH…EXEC` 两条原本在 map 中的键与译文同步更换。
- **证据**：语法脚本断言 `-- 计数 0` 且 `PING\nPING hello` 存在。

### IT-N544 · redis-cheatsheet `SINTER` params 承诺不存在的 `STORE`（中）
- **根因**：`SINTER/SUNION/SDIFF` 三命令不接受 `STORE`，存结果必须用 `SINTERSTORE/SUNIONSTORE/SDIFFSTORE`。
- **修复位点**：`params` 改「存结果须用 SINTERSTORE / SUNIONSTORE / SDIFFSTORE」；`example` 补一行 `SINTERSTORE out set1 set2`；EN map 把旧键 `STORE 可存结果` 换成新键（避免英文态漏中文）。
- **证据**：语法脚本断言 params 含三个 `*STORE` 命令且 example 含 `SINTERSTORE out set1 set2`。
