## 1. 失败点（只读复核确认仍成立）

台账 F-N189 记录 3 个失败点，本批复核后**新增发现第 4 个**：

1. **趋势图 div 永不出现**：`__<pre>Render()` 里 `var v=parseFloat(arr[j].d[rk])`，而 `rk` 存的是整段结果文本（`ResText` 截 80 字，如「输入： … 校验和： ✅ 通过」）⇒ `parseFloat` 恒 `NaN`，`nums.length>=2` 永不成立，`#<pre>Chart` 一直空白。
2. **「导出明细 CSV」名不符实**：导出的是 `#<pre>Table`，而该表由 `TBKit.history.list().slice(0,10)` 渲染成「最近 10 条历史表」，不是本次计算明细；且表格只有「时间 / 输入 / 结果」3 列，缺结论。
3. **失败样本从不入表**：`ResText` 用 `/请输入|无效|不正确|错误|Error|NaN/` 整段过滤 ⇒ CNPJ / IMEI / NIE / ICCID 校验失败的结果文本被丢弃，首次点击「导出」只剩表头，「数据表 / 历史」也不记录失败尝试。
4. **（新增）空表格时点击导出无任何反应**：`exportTable` 在无 `<tr>` 时返回 `false`；而 `Render()` 只在 `Extras()` 成功写入历史时才执行。若用户打开页面后一直未产生有效结果（或清空历史），`#<pre>Table` 为空，点击按钮静默失败。

**范围复核**：预探查发现该模板派生页远多于台账写的「6 个校验页 + 文本反转页」——实为 **15 页**（每页都恰好有 `exportTable('#xxxTable')` ×1 与恒 NaN 的 `parseFloat(arr[j].d[rk])` ×1）。本批先修台账点名的 7 页，剩余 8 页（`tin-validator`、`gstin-validator`、`tfn-validator`、`pan-validator`、`curp-validator`、`dni-validator`、`meid-validator`、`sort-code-validator-validator`）留第 41 批按同一模板续修，避免逐页实现漂移。

## 2. 根因

同一份模板代码被复制到 15 个页面，模板本身把**「结果展示文本」误当成「可绘图数值」**，又把「历史摘要表」当成「本次明细表」导出；`ResText` 的过滤正则本意是排除空态，却把合法的计算结果（含「无效 / 错误」字样）一并丢掉。三个问题同源：**记录结构里没有独立的数值 / 结论字段**。

## 3. 修复位点（统一模板，7 页逐字同构）

由 `/tmp/fn189_patch.py`（临时脚本，用完即删，未入库）以**精确边界断言**整体替换每页 `function __<pre>ResText(){` → `function __<pre>Presets(){` 之间的 5 个函数，模板只带 4 个参数（函数前缀 / 变量前缀 / DOM id 前缀、结果容器 id、计算函数名、csv 文件名）。替换前断言起止标记各出现 1 次、旧块含 `exportTable` / `chart.line` / `matrix.table`，替换后断言 `__tbScore` 恰好 4 处、`Score` 函数存在、无错误下划线前缀 ⇒ 杜绝「只删一半致 SyntaxError」（既有教训）。

1. **新增 `__<pre>Score(t)` 作为数值结论单一真源**：失败 / 警告 / 空态特征（`❌` `⚠️` `无效` `未通过` `失败` `Invalid` `Failed` `must be` …）→ `0`，其余（含纯文本类结果）→ `1`。
2. **`ResText()` 不再过滤失败样本**：只过滤空态前缀 `/^(等待输入|请输入文本|Waiting for input|Please enter text)/`，其余结果摘要照常截 80 字返回 ⇒ 失败样本入库。
3. **`Extras()` 写入 `rec.__tbScore = __<pre>Score(res)`**：与语言无关的固定键，避免中英切换在同一 localStorage 里混存两套键。
4. **`Render()` 表格新增「结论」列**：表头 `en?'Verdict':'结论'`，单元格由 `__tbScore` 推 `通过 / 未通过`（EN `Pass / Fail`），缺字段显示 `-`；历史恢复回调 `k==='__tbScore'` 时跳过回填（内部字段不是输入控件）。
5. **趋势图数值源改为 `parseFloat(arr[j].d.__tbScore)`**，序列名改 `en?'Validity trend':'有效性趋势'` ⇒ 两次不同计算后图表真实渲染，语义与 0/1 数据一致。
6. **`Export()` 先确保表格已渲染**：`document.querySelector('#<pre>Table')` 无 `<tr>` 时先按当前快照调 `Render()` 补渲染，再 `exportTable` ⇒ 消除「点击无反应」。
7. **刻意不改按钮文案 / 静态中文 / en map**：表格已升级为「时间 + 全部输入 + 结论 + 结果摘要」的完整明细（每行一次计算），「导出明细 CSV」名实相符；改按钮中文会牵动全站 105 页静态文案与 `js/tool-i18n-en.js` / 15 个页面级 en map，收益不抵 EN 态 CJK 泄漏风险。新增文案全部 `en ? English : 中文` 动态双语。

**同构性证据**：7 页替换段归一化（函数名 / DOM id / csv 名 / 结果容器 / 计算函数 5 处参数统一占位）后**逐字一致**，两态锁内置该断言。
