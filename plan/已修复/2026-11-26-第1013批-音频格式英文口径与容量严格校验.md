## 2. 音频容量估算输入与单位错误

- `calcPCM()` 新增 `readNum()` 严格校验：采样率 1–768000 Hz 整数、位深 1–64 bit 整数、声道 1–8 整数、时长 0.001–86400 秒；任一项为空、0、负数、越界或应为整数的字段填小数，均在结果区给出明确范围并清空结论。
- 单位统一十进制：`totalBytes / 1e6` 得 MB；MP3/AAC 按 `kbps × 1000 × 时长 / 8 / 1e6`；公式说明与格式体积表同步 `1,000,000`。
- 算例：44.1 kHz / 16-bit / 立体声 / 180 s → PCM 31.75 MB；MP3 320 kbps → 7.20 MB（旧实现 7.03 MB）。
- 深度解析与指南同步：10.58 MB、105.8 MB、7.20 / 4.32 / 2.88 MB；更新 `content_deepdive.json`、`en/music/audio-converter.json`、`guides/audio-converter-guide.html`。

## 3. 音频分析容量输入与单位

- `calcAudioSize()` 同样接入 `readNum()`，逐项校验并区分空值与合法数值；非法输入清空结果。
- 统一十进制：总大小 `bytes / 1e6` MB，每秒 `bytesPerSec / 1000` KB/s 并标注「十进制」。
- 算例：66.1 kHz / 16-bit / 立体声 → 264.60 KB/s、60 秒 15.88 MB、每小时 952.56 MB（旧实现 258.40 KB/s）。
