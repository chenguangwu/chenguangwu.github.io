### 薄透镜图：焦点处错误成像且无效输入保留旧图

- 失败点：① `f=0.1m / d_o=0.1m` 时页面仍显示「实像·倒立·放大」，`#thinLensRay` 的 SVG 坐标含 `Infinity`；② 随后清空焦距，早退未清 `#thinLensNature` 与 `#thinLensRay`，旧图和旧结论仍保留。
- 根因：① `1/dᵢ = 1/f − 1/d_o = 0` ⇒ `dᵢ=Infinity`、`m=−Infinity`，`calcTool()` 的 dataGrid 用 `toFixed` 输出 `Infinity`（被结果层洗成 `—`），`calcRay()` 却继续按 `di>0` 判实像、`Math.abs(m)>1` 判放大，并把 `yI=Infinity` 直接拼进 SVG；② `__tbInputGuard` 命中时 `calcTool()` 只写结果区就 `return`，从不调用 `calcRay()`，而清图逻辑只在 `calcRay()` 内。
- 修复位点（`tools/optics/thin-lens-equation.html`）：
  1. `calcTool()` 在 guard 早退分支补 `try{ calcRay(); }catch(e){}`，失效态由 `calcRay()` 统一的 `!(f>0&&do_>0)` 分支清空结论与光路图。
  2. `calcTool()` 与 `calcRay()` 都用相对容差 `Math.abs(do_-f) <= 1e-9*Math.max(f,do_)` 判焦点边界：结果区改输出「物距等于焦距：出射光平行，像在无穷远，不形成有限像」，结论区输出「像距 d_i = 无穷远 / 放大率不定义 / 出射光平行 · 像在无穷远 · 不形成有限像」，并**清空**会带 Infinity 坐标的错误光路图。
  3. 把 `en`（英文态判定）提前到焦点分支之前，保证新增动态文案在英文态也走 helper，不漏译。
- 证据：`LENSFOC svgEmpty=1 svgInf=0 msg=1 nat=1`（修复前 `svgEmpty=0 svgInf=1 msg=0 nat=0`）、`LENSCLR first=1 empty=1 restore=1`（修复前 `empty=0`）、`LENSSIDE virt=1 real=1`（焦点两侧护栏，修复前后都绿）。

### D-N60 网格渐变 PNG 与预览的层叠顺序相反

- 失败点：把红、蓝控制点拖到同一位置，CSS 预览中心是首层红，PNG 导出中心却是后画的蓝。
- 根因：CSS 的多个 `background-image` 是**第一层在最上**，而 canvas 是**后画的覆盖先画的**；`downloadPNG()` 用 `colors.forEach` 从首到末绘制，正好把层叠方向反了过来。
- 修复位点（`tools/design/mesh-gradient.html` `downloadPNG()`）：改为 `colors.map((c,i)=>({c,p:pos[i]||[50,50]})).reverse().forEach(...)`，让 `colors[0]` 最后绘制、位于最上层；底层 `ctx.fillStyle=colors[0]` 对应 CSS `background-color`，保持不变。径向近似误差的既有声明不受影响。
- 证据：用可控 `document.createElement('canvas')` 桩捕获 `addColorStop(0,c)` 的绘制序列。两色重合 `MESHLAYER css=1 order=#0000ff,#ff0000 ok=1`（修复前 `order=#ff0000,#0000ff ok=0`）；三色重合 `MESH3 order=#333333,#222222,#111111 ok=1`（修复前正序、`ok=0`）。`ok` 判据是「最后绘制的颜色 === CSS 首层颜色」，即重合点预览与导出颜色一致。
