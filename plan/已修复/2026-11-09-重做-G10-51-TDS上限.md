# 复核失败重做批次 · 申请再次复核

## 条目

- 来源：`plan/复核失败/2026-11-09-第七批.md` → `## G10-51 TDS 输入上限未生效`
- 失败点：输入 `5001` 仍输出「5001 ppm - 不宜饮用」。输入控件 `min=0 max=5000` 与错误提示均声明 0–5000，但 `evaluate()` 只拦 `tds<0` 与 `!isFinite(tds)`。
- 根因：① 缺上界判断；② `parseFloat(...) || 0` 把 NaN 与非法字符串兜底成合法 0，掩盖无效输入；③ 分级表末档 `max:99999` 与声明范围矛盾，静态分级表显示「1000 ~ + ppm」。
- 上次修复为何不彻底：上一轮只补了负值与非有限值拦截，未把「控件声明的区间」落实为校验条件，也未处理分级表本身的越界上限。

## 修复位点

- `tools/energy/water-tds-evaluator.html`：末档 `{ min: 1000, max: 99999 }` → `max: 5000`，使静态分级表与结果卡的「分级范围」落在 0–5000 内。
- 同文件 `evaluate()`：改为 `tdsRaw=String(...).trim(); const tds=parseFloat(tdsRaw);`，条件扩为 `!isFinite(tds) || tds<0 || tds>5000`；越界时清空 `tdsBar` 宽度/背景/文本、`vizGrade` 等级与颜色、`result` 旧结论，并给出中英双态范围提示（英文态不泄漏中文）。
- 保留合法 0 与 5000 闭区间端点；空值仍由原有空态守卫处理。
