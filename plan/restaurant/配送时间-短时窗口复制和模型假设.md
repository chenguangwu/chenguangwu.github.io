# 配送时间窗口复制不一致及模型假设

- 受影响工具：`tools/restaurant/delivery-time.html`
- 问题：结果窗口下限使用 `Math.max(0, minTime)`，复制文本却使用 `Math.max(1, minTime)`；例如距离和各等待时间均为 0 时，页面显示 0～5 分钟，复制为 1～5 分钟。窗口始终固定为估计值上下 5 分钟，未说明这是人为范围而非基于实际订单的可靠区间；备餐与骑手等待直接相加，也未说明它们不能重叠的假设。
- 解决方案：统一页面与复制结果的边界；说明固定区间和串行阶段假设，支持用户按本地经验设置缓冲，或用独立阶段与重叠模式表达实际流程，避免将范围当作送达承诺。
- 验证建议：核对 0 分钟及小于 5 分钟估计、正常估计和复制结果；用备餐与等待重叠的样本验证假设说明。
