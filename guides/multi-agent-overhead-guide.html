多智能体通信开销 使用指南

按智能体数量与消息频率估算全连接多智能体系统的通信开销，适用于多 Agent 架构设计、通信瓶颈识别与成本评估。

计算公式与原理

消息总数 = n(n − 1) × 轮数；总流量 = 消息总数 × 单条大小

全连接广播模式下每个智能体每轮要向其余 n−1 个发消息，通信量随智能体数量呈平方增长，这是多智能体系统规模化的主要瓶颈。改为分层或共享黑板（blackboard）可把复杂度降到线性。

使用步骤

  1. 填写「智能体数」。
  2. 填写「通信轮次」。
  3. 填写「单消息 KB」。
  4. 结果区会即时更新；可一键复制结果用于记录或汇报。

典型使用场景

  • 全连接拓扑下每轮消息数=C(n,2)=n(n−1)/2，随智能体数平方增长。
  • 开销=消息数×单消息体量(上下文/token)，是通信瓶颈与成本主因。
  • 可用分层/星型/广播拓扑削减边数，或用摘要压缩降低单消息体量。

算例参考

  • 全连接开销：n=10 个智能体全连接：每轮消息=10×9/2=45 条。若单条含 2k token，每轮通信≈90k token；n=20 时消息=190，开销约 4 倍，增长极快。

注意事项

结果为按上述公式得到的理论估算值，实际表现受数据分布、实现细节与运行环境影响，落地决策请以实测为准；本工具纯前端运行，输入不上传服务器。

怎么降低多智能体通信成本？
改全连接为星型/分层(中心协调)，减少边数；消息用摘要而非全文；并设定通信轮次上限，避免无限对话空转。
全连接有必要吗？
多数任务不需要。全连接让任意两体直连、信息同步快但成本高；若任务可分解，子团队+汇总更高效，性价比更好。
