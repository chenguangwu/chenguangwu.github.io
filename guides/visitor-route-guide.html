参观流线规划 使用指南

以展厅为节点、通道距离为边权，用 Dijkstra 算法规划入口到出口的最短参观流线，并支持按顺序串联必看节点；空值、非数值与负距离会被排除并提示，不会静默当成 0。

功能说明

页面把当前展厅列表建成无向图，每条通道的距离作为非负权重。起点、必看节点与终点按输入顺序分段求最短路径后拼接，总距离为各段之和。端点已失效的通道、距离为空或为负数的通道都不会进入图，并在结果上方列出原因；这样未知通道不会因为权重 0 而被误选为最短路径。

典型使用场景

  • 设计常设展动线：入口→青铜馆→陶瓷馆→书画馆→玉器馆→出口，比较不同串联顺序的总步行距离。
  • 限流时把某段通道距离调大，观察路线是否绕开该区域。
  • 只去重点馆时，把重点馆填入“必看节点”，按顺序分段计算。

操作步骤

  1. 确认展厅列表完整，修改名称后旧通道端点会标红。
  2. 逐条填写通道两端与距离（米）；已知同址通道可明确填 0，未知距离必须留待补测而不是填 0。
  3. 选择起点、终点，必要时填写逗号分隔的必看节点。
  4. 点击“规划最短流线”，查看路径、分段距离与总距离；有无效通道时先按提示修正。

算例参考

  • A（入口）→B 20 m、B→C 30 m、A→C 直连 80 m：A→B→C 合计 50 m，短于直连 80 m。
  • 若 B→C 距离留空，该边被排除；此时只能走 A→C 80 m，并在结果上方提示“距离为空”。
  • 若某条通道填 −10 m，该边被拒绝，不再取绝对值 10 m 参与计算。

注意事项

Dijkstra 只适用于非负权重，因此负距离必须修正而不是取绝对值。距离为 0 只应出现在确实同址的通道；未知通道按 0 计算会制造一条“免费捷径”。端点名称含 HTML 字符时，页面统一转义后再显示，不会改变提示结构。路线优化只看距离，不自动考虑客流、单向限流或无障碍条件。

通道距离留空会怎样？
该通道被排除并在结果上方提示，不会当成 0 参与最短路径；请补测或删除该通道。
负距离为什么不再自动取绝对值？
负权会破坏 Dijkstra 的前提，也可能造成前驱成环；工具直接拒绝并提示修正，避免给出错误路线。
为什么有时绕路反而更短？
算法按累计权重求全局最短，直线近不代表总距离小；经中转节点可能累计更少。
必看节点如何串联？
按输入顺序逐段求最短再拼接，不会自动重排顺序；如需优化顺序，请调整输入次序后比较总距离。

为什么有时绕路反而更短？
Dijkstra 按边的权重（通道距离）求全局最短，并非直线近就快；经中转节点可能累计权重更小（如 A→B→C=50m < 直连 80m）。规划以算法结果为准，凭直觉易误判。
权重除了距离还能用什么？
可把边权设为通行时间、拥挤度或能耗，算法同样适用；若要考虑「必经重点馆」，可设其为中间节点分段求解再拼接路径，得到带约束的最短动线。
