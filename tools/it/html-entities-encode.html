🔤 HTML Entities Encode

Encode and decode HTML entities (named and numeric) in your browser — keep markup and text safe.

📐 工作原理与说明
逐字符取码点，满足下列任一条件才编码：开启全部编码，或码点大于 127，或字符是与号、小于号、大于号、双引号、单引号。命名模式且该字符存在命名实体时输出命名实体；十进制模式输出与号井号加十进制码点再加分号；十六进制模式输出与号井号 x 加十六进制码点再加分号；其余情况回退为十进制形式。不满足编码条件的字符原样保留。解码走单次纯文本扫描：按「&#十进制 / &#x十六进制 / &命名实体」三种形态匹配，分号可省略；命名实体查 HTML5 全量命名实体表（2125 条，含多码点实体），无分号时仅解 HTML5 允许省略分号的常用子集（amp/lt/gt/quot/nbsp/copy/reg）；码点超出 0–0x10FFFF 或落在代理区 0xD800–0xDFFF 时原样保留。全程不建 DOM、不把输入交给 innerHTML，因此不会触发外部资源请求，也不会把解出的与号二次解码
在文本与 HTML 实体之间双向转换。
  • 编码：可只转义必要字符，也可把全部非 ASCII 字符转为数值实体。
  • 解码：需同时支持命名实体与数值实体（含 &#xHH; 十六进制形式）。
  • 陷阱：重复转义会产生 &amp;amp; 这类双转义，显示出错。
  • 用途：模板输出、富文本存储、跨系统数据交换。

❓ 常见问题（FAQ）

全量编码会不会影响中文？
中文也可编成 &#20013; 形式，但体积大，通常只编码特殊字符。
全量编码和只转义危险字符有什么区别？
只转义 < > & " ' 五个字符能防 XSS，且中文与排版保持原样；全量编码会把每个非 ASCII 字符都转成 &#xXXXX;，虽能绕开部分编码问题，但体积变大、可读性变差，旧编辑器回显时还可能变成乱码。日常建议只转义危险字符。
