✅ JSON Schema Verifier

JSON Schema Verifier is available directly in your browser, with no data uploaded.

📐 工作原理与说明

JSON Schema 是一种用 JSON 描述数据结构的规范：用 type 约束字段类型、required 标记必填、properties 定义子字段、additionalProperties 控制是否允许额外字段。本工具在浏览器内解析 Schema 与待校验 JSON，逐条比对约束并定位首个错误位置，数据不出本地。

📚 深度解析：JSON Schema 验证器

💡 常见使用场景

  • 接口联调：用一份 Schema 约束请求体 / 响应体，双方按同一份契约开发，提前发现字段类型或必填项不符。
  • 配置校验：在 CI 或本地校验配置文件（如 JSON 配置）是否符合预期结构，避免上线后解析失败。
示例：校验一个对象
Schema： ```json {"type":"object","required":["name","age"],"properties":{"name":{"type":"string"},"age":{"type":"integer"}}} ``` 数据 `{"name":"Alice","age":"30"}` → 报错：`age` 应为 integer 但收到字符串。改为 `30` 后通过。
示例：数组元素约束
`{"type":"array","items":{"type":"number"}}` 校验 `[1,2,"x"]` → 报错：第 3 个元素不是 number。

❓ 常见问题（FAQ）

支持哪个 Schema 版本？
工具以常用的 Draft-07 / 2020-12 风格为主，覆盖 type、required、properties、items、enum、format 等常用关键字；极细分的私有关键字可能不被完全支持。
required 和 type 怎么配合？
`required` 列出必须出现的字段名（缺一个即报错）；`type` 规定该字段的数据类型（string/number/integer/object/array/boolean/null），类型不对也会报错。
报错信息看不懂怎么办？
错误信息通常含"路径 + 期望类型 + 实际值"，例如 `age: expected integer, got string`。先按路径找到对应字段，再对照 Schema 修正类型或补必填项。
