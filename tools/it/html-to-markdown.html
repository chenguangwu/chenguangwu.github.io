📝 HTML to Markdown

HTML to Markdown

📐 工作原理与说明
DOMParser 解析为文档后递归转换，行内与块级分别处理。行内：文本节点先压缩连续空白再做 Markdown 元字符转义（反斜杠、*、_、`、[、]）；STRONG/B → 两侧 **，EM/I → 两侧 _，DEL/S → 两侧 ~~；CODE 在 PRE 内取原文作三反引号代码块，否则作单反引号行内码（两者内部一律不转义）；A → [文本](href)、IMG → ![alt](src)；BR → 行尾两个空格加换行（硬换行）。块级：H1-H6 → 对应个数的 # 加递归文本；P → 递归文本加两个换行；HR → ---；PRE → 三反引号块并去掉尾部换行；BLOCKQUOTE → 每行加 > 前缀；UL → 每项 - 前缀、OL → 每项 序号. 前缀，列表项内部的换行保留、续行按项目符号宽度缩进（嵌套列表因此不丢层级）；TABLE → 首行作表头、第二行全为 --- 分隔、其余为数据行，单元格取递归 Markdown 后把换行拍平、竖线转义；SCRIPT/STYLE/NOSCRIPT 整段丢弃。最后把 3 个以上连续换行压成 2 个并去首尾空白
把 HTML 转换为 Markdown 文本。
  • 映射：h1–h6 → #~######，strong/b → **，em/i → _，a → [文本](链接)，img → ![alt](src)。
  • 结构：列表、引用、代码块、表格需按 Markdown 语法保留层级与对齐。
  • 丢失：class、style、脚本等表现层信息会被丢弃，Markdown 不表达样式。
  • 转义：内容中的 * _ [ ] 等需转义，避免渲染错乱。

Formula & Standard References

Item Formula / Note Source / Standard
Heading mapping h1-h6 map to one to six # prefixes CommonMark specification
Links and images a[href] to [text](url); img to ![alt](src) CommonMark specification
Emphasis strong to **text**, em to *text* CommonMark specification
📌 说明
  • 基于解析后的 DOM 节点逐层转换，保留多层列表结构。
  • 支持 h1~h3、p、ul/ol、table、a、img 与代码块。
  • 输出为纯 Markdown 文本，未联网处理。

💡 常见使用场景

  • 把网页内容转成轻量 Markdown。
  • 把旧站点文章批量迁到 Markdown 博客：先转格式再人工校对，比逐篇重写省时得多。
转换
`<h1>标题</h1><p>文本 <b>粗</b></p>` → `# 标题 文本 **粗**`。

❓ 常见问题（FAQ）

复杂表格能转吗？
多数能，但合并单元格等需人工修。
转换后格式丢了怎么办？
Markdown 的表达能力弱于 HTML：合并单元格、内联样式、自定义容器与脚本交互都没有对应语法，通常降级为纯文本或被丢弃。策略是先转换、再对复杂区块单独手工处理；若原文档大量依赖这些特性，保留 HTML 反而是更务实的选择。
