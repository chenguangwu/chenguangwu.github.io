🗄️ SQL Format

📐 工作原理与说明
先删除行注释（双横线到行尾）与块注释，再把连续空白压缩为单个空格并去掉首尾空白。随后按子句关键字列表（SELECT、FROM、WHERE、GROUP BY、ORDER BY、HAVING、LIMIT、OFFSET、各种 JOIN、UNION ALL、UNION、ON、VALUES、SET）依次把「关键字」（按词边界、忽略大小写，关键字内部空格按空白匹配）替换为「换行 + 大写关键字 + 换行 + 缩进」，并把每个逗号及其后空白替换为「逗号 + 换行 + 缩进」。再逐行处理：以主要关键字开头的行保持原样，其余非空行且尚未以缩进开头时补上缩进。开启关键字大写时，对关键字列表做整词、忽略大小写的替换为其大写形式。最后合并连续空行并去掉首尾空白
格式化 SQL 语句，提升可读性。
  • 处理：关键字统一大小写，主要子句（SELECT、FROM、WHERE、JOIN 等）各占一行并缩进。
  • 语义：格式化只改排版，不改变执行语义与结果。
  • 风格：关键字大写或小写依团队约定；复杂条件与子查询做层级缩进。
  • 用途：统一 SQL 书写风格，便于代码评审与问题排查。

❓ 常见问题（FAQ）

会改变执行计划吗？
不会，仅调整空白与大小写。
格式化后结果变了是怎么回事？
纯格式化不会改变语义，但要注意两点：一是注释里的优化器提示（如 /*+ INDEX(...) */）若被移动或删除，会直接影响执行计划；二是某些方言里换行位置会影响语义。格式化后建议对比关键查询的执行计划。
