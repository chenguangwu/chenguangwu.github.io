📄 JSON Repairer

JSON Repairer - Fix broken JSON (trailing commas, single quotes, comments) and validate it locally. Free, browser-only.

📐 工作原理与说明
按固定顺序修复：先删除块注释，再删除行注释；把「花括号、逗号、方括号或冒号 后跟单引号包裹的键名再加冒号」的形式改为双引号包裹的键名；把「冒号后跟单引号包裹的值」改为双引号包裹的值；最后删除右花括号或右方括号之前多余的逗号
修复格式不规范的近似 JSON 文本。
  • 常见错误：尾随逗号、单引号、未加引号的键、混入注释、缺少逗号或括号。
  • 策略：补齐缺失的引号/逗号/括号，去除注释，把单引号转为双引号。
  • 风险：修复是启发式的，可能改变原意，重要数据必须人工复核。
  • 场景：处理从日志、LLM 输出或非严格配置中粘贴的内容。

⚠️ 使用说明与注意事项
  • 修复器会移除 /* */ 与 // 注释、把单引号键/值转成双引号、删除对象/数组尾随的逗号，覆盖大多数复制粘贴造成的错误。
  • 修复是启发式的：若结构本身严重损坏（缺少括号或引号未闭合），仍可能失败，请对照错误提示手动修正；字符串内容（URL、正则、含 // 的文案）不会被当作注释删除。
  • 处理敏感数据时请在本地完成，不要上传到第三方修复网站。

💡 常见使用场景

  • 修复缺引号、尾逗号等非法 JSON。
  • 救回一段粘错的不完整 JSON：补齐缺失的引号与花括号，先从日志里恢复出可读结构，再确认内容是否可信。
修复
`{a:1,}` → 修复为 `{"a":1}`（补键引号、去尾逗号）。

❓ 常见问题（FAQ）

自动修复会改语义吗？
仅修语法错误，不改变字段与值。
修复后的数据能直接用吗？
不能盲信。修复器只能按启发式规则猜测缺失部分——多一个逗号是笔误还是少了一个元素，工具无从判断。正确做法是把修复结果当作「可读性恢复」用于排查，之后回源头重新获取完整数据；若必须消费，务必再做一次 Schema 校验。
