🖥️ Nginx Config Generator

Nginx Config Generator - Pick static site or reverse proxy and fill params to emit a server block config. Free, browser-only.

📐 工作原理与说明
按模式取值：域名为空时用下划线占位；域名逐项校验只允许字母/数字/点/连字符/下划线/通配符；静态目录与证书路径校验为以 / 开头的可打印 ASCII 且不得含分号、大括号、$ 或控制字符，含空格的路径输出时加双引号并按 Nginx 语法转义引号与反斜杠；反向代理地址用 URL 解析校验 http/https；端口必须是 1–65535 的整数。静态模式生成 server 块，依次写入监听端口、服务名、根目录、默认首页，以及「依次尝试请求路径、路径作为目录、否则返回 404」的 location；反向代理模式生成 server 块，依次写入监听端口、服务名，以及把请求转发到所填上游地址的 location，并设置转发请求头中的主机名与客户端真实地址。输出时对整段配置做 HTML 转义后在代码块中展示
按场景生成 Nginx server 配置。
  • 场景：静态站点、反向代理、HTTPS、负载均衡、单页应用（SPA）回退。
  • 核心项：listen 端口、server_name、root/index、location 匹配规则与优先级。
  • HTTPS：ssl_certificate、ssl_certificate_key，并限制协议版本与加密套件。
  • 反代：需设置 proxy_set_header 传递真实客户端 IP，否则后端日志全是代理 IP。

⚠️ 使用说明与注意事项
  • 反向代理的 proxy_pass 末尾是否带 / 影响路径拼接：带 / 会剥离 location 前缀，按需选择。
  • 配置改完用 nginx -t 校验语法，再 nginx -s reload 生效，避免写错导致服务中断。
  • 生产应补 TLS（listen 443 ssl）、gzip、缓存头等；本工具只生成最小可用骨架。

❓ 常见问题（FAQ）

生成后怎么用？
放入 conf.d 并 `nginx -t` 校验后 reload。
生成后还要补什么？
至少三件事：一是 HTTPS 的收尾（本工具可生成证书与私钥路径，仍需自行补 HTTP/2 与 80→443 跳转）；二是安全头（HSTS、X-Content-Type-Options，CSP 视情况）；三是上传大小与超时（client_max_body_size、proxy_read_timeout），默认值常不适合实际业务。上线前务必 nginx -t 校验。
