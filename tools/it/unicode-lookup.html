🌐 Unicode Query

📐 工作原理与说明
码位显示规则：字符码点转十六进制后格式化为 U+XXXX（至少 4 位大写十六进制，不足补零）；搜索支持 U+XXXX / 0xXXXX 码点、Unicode 字符名（内置 1342 条标准名称，覆盖全部可浏览区段与常用符号）与逐字符查询，浏览模式按区段起止遍历；表外字符按 CJK / Hangul 规则推导名称或如实标注未收录
Unicode 为世界上大多数字符分配唯一码点，是跨系统文本交换的基础。
  • 码点：写作 U+XXXX，范围 U+0000–U+10FFFF，共分为 17 个平面。
  • 编码方式：UTF-8（1–4 字节，兼容 ASCII）、UTF-16（2 或 4 字节）、UTF-32（定长 4 字节）。
  • 组合字符：重音等可由基础字符加组合符构成，如 e + ́ 显示为 é。
  • 注意：字形相同的字符可能码点不同（如全角与半角、兼容字符）。

📚 深度解析：Unicode 字符查询

💡 常见使用场景

  • 按名称或码点反查字符，常用于排查乱码、找特殊符号。
  • 排查形近字符导致的 bug：确认一个看起来像空格的字符到底是 U+0020 还是 U+00A0，或找出某个符号的确切码点。
查 U+2603
输入码点 `U+2603` → 输出 `☃`（雪人 Snowman）；按名称 `snowman` 也能命中。名称来自内置 Unicode 标准名称表，覆盖页面可浏览区段与常用符号区。

❓ 常见问题（FAQ）

码点写错会怎样？
超出 U+10FFFF 或格式不合法的码点不会按码点解析，会退回逐字符查询；区段外的合法码点仍可查看详情，名称按规则推导或如实标注未收录。
为什么同一个字有两个码点？
可能涉及三种情况：全角/半角形式（如 Ａ 与 A）、兼容区字符（为兼容旧编码而重复收录），以及组合字符（基础字母 + 组合音标，如 é 可由 e + U+0301 组成）。处理文本时应先做 Unicode 归一化（NFC/NFKC），否则比较与检索会出现「看起来一样却不相等」。
