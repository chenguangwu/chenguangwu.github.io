🌎 Locale Lookup

📐 工作原理与说明
BCP 47 解析：按 - 或 _ 分割后做 canonical 规范化（语言小写 / script 首字母大写 / region 大写）；查表按「精确 → language+region（script 须一致）→ 逐级截尾」回退，故 EN-US / en_us / zh-Hans-CN 均可命中；库未收录时按 RFC 5646 语法校验 language(-extlang)(-script)(-region 两位字母或三位 UN M.49 数字)(-variant 含 4 位数字)(-extension singleton)(-privateuse x-)；用户输入与子标签写回页面前统一 HTML 转义
查询 BCP 47 区域设置（locale）标识。
  • 结构：language[-Script][-REGION]，如 zh-Hans-CN、en-US、pt-BR。
  • 组成：语言（ISO 639）、文字（ISO 15924，如 Hans/Hant）、地区（ISO 3166-1）。
  • 影响：决定日期、数字、货币的格式化方式，排序规则与翻译选择。
  • 回退：找不到精确匹配时按语言回退，如 zh-CN → zh。

❓ 常见问题（FAQ）

locale 影响什么？
日期/数字/货币格式与翻译。
为什么同一段代码在不同环境输出不同？
因为格式化会取运行环境的默认 locale：日期分隔符、千分位符号、小数点、一周起始日都可能不同。服务端渲染时用户 locale 与服务器 locale 又常常不一致。稳妥做法是显式指定 locale 参数，并在测试中覆盖主要目标区域。
