📚 技术说明

encodeURI vs encodeURIComponent

encodeURI：用于编码完整的 URL，保留 URL 特殊字符（如 : / ? # [ ] @ ! $ & ' ( ) * + , ; =）。适用于整个 URL 编码。

encodeURIComponent：用于编码 URL 组件（如参数值），除了字母数字和 - _ . ! ~ * ' ( ) 外全部编码。适用于查询参数值编码。

URL 规范化

URL 规范化包括：统一协议和主机名小写、移除默认端口（http:80 / https:443）、移除多余斜杠、解码不必要的百分号编码、排序查询参数等，使同一资源的不同 URL 表示形式统一。

百分号编码规则

百分号编码使用 % 后跟两位十六进制数表示一个字节。对于 UTF-8 字符，每个中文字符通常编码为 3 个字节（如 %E4%B8%AD）。URL 中的保留字符需要编码才能作为参数值使用。

💡 常见使用场景

  • 构造查询参数：把含空格、&、=、中文的值安全拼进 URL，避免被误解析为分隔符。
  • 在 HTML 表单、API 请求里转义特殊字符。
  • 还原被编码的链接，查看原始参数。
参数编码
把 a b&c=d 编码为 a%20b%26c%3Dd，服务端收到后能正确还原成参数 a=「a b」、c=「d」，而不会被 & 误断成两个参数。

❓ 常见问题（FAQ）

encodeURIComponent 和 encodeURI 有什么不同？
encodeURIComponent 会编码几乎全部特殊字符（含 & = ? /），适合编码「参数值」；encodeURI 保留 : / ? # 等结构字符，适合编码「整条 URL」，用错会导致参数被切开。
哪些字符必须编码？
空格、#、%、&、+、=、?、/、非 ASCII 字符（如中文）在作为参数值出现时都应编码，否则会破坏 URL 结构或被服务端错误解析。
