🔄 Line Ending Converter

📐 工作原理与说明
先统计原文中三种换行的数量：回车换行、单独回车（回车后不紧跟换行）、单独换行（换行前不是回车），总换行数为三者之和；总数为 0 时提示文本中未检测到换行符。随后把文本中所有换行统一替换为目标换行符。展示三种换行的数量与总换行数，并给出主换行符判定、文本行数（总换行数不为 0 时取总换行数加 1，否则为 1）、字符数与 UTF-8 字节数
在 LF、CRLF、CR 三种换行符之间转换。
  • 三种行尾：LF（\n，Unix/macOS）、CRLF（\r\n，Windows）、CR（\r，旧 Mac）。
  • 转换：统一替换行结束符；需避免误替换文本中表示换行的字面 \n 字符串。
  • 统一策略：Git 可用 core.autocrlf 或 .gitattributes 规范行尾。
  • 问题：混用行尾会造成 diff 噪音，并让 shell 脚本报 ^M 错误。

❓ 常见问题（FAQ）

为何要统一？
跨平台脚本/校验常因换行不一致报错。
Git 能自动处理换行吗？
可以。core.autocrlf=true 在检出时转 CRLF、提交时转 LF（适合 Windows）；Linux/macOS 应设为 input（提交时转 LF，检出不变）。更可靠的做法是在仓库里加 .gitattributes（如 * text=auto）统一约定，避免依赖每个人的本地配置。
