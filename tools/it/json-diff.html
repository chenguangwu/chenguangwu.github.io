📐 工作原理与说明
左右文本各自 JSON.parse 后比对，产出路径级差异列表，按 op 分为 add（新增）、del（删除）、mod（修改）三类并分别计数，同时统计两侧相同的节点数；差异数为 0 时提示两个 JSON 完全相同。对比模式分两种：深度对比递归展开每一层（数组默认按下标逐项对齐），简单对比只看顶层键、嵌套变化合并成一处 mod。勾选「数组按内容匹配」后，数组改用「规范序列化键 + 最长公共子序列」先对齐相同元素再比对，元素换序不再被报成逐项修改。行级对照把两侧按缩进 2 空格序列化后按行切分，再做逐行差异生成左视图、右视图与合并视图。任一侧为空时提示输入完整
对比两份 JSON 并标出差异。
  • 方法：递归比较两棵 JSON 树，标记新增、删除与值变更的节点。
  • 数组：默认按索引对齐；勾选「数组按内容匹配」后按元素内容对齐，后者对元素顺序变化更友好。
  • 输出：变更路径（如 a.b[0].c）、旧值、新值与变更类型。
  • 用途：接口变更审查、配置比对、回归测试断言。

❓ 常见问题（FAQ）

数组顺序影响对比吗？
默认按位置比对；勾选「数组按内容匹配」后改为按元素内容对齐，元素换序不再被报成逐项修改。
为什么数字 1 和字符串 "1" 被判为不同？
因为 JSON 是有类型的，类型不同即视为不同值，这是严格比较的默认行为。若只关心结构差异，可开启「忽略类型」或先做规范化；同时注意 1.0 与 1 这类表示差异，以及对象键顺序——键序在语义上无意义，但朴素文本对比会把它当差异。
