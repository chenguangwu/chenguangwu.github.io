📐 工作原理与说明
The chart shows the theoretical entropy upper bound for each random password; with one password, it adds character pools category by category and shows the upper bound as each set is enabled. Passphrases are not estimated from a character pool: their choice space is N words drawn without replacement from 64, plus the independent trailing digit and symbol choices. Fixed capitalization and separators add no entropy.
Generated with a cryptographically secure random source (crypto.getRandomValues), with adjustable length and character sets (upper- and lowercase letters, digits, symbols). Random passwords force at least one character from every enabled category, so the page shows a theoretical upper bound (≤ length × log₂(pool size)); actual randomness is lower. Passphrases draw words without replacement and add any trailing random digit/symbol, so the value shown is the exact entropy of that generation process.

  • 长度优先: 密码长度比复杂度更重要，16位随机密码远强于8位复杂密码
  • 唯一密码: 每个账户使用不同密码，使用密码管理器管理
  • 避免常见模式: 不要使用生日、姓名、qwerty、123456等常见密码
  • 密码短语: 由多个单词组成的密码短语更容易记忆且更安全
  • 定期更换: 重要账户密码建议每90天更换一次
  • 启用2FA: 重要账户务必开启双重验证
  • 不要共享: 不要通过邮件、即时通讯等方式发送密码
  • 谨慎存储: 使用专业密码管理器，不要明文存储在文档中

❓ 常见问题（FAQ）

多长够安全？
随机含四类字符 12+ 位可抗在线爆破，离线需更长。
为什么有的网站不接受我生成的口令？
通常是字符限制：部分系统不允许某些符号、限制长度上限，或要求必须包含（或禁止包含）特定字符类别。另有少数系统在传输或存储时错误处理了特殊字符。遇到这种情况应在允许的字符集内重新生成，而不是把口令改短来迁就规则。
