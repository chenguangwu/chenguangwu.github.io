按选项处理：开启移除注释时删掉块注释；随后把连续空白压缩为单个空格，把左花括号连同两侧空白替换为「空格 + 左花括号 + 换行 + 缩进」，把分号及其后空白替换为「分号 + 换行 + 缩进」，把逗号及其后空白替换为「逗号 + 空格」，把右花括号连同两侧空白替换为「换行 + 右花括号 + 两个换行」，最后合并连续空行。缩进按选项取制表符或指定数量的空格
压缩或美化 CSS 代码。
  • 压缩：删除注释与多余空白、去掉最后一条声明的分号、缩写颜色（#ffffff → #fff）。
  • 美化：反向格式化，按规则缩进换行，便于阅读与 diff。
  • 风险：激进压缩可能影响 CSS hack（如 * _ 前缀）与 @media 语义，需回归测试。
  • 收益：减小体积、加快解析；与 gzip/brotli 压缩叠加使用效果更佳。

📖 使用说明

功能说明

  • 美化格式化：统一缩进、换行，使CSS结构清晰易读
  • 压缩：移除所有注释、空白、换行，生成最小体积CSS
  • 压缩率统计：实时显示压缩前后体积对比
  • 历史记录：自动保存处理记录，可快速恢复

压缩优化项

  • 移除 /* comments */ 注释
  • 移除多余空白字符和换行
  • 移除最后一个分号
  • 保留必要空格（选择器之间）
  • 颜色值优化（如 #ffffff → #fff）

❓ 常见问题（FAQ）

压缩影响调试吗？
会，生产用压缩、开发用源文件。
为什么要配合 source map？
压缩后所有规则挤在一行，浏览器 DevTools 里看到的位置无法对应源码。生成 .map 文件并在产物末尾保留对应注释，DevTools 就能映射回原始文件与行号，定位问题时不必先切回未压缩版本。
