📄 JSON Formatter

Syntax highlighting, tree view, sorting, escape/unescape, JSONP extraction. Pure frontend, no upload.

📐 工作原理与说明
对最近一次合法 JSON 递归统计各类型节点数：对象、数组、字符串、数字、布尔、空值，以及总节点数、最大层级深度、对象键总数。柱状图按对象、数组、字符串、数字、布尔、空值的固定顺序展示节点数分布（图高 200）。明细表逐行输出统计项与数值：总节点数、最大层级深度、对象键总数、值节点数（字符串 + 数字 + 布尔 + 空值之和）、序列化字符数（重新序列化后的字符串长度），随后再逐行输出上述六类各自的节点数；表头在英文态下替换为对应英文
将 JSON 文本解析为对象树后重新序列化：美化按 2/4 空格缩进、保留层级；压缩去除空白；校验在解析失败时定位错误行列。支持语法高亮与层级折叠便于阅读。
  • 合法 JSON 要求双引号键、无尾逗号、无注释（JSON5 才支持）。
  • 排序规则：默认字典序（Unicode 逐字符比较，10 排在 2 前）；可切换自然序（数字段按数值比较，2 排在 10 前）。整数形式键名也会按所选规则保持顺序，不会因 JavaScript 对象枚举改写。
  • 超出 JavaScript 安全整数范围或有效数字过多的数字按原始字面量保留，避免大 ID 被悄悄改写。
  • 纯前端解析，粘贴内容不离开浏览器，适合脱敏前本地处理。

💡 常见使用场景

  • 美化 / 压缩 JSON：把压缩成单行的 JSON 按缩进展开便于阅读，或反向压缩以节省网络传输与日志体积。JSON 语法规范见 RFC 8259（https://datatracker.ietf.org/doc/html/rfc8259）。
  • 定位语法错误：解析失败时本工具会标出错误所在的行与列，快速定位缺引号、尾逗号、注释等非法的位置。
  • 本地脱敏前处理：粘贴含敏感字段的 JSON，在浏览器内格式化 / 抽取，内容不上传，适合在提交到协作工具前先理清结构。
格式化与压缩
输入 {"name":"John","age":30,"tags":["a","b"]} 点击美化后按 2 空格缩进展开为多行；点击压缩则去除所有空白回到单行。仅调整空白，键值与顺序不变。
校验报错定位
输入 {"a":1,}，末尾多了一个逗号（非法尾逗号），解析失败并提示错误行列（如第 1 行第 8 列附近），据此删除多余逗号即可通过。标准 JSON 不允许尾逗号与注释。

❓ 常见问题（FAQ）

格式化会改变数据吗？
不会。格式化只增删空白与调整缩进，键值、数组顺序、数据类型全部保持不变；压缩是格式化的逆操作。
为什么解析失败会报出行列？
JSON 解析器在遇错时记录已消费的字符位置，可换算成行号与列号。常见错误：键或字符串用了单引号、键名无双引号、存在尾逗号、混入了 // 或 /* 注释（标准 JSON 不支持，JSON5 才支持）。
大文件会变慢吗？
纯前端解析对几 MB 的 JSON 一般仍可接受；若文件极大（数十 MB），建议先用日志 / 编辑器的局部片段排查，避免一次性粘贴卡顿。
