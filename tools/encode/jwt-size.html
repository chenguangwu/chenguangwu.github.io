📏 JWT Length Estimator

Estimate JWT string length for given header and payload structures.

📐 计算公式与说明

JWT = base64url(header) + . + base64url(payload) + . + base64url(signature)

Base64 编码约膨胀 33%。

📚 深度解析：JWT 令牌长度估算与开销

💡 常见使用场景

  • 按 header/payload/signature 大小估算编码后 JWT 总长度。
  • 评估会话令牌对请求头体积的影响。
  • 判断是否需要用紧凑声明减少长度。
精简声明
header+payload 各 120 字节、签名 32 字节，Base64 膨胀约 33% 后令牌约 250 字节，适合放入 Cookie。
声明过多导致超长
payload 达 1 KB 时令牌可超 1.4 KB，可能触及网关头部上限，应裁剪非必要声明。

❓ 常见问题（FAQ）

JWT 为什么会变长？
三段均由 Base64URL 编码，原始 JSON 体积会膨胀约 33%，签名段再叠加固定长度。
多长算安全？
安全性与长度无直接关系，但过长会占用请求头配额，建议仅放必要声明。
