🤖 Multi-Agent Communication Overhead Estimator

Estimate the communication overhead of a fully-connected multi-agent system from agent count and message frequency, before you commit to an architecture.

📐 计算公式 / 原理
多智能体通信开销（本页代码口径）：消息总数=智能体数 n×(n−1)×轮数（全连接两两通道，每轮每对通道双向各计 1 条）；总流量 KB=消息总数×单条消息大小 KB。校验：无强校验，空值按 0 兜底。判据：无固定分级，n 增大消息总数按平方量级增长。
全连接广播模式下每个智能体每轮要向其余 n−1 个发消息，通信量随智能体数量呈平方增长，这是多智能体系统规模化的主要瓶颈。改为分层或共享黑板（blackboard）可把复杂度降到线性。

📐 计算公式与说明

判读与延伸（与上方公式互补，共用同一组输入）：两两通道数=n×(n−1)；每智能体消息=n×(n−1)×轮数÷n=(n−1)×轮数；增加 1 个智能体后消息总数变为原值的(n+1)×n÷(n×(n−1)) 倍，页面按同口径展示扩张倍率与历史对照。校验：与上方一致，空值按 0 兜底。判据：无固定分级，轮数与消息规模线性正相关。

随智能体数平方增长，需谨慎设计拓扑。

📚 深度解析：多智能体通信开销

💡 常见使用场景

  • 全连接拓扑下每轮消息数=C(n,2)=n(n−1)/2，随智能体数平方增长。
  • 开销=消息数×单消息体量(上下文/token)，是通信瓶颈与成本主因。
  • 可用分层/星型/广播拓扑削减边数，或用摘要压缩降低单消息体量。
全连接开销
n=10 个智能体全连接：每轮消息=10×9/2=45 条。若单条含 2k token，每轮通信≈90k token；n=20 时消息=190，开销约 4 倍，增长极快。

❓ 常见问题（FAQ）

怎么降低多智能体通信成本？
改全连接为星型/分层(中心协调)，减少边数；消息用摘要而非全文；并设定通信轮次上限，避免无限对话空转。
全连接有必要吗？
多数任务不需要。全连接让任意两体直连、信息同步快但成本高；若任务可分解，子团队+汇总更高效，性价比更好。
