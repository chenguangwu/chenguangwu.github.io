⏱️ Epoch Training Time Estimator

Estimate the time for one epoch and for the whole run from per-step cost and step count. Useful for scheduling and compute budgeting.

📐 计算公式 / 原理
总步数 = ⌈轮数 × 样本数 / 批量⌉；训练时长(小时) = 轮数 × 样本数 / 批量 / 速度 / 3600
把步数除以单卡吞吐（样本/秒）再换算成小时，用于排期与算力预算评估。速度为经验值，实际受数据加载、混合精度、通信开销影响，多卡时还要乘上并行效率（通常 0.7–0.9）。

📐 计算公式与说明

训练耗时估算口径说明（本页代码口径，与上方公式互补）：输入按空值即 0 兜底，总步数与时长任一结果非有限（批量或吞吐为 0、输入为空）即追加提示「部分结果无定义（分母为 0 或输入为空）」。判据：无固定分级；时长与吞吐成反比、与轮数×样本数成正比，批量同时决定步数取整与单批量计算量，加大批量减少步数但单步耗时上升，需整体权衡而非单看一项。

未计通信与 I/O 开销。

📚 深度解析：单轮训练时长

💡 常见使用场景

  • 单轮时长≈每步平均耗时×步数；总时长=单轮×轮数(+验证/通信开销)。
  • 步数=⌈样本数/batch⌉，故增大 batch 可减少步数、缩短单轮(受显存上限)。
  • 分布式加速比受通信与负载均衡限制，并非线性随 GPU 数提升。
训练排期
每步 50ms、步数 313、轮数 10 → 单轮≈15.65s，总训练≈156s 不含验证。若数据并行 4 卡步数减半则单轮≈7.8s。

❓ 常见问题（FAQ）

显存不够 batch 又想快怎么办？
用梯度累积模拟大 batch(不增显存)，或降低精度(混合精度)提速；也可优化数据管道减少 IO 等待，避免 GPU 空转。
实测比估算慢很多？
多半是数据加载瓶颈或通信开销。检查 DataLoader 预取、SSD/缓存、NCCL 拓扑；纯计算外的等待会显著拉长单轮。
