  • 除錯後端返回的鑑權 Token：把前端拿到的 JWT 貼上進來，秒看 Header / Payload，確認角色、過期時間等宣告是否正確。

    • 

  • 本地驗籤與教學演示：用 HS256/384/512 配合金鑰在瀏覽器內驗籤，理解簽名如何保證 Token 不被篡改。

用金鑰驗籤
在簽名驗證區選擇 HS256 並填入金鑰（如 your-256-bit-secret），點選驗證簽名。金鑰正確時顯示「簽名有效」，金鑰不符或被篡改時顯示「簽名無效」並給出期望簽名字首，便於比對。


❓ 常見問題（FAQ）




JWT 和 Session 有什麼區別？
Session 把狀態存在服務端，客戶端只持有一個隨機 ID；JWT 把宣告（如使用者 ID、角色、過期時間）編碼進 Token 本身，服務端憑金鑰即可校驗，適合無狀態、跨服務的鑑權，但登出需靠短過期時間 + 重新整理機制或黑名單。


本地驗籤安全嗎？
HS 系列是對稱演算法，驗籤需要和服務端相同的金鑰，金鑰絕不能暴露給前端或提交到倉庫；RS/ES/PS 等非對稱演算法可用公鑰驗籤，私鑰留服務端。本工具純前端執行，金鑰不上傳，僅用於你自己的本地除錯。


為什麼 exp 已經過期還能解析？
解析（Decode）只是把 Base64 還原成 JSON，不做有效性判斷；只有驗籤和過期檢查才會提示狀態。過期僅代表該 Token 不應再被服務端接受，不代表內容不可讀。
