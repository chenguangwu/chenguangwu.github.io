📚 技術說明

encodeURI vs encodeURIComponent

encodeURI：用於編碼完整的 URL，保留 URL 特殊字元（如 : / ? # [ ] @ ! $ & ' ( ) * + , ; =）。適用於整個 URL 編碼。

encodeURIComponent：用於編碼 URL 元件（如引數值），除了字母數字和 - _ . ! ~ * ' ( ) 外全部編碼。適用於查詢引數值編碼。

URL 規範化

URL 規範化包括：統一協議和主機名小寫、移除預設埠（http:80 / https:443）、移除多餘斜槓、解碼不必要的百分號編碼、排序查詢引數等，使同一資源的不同 URL 表示形式統一。

百分號編碼規則

百分號編碼使用 % 後跟兩位十六進位制數表示一個位元組。對於 UTF-8 字元，每個中文字元通常編碼為 3 個位元組（如 %E4%B8%AD）。URL 中的保留字元需要編碼才能作為引數值使用。

📚 深度解析：URL 編碼 / 解碼

💡 常見使用場景

  • 構造查詢引數：把含空格、&、=、中文的值安全拼進 URL，避免被誤解析為分隔符。
  • 在 HTML 表單、API 請求裡轉義特殊字元。
  • 還原被編碼的連結，檢視原始引數。
引數編碼
把 a b&c=d 編碼為 a%20b%26c%3Dd，服務端收到後能正確還原成引數 a=「a b」、c=「d」，而不會被 & 誤斷成兩個引數。

❓ 常見問題（FAQ）

encodeURIComponent 和 encodeURI 有什麼不同？
encodeURIComponent 會編碼幾乎全部特殊字元（含 & = ? /），適合編碼「引數值」；encodeURI 保留 : / ? # 等結構字元，適合編碼「整條 URL」，用錯會導致引數被切開。
哪些字元必須編碼？
空格、#、%、&、+、=、?、/、非 ASCII 字元（如中文）在作為引數值出現時都應編碼，否則會破壞 URL 結構或被服務端錯誤解析。
