# 输出守卫注入排除清单（scripts/_inject_output_guard_v8.py 默认加载）
#
# 背景：v8 的 transform() 是**静态分析**——只要发现 innerHTML 数值输出点就要求注入。
# 但它无法识别「源码已有兜底」与「空值运行时不可达」，因此 dry-run 会长期报一批
# **真机不存在 NaN 路径**的页面，形成悬空待办。本清单把它们固化排除，使 dry-run 归零。
#
# 判定依据（2026-09-23 逐页实证，非推断）：
#   · jsdom 真机模拟：加载页面 → 清空**全部**输入控件（number/text/textarea 置 ''
#     、select 置 selectedIndex=-1）→ 触发 input/change → 扫描所有 [id] 容器文本
#     是否出现独立 NaN / Infinity 词。36 页中仅 3 页命中，且 3 页均为 select 页
#     **无空值选项、有默认选中项** ⇒ 真机用户无法构造该状态，属探针过度构造的假阳性。
#   · 源码兜底核验：如 hvac/fresh-air-load 的 `num()` 把 isNaN 转 null、`fmt()` 把
#     null/NaN 渲染为 '--'，真机输出永远不含字面 NaN。
#
# 排除原因分类（行尾标注）：
#   [A] harness 桩盲区：注入后所属行业 verify 立即失败（headless 无真实 DOM，动态
#       <select> 取不到值 → 插值 NaN → 守卫对**真机正确的输出**误触发）。
#       —— 已实证：注入→verify 失败→回退→verify 恢复全过，一一对应。
#   [B] 文本回显页：输出含用户原文，守卫的 /NaN/ 文本检测会把**用户输入的 "NaN"
#       字样**误判为计算错误并替换掉正常结果。it/html-escape 已实证（注入点
#       `const __h0=text` 直接就是用户输入）。
#   [C] 真机兜底页：源码已做 isNaN/null 兜底，或空值运行时不可达。
#
# 维护：新增分类页请重跑 `/tmp/jsdom_empty_probe.cjs`（真机模拟）后再决定是否列入。
#       本清单只影响 dry-run 报告，不影响真机行为。
